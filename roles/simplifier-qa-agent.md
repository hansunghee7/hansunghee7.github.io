# simplifier-qa-agent — 나만의 LLM(RAG 에이전트) 구축 스레드 요약

## ① 목적과 범위
사장님(한성희/Simplifier) 본인의 블로그 글(~600개)과 책 2권(《기획자의 질문법》
《UX의 언어들》)을 근거로 답하는 RAG 기반 AI 에이전트 "Simplifier Q&A"를
Simplifier Studio(`insight-7b3e9f2c/ask.html`) 안에 실제로 배포·운영 가능한
수준으로 만드는 스레드. 이후 같은 코퍼스를 Claude Code 안에서 직접 활용하는
`prd-draft` 스킬로 확장해, PRD/전략 문서를 사장님 자신의 프레임워크로 작성하는
데까지 이어졌다(첫 실사용: `shorts-lab/LAUNCH_PRD.md`).

## ② 확정된 주요 결정사항
- **비용 원칙(최우선, 반복 확인 필요)**: "가성비 좋고 무료로 접근할 수 있는
  방법을 항상 먼저 제안할 것" — 구독 해지까지 언급된 강한 요구. Claude/Anthropic
  유료 상품으로 유인하지 말 것.
- **아키텍처**: Voyage `voyage-4`(1024차원) 임베딩 + Supabase pgvector
  (`content_chunks` 테이블, `match_content_chunks` RPC) + Cloudflare Worker
  (`simplifier-agent/worker-ask.js`, 키는 서버 사이드에만) + Gemini
  `gemini-flash-lite-latest`(무료 티어 한도 때문에 여러 모델 교체 끝에 정착).
- **데이터 경계(절대 원칙)**: 책 원문은 공개 저장소에 절대 포함 안 됨. 블로그만
  GitHub Actions(`scripts/sync_agent_corpus.py`)로 자동 동기화, 책은 로컬에서만
  `scripts/ingest.py`로 수동 임베딩(`book_sources/`는 .gitignore 대상).
- **피드백 루프 구축 완료**: `qa_feedback` 테이블 + 👍👎 UI가 모든 Q&A를 기록.
  "정확도를 어떻게 올릴까"라는 질문에 대한 답은 이 로그를 실제로 리뷰하는
  것 — 아직 실행 안 됨(③ 참고).
- **범위를 의도적으로 좁힘**: 방문자 공개용 버전(회원가입/결제 인프라 필요),
  검색 재랭킹, 쿼리 라우터는 전부 "지금 안 해도 됨"으로 사용자가 직접 판단.
  Studio의 운영 데이터(사이트/SNS/북 인사이트 등)도 RAG 코퍼스에 넣지 않기로
  함 — 지식 콘텐츠가 아니라 분석 데이터라 답변 품질을 오히려 떨어뜨릴 수 있음.
- **UX 완성**: 마크다운 렌더링, 실시간 스트리밍+타이프라이터 애니메이션, 에러
  재시도 버튼, 출처 칩(블로그는 원문 링크, 책은 예스24 링크 — Supabase에
  `source_url` 수동 백필 필요했음), 복사 버튼, 멀티턴 대화 기억(최근 5턴을
  클라이언트가 들고 있다가 Worker에 같이 전송 → Gemini `contents` 히스토리로
  전달). 메뉴명은 "AI에게 물어보기" → "Simplifier Q&A" → **"Simplifier와의
  대화"**로 최종 확정.
- **시스템 프롬프트 2모드**: 사실 확인(자료에 없으면 "못 찾음") vs 코칭(검색된
  방법론을 실제로 적용해 사용자에게 질문 던지기) — 사용자가 코칭 모드를 선택.
- **`prd-draft` 스킬 신설**: `GitHub/.claude/skills/prd-draft/`(특정 저장소 안이
  아니라 두 저장소가 공유하는 최상위 폴더에 위치). `scripts/search_corpus.py`가
  같은 Voyage/Supabase 코퍼스를 검색해오면, Gemini를 거치지 않고 **Claude Code가
  직접** 그 근거로 PRD/전략 문서를 작성한다 — 프로덕션 챗봇(가벼운 모델)보다
  추론 품질이 높은 걸 개인 생산성에 활용하는 설계. Voyage 무료 티어(분당 3회)
  때문에 검색어 사이 21초씩 쉬도록 페이싱 넣음.
- **첫 실사용 검증**: `shorts-lab/LAUNCH_PRD.md`(신기한 아파트사전 채널 수익화
  PRD) 작성 중, `PUBLISHING.md`를 얕게만 읽고 쓴 v1이 이미 확정된 "다크 런칭"
  규칙(리빌 전까지 심플리파이어 쪽에서 채널 언급 금지)과 충돌하는 잘못된 실행
  순서를 제안한 적이 있음 — 재점검 후 v2에서 수정. **교훈: 이 스킬을 쓸 땐
  대상 프로젝트의 기존 정본 문서를 얕은 검색만으로 대체하지 말고 반드시 전체를
  먼저 읽을 것.**
- **`CLAUDE.md`의 "main 직접 push 금지" 규칙(2026-08-29 도입)을 뒤늦게 확인**:
  이 스레드가 세션 중 만든 커밋들(복사버튼·대화기억·메뉴명·칩크기·책링크 등)은
  전부 그 규칙 도입 전이라 예외로 처리됨. **앞으로 이 저장소에 낼 변경은 작업
  브랜치 + PR(auto-merge) 방식을 따라야 함.**

## ③ 진행 중이거나 남아있는 작업
- [ ] `qa_feedback`의 👎 로그를 실제로 리뷰하는 습관 — 아직 시작 안 함(정확도
      개선의 1순위로 합의됐지만 실행 전).
- [ ] 골든 테스트셋(질문-정답 문서 20~30개) 구축 — 튜닝을 감이 아니라 데이터로
      판단하기 위한 다음 단계, 아직 없음.
- [ ] `shorts-lab/LAUNCH_PRD.md`의 "확인 필요" 표시 항목들(RICE 점수 정식화,
      브랜드 결합 가설 검증, 채널명 최종 재검토) — 사장님 판단 대기.
- [ ] `scripts/ask.py`(로컬 CLI 테스트용)는 대화 기억(멀티턴)을 아직 지원 안 함
      — Worker/`ask.html`에만 구현됨. 급하진 않지만 어긋나 있는 상태.
- [ ] `prd-draft` 스킬은 정식 eval(벤치마크) 없이 사용자 확인만으로 검증됨 —
      개인용 도구라 지금은 충분하다고 판단했지만, 스킬이 자주 안 좋은 결과를
      내면 정식 iteration(스킬 생성기 워크플로우) 고려.
