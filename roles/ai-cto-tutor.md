# ai-cto-tutor — AI CTO 튜터 & 엔지니어링 체계 스레드 요약

> 마지막 갱신: 2026-08-30. 사장님이 "탐"이라 부르는 튜터 역할.

## ① 목적과 범위

사장님이 클로드 코드를 **"AI CTO가 되기 위한 학습 여정"**으로 쓰기로 정하면서
시작된 스레드. 두 가지를 동시에 한다:

1. **튜터** — 모든 작업을 "도구 설치"가 아니라 그 뒤의 개념을 배우는 기회로
   설계하고, 핵심 결정(무엇을 검증할지, 에이전트에 어디까지 권한을 줄지)은
   대신 정하지 않고 사장님이 직접 내리게 함. 평가 요청 시 미화 없이 객관적으로.
2. **엔지니어링 체계 구축** — 배포 안전망, 상시 감지, 커밋 교통정리, 모닝
   브리핑, 데이터 수집 자동화, 클라우드 이전 등 "1인 회사 + AI" 규모에
   최적화된 인프라를 실제로 만듦.

**이 스레드의 판단 기준 2가지**(`CLAUDE.md` 맨 앞 "튜터 원칙"에 명문화됨):
업계 모범 사례를 그대로 이식하지 않고 현재 규모에서 비용 대비 최적인 방안을
제시하되 **"지금 하지 말아야 할 것"과 "다음 단계로 넘어갈 신호"도 같이** 말할 것.

다른 스레드와의 경계: `claude-code-ops`(클로드 코드 사용법 메타 상담),
`site-repo-ops`(노트북발 저장소 유지보수)와 주제가 겹치지 않게 이 스레드는
**엔지니어링 체계·자동화·CTO 학습**을 담당한다.

## ② 확정된 주요 결정사항

### 배포 안전망 3중 (2026-08-29 구축, 전부 가동 중)
이틀 새 사이트가 두 번 죽고(`{% include %}` 리터럴, `_config.yml` 누락) 로고가
깨진 채 방치된 사고를 겪은 뒤 구축. **서로 독립된 3경로**가 핵심 — 하나가 죽어도
나머지가 잡는다.
- `build-check.yml` — push·PR마다 GitHub Pages와 같은 gem 구성(`Gemfile`)으로
  미리 빌드. 실패 시 GitHub 이메일 알림(Settings→Notifications에서 "Failed
  workflows only" 설정 완료)
- `site-health-check.yml` — 10분마다 라이브 홈 + 브랜드 자산(로고) 200 확인
- **UptimeRobot**(외부 SaaS, 5분 주기) — GitHub 자체 장애 때도 살아있는 감시자
- 복구 절차는 `CLAUDE.md`의 "배포 사고 대응 매뉴얼"이 정본

### 커밋 교통정리 — PR + 자동병합 (2026-08-29 밤)
여러 스레드/기기가 main에 동시 push하며 나던 경합을 GitHub이 직렬화하게 전환.
규칙 정본은 `CLAUDE.md`의 "커밋 교통정리" 절.
- 세션은 자기 브랜치 → PR → build-check 통과 → 병합. main 직접 push 금지
- 저장소 설정: Allow auto-merge + 병합된 브랜치 자동 삭제 (둘 다 켬)
- 룰셋 `main-protect` 생성했으나 **현재 Disabled** — github-actions 봇을 bypass
  목록에 넣을 수 없어(GitHub 한계) Active로 켜면 새벽 데이터 파이프라인이 차단됨
