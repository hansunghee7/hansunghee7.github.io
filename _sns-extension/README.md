# Simplifier SNS 인사이트 수집기 (크롬 확장, 개인용)

LinkedIn·Facebook·Instagram·Threads·리멤버 프로필을 열 때 팔로워 수를
자동으로 읽어서, Simplifier Studio의 "SNS 인사이트"에 기록해주는 개인용
크롬 확장입니다. 여기에 더해, 완전히 다른 계정("신기한 아파트사전")의
네이버 클립·인스타그램·스레드·페이스북·틱톡·X 채널 페이지를 열 때
팔로워 등 채널 요약 수치를 읽어 "콘텐츠 인사이트"(`content-insight.html`)
에도 기록합니다(아래 2026-09-01 항목).

## ⚠️ 코드가 바뀌면 "새로고침"만으로는 안 될 수 있습니다

`chrome://extensions`의 새로고침 버튼은 **지금 로드된 그 폴더 안의 파일을
다시 읽는 것**뿐입니다. GitHub에서 새로 받아오는 게 아닙니다. 그 폴더가
예전에 내려받은 zip을 그대로 쓰고 있다면, 아무리 새로고침해도 코드는
그대로입니다(2026-09-03 실제로 하루 종일 헤맨 원인 — 코드는 이미 고쳤는데
사장님 PC의 확장 폴더가 예전 버전이라 반영이 안 됐었다).

**바뀐 코드를 확실히 반영하려면(컴맹 기준 순서)**:
1. `https://github.com/hansunghee7/hansunghee7.github.io/archive/refs/heads/main.zip`
   주소로 새 zip을 받는다.
2. 그 zip을 더블클릭해 압축을 푼다.
3. `chrome://extensions`에서 기존 "Simplifier SNS 인사이트 수집기"를 삭제한다.
4. "압축해제된 확장 프로그램을 로드합니다"로 방금 푼 폴더 안의 `_sns-extension`을
   다시 선택한다.
5. 확장 아이콘을 눌러 "GitHub 연결됨"인지 확인 — 아니면 다시 로그인.
6. 확인하려던 사이트 탭을 완전히 닫았다 새로 연다.

폴더를 새로 지정하면 확장 ID가 바뀌어 로그인 정보가 초기화될 수 있다 —
5번에서 다시 로그인하면 된다.

공통 함수). 이미 저장돼 있던 정크 3건(`content_tiktok_7680573654341586196`
등)도 `assets/data/naver-content.json`에서 직접 지웠다.

## 2026-09-03 변경 — 네이버 클립 개별 조회수, 링크가 아니라 라벨로 찾도록 수정

2026-09-02에 넣은 href 기반 방식이 실제로는 0건만 잡았다. 사장님이
개발자도구로 클립 카드를 직접 열어 확인해주신 결과, 클립 카드는
`<a href>`가 아니라 `<button aria-label="캡션">`이었다 — href 자체가
없으니 href로 항목을 구분하는 기존 방식(인스타·틱톡과 같은 방식)은
원천적으로 안 맞았다. 대신 카드 안에 조회수가
`<span>조회수</span><span>404</span>` 형태로 라벨+숫자 형제 span으로
정확히 있어서, 그 라벨 텍스트로 찾는 방식(`collectLabeledCards`)으로
바꿨다. 진짜 링크가 없어 완벽한 고유 id는 없고, 카드의 캡션(aria-label)
문자열을 해시해 id로 쓴다 — 캡션이 바뀌면 새 항목으로 잡힐 수 있다는
뜻이지만, 클립 개수가 적어 지금은 이 정도로 충분하다.

확장을 새로고침하고 클립 채널 페이지를 한 번 방문한 뒤, 팝업의
"최근 수집 기록"에 `네이버클립` 항목이 성공(조회수 개수 포함)으로
찍히는지 확인해주세요.

## 2026-09-02 변경 — 네이버 클립 개별 조회수 첫 시도 (2026-09-03에 수정됨)

클립이 2개로 늘고 실제 조회수 반응이 보이기 시작해, 채널 요약만 읽던
클립도 인스타·틱톡처럼 게시물별 조회수를 시도했다. 첫 시도는 href
기반이었는데 실제로 안 맞았다 — 자세한 내용은 위 2026-09-03 항목 참고.

## 2026-09-01 변경 (7) — 릴스 캡션이 비어 있을 때 링크 라벨로 대체

인스타 릴스 캡션은 보통 썸네일 `<img alt>`에 들어있는데, 가끔(실측 1건)
그 항목만 alt가 비어 콘텐츠 인사이트에 "(제목 없음)"으로 뜨는 경우가
있었다. alt가 없으면 링크 자체의 `aria-label`·`title` 속성도 같은
캡션을 담고 있는 경우가 많아 대신 읽도록 폴백을 추가했다.

## 2026-09-01 변경 (6) — "확장 새로고침 후 탭 방치" 시 조용히 실패하던 문제 방지

**중요: 확장을 `chrome://extensions`에서 새로고침한 뒤에는, 이미 열려
있던 스튜디오 탭도 반드시 새로고침(F5)하세요.** 안 그러면 그 탭의
content-script가 예전 연결을 문 채 "고아" 상태가 되어, 새로고침
버튼을 눌러도 `chrome.runtime`이 없어서 아무 일도 안 일어납니다
(2026-09-01 실제 발생 확인 — "Cannot read properties of undefined
(reading 'sendMessage')"). 코드에서도 이 경우 예외를 조용히 삼키도록
방어했지만, 근본적으로는 탭을 새로고침해야 다시 연결됩니다.

## 2026-09-01 변경 (5) — 화면 밖 썸네일까지 스크롤해서 로딩

인스타 썸네일은 잡혔는데 틱톡 그리드 두 번째 항목(화면 스크롤 안 된
위치)은 계속 안 잡혔다 — 지연 로딩이 화면에 실제로 보여야만 트리거되기
때문. 백그라운드 라운드로 열렸을 때(`document.hidden`, 사용자가 직접
보는 탭이 아닐 때만)는 썸네일 없는 타일을 화면 안으로 스크롤해 로딩을
강제로 유도한다. 사용자가 직접 보는 탭에서는 화면이 제멋대로 스크롤되면
안 되므로 이 동작을 안 한다 — 그런 탭은 다음 백그라운드 라운드(새로고침
버튼)가 마저 채워준다.

## 2026-09-01 변경 (4) — 썸네일이 여전히 안 뜨던 문제 수정

병합 후 실제로 확인해보니(사장님 화면 캡처) 썸네일이 여전히 빈 회색
박스였습니다 — 틱톡은 `<img src>`가 지연 로딩용 1x1 투명 gif
자리표시자였고, 인스타는 `<img>` 자체가 그 링크 안에 안 잡혔습니다.
`data-src`류 속성·`srcset`·배경이미지(`background-image`)까지 순서대로
확인하도록 고치고, 조회수만 찾고 바로 끝내지 않고 썸네일이 채워질
때까지(최대 15초) 더 기다리도록 했습니다.

## 2026-09-01 변경 (2) — 인스타 릴스·틱톡 게시물별 조회수 추가

## 2026-09-01 변경 (1) — "신기한 아파트사전" 채널 요약 추가, 확장을 새로고침하세요

네이버 클립·인스타그램·스레드·페이스북·틱톡·X("신기한 아파트사전" 채널)
프로필 페이지를 열면 팔로워(플랫폼에 따라 팔로잉·콘텐츠 수·좋아요도)를
읽어 `assets/data/naver-content.json`의 `channels`에 기록합니다.
클립은 네이버 쪽 API가 로그인 세션을 요구해서 서버 자동화(GitHub

"심플리파이어" 회사 계정과 무관해서, 방문해도 다른 5개 SNS를 한꺼번에

"다른 채널" 카드는 실제로 값이 잘 잡히는 채널이 자동으로 위로 오도록
정렬됩니다.

**버그 수정**: 기존 회사 스레드(`threads`) 규칙에 URL 범위 제한이 없어서,
"신기한 아파트사전" 스레드를 방문했을 때도 회사 스레드 팔로워로 잘못
기록되는 문제가 있었습니다(2026-09-01 실제 발생 확인). 이제 회사 스레드는
`@simplifier_seoul`로 정확히 좁혔습니다.

## 2026-08-30 변경 — 확장을 새로고침하세요

네 가지가 바뀌었습니다. **`chrome://extensions`에서 이 확장의 새로고침
아이콘을 한 번 눌러야 적용됩니다.**

1. **브런치·네이버블로그·로켓펀치는 이제 서버가 자동 수집합니다.**
   로그인 없이 공개 페이지에서 숫자가 보이는 채널이라, GitHub Actions가
   매일 새벽 4시에 대신 긁습니다(`scripts/fetch_sns_public.py`).
   PC를 안 켜도 기록이 쌓입니다. 확장이 여는 탭은 8개 → 5개로 줄었습니다.
   여기 남은 5개는 전부 **로그인해야만 숫자가 보여** 서버에서 못 읽는
   채널입니다(링크드인은 공식 API마저 팔로워 수를 파트너 전용으로 막았고
   신규 접수도 닫혀 있습니다).
2. **탭이 사용자 창에 끼어들지 않습니다.** 최소화된 별도 창을 잠깐 만들어
   거기서 열고 통째로 닫습니다. 작업 표시줄에 창 하나가 잠깐 생겼다
   사라지는 정도입니다.
3. **탭이 두 배로 열리던 버그를 고쳤습니다.** SNS를 자연스럽게 방문해
   한 바퀴 돈 직후에 새로고침 버튼까지 누르면 라운드가 겹쳐 16개가
   열렸습니다. 이제 라운드가 도는 동안(90초) 들어온 추가 요청은
   무시합니다.
4. **선택자가 깨져도 조용히 지나가지 않습니다.** 지금까지는 팔로워 수
   문구를 못 찾으면 콘솔 로그만 남고 아무도 몰랐습니다. 이제 같은
   플랫폼이 **2번 연속** 실패하면 팝업에 노란 경고("○○ 팔로워 수를 N번
   연속 못 찾았습니다")가 뜨고 알림도 옵니다. 성공하면 경고는 저절로
   사라집니다.

## 설치 방법 (한 번만 하면 됨)

1. 크롬 주소창에 `chrome://extensions` 입력 후 이동
2. 오른쪽 위 "개발자 모드" 켜기
3. "압축해제된 확장 프로그램을 로드합니다" 버튼 클릭
4. 이 폴더(`_sns-extension`)를 선택
5. 브라우저 오른쪽 위 확장 아이콘 목록에서 "Simplifier SNS 인사이트 수집기" 아이콘 클릭
6. "GitHub 연결" 버튼 클릭 → 뜨는 창에서 GitHub 로그인(글쓰기 CMS 로그인할 때와 동일한 방식)

여기까지 하면 끝입니다. 이후로는 평소처럼 멀티 퍼블리싱에서 "새 글쓰기
열기" 버튼으로 각 SNS를 방문할 때마다, 그 화면에 보이는 팔로워 수가
자동으로 기록됩니다.

## 확인하는 곳

Simplifier Studio → "SNS 인사이트" 탭에서 쌓인 기록을 그래프로 볼 수
있습니다.

## 참고

- 이 확장은 오직 본인 브라우저 안에서만 동작하고, 본인이 실제로 로그인한
  화면에 보이는 숫자만 읽습니다. 어딘가에 몰래 접속하거나 비밀번호를
  가져가지 않습니다.
- 사이트가 화면을 바꾸면 숫자를 못 찾을 수 있습니다. 그럴 땐 그 페이지에
  실제로 어떻게 적혀 있는지 알려주시면 바로 고칠 수 있습니다.
- 크롬 확장을 새로고침해야 할 때(코드가 바뀌었을 때)는 `chrome://extensions`
  에서 이 확장의 새로고침 아이콘을 누르면 됩니다.
