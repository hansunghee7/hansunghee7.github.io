# 슈퍼구루 (사장님 명명 2026-10-22)

"구루들의 실용성 있는 방법을 찾는 스킬." 링크가 살아있는지가 아니라 **커뮤니티 공감(여러 사람의 반복 추천, 스타 수)** 을 기준으로 하고, 결과는 조사 보고서가 아니라 **우리가 바로 할 순서안**으로 끝낸다. 슈퍼리서치(공용-오케스트레이션 #3)의 자매 절차다.

## 본보기 3건 (이 절차의 근거 실측)
- 멀티 플랫폼 영상 등록·관리 (docs/슈퍼발행.md): 자료 C:/work/_ops/crosspost_research/
- 롱폼 유튜브·구글 검색 노출 (챕터·키워드 줄 적용): 자료 C:/work/_ops/guru_search/
- 로컬 오픈 영상 모델 vs Flow 실측 방법: 자료 C:/work/_ops/guru_local/

## 순서
1. **입력**: 주제 한 줄 + 우리 현황 실측 숫자(비밀·가격·고객 정보 없이). 현황 숫자가 질의의 절반이다.
2. **질의 틀(고정)**: 영향 큰 순서 / 가장 싼 순서 / 과대평가된 것·저평가된 것 / 흔한 실수와 편향 / 합의와 엇갈림 / 경고 사항. "커뮤니티 공감 중심, 수치는 대략, 지어내지 말고 확실하지 않으면 확신 낮음"을 문장으로 넣는다.
3. **병렬 조사**(같은 본문으로 셋): 제미나이 검색 `python scripts/ops/gemini_route.py --search --who 핏 --max-output-tokens 7000 @질의.txt`, 덱스 `bash scripts/ops/ask_dex.sh 카드 출력`, 비티 `BT_MODEL=vertex bash scripts/ops/ask_bt.sh 카드 출력`. 덱스·비티 카드 첫 줄은 `업무대장: DX<n>`/`BT<n>`이고 번호는 `python scripts/ops/ledger_row.py add dex|bt "제목" --next "…"`로 먼저 만든다. 각각 추적되는 백그라운드로 건다.
4. **정리**: 합의(셋이 같음) / 엇갈림(그대로 쓰지 않고 이유 기록) / 근거 없는 숫자는 `[추정]`. 제미나이 출처 링크는 vertexaisearch 리디렉션이라 본문만 읽고, 쓸 링크는 열어서 대조한다.
5. **우리 현황 대조**: 이미 하는 것, 빈 곳, 이미 정한 결정과 충돌하는 것(recall.py·proc.py로 먼저 찾고, 바꾸자면 '기존 원문 X → 새 근거 Y').
6. **실행안**: 순서안 P1~P4(싼 것부터), 도입 보류 목록(근거는 `[실측: …]` 또는 `[실측 불가: …]`), 다음 단계로 넘어갈 전환 신호.
7. **기록**: 공정 카드 한 장(proc.py add, 사장님 말 --boss), 정본 문서 또는 업무대장 행, 필요하면 실행 도구와 작업 등록. 사장님 보고는 20줄 한 장.

## 지키는 것
- 공개 조사라서 비밀·고객 정보·가격은 질의에 넣지 않는다.
- 숫자와 링크는 내가 열어 확인하기 전까지 `[추정]`.
- 조사만으로 끝내지 않는다: 실행 가능한 항목은 같은 턴에 실행(슈퍼백로그 원칙), 사람 결정이 필요한 것만 '정하실 것'에.
- 제품·방향 결정은 사장님 몫이다(예: 모델 내려받기, 유료 도입).
