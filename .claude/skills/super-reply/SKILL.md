# 슈퍼회신: 회신 초안 만들기

2026-10-22 벤처스퀘어 멘티 배정 메일 회신에서 세 번 고친 끝에 정리한 방식이다. 첫 초안에서 이미 잡힌 일정을 빼먹고, 구글 밋 링크만 보고 오프라인 일정을 온라인으로 적은 사고가 근거다.

## 원칙 넷
1. **보내지 않는다.** 마야는 임시보관함까지만 한다. 발송은 사장님이 직접 한다(외부 발신은 에이전트 금지).
2. **사실은 조회해서 넣는다.** 기억이나 요약에 있는 일정·장소를 믿지 않고, 이번 턴에 캘린더와 원문을 직접 읽는다.
3. **모르는 것은 단정하지 않는다.** 확인하지 못한 항목은 빼거나 "협의하겠다"로 쓰고, 사장님께 되묻기 전에 먼저 찾아본다.
4. **사장님은 전문을 본다.** 초안을 만든 뒤 채팅에 전문을 그대로 붙이고, 무엇을 어디서 확인했는지 항목별로 적는다.

## 순서
1. **원문 읽기**: `search_threads`로 스레드를 찾고 `get_thread`로 본문을 읽는다. 받은 안내에서 요청 사항, 기한, 숫자(기간, 횟수, 수당)를 뽑는다.
2. **캘린더 조회**: `list_events`로 상대 이름, 행사명, 상대 이메일을 각각 `fullText`로 검색한다. "멘토링"처럼 일반어 하나로만 찾지 않는다(제목에 그 단어가 없는 일정이 빠진다). 기간은 오늘부터 원문 기한까지.
3. **일정 해석**:
   - 시각은 시작과 끝을 함께 적는다.
   - 온라인인지 오프라인인지는 `location` 필드와 설명란의 지도 링크로 판단한다. 구글 밋 링크는 자동으로 붙는 경우가 많아 근거가 아니다.
   - 장소 이름이 지도 링크(`naver.me` 등)에만 있으면 `curl -sIL -m 30`으로 목적지 주소를 얻고, 모바일 장소 페이지 제목에서 이름을 읽는다. 읽지 못하면 "오프라인"까지만 적는다.
   - 참석 수락 여부(`responseStatus`)가 `accepted`일 때만 "확정"이라고 쓴다.
4. **초안 쓰기**: 첫 줄 인사, 받았다는 확인, 확정된 일정 목록, 남은 협의 사항, 상대에게 요청할 것, 맺음 순으로 쓴다. 사장님 말투(정중, 짧게)를 따르고 긴 줄표를 쓰지 않는다.
5. **초안 넣기**: `create_draft`에 `replyToMessageId`를 주어 같은 스레드 답장으로 만들고 `includeSignature: true`로 서명을 붙인다. 고칠 때는 초안 본문을 직접 고치는 도구가 없으므로 `delete_draft` 후 다시 만든다(이전 초안을 남기지 않는다).
6. **보고**: 초안 전문, 조회한 일정 목록, 모르는 항목을 채팅에 쓰고 사장님이 정할 것이 없으면 "없음"이라고 쓴다.

## 초안에 넣지 않을 내용
- 일정이 없는 사람의 날짜는 지어내지 않는다.
- 상대 연락처(전화번호, 개인 이메일)는 초안 본문에 옮기지 않는다.
- 평가 점수나 내부 판단은 외부 회신에 쓰지 않는다.
- 사장님 일정표의 다른 약속 내용은 회신에 넣지 않는다.

## 점검 목록(초안 전에 한 번)
- 상대 이름, 이메일, 행사명으로 각각 캘린더를 검색했는가
- 확정과 협의 중이 구분되어 있는가
- 온라인과 오프라인의 근거가 장소 정보인가
- 받은 안내의 기한과 횟수 조건을 어기지 않았는가
- 사장님이 직접 보낼 수 있게 받는 사람이 맞는가
