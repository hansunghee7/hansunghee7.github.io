# 잉크: 홈페이지용(유입형) 8단계

카드의 `현재단계`에 해당하는 단계부터 진행한다. 단계를 건너뛰지 않는다. 사장님 손이 필요한 단계는 1(위임 시 생략)과 7뿐이다. 단계를 마칠 때마다 카드의 `현재단계`, `다음행동`, 해당 칸을 갱신한다.

## 1. 주제 확정
- 할 일: 주말 슬롯표에서 1~2주치 주제를 사장님과 한 번에 확정한다. 후보는 `docs/질문하기_파이프라인.md` 5-3절(실측 데이터 기반 후보 3~5개)로 뽑고, 1차 타깃은 `docs/브랜딩_가이드.md` 3절로 확인한다.
- 사장님이 주제를 위임하셨으면("알아서 정하라") 마야가 같은 절차로 후보를 뽑아 하나를 정하고, 고른 이유와 버린 후보를 카드에 남긴다. 위임 메시지는 카드 `위임` 칸에 인용한다.
- 산출물: 카드 `제목`(가제), `슬롯`, `소재유형`, `승인.주제확정` 또는 `위임`.
- 다음 단계 조건: 승인 인용 또는 위임 인용이 카드에 있다.

## 2. 딥리서치·검증과 다이얼로그 수집 (병행)
- 할 일: 헤르메스 딥리서치를 발주하고 제미나이 검증을 거친다. 같은 시간에 심플리파이어 다이얼로그로 사장님의 콘텐츠 관점을 수집한다. 일반 지식으로 먼저 쓰지 않는다.
- 산출물: 카드 `리서치`(발주일, 보고서 경로, 검증 결과), `다이얼로그`(수집일, 요약 경로). 보고서 경로는 push되어 열리는 경로만 적는다.
- 다음 단계 조건: 두 칸이 채워졌다. "열람 실패", "조건 불명", "검증 안 됨" 항목과 출처 없는 수치는 버린다. 수치와 고유명사는 마야가 원문 표본을 직접 대조한다.
- 읽을 곳: 딥리서치는 `solar-bible/docs/딥리서치_파이프라인.md`(발주 채널은 `solar-bible/mailbox/README.md`). 제미나이 검증 호출법은 진행상황.md 또는 `docs/진행상황_아카이브/`의 "제미나이 API로 질의하고 답 받는 법"(2026-09-16). 외부 LLM에 직접 발주할 때만 `multi-llm-handoff` 스킬.
- 다이얼로그 호출법은 이 저장소에서 위치가 확인되지 않았다(2026-09-20). 모르면 그 자리에서 한 번 묻고, 알게 된 위치를 이 줄에 적어 PR로 고친다. 수집하지 못했으면 카드에 사유를 적고 사장님 컨펌 화면에 그 사실을 올린다.

## 3. 시놉시스 (마야 단독, 사장님께 묻지 않는다)
- 할 일: 흐름을 7줄 안팎으로 짠다(훅, 문제, 원인, 전환, 처방, 독자 행동). 앞뒤 연결이 어색한 곳은 다리 문장으로 표시한다.
- 산출물: 카드 `시놉시스`.
- 다음 단계 조건: 각 줄이 2단계에서 얻은 출처 또는 다이얼로그 요약과 연결된다.
- 읽을 곳: `docs/질문하기_파이프라인.md` 5-2절 0번.

## 4. 본문
- 할 일: 산문을 기본으로 쓴다. AEO·SEO·GEO를 반영한다. 사장님 개인 경험은 넣지 않고 1인칭 경험을 지어내지 않는다. 화요일 글은 SNS 정보성 변형도 같이 만든다.
- 산출물: 전문을 비공개 `simplifier-cxo-db/ink/초안/`에 저장(공개 저장소에는 커밋하지 않는다). 마야가 덧붙인 판단 문장은 카드 `덧붙인곳`에.
- 다음 단계 조건: 5-3절의 세 줄 확인을 통과했다.
- 읽을 곳: `docs/WRITING_GUIDE.md` 5-2-1절(대분류2), 5-3절, 4절, 6절(금지 목록), 4-2절(제목과 도입). 어투는 `docs/퍼스널_브랜딩_가이드.md`. SNS 변형은 `docs/SNS_라이팅_가이드.md`.

## 5. 제목과 이미지 후킹 채점
- 할 일: 제목과 이미지 각각 1안과 대안 1개를 만든다. 이미지는 글의 빅아이디어를 한 문장으로 적은 뒤 후보를 실제로 열어서 보고 조건표로 채점한다. 사진 설명문만 보고 고르지 않는다.
- 산출물: 카드 `점수.제목후킹`, `점수.이미지후킹`, 후보 URL.
- 다음 단계 조건: 이미지 채점이 끝났다. 제목은 점수 기준이 생기기 전까지 1안과 대안, 고른 이유만 적는다.
- 읽을 곳: 이미지 조건 8개는 `docs/질문하기_파이프라인.md` 5-2절 단계 3, 선택 절차는 같은 문서 5-1절. `docs/후킹_가이드.md`가 생기면 그 문서가 정본이다.

## 6. 검수: 검수 인턴, 이어서 마야 최종 검수
- 검수 인턴(`scripts/check_ink_card.py`)은 준비 중이다. 그 전까지 카드의 빈칸과 단계 순서를 직접 점검한다.
- 마야 최종 검수: 글을 쓴 맥락을 모르는 새 서브에이전트(`Agent` 도구, 소넷 또는 오퍼스)에게 전문과 점수표만 주고 채점시킨다. 시놉시스, 의도, 대화 내용은 주지 않는다. 마야는 결과를 판정하고 감점 항목을 고친 뒤 다시 채점시킨다.
- 산출물: 카드 `점수.본문`, `점수.채점자`, `점수.감점항목`.
- 다음 단계 조건: 점수가 기준점 이상이다(기준점은 사장님 컨펌 사항, 정해지기 전에는 34점을 임시 기준으로 쓰고 임시라고 밝힌다).
- 읽을 곳: `docs/WRITING_GUIDE.md` 5-4-1절(유입형 점수표).

## 7. 사장님 컨펌 (1회)
- 할 일: 최신 전문, 제목 1안과 대안, 이미지 1안과 대안, 점수와 감점 항목, 덧붙인 곳, 리서치 출처 목록을 한 화면에 올린다. 질문은 하나.
- 산출물: 카드 `승인.발행확정`(사장님 원문 인용과 시각).
- 다음 단계 조건: 최신 전문에 대한 명시적 승인이 인용되어 있다. 수정이 들어오면 상태를 되돌리고 반영본 전문을 다시 올린다. 반영할 때 분량을 늘리지 않는다.

## 8. 커밋, 발행, 라이브 점검, 실적
- 할 일: 마야 전용 worktree에서 `log_assets/markdown/<제목>.md`로 PR을 열고 auto-merge한다. 예약 발행이 실측 검증되기 전에는 발행일 당일에 `published: true`로 병합한다. 발행 자동화가 멈춰 있으면 PR 안에서 스크립트 단계를 수동으로 실행한다.
- 발행 뒤 라이브 URL 200, 목록 카드, `assets/data/posts.json`, `sitemap.xml`, 대표 이미지를 직접 확인한다. `publish_plan.json`의 해당 슬롯을 갱신한다. 발행 7일 뒤 실적을 적는다.
- 산출물: 카드 `발행`, `실적`. 인수인계 "한 것"에 숫자(점수, 예약 시각과 실제 공개 시각)를 적는다.
- 읽을 곳: `docs/역할노트-마야.md` 9절, `docs/예약_발행.md`, `docs/질문하기_파이프라인.md` 5-2절 7~8번. category는 `docs/SNS_라이팅_가이드.md` 5절의 판단 순서(실제 주제 먼저).
