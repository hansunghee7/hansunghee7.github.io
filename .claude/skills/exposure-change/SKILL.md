# 노출 범위를 바꿀 때: 승인 없이 열지 않는다

이 저장소는 main에 병합되면 **곧바로 라이브**입니다. 스테이징 환경이 없습니다.
그래서 사고는 "미완성 화면이 보인다"가 아니라 **공개로 승격하는 순간이 다른
작업에 묻어서 나가는 것**으로 났습니다(2026-08-29, PR #9·#10으로 되돌림).

## 무엇이 "노출 범위 변경"인가

- `noindex` 제거 → 검색에 열림
- `preview: true` 해제 → 정식 페이지로 승격
- `sitemap.xml`에 URL 추가 (블로그 글 발행은 제외, 평상 업무)
- `llms.txt`에 링크 추가 → AI 검색에 열림
- `_includes/header.html`에 링크 추가 → GNB 메뉴에 노출

## 절차

1. **먼저 사장님께 확인받으세요.** 노출은 되돌려도 이미 본 사람은 되돌릴 수 없고,
   검색엔진에 색인되면 제거에 시간이 걸립니다.
2. **노출 변경은 그것만 담은 PR로.** 기능 작업과 같은 PR에 넣지 마세요.
   위 사고가 정확히 그렇게 났습니다.
3. 확인을 받았으면 PR 본문에 이유와 함께 **`노출-승인`**을 적으세요.
   예: `노출-승인: 강연 페이지 공개 합의 (2026-08-30)`

`build-check`가 PR마다 `scripts/check_exposure_changes.py`로 검사합니다. 노출이
넓어지는데 승인 표시가 없으면 **병합이 막힙니다.** 무엇이 새로 공개되는지
목록으로 찍어주니, 의도치 않은 항목이 섞였는지 그걸로 확인하세요.

⚠️ **확인 없이 표시만 붙이지 마세요.** 그러면 이 검사는 무의미해집니다.
기계는 "승인했다는 선언"이 있는지만 볼 수 있지, 실제로 승인받았는지는
모릅니다.

## 테스트는 라이브에서 하되 노출만 막는다

별도 스테이징 서버를 두지 않습니다. 화면 몇 개짜리 정적 사이트에서 빌드 환경을
둘로 나누면 **두 환경이 어긋날 때 지금보다 나빠집니다**("스테이징에선 됐는데
라이브에서 깨졌다"가 제일 비쌉니다). 대신 `preview/` 아래에 `noindex`를 달아
올리고, 눈으로 확인한 뒤 위 절차로 승격합니다.

`robots.txt`가 `Allow: /`인 것은 의도된 것입니다. 크롤러를 막으면 `noindex`
태그를 **읽지 못해서** 오히려 URL이 검색에 뜰 수 있습니다. 읽게 허용하고
noindex로 거절하는 게 맞습니다.
