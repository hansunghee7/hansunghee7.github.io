# 로컬 지시서: tasks/todo 새 지시서 알림·트리거 구축 (N171/N173)
사장님확인: 아니오
발주: 클라우드 탐(사장님 지시 2026-10-07). 받는 쪽: 로컬 탐 세션(구현은 Qwen·로컬 스크립트).
- 목표: 클라우드가 `tasks/todo`에 지시서를 올리면 로컬이 세션 시작을 기다리지 않고 알게 한다. 클로드 토큰 0, 상시 감시는 기존 `pending-detector`(헤르메스 크론, 1분, no-agent, 본체 `scripts/hermes_ops/pending_detector.py`)와 같은 방식으로 만든다. 기존 감지기는 solar-bible의 `tasks/pending*`만 보므로 이 저장소의 `tasks/todo`는 같은 틀의 별도 no-agent 스크립트(예: `scripts/hermes_ops/todo_detector.py`, 시험은 `test_pending_detector.py` 틀 참고)로 감지한다. 기존 감지기를 고쳐 섞지 않는다.
- 설계:
  1. 감지: `git fetch origin` 후 origin/main의 `tasks/todo/*.md`(PR이 main에 병합돼야 보인다, 작업 트리는 건드리지 않고 `git ls-tree`·`git show origin/main:<경로>`로 읽는다) 중 `C:/work/_ops/todo_seen.json`에 없는 새 파일을 찾는다.
  2. 기록: 새 파일명을 `C:/work/_ops/todo_inbox.log`에 한 줄 추가(탐 세션이 하이~ 때 읽는다).
  3. 사장님 알림: 파일 둘째 줄이 `사장님확인: 예`일 때만 마야 형식 1초 컨펌 알림(승인·돈·할 일): `python scripts/ops/tg_boss.py text "<제목, 선택지 개수, 추천 번호 한 줄>" --persona 탐`(서브명령은 text·photo·doc, `--persona`는 필수). **아니오이면 폰으로 보내지 않는다**(CLAUDE.md 결정 없는 알림 금지).
  4. 로컬 탐 세션 깨우기: 떠 있는 세션이 있으면 `SendMessage`, 없으면 inbox 로그. 세션을 새로 띄우는 방안(헤드리스 `claude -p`)은 주간 한도를 쓰므로 만들지 말고 장단점만 한 줄로 보고(사장님 결정).
- 지킬 것: `scripts/ops/jobs.toml`에 `kind = "hermes_cron"` 항목(기존 `hermes:pending-detector` 항목 형식 참고, period_min = 1)으로 등록하고 지금 1회 실행해 성공 증거, 첫 자동 실행 결과까지 확인해야 완료. 알림 중복 방지(seen 파일). 지시서 내용은 알림에 싣지 않고 파일명만.
- 증거: 시험용 더미 지시서로 inbox 기록과 (예 지시서일 때) 텔레그램 수신 확인. 끝나면 `python scripts/ops/worklog.py add --who 탐 "..." --task N171 --evidence <경로>`로 증거를 남기고 `git mv tasks/todo/<이 파일> tasks/done/`, PR.
