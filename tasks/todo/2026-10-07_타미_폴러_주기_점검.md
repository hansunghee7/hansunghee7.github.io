# 로컬 지시서: 타미 지시서 감시 주기 15분 → 2분 (측정 먼저)

발주: 클라우드 탐(사장님 지시 2026-10-07: 15분은 병목). 받는 쪽: 로컬 탐 세션.

## 먼저 알아둘 것(클라우드가 본 증거)
- 10/7 병렬 발주 때 solar-bible에 카드를 올린 시각(01:45 UTC)과 폴러의 `received` 커밋 시각(10:47 KST = 01:47 UTC)이 약 2분 차이였다. `pending-detector`(1분 주기, no-agent)가 폴러를 깨우므로 15분 크론은 "예비용"이라는 `jobs.toml` 주석과 맞는다.
- 그래서 실제 병목이 15분인지 먼저 로컬 로그로 확인한다. 이미 2분 안팎이면 크론 주기만 2분으로 낮추는 것은 이득이 작다.

## 할 일
1. `hermes:solar-bible-tasks-poller`, `solar-bible-long-poller`, `pending-detector` 세 크론의 현재 주기와 최근 20회 실행 간격을 기록한다(헤르메스 로그).
2. 카드가 올라온 시각 → `received` 커밋 시각 지연을 최근 카드 5건으로 계산한다(`git log` 시각 차).
3. 판정:
   - 지연이 5분 이하이면 **변경하지 않고** 측정치를 이 지시서 아래에 적어 닫는다.
   - 지연이 5분을 넘는 경로가 있으면 그 크론만 `hermes cron edit <id> ...`로 2분으로 낮춘다. 실행본은 헤르메스 홈 사본이라 `scripts/ops/hermes-poller/` 사본과 `scripts/ops/jobs.toml`(period_min, stuck_min)도 같이 고친다.
4. 바꿨다면 지금 1회 실행해 성공 증거를 확인하고, **첫 자동 실행 결과까지 확인해야 완료**(CLAUDE.md 주기 작업 규칙).

## 명시
- 타미와 폴러는 로컬·무상 스크립트라 주기를 2분으로 줄여도 **클로드 토큰 소모는 0**이다. 비용은 카드가 있을 때 도는 `hermes chat`(upstage solar-pro4)뿐이고 빈 실행은 호출 0이다.
- `tasks/todo`(Claude 세션용 갈래)는 이 폴러의 대상이 아니다. 주기를 줄여도 todo는 빨라지지 않는다.

끝나면 `git mv tasks/todo/<이 파일> tasks/done/`, PR.
