# 로컬 지시서: N156 M0 사전 점검 (읽기 전용)
사장님확인: 아니오
발주: 클라우드 탐. 받는 쪽: 로컬 탐 세션(스크립트 + 타미 수집, 소넷 서브에이전트 금지). 정본: `docs/설계_N156_운영DB화.md`, SQL: `tools/db/`.
- 목적: M2 적용 전에 설계가 실제 환경과 맞는지 읽기만 해서 대조한다. 쓰기·적용 없음.
- 할 일(결과 5줄 이내를 이 지시서 맨 아래 "M0 결과"에 붙인다. 비밀값·프로젝트 ID·키는 쓰지 않는다):
  1. 시험 프로젝트의 표 목록과 행 수가 설계 문서의 "지금 있는 것"과 같은지(`opsdb.py count`로 표별 행 수). 다른 표가 더 있거나 없는 표가 있으면 이름만 적는다.
  2. `import_ops_tables.py`가 **비우고 다시 채우는 표**와 **이어 붙이는 표** 목록(코드를 읽고 정리). M3 잠금 대상 표(`agent_calls`, `gpu_gate_log`, `vertex_usage`, `metrics_snapshots` 등)가 비우고 채우는 쪽이면 M1에서 이어 붙이기로 바꿔야 한다고 표시한다.
  3. 업무대장 상태 값의 실제 종류: `select distinct status from tasks`로 뽑아 `task_status` 시드 8종(진행·대기·확인필요·사장님·보류·완료·완료·증거·결정) 밖의 값을 적는다.
  4. Supabase 무료 프로젝트의 한도·일시정지·백업 정책을 **공식 문서**로 확인(덱스 한 곳에 사실 확인을 맡겨도 된다. 질문에 프로젝트 ID 금지). 확인 못 한 것은 "미확인"으로 둔다.
  5. 읽기 전용 키를 따로 발급할 수 있는지(금고 등급 분리 가능 여부)만 확인하고 발급은 하지 않는다.
- 끝나면 `git mv tasks/todo/<이 파일> tasks/done/`, 이 저장소 PR, `cloud_ping.py`가 있으면 완료 신호 한 개.
