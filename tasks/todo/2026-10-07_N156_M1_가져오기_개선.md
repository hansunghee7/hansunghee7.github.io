# 로컬 지시서: N156 M1 가져오기 개선 (ingest_runs·task_events 기록, 로그 표 이어 붙이기)
사장님확인: 아니오 (코드 변경, 운영 DB 쓰기 없음. M2 SQL 적용 승인은 이 지시서의 증거가 나온 뒤 별도로 올린다)
발주: 클라우드 탐. 받는 쪽: 로컬 탐 세션(구현은 로컬 스크립트·Qwen, 소넷 서브에이전트 금지). 선행: `N156_M0_사전점검` 결과. 정본: `docs/설계_N156_운영DB화.md` M1, SQL `tools/db/migrate_N156.sql`.
- 목표: `scripts/ops/import_ops_tables.py`가 ① 실행 한 번마다 `ingest_runs`에 시작·종료·행 수·종료 코드를 남기고(실패도) ② `tasks`를 다시 채울 때 이전 값과 비교해 바뀐 칸을 `task_events`(source=`import-diff`)에 덧붙이고 ③ 로그 표(`agent_calls`·`gpu_gate_log`·`vertex_usage`)는 "비우고 다시 채움" 대신 "DB에 없는 줄만 이어 붙임"(10/5에 일부 완료한 방식)으로 통일하고 ④ `tasks.status_family`를 채운다.
- **M2 적용 전에도 깨지면 안 된다**: 새 표(`ingest_runs`, `task_events`)·새 칸(`status_family`)이 DB에 아직 없으면 그 기록만 건너뛰고(존재 확인 후) 기존 동작은 그대로 한다. 그래서 M1을 먼저 배포하고 안정되면 M2를 적용할 수 있다.
- 시험(실제로 돌려 실측): ① `--dry`로 변경 없음 확인 ② 같은 명령을 2회 실행해 행 수 동일 ③ md에서 상태 하나를 바꾼 시험 행으로 `task_events`에 1행이 생기는지(M2 적용 뒤) ④ 로그 표에 중복이 안 생기는지. 단위 시험은 DB 없이 도는 부분(변경 비교 함수)을 따로 만들어 `unittest`로.
- 지킬 것: 주기 작업 변경이므로 지금 1회 실행해 증거, **첫 자동 실행 결과까지** 확인(`fn:opsdb-sync`, `jobs.toml`). 원본 md·csv는 읽기만. 키 값은 코드·로그에 없다.
- 끝나면 결과 5줄을 이 지시서 맨 아래 "M1 결과"에 붙이고 `git mv tasks/todo/<이 파일> tasks/done/`, PR. 증거가 나오면 클라우드 탐이 M2 적용 승인(마야 형식 알림)을 사장님께 올린다.
