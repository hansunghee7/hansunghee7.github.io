# 로컬 지시서: 클라우드 깨우기 신호 발신기 구축 (N180)
사장님확인: 예 (워크플로를 비공개 저장소 기본 브랜치에 넣는 승인, 마야 형식 텔레그램 1건: 제목=N180 통신망 워크플로 승인, 본문=시험 브랜치에서 11초 도착 실측·비밀 추가 없음·추천 승인)
발주: 클라우드 탐. 받는 쪽: 로컬 탐 세션(구현은 로컬 스크립트·Qwen, 소넷 서브에이전트 금지). 설계 정본: `docs/설계_N180_에이전트_통신망.md`.
- 배경: 클라우드가 비공개 저장소 우편함 PR(422번)을 구독하고, `mailbox/signals/**` 푸시 시 봇이 그 PR에 댓글을 단다(시험 브랜치 `mailbox/signals`에서 E2 성공, 푸시→이벤트 약 11초). 자기 계정 댓글은 안 오므로 로컬이 `gh pr comment`로 직접 다는 방식은 쓰지 않는다.
- 만들 것: ① `scripts/ops/cloud_ping.py`: `python scripts/ops/cloud_ping.py --event task_done|card_done|signal --id <파일이름 또는 신호이름> --by <누가> --ref <저장소 경로>`. 비공개 저장소 `mailbox/signals/<UTC시각>-<id>.json`을 `gh api -X PUT repos/<owner>/<repo>/contents/...`(branch=`mailbox/signals`)로 한 개 올린다. 내용은 설계 문서의 페이로드 v1(공개 가능한 값만, 로컬 경로·결과 내용·비밀 금지). 같은 id는 한 번만, 30초 안에 여러 건이면 묶어서 한 개로. 실패해도 호출한 작업은 멈추지 않는다(3초 안에 포기, 로그만). ② 타미 폴러(`pending_poller.py` 실행본과 `scripts/ops/hermes-poller/` 사본 둘 다)가 카드를 `tasks/done`으로 옮긴 직후 `cloud_ping.py --event card_done`을 부르게 한다. ③ 로컬 탐 마무리 절차(지시서를 `tasks/done`으로 옮겨 PR 병합한 직후)에 `cloud_ping.py --event task_done` 한 줄을 넣는다(`session-end`나 `hermes-delegate` 스킬 중 맞는 곳). ④ `session_brief.py` 클라우드 모드에 "우편함 PR(422번, 비공개 저장소)을 `subscribe_pr_activity`로 구독하라" 한 줄을 출력하게 한다.
- 시험(E4, 실제로 돌려 실측): (a) 더미 신호 1건을 올려 클라우드 도착까지 걸린 시간 기록. (b) 5건을 10초 안에 올려 묶임·순서·누락 확인. (c) 같은 id 재발신이 한 번만 가는지. 결과를 이 지시서 맨 아래 "E4 결과"에 5줄 이내로 적는다.
- 워크플로 승격: 사장님 승인(위 알림) 뒤에 시험 브랜치의 `.github/workflows/mailbox-ping.yml`을 비공개 저장소 기본 브랜치에 PR로 넣는다(`GITHUB_TOKEN`만 사용, 비밀 추가 없음). 승인 전에는 시험 브랜치에서만 쓴다.
- 지킬 것: 폴러 변경은 주기 작업 변경이므로 지금 1회 실행해 성공 증거, 첫 자동 실행 결과까지 확인해야 완료(`jobs.toml` 영향 작업 확인). 실행본(헤르메스 홈)과 저장소 사본을 같이 고친다(자동 동기화 없음). 호스팅 모델에 파일 내용을 보내지 않는다.
- 끝나면 `git mv tasks/todo/<이 파일> tasks/done/`, 이 저장소 PR, `cloud_ping.py`로 완료 신호 한 개.
