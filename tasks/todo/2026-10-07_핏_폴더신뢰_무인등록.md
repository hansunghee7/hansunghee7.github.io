# 로컬 지시서: 핏 CLI 폴더 신뢰 확인창 무인 처리 (shorts-lab-clone)
사장님확인: 아니오 (사장님 지시 2026-10-07: 수동 개입 없이 처리)
발주: 클라우드 탐. 받는 쪽: 로컬 탐 세션(구현은 로컬 스크립트, 타미는 실행 감시).
- 증상: 핏의 CLI 세션이 `shorts-lab-clone` 폴더의 "Yes, I trust this folder" 확인창에서 멈춘다.
- 목표: 그 **한 폴더**를 신뢰 목록에 사전 등록하는 스크립트를 만들고, 핏의 시작 절차(또는 타미 감시)가 세션을 띄우기 전에 실행되게 한다.
- 설계(순서 지킬 것):
  1. 안전 확인 먼저: 폴더의 git 원격이 우리 저장소(`hansunghee7/shorts-lab`)이고 `git status`·HEAD가 원격과 맞는지 스크립트가 검사한다. 맞지 않으면 등록하지 않고 멈춘다(신뢰 등록은 그 폴더의 훅·MCP 설정을 실행해도 된다는 뜻이다).
  2. 등록: Claude Code 사용자 설정 파일(`~/.claude.json`)의 해당 프로젝트 항목에 신뢰 수락 표시를 넣는다. 정확한 키 이름은 **현재 설치된 CLI 버전에서 확인**하고(신뢰 창을 한 번 수락한 뒤 설정 파일의 변화를 diff로 확인하는 방법이 확실), 추측으로 쓰지 않는다.
  3. 안전장치: 수정 전 설정 파일 백업, JSON 파싱 후 해당 폴더 경로 하나만 추가(와일드카드·상위 폴더 금지), 이미 있으면 아무것도 하지 않음, 실패하면 원본 복구.
- 막히면 우회하지 말 것: 권한·안전 검사가 이 설정 수정을 막으면 우회·문자열 치환을 하지 말고 막힌 사실과 `[해결 경로: …]`를 보고한다(L5 사건 교훈, 교본 시행착오 절).
- 검증: 스크립트는 시험용 임시 폴더로 먼저 시험하고(실제 설정 파일 복사본), 그다음 실제 폴더에서 핏 세션을 새로 띄워 확인창이 안 뜨는지 본다. 증거는 설정 파일 변경 전후 diff(경로 외 값은 가리기)와 핏 세션 시작 로그. 설계·스크립트는 덱스·Vertex 중 한 곳에 위험 검토(소넷 서브에이전트 금지).
- 끝나면 `git mv tasks/todo/<이 파일> tasks/done/`, PR.
