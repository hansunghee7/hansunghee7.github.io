1. 원칙 다섯 가지

  1. 상태 열이 신호등이다. 사장님이 개입하는 방법은 언제나 똑같다 — 상태 한 칸 바꾸기. 색깔 표시는 쓰지 않는다(기계가 못 읽는다). 폰 드롭다운에는 사람이 쓰는 단어만 노출한다(검증 목록 제한) — 기계 전용 단어(진행중류)를 실수로 누르면 비싼 단계가 잘못 시작된다.
  2. 판단이 단순한 일은 API로, 창작은 하루 한 번 세션으로. 세션이 하루 종일 시트를 지켜보는 구조는 만들지 않는다. 정렬·조립처럼 판단이 0인 결정론적 스크립트도 세션 안에서 돌리지 않는다 — 지켜보는 데 토큰을 쓰는 건 ffmpeg를 토큰으로 사는 셈이다(위치는 §9).
  3. 사람은 두 군데 앞에 선다 — 돈이 나가기 직전, 밖으로 나가기 직전. 이미지는 싸니까 기계가 마구 찍고, 영상은 비싸니까 사장님이 확정한 이미지로만 만든다. 업로드는 실수가 공개되는 지점이라 사람이 본다. 돈 나가는 비동기 단계(리서치· 이미지·영상)는 발주 직후 "진행중" 상태로 스스로를 잠가 이중 발주를 막는다.
  4. 자동화는 한 계단씩. 두 계단을 한 번에 올리지 않는다.
  5. 자동으로 가져온 사실도 검증은 남긴다. 출처 URL이 있는 사실만 대본에 쓰고, 그 URL을 실제로 열어 숫자가 본문에 있는지까지 확인한다(URL 존재만으로는 검증이 아니다 — ep07 사고 재확인). 못 찾으면 [미확인] 표시를 남긴다.

2. 단계별 상세

"누가" 칸의 굵은 글씨가 사람이 꼭 필요한 자리다. "예외만"은 문제가 생긴 것만 사장님께 올라온다는 뜻이다.

# 단계 들어가는 것 → 나오는 것 누가 어떻게 상태 변화 실패하면
0 성과 기록 발행 3일 후 숫자 → 시트 "성과" 탭 자동 assets/data/*.json(콘텐츠 인사이트가 이미 수집)에서 Actions가 다리 하나로 우편함 POST. 사람이 적는 건 "체감 지속률" 3단(상/중/하) 한 칸만 — 발행 후 각 플랫폼 자체 분석 화면을 열어본 김에 30초 — 빈 칸이면 아침 세션이 알림
1 주제 후보 채우기 성과 탭(장르 라벨별 상대 순위, 10편↑) + 기존 후보 + 블로그 587편(조회 상위·미숏폼화) → 새 후보 10개/주제군 자동 주 1회 Routine이 우편함으로 시트에 씀. 후보 줄에 부모 글 URL·장르 라벨 열 (신규) → 후보 후보 5개 미만이면 알림
2 주제 픽 후보 → 이번 주 3개 사장님 폰에서 상태를 픽으로, 발행예정일 + 이번 주 발행 목표 편수 적기 후보 → 픽 —
3 딥리서치 주제 → 출처 달린 보고서 자동(§9 3a/3b 참고) 픽 직후 발주, 즉시 리서치중(작업 ID 기록), 15분 폴링, 끝나면 드라이브에 구글 문서로 저장 픽 → 리서치중 → 리서치완료 실패 시 아침 세션이 웹검색으로 대체
4 대본 초안 보고서 → 대본(구글 문서) + 출처 정리 + 장르 라벨 자동(아침 세션) 매일 아침 Routine이 리서치완료 줄만 처리(0개면 즉시 종료). 출처 URL을 실제로 열어 숫자 확인, 못 찾으면 [미확인] 표시. 장르 라벨을 주제관리 탭 고정 열에 저장(발행·성과까지 추적) 리서치완료 → 초안 기준 미달이면 초안에 표시하고 넘김
5 대본 확정 초안(구글 문서) → 확정 대본 사장님 [미확인] 표시 줄 위주로 구글 문서에서 고치기, 시트는 상태만 대본으로 (10분). 장르 라벨이 맞게 붙었는지 확인 초안 → 대본 —
6 음성 대본 → 나레이션 파일 사장님 (Typecast, 목소리 확정 전까지 자동화 안 함 — 5번째 사람 자리로 정직하게 센다) 파일을 드라이브 폴더 voice/에 저장 — —
7 정렬 음성 + 대본 → 문장별 타이밍 자동, 위치는 §9 미정 Whisper로 정렬, 8초 초과 블록 확인. 세션이 아닌 결정론적 실행(원칙 2) — 초과 블록 있으면 메일 알림
8 프롬프트 생성 대본 + 장르 → 씬별 이미지·영상 프롬프트 자동 변환기를 UI 없는 함수로 분리해 상태 신호로 트리거. 장르는 주제관리 탭 열에서 읽음 대본 → 프롬프트 잘림·오류는 "오류" 열에
9 프롬프트 검사 프롬프트 → 통과/문제 씬 자동, 예외만 8번과 같은 실행 안에서 이어서 검사(트리거 절약). 문제 씬 번호를 "문제씬" 열에 — 문제 씬만 사장님이 거울 페이지에서 수정
10 이미지 생성 이미지 프롬프트 → 씬당 후보 여러 장 자동 발주 즉시 이미지중, 씬별 작업 ID·재시도 횟수 열. 중개 API(fal.ai 등) 저가 모델 프롬프트 → 이미지중 —
11 이미지 검수 후보 이미지 → 통과/반려 + 이유 자동, 예외만 검수 기준서 + 이미지를 Claude API로, 구조화 출력({scene, verdict, reason})으로 판정. 기준서는 캐싱. 반려면 최대 3회(시도 횟수 열로 셈) 이미지중 → 이미지 3회 실패 씬만 사장님께
12 이미지 확정 통과 후보 → 씬당 1장 사장님 거울 페이지 이미지 모드만(3모드 한 번에 안 만듦) 폰 스와이프로 (5분). 돈 나가기 직전 관문 + 예산 상한 기계 관문(확정 씬 수 × 단가가 상한 넘으면 영상 생성 전 정지·알림) 이미지 → 이미지확정 —
13 영상 생성 확정 이미지 + 영상 프롬프트 → 씬 클립 자동 발주 즉시 영상중. 중개 API로 image-to-video. 실패 씬 재시도 1회, 두 번째 실패는 재발주 금지(비싼 단계) 이미지확정 → 영상중 알림
14 조립 클립 + 나레이션 + 자막 → 초벌 영상 + 발행 재료 자동, 위치는 §9 미정 veo/가 다 차면 ffmpeg로 이어붙임. 같은 자리에서 final/epNN_publish.md(제목 후보 3·설명·해시태그·고정 댓글) 생성 — 부모 글 UTM 링크는 §9 판단 후 영상중 → 조립 —
15 업스케일 초벌 → 고화질 자동 Video2X(realesrgan-plus, 2배)를 조립 스크립트 마지막 줄로. 첫 1편은 업스케일 유/무 A/B로 눈으로 비교해 차이 없으면 이 줄을 지운다(§10) — —
16 공개 확인·업로드 고화질 + publish.md → 유튜브·인스타·틱톡 사장님 끝까지 한 번 보고, publish.md(제목·설명·해시태그·링크) 붙여넣어 올리기. 밖으로 나가기 직전 관문 — 영상뿐 아니라 제목·설명·링크까지 여기서 본다 조립 → 발행 —
17 성과 기록 → 0번으로 자동 0번과 동일

사람이 손대는 시간, 편당: 픽 1분 + 대본 10분 + 음성 준비(목소리 확정 전까지 별도) + 이미지 확정 5분 + 공개 확인·업로드 10분 = 약 26분 + 음성. 지금은 편당 두세 시간이다.

3. 상태 열 정의 (시트 "상태" 칸)

후보 → 픽 → 리서치중 → 리서치완료 → 초안 → 대본 → 프롬프트 → 이미지중 → 이미지
   → 이미지확정 → 영상중 → 조립 → 발행
  • 사장님이 바꾸는 것(폰 드롭다운 검증 목록에 노출): 픽, 대본, 이미지확정, 발행 (네 번) — 그대로.
  • 기계만 쓰는 것(진행중류 포함, 드롭다운엔 없음 — 우편함 스크립트가 검증을 우회해 씀): 나머지 전부.
  • 규칙: 기계는 자기 앞 단어가 켜졌을 때만, 그리고 LockService로 잠근 뒤 움직이고, 자기 단어를 켜고 멈춘다. 리서치중·이미지중·영상중처럼 몇 분~몇십 분 걸리는 단계는 발주 즉시 이 진행중 단어로 바꿔 폴링이 같은 일을 두 번 시키지 않게 한다 (compare-and-set). 뒤로 돌리고 싶으면 사장님이 앞 단어로 되돌린다.
  • 실패·오류는 상태 단어에 섞지 않는다(신호등이 복잡해짐) — 별도 "오류" 열에 이유를 적는다. 씬·행마다 시도 횟수 열을 둬 재시도 상한을 이 열로 센다.

4. 사람이 남는 자리와 이유

자리 왜 사람인가 자동화하면 안 되는 이유
주제 픽 채널의 취향 취향을 자동화하면 남들과 같은 채널이 된다
대본 확정 목소리와 사실 책임 오보의 책임은 사람 이름으로 나간다
음성(당분간) 목소리 미확정 Typecast API 붙는 날 자동화 대상, 지금은 정직하게 5번째 사람 자리
이미지 확정 돈 나가기 직전 여기서 1분 쓰면 영상 비용 수천 원이 안 새어나간다
공개 확인·업로드 밖으로 나가기 직전 나간 뒤엔 되돌려도 이미 본 사람은 못 되돌린다
예외 알림 3번 실패한 씬, 8초 초과 블록 기계가 못 푸는 것만 사람에게

나중에 사람을 뺄 수 있는 자리: 이미지 확정(검수 AI가 사장님 판정과 20장 이상 일치하고, 반려 사유까지 같을 때 — 통과/반려만 맞는 건 우연일 수 있음). 절대 빼지 않을 자리: 주제 픽, 공개 확인·업로드. 이미 뺀 자리(v3): 업스케일(15번, §10) — 판단 없고 돈도 밖도 아닌 순수 기계 작업.

5. 성과 → 후보 반영 규칙 (마야 제안, v3 신규)

  • 게이트: 발행 10편 미만이면 자동 가중 없음 — 표본이 적을 때 조회수는 그날의 알고리즘 운을 학습하게 만든다. 지금은 그냥 쌓는다.
  • 10편마다: 장르 라벨별 그 라운드 조회수의 상대 순위(중앙값 대비 배수)로, 다음 10편 후보 생성 시 상위 장르 비중을 6:4 정도로만 높인다. 하위 장르를 후보에서 아예 빼지 않는다(탐색을 완전히 닫지 않음).
  • 사람 확인 지점: 자동은 "추천 순서·비중"만 바꾸고 최종 픽은 여전히 사장님(2번 단계 그대로) — 새 관문이 아니라 픽 화면에 참고 정보 한 줄.
  • 지표 교체 조건: "체감 지속률" 3단이 실제로 쌓이면 조회수 대신 지속률을 1순위 지표로 바꾼다.

6. 만드는 순서 (계단)

계단 만드는 것 사장님이 할 일 기준: 다음 계단으로
1 우편함("모든 사용자"+비밀키) + 상태 열 + 주제관리 탭 + 폴더 규칙 코드 붙여넣기, 웹앱 배포 클릭, 드라이브 폴더 만들기, 비밀키를 안전한 곳에 숏감독이 시트 셀 하나에 글자를 쓰는 데 성공

9. 사장님 판단이 필요한 것 (v3에서 새로 정리, 임의로 정하지 않음)

리뷰 4개가 갈린 지점. 숏감독이 대신 고르지 않고 여기 옵션만 남긴다.

  • 정렬(7번)·조립(14번)을 어디서 돌릴까.
  • 안 A (탐): GitHub Actions. Apps Script가 상태 변화를 보고 repository_dispatch, Actions가 Drive 파일을 서비스 계정으로 받아 처리. PC가 파이프라인에서 완전히 빠진다(매일 아침 /remote-control 고장 지점 제거). 조건: shorts-lab이 공개 저장소여야 무료 — 지금 비공개라면 분당 과금.
  • 안 B (노트): PC의 파이썬 스크립트(세션 아님, 윈도우 작업 스케줄러 10분마다 감시). pipeline/에 이미 정렬·조립 코드가 있어 감시 루프만 얹으면 됨. PC는 유지되지만 세션은 아니라 원칙 2는 지킨다.
  • 판단 기준: 매일 아침 PC를 켜는 습관을 없애고 싶은지, 아니면 이미 있는 PC 코드를 그대로 재사용하고 싶은지.
  • 부모 글(홈페이지 옛글) UTM 링크를 14·16번에 지금 넣을까.
  • 찬성(시안): 숏폼이 회사 KPI(홈페이지 방문)에 기여하는 유일한 통로. 지금 넣지 않으면 자동화가 잘될수록 회사와 무관한 채널만 커진다.
  • 보류(마야): "이 채널이 지금 회사와 어떤 관계로 보여도 되는지"는 마케팅 실행보다 위 단계의 결정이라, 그 판단이 서기 전엔 넣지 않는 게 안전.
  • 이 저장소는 공개라 판단 근거(수익화·채널 운영 방침)는 여기 적지 않는다. 비공개 저장소(simplifier-cxo-db)에서 판단하고 결과만 이 문서에 반영한다.
