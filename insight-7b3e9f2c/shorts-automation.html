1. 원칙 다섯 가지

  1. 상태 열이 신호등이다. 시트의 "상태" 칸 한 줄이 모든 자동 단계의 출발 신호다. 사장님이 개입하는 방법은 언제나 똑같다 — 상태 한 칸 바꾸기. 색깔 표시는 쓰지 않는다 (기계가 못 읽는다).
  2. 판단이 단순한 일은 API로, 창작은 하루 한 번 세션으로. 후보 생성·그림 검수· 프롬프트 검사는 시트가 API를 직접 부른다 (한 번에 몇십 원). 대본처럼 절차와 기준서가 필요한 일만 아침 세션 하나가 몰아서 한다. 세션이 하루 종일 시트를 지켜보는 구조는 비싸서 만들지 않는다.
  3. 사람은 두 군데 앞에 선다 — 돈이 나가기 직전, 밖으로 나가기 직전. 이미지는 싸니까 기계가 마구 찍고, 영상은 비싸니까 사장님이 확정한 이미지로만 만든다. 업로드는 실수가 공개되는 지점이라 사람이 본다.
  4. 자동화는 한 계단씩. 한 계단이 한 주 잘 돌면 다음 계단. 두 계단을 한 번에 올리지 않는다.
  5. 자동으로 가져온 사실도 검증은 남긴다. 딥리서치가 출처 없는 숫자를 지어낸 실제 사례(ep07)가 있다. 출처 URL이 있는 사실만 대본에 쓴다 — 이 검증이 빠지면 자동화가 오보를 자동으로 만든다.

2. 단계별 상세

"누가" 칸의 굵은 글씨가 사람이 꼭 필요한 자리다. "예외만"은 문제가 생긴 것만 사장님께 올라온다는 뜻이다.

# 단계 들어가는 것 → 나오는 것 누가 어떻게 상태 변화 실패하면
0 성과 기록 발행 3일 후 숫자 → 시트 "성과" 탭 사장님 (지금) / 자동 (나중) 플랫폼별 조회·시청률·팔로우 적기 — 빈 칸이면 아침 세션이 알림
1 주제 후보 채우기 성과 탭 + 기존 후보 → 새 후보 10개/주제군 자동 주 1회 Routine이 우편함으로 시트에 씀 (신규) → 후보 후보 5개 미만이면 알림
2 주제 픽 후보 → 이번 주 3개 사장님 폰에서 상태를 픽으로, 발행예정일 적기 후보 → 픽 —
3 딥리서치 주제 → 출처 달린 보고서 자동 Apps Script가 제미나이 딥리서치 API 호출(백그라운드), 5분마다 확인, 끝나면 드라이브 폴더에 구글 문서로 저장 픽 → 리서치완료 실패 시 아침 세션이 웹검색으로 대체
4 대본 초안 보고서 → 대본 + 출처 정리 + 장르 제안 자동 (아침 세션) 매일 아침 Routine 세션이 리서치완료 줄을 찾아 SCRIPT_PROCESS 기준으로 초안, 출처 있는 사실만 사용 리서치완료 → 초안 기준 미달이면 초안에 표시하고 넘김
5 대본 확정 초안 → 확정 대본 사장님 읽고 고치고 상태 바꾸기 (10분) 초안 → 대본 —
6 음성 대본 → 나레이션 파일 사장님 (지금, Typecast) / 자동 (API 붙이면) 파일을 드라이브 폴더 voice/에 저장 — —
7 정렬 음성 + 대본 → 문장별 타이밍 자동 (PC) PC 세션이 Whisper로 정렬, 8초 초과 블록 확인 — 초과 블록 있으면 알림
8 프롬프트 생성 대본 + 장르 → 씬별 이미지·영상 프롬프트 자동 지금 시트 버튼("제미나이 대본 변환")을 상태 신호로 자동 실행 대본 → 프롬프트 —
9 프롬프트 검사 프롬프트 → 통과/문제 씬 자동, 예외만 검사기(길이·역동성 2종 이상·한글 금지·라벨 규칙)가 문제 씬만 표시 — 문제 씬만 사장님이 거울 페이지에서 수정
10 이미지 생성 이미지 프롬프트 → 씬당 후보 여러 장 자동 시트가 중개 API(fal.ai 등)로 저가 모델 호출, img/s07_1.png 식으로 저장 — —
11 이미지 검수 후보 이미지 → 통과/반려 + 이유 자동, 예외만 검수 기준서 + 이미지를 Claude API로 보내 판정. 반려면 프롬프트 손봐 최대 3회 재생성 프롬프트 → 이미지 3회 실패 씬만 사장님께
12 이미지 확정 통과 후보 → 씬당 1장 사장님 거울 페이지 "이미지 생성" 모드에서 고르기 (5분). 돈 나가기 직전 관문 이미지 → 이미지확정 —
13 영상 생성 확정 이미지 + 영상 프롬프트 → 씬 클립 자동 중개 API로 image-to-video, veo/s07.mp4 저장. 모델은 설정 칸에서 바꿈 이미지확정 → 영상 실패 씬 재시도 1회 후 알림
14 조립 클립 + 나레이션 + 자막 → 초벌 영상 자동 (PC) veo/가 다 차면 PC 세션이 ffmpeg로 이어붙임, final/ep07_raw.mp4 영상 → 조립 —
15 업스케일 초벌 → 고화질 사장님 Video2X (realesrgan-plus, 2배) — —
16 확인·업로드 고화질 → 유튜브·인스타·틱톡 사장님 끝까지 한 번 보고 올리기. 밖으로 나가기 직전 관문 조립 → 발행 —
17 성과 기록 → 0번으로 발행 3일 후

사람이 손대는 시간, 편당: 픽 1분 + 대본 10분 + 이미지 확정 5분 + 업로드 10분 = 약 30분. 지금은 편당 두세 시간이다.

3. 상태 열 정의 (시트 "상태" 칸에 들어갈 단어)

후보 → 픽 → 리서치완료 → 초안 → 대본 → 프롬프트 → 이미지 → 이미지확정 → 영상 → 조립 → 발행
  • 사장님이 바꾸는 것: 픽, 대본, 이미지확정, 발행 (네 번).
  • 기계가 바꾸는 것: 나머지 전부.
  • 규칙: 기계는 자기 앞 단어가 켜졌을 때만 움직이고, 자기 단어를 켜고 멈춘다. 뒤로 돌리고 싶으면 사장님이 앞 단어로 되돌리면 된다 (예: 대본이 마음에 안 들면 초안으로).
  • 시트의 "드롭다운 칩"으로 만들면 단어마다 색이 자동으로 붙는다. 지금 노란색으로 보던 느낌은 그대로 남는다.

4. 사람이 남는 자리와 이유

자리 왜 사람인가 자동화하면 안 되는 이유
주제 픽 채널의 취향 취향을 자동화하면 남들과 같은 채널이 된다
대본 확정 목소리와 사실 책임 오보의 책임은 사람 이름으로 나간다
이미지 확정 돈 나가기 직전 여기서 1분 쓰면 영상 비용 수천 원이 안 새어나간다
확인·업로드 밖으로 나가기 직전 나간 뒤엔 되돌려도 이미 본 사람은 못 되돌린다
예외 알림 3번 실패한 씬, 8초 초과 블록 기계가 못 푸는 것만 사람에게

나중에 사람을 뺄 수 있는 자리: 이미지 확정(검수 AI가 사장님 판정과 20장 이상 일치하면), 업스케일(명령줄 자동화 가능, 지금은 안 함). 절대 빼지 않을 자리: 주제 픽, 업로드.

5. 만드는 순서 (계단)

계단 만드는 것 사장님이 할 일 기준: 다음 계단으로
1 우편함 + 상태 열 + 주제관리 탭 + 폴더 규칙 코드 붙여넣기, 웹앱 배포 클릭, 드라이브 폴더 만들기 숏감독이 시트 셀 하나에 글자를 쓰는 데 성공
2 거울 페이지 (검토·이미지·영상 세 모드) 주소 즐겨찾기 ep07을 이 페이지로 끝까지 진행
3 아침 Routine (대본 초안) + 딥리서치 자동 리서치 주문서 확인 픽 → 초안까지 손 없이 한 편
4 이미지 생성 + 검수 API fal.ai 계정, 키 등록 검수 판정과 사장님 판정 일치율 확인 (20장)
5 영상 생성 API (모델 실험 후 확정) 실험 3씬 눈으로 비교, 청구서 확인 편당 비용이 Flow 구독보다 싸거나 손이 덜 감
6 조립 자동 + 성과 탭 PC 절전 끄기, 아침 /remote-control 성과가 후보 생성에 반영됨

6. 사장님이 할 일 — 처음 한 번 (컴맹용)

한 번만 하면 되는 준비다. 순서대로, 모르면 그 줄에서 멈추고 물어보면 된다.

  1. 구글 드라이브 데스크탑 설치 (PC와 노트북 둘 다). 설치 후 내 드라이브/shorts/ 폴더를 만든다. 폴더에서 오른쪽 클릭 → "오프라인 사용" 켜기. 이걸 안 켜면 PC 세션이 파일 껍데기만 본다.
  2. PC 절전 끄기. 윈도우 설정 → 전원 → "절전 모드: 안 함". 원하면 바이오스에서 아침 자동 켜기, 작업 스케줄러로 밤 자동 끄기.
  3. 시트에 코드 붙여넣기 (숏감독이 줌). 시트 메뉴 확장 프로그램 → Apps Script → 새 파일 → 붙여넣기 → 저장 → 오른쪽 위 "배포" → "새 배포" → 종류 "웹 앱", 실행 사용자 "나", 액세스 "나만" → 배포 → 나온 주소를 숏감독에게 알려주기.
  4. 주제관리 탭 바꾸기. 숏감독이 새 탭을 만들어 주면, 기존 후보를 옮기고 상태 단어를 채운다 (회색은 발행, 노랑은 픽, 나머지 후보).
  5. fal.ai 계정 (계단 4에서). 가입 → API 키 복사 → 시트 메뉴 "API 키 등록"에 붙여넣기. 키는 채팅에 붙이지 않는다 — 시트에만.

7. 사장님이 할 일 — 매일 (컴맹용)

  • 아침: PC 켜고 클로드 코드에서 /remote-control 한 줄. 끝.
  • 폰에서 언제든: 시트 앱을 열어 상태 칸을 바꾼다. 그게 지시다.
  • 후보 중 마음에 드는 것 → 픽
  • 초안 읽고 고쳤으면 → 대본
  • 거울 페이지에서 그림 골랐으면 → 이미지확정
  • 올렸으면 → 발행
  • 알림이 오면: "7번 씬 3번 실패"처럼 온다. 거울 페이지에서 그 씬만 본다.
  • 저녁: PC 세션에 "바이~". 세션 닫기.

이 외의 것은 하지 않는다. 파일을 채팅에 올리지 않고, 프롬프트를 복사해 다니지 않는다. 그런 일이 생기면 파이프라인이 덜 된 것이니 숏감독에게 말한다.

9. 아직 정하지 않은 것

  • 음성을 Typecast API로 자동화할지 (목소리 확정 필요) — 지금은 사장님이 만든다.
  • 리서치를 픽 직후 자동으로 돌릴지, 초안을 보고 방향을 정한 뒤 돌릴지 — 추천은 전자.
  • 영상 모델 — Kling·Wan·Veo 3씬 실험 후 결정.
  • 성과 → 후보 반영 규칙 — 열 줄 쌓인 뒤 정한다.

10. 하지 않을 것과 다음 단계 신호

지금 하지 않는다: 로그인 있는 웹서비스, 별도 DB, 미니PC, 사람 확인 없는 완전 자동, 업스케일 자동화, 시트 대신 파일을 공책으로 쓰기.

신호가 오면 다시 판단한다: - 편집자 등 다른 사람이 접근해야 한다 → 웹서비스·권한 - 에피소드 10편 초과, 채널 2개 초과 → 채널별 시트 분리, 인덱스 - 밤에도 돌아야 할 배치가 매일 생긴다 → 미니PC 또는 GPU 클라우드 비교 - 검수 AI 일치율 90% 넘게 20장 → 이미지 확정에서 사람 빼기 검토
