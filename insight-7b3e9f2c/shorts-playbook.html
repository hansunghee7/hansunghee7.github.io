숏폼 파일럿 실행 매뉴얼숏폼 공정 정본숏폼 대본 공정숏폼 연출 사전숏폼 제작진 역할

PROCESS.md·SCRIPT_PROCESS.md·VISUAL_GRAMMAR.md·PRODUCTION_ROLES.md는 "엔진 설계도" — 제가(숏감독) 대본·씬 플랜을 만들 때 내부적으로 참조하는 규칙서입니다. 사장님이 그 규칙을 직접 알거나 신경 쓸 필요는 없습니다. 이 문서는 그 엔진을 돌려서 실제로 반복하는 루프만 남긴 실행 매뉴얼입니다.

⚠️ 역할 분담 재조정 (2026-08-30) — Claude Max 사용량 절약

클로드 코드(숏감독) 세션은 비쌉니다. 특히 G4(씬 설계)는 에이전트를 여러 개 굴리는 작업이라 세션 하나에서 수십만 토큰을 씁니다. 반면 대본 초안·리서치·팩트체크는 클로드 코드가 아니어도 되는 작업입니다 — 실제로 이미 이번 세션에서 딥리서치· 외부 팩트체크·쇼츠 디렉터 리뷰는 전부 다른 AI 도구에서 해서 가져왔고, 그게 품질도 더 좋았습니다.

그래서 다음부터 이렇게 나눕니다.

단계 어디서 왜
G0 소재 선정 클로드 코드 밖 (제미나이·챗GPT 등) 브레인스토밍이라 코드 실행이 필요 없음
G1 대본 작성 + 리서치 + 팩트체크 클로드 코드 밖 SCRIPT_PROCESS.md를 참고자료로 붙여넣으면 다른 AI도 같은 규칙(시그니처 표현 우선순위·서사 템플릿 4자리·단위 환산·측정 목표치)으로 쓸 수 있음. 이미 문서화가 끝나서 제가 매번 옆에서 잡아줄 필요가 줄었음
G2 음성 녹음 Typecast (수동, 원래도 여기서 안 함) —
G3 정렬 · G4 씬 설계 · G5 합성 숏감독(여기) Whisper·ffmpeg 실행, validate_scene_plan.py 기계 검증, 에이전트 오케스트레이션, 크레딧 비용 계산처럼 코드를 실제로 돌려야 하는 일
G6 발행 메타데이터 초안(제목·설명·태그) 클로드 코드 밖 → 완성본만 붙여넣기 카피라이팅도 코드 실행이 필요 없음. 최종 저장·업로드 확인만 여기서
공정 문서화·의사결정 기록·비용 최적화 판단 숏감독(여기) 전체 맥락과 저장소 구조를 계속 들고 있어야 하는 일

넘길 때 형식: 다른 AI에게 대본을 시킬 때 SCRIPT_PROCESS.md 전체(또는 최소 "우리 채널 시그니처 표현 사전"·"서사 템플릿 슬롯"·"5단계 측정과 조정" 절)를 그대로 붙여넣으세요. 완성된 대본을 여기로 가져오시면, 제가 대본을 새로 쓰는 게 아니라 체크리스트 대조 검증만 하고 바로 G3로 넘어갑니다 — 이게 가장 가벼운 시작점입니다.

그 외 밖에서 할 수 있는 것 (사용량이 더 급하면)

  • 경쟁 채널 조사(동시대성 체크) — 이 환경은 youtube.com에 직접 못 들어가서 WebSearch 스니펫만으로 확인합니다. 사장님이 브라우저로 직접 채널을 훑어보시는 쪽이 더 정확하고 빠릅니다.
  • 주제 후보 목록 확장(topics.json) — 새 소재 브레인스토밍은 다른 AI와 하고, 확정된 후보 목록만 저한테 붙여넣어 주시면 파일 갱신만 제가 합니다.
  • 씬 이미지 실제 생성(나노바나나 프로) — 이건 원래도 사장님이 직접 하는 구간입니다. 생성 결과(스크린샷)만 공유해주시면 다음 프롬프트를 그걸 보고 씁니다.
  • 한 세션에 여러 에피소드를 동시에 굴리지 않기 — 이번 세션처럼 ep03·ep04를 번갈아 작업하면 대화가 길어지면서 매 턴 처리 비용이 늘어납니다. 가능하면 에피소드 하나당 세션 하나로 끊어서 시작하는 게 더 쌉니다.
  • 정말 급하면: 상대적으로 기계적인 작업(문서 재생성, 파일 정리처럼 창의적 판단이 적은 일)은 제가 에이전트를 돌릴 때 더 가벼운 모델을 지정해서 비용을 낮출 수도 있습니다 — 필요하면 말씀해주세요.

지금의 현실적 제약 (이것 때문에 루프가 이런 모양)

  • Typecast: 공개 API가 없어서 브라우저에서 직접 생성·녹음 캡처 — 수동.
  • Veo(Google Flow): API를 안 쓰고 Flow UI에 프롬프트를 직접 붙여넣어 클립 생성 — 수동.
  • 나노바나나 프로(이미지 선생성, 2026-08-30 필수화): 젬(Gem)에 이미지 프롬프트를 직접 붙여넣어 생성 — 수동. Flow 직접 텍스트→영상 생성은 결과가 들쑥날쑥해서 폐기.
  • 이 수동 단계들은 사람(사장님)만 할 수 있는 구간이고, 그 앞뒤를 숏감독이 채웁니다.

루프 (2026-08-30 갱신)

① 소재+대본+음성(사장님, 클로드 코드 밖) → ② 체크리스트 검증(숏감독, 가벼움)
   → ③ 정렬(숏감독, Whisper) → ④ 씬 이미지 프롬프트(숏감독)
   → ⑤ 이미지 생성(사장님, 나노바나나) → ⑥ 모션 프롬프트(숏감독, 실제 이미지 보고 확정)
   → ⑦ Flow 영상 생성(사장님) → ⑧ 합성(숏감독, ffmpeg) → ⑨ 리뷰(같이)
  1. 소재+대본+음성 (사장님, 클로드 코드 밖) — 다른 AI로 대본까지 완성하고 Typecast로 녹음까지 마친 뒤 결과물(대본 텍스트 + 음성 파일)을 가져옵니다.
  2. 체크리스트 검증 (숏감독) — templates/episode/CHECKLIST.md G1 항목 대조, 측정치(길이·숫자밀도·문장평균·36자+·격식체) 재확인. 문제 있으면 여기서만 가볍게 되돌려드립니다.
  3. 정렬 (숏감독) — Whisper로 실제 발화 타이밍 정렬, 8초 초과 블록 확인.
  4. 씬 이미지 프롬프트 (숏감독) — 04-scenes/image_prompts.md 작성. 결과물: 이미지 프롬프트 목록.
  5. 이미지 생성 (사장님) — 나노바나나 프로(젬)에 순서대로 붙여넣어 생성, 결과를 공유.
  6. 모션 프롬프트 (숏감독) — 실제 생성된 이미지를 보고 04-scenes/video_prompts.md 확정 (이론상 명세만으로 미리 다 쓰지 않음 — ep02 교훈).
  7. Flow 영상 생성 (사장님) — 이미지를 첫 프레임으로 Flow에서 클립 생성.
  8. 합성 (숏감독) — ffmpeg로 클립+나레이션+자막 합성.
  9. 결과 리뷰 (같이) — 다음 라운드 반영점 논의.

이미지가 잔잔하거나, 인포그래픽이 이상함 ④번부터 다시 (숏감독이 VISUAL_GRAMMAR.md 기준으로 재작업)
Flow 결과물이 이미지·모션 프롬프트 의도와 다르게 나옴 어떤 씬인지·뭐가 이상한지만 알려주시면 ⑥번을 다시 돌립니다
엔진 문서(VISUAL_GRAMMAR.md 등) 자체가 틀렸다고 판단될 때만 문서를 고치고 결정 로그에 남김 — 이건 드문 경우

원칙: 사장님은 매번 이 문서·엔진 문서를 다시 읽을 필요 없습니다. "이 씬 이상해" "대본 이 부분 어색해" 정도의 피드백만 주시면, 어느 엔진 규칙을 적용해서 고칠지는 숏감독이 판단합니다.
