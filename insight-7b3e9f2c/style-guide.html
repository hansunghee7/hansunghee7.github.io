실제로 있었던 사고 — Fontshare에서 Boska를 로드할 때 이탤릭 스타일을 따로 요청하지 않으면(font-style:italic을 줘도) 업라이트로 렌더링됩니다. 이탤릭이 필요하면 요청 weight를 기본weight + 1로 걸어야 합니다(200→201, 300→301, 400→401 — Fontshare 자체 규칙). 히어로 강조 텍스트가 기울어지지 않고 그대로 나온 실제 버그였습니다(2026-08-26).

카테고리 태그는 크림 배경에 검정 글씨(색 반전), Pretendard 11px 600. 상태 배지("완결" 등)는 반대로 배경 없이 옅은 보더만 두른 pill입니다 — 태그보다 존재감을 낮춰서 부제 취급되게 합니다.

새 페이지·섹션을 만들 때 체크리스트

  1. 색은 위 팔레트에서만 고른다 — 새 hex 값을 추가하지 않는다.
  2. 헤드라인은 Boska, 서술형 문장은 세리프, 태그·라벨·버튼 같은 기능적 UI 텍스트는 Pretendard — 세 폰트를 역할대로만 쓴다.
  3. Boska를 이탤릭으로 쓰면 weight+1 로드를 잊지 않는다(위 사고 사례 참고).
  4. 섹션 간격은 130 / 96 / 72px 리듬을 따르고, 좌우 거터는 32 / 16px을 쓴다 — 새 값을 눈대중으로 정하지 않는다.
  5. index.html처럼 스테이징과 짝을 이루는 페이지는 반드시 공유 include로 뽑아서 중복 편집을 막는다(_includes/home-body.html 사례). 반대로 about·speaking처럼 짝이 없는 단독 layout: null 페이지는, 톤(색·폰트)만 같으면 충분하고 값 자체를 억지로 공통 파일로 뽑지 않는다 — 실제로 비교해보면 페이지마다 여백·크기가 의도적으로 다르게 튜닝돼 있어서, 억지로 합치면 불필요한 추상화만 늘어난다.
  6. 새 시각 컴포넌트(카드·배지 등)를 만들기 전에 위 컴포넌트 목록에 재사용할 게 있는지 먼저 확인한다.

실제로 있었던 사고 (재발 방지용 기록)

Boska 이탤릭 업라이트 렌더링 — 위 타이포그래피 항목 참고. Fontshare weight+1을 안 걸면 기울어지지 않음.
카드 태그가 세로로 찌그러짐 — 카테고리 태그를 flex 컨테이너 안에 넣으면서 flex-shrink:0과 white-space:nowrap을 안 줬더니, 옆의 다른 요소에 밀려 태그 폭이 26px까지 줄어들고 글자가 세로로 줄바꿈됐습니다. flex 안에 텍스트 라벨을 넣을 땐 항상 이 두 속성을 같이 준다(2026-08-29).
모달 트리거가 모달 앞에 떠 보임 — <details>를 CSS 모달로 쓸 때, 열려 있는 동안 summary의 z-index가 backdrop/모달카드보다 높으면 트리거 버튼이 모달 위에 떠 보입니다. 열려 있는 동안 summary는 backdrop에 자연스럽게 가려지게 두고, 닫기는 모달 안의 별도 버튼/Esc가 담당하게 한다(2026-08-29).
