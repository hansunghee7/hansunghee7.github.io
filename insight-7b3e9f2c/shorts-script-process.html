원칙

대본은 창작이 아니라 측정 대상이다. 벤치마크(신비한 건축사전)를 수치로 분해해 목표치를 세우고, 초안을 그 수치에 맞춰 깎는다. "좋아졌다"는 느낌이 아니라 자릿수로 확인한다.

모든 숫자는 1차 출처를 확인한 것만 넣는다. 검색 AI든 딥리서치든 결과물은 초안이지 근거가 아니다.

1단계 — 벤치마크 측정 (채널당 1회, 이미 완료)

레퍼런스 영상의 자막(SRT)을 받아 기계적으로 센다. 감상이 아니라 통계다.

측정 항목과 신기한 아파트사전의 목표치:

항목 벤치마크 실측 목표
길이 161초 100~160초
숫자 밀도 8.0초당 1개 5~8초당 1개
문장 평균 길이 26.8자 20~27자
문장 길이 진폭 최소 4자 / 최대 76자 짧은 문장과 긴 문장을 섞을 것
36자+ 긴 문장 비율 28% 15% 이상
격식체(~습니다/~입니다) 비율 72% 65~75%
캡션 큐 평균 1.86초 · 14.4자 문장을 이 리듬에 맞춰 끊는다

주의: 자동 생성 자막은 마침표를 자주 빠뜨린다. 문장 두 개가 하나로 붙어 길이가 부풀 수 있다. 최대값은 참고치로만 쓰고 맹신하지 않는다.

"문장을 짧게"만 지키면 실패한다. 전부 20자 안팎으로 고르면 밋밋해진다. 긴 설명 뒤에 8자 안팎 짧은 문장을 박아 리듬을 만드는 것이 핵심이다.

2단계 — 소재 확정 (G0)

channel.json의 content_engine을 통과해야 한다.

익숙한 것 → 이상한 발견 → 상식 충돌 → 왜? → 숨겨진 원리 → 인식 전환

훅이 "X인데 Y입니다" 모순 구조로 한 문장에 써지지 않으면 소재를 바꾼다. '신기함'이 아니라 '상식의 배신'이 자산이다.

  • ep02 예: "탱크는 사라졌는데 물은 여전히 70미터 위까지 올라간다"

후보는 여러 개를 동시에 놓고 경쟁시킨다 (2026-08-30, ep03에서 확립). 소재 하나씩 순서대로 검토하지 말고 8~10개 후보를 한 번에 뽑아 훅 강도로 순위를 매긴다 — 1위가 항상 최종 채택은 아니다. 순위를 매기기 전에 경쟁 채널 중복 확인을 먼저 통과한 것만 남긴다: 훅 강도 1위였던 "배수구에서 냄새가 안 나는 이유"는 벤치마크(신비한 건축사전)가 이미 다룬 것으로 확인돼 후보에서 제외됐고, 3위였던 "택배차 진입 불가"가 최종 채택됐다 (리서치 단계에서 §5.4로 한 번 더 겹침 확인). 순서: 후보 나열 → 경쟁 채널 중복 확인(탈락시키기) → 남은 후보끼리 훅 강도 순위.

3단계 — 리서치

templates/RESEARCH_BRIEF.md로 외부 검색 AI에 의뢰하거나 직접 조사한다. 받은 결과는 그대로 쓰지 않는다.

검증 순서 1. URL 없는 수치는 전부 보류 2. 대본에 실제로 쓸 것만 1차 출처를 직접 연다 (전부 검증할 필요 없다) 3. 정책·통계는 대상 범위를 확인 — 다른 범위의 통계를 섞는 오염이 가장 흔하다 4. 결과를 01-script/sources.md에 확정 / 보류 / 폐기로 기록

숫자는 친숙한 대상으로 환산해 함께 적어둔다. 벤치마크의 핵심 기법이다. - 7~10m → 아파트 세 개 층 높이 - 6,369만m³ → 500m 땅에 63빌딩 높이로 쌓는 양 (벤치마크 사례)

환산은 대본에 나오는 단위 전부에 적용한다 — 일부만 하면 티가 난다 (2026-08-30, ep04). ep04 초안에서 뉴턴(→11kg 캐리어)·풍속(→걷는 속도)은 환산했으면서 파스칼(40·12.5·5)은 숫자 그대로 5번 반복했다가 "전문 강의처럼 들린다"는 피드백을 받았다. 특히 파스칼처럼 일상에서 안 쓰는 단위는 우선순위가 높다 — 미터·킬로그램처럼 어느 정도 감이 오는 단위보다 먼저 환산 대상으로 체크할 것. 대본을 다 쓴 뒤 "이 대본에 나오는 단위를 전부 나열하고, 각각 환산했는지"를 스스로 점검하는 한 단계를 4단계 말미에 추가한다.

리서치 브리프에 "유사 콘텐츠 조사" 항목을 넣는다 (2026-08-30, ep03). 사실 검증과 별개로, 이 소재를 정면으로 다룬 유튜브 콘텐츠(특히 벤치마크·경쟁 채널)가 있는지 딥리서치에 같이 물어본다. G0에서 이미 한 번 걸렀어도, 리서치 단계에서 더 자세한 내용을 보면 미묘하게 겹치는 인접 소재가 새로 드러날 수 있다 (ep03은 이 단계에서 "택배차 진입 층고 갈등"을 정면으로 다룬 영상이 없음을 재확인 — sources.md §5.4).

1차 출처로 확인 안 된 "해석성 주장"은 별도로 표시해둔다. 조문·통계처럼 원문에 박힌 사실이 아니라 "이 숫자는 승용차 기준으로 정해진 것이다"처럼 정황상 추론인 문장은, 나중에 외부 리뷰나 팩트체크에서 문제 제기될 걸 대비해 sources.md에 "추론이다"라고 미리 적어둔다 — 나중에 급하게 판단하지 않도록.

안전·재난 대응 설비를 다룰 때는 "상시 가동"처럼 들리는 표현을 특히 의심한다 (2026-08-30, ep04 — 외부 팩트체크에서 발견). 리서치 결과를 요약하며 "평소엔 센서가 압력을 유지하고요"라고 썼는데, 실제로는 화재감지기가 작동해야 송풍기· 댐퍼가 가동되는 트리거 기반 시스템이었다 — 딥리서치 원문엔 "화재가 감지되어 가동되면"이라고 정확히 적혀 있었는데 요약 과정에서 트리거 조건이 빠졌다. 소방·제연·스프링클러 같은 설비를 서술할 때는 "평소/항상/24시간"류 표현을 쓰기 전에 그 설비가 상시 가동인지 감지 트리거 기반인지 리서치 결과에서 다시 확인한다.

4단계 — 초안

섹션 구성은 channel.json의 script_structure를 따른다. 훅 → 문제 제시 → 반전 1~3 → 엔딩. CTA는 넣지 않는다.

  • 정보를 나열하지 않는다. 질문 → 답 → 더 큰 질문 체인으로 굴린다.
  • 감정을 강요하지 않는다. "충격!" "놀라운" 금지. 그런데… 문제는… 사실…로 전개.
  • 핵심 용어가 처음 나오는 자리는 명사형으로 끊는다. (고가수조 방식입니다. 부스터펌프.)
  • 종결어미를 흩뿌린다. ~거든요 ~죠 ~고요 ~거죠를 서너 군데.
  • 엔딩은 처음 던진 질문을 닫는다. 마지막 줄은 짧은 명사형 한 줄.

서사 템플릿 슬롯 (2026-08-30 발견, ep03). 사실관계가 정확해도 "반전이 약하다"는 평가를 받을 수 있다 — 정보를 순서대로 나열만 하고, 갈등과 전환을 독립된 한 문장으로 응축하는 자리를 비워뒀기 때문이다. 벤치마크는 아래 네 자리를 항상 채운다. 초안을 쓸 때부터 이 자리를 의식적으로 채워라. 다 쓰고 나서 피드백을 받고 채우려 하면 이미 구조가 밋밋하게 굳어 있어 고치기 어렵다 (ep03은 이걸 못 채운 채로 7차까지 갔다).

자리 역할 ep03 예시 우선순위
도입 평범한 대상을 지목 "아파트 앞에 택배차가 도착했습니다." —
난관 압축 갈등을 한 문장 감탄사로 응축 (시그니처 표현 사전 참고) "환장할 노릇입니다." 필수
전환 해결 주체가 발상을 뒤집는 순간을 명시 "그래서 정부가 발상을 뒤집습니다." 최대한 반영(시제 유연)
결론 처음 던진 질문을 닫으며 인식 전환 "그래서 아파트가 못 바꾼 걸, 사람이 몸으로 바꾸고 있는 겁니다."

4.5단계 — 외부 리뷰 (권장, 2026-08-30 확립)

가능하면 초안을 별도 세션·다른 AI에게 냉정하게 검토받는다. 자체 검토만 반복하면 "기술적으로는 맞는데 밋밋하다" 유형의 문제를 스스로 못 잡아낸다 — ep03은 혼자 7차까지 고쳤는데도 못 잡았던 "반전이 약하다"는 문제를, 외부 리뷰(88/100, 구조적 지적 4가지) 한 번으로 8차에서 해결했다.

받은 피드백을 전부 반영하지 않는다. 채널 원칙(감정 강요 금지, 격식체 비율, content_engine)과 충돌하는 제안은 거른다. "우리가 인정하고 적용할 부분은 뭘까"로 선별하고, 왜 그 항목만 적용했는지 남긴다.

피드백이 1차 출처로 확인 안 된 해석성 주장을 지적하면: 1. 안전한 대안 문구를 함께 제시한다. 2. 최종 결정은 PD(사장님) 몫이다 — 강한 표현을 그대로 쓰기로 결정해도 정당한 선택이다(조회수 대 팩트체크 리스크는 사업 판단이지 대본 판단이 아니다). 3. 어느 쪽으로 결정했든 sources.md에 근거와 리스크를 남긴다 — ep03의 "사용자 확정: 검증 안 된 해석성 주장을 그대로 유지" 섹션이 재사용 가능한 기록 형식이다.

5단계 — 측정과 조정

초안을 1단계 표에 대고 잰다. 어긋난 항목만 고친다.

ep02 실제 경과:

항목 1차 초안 리듬 조정 후 리서치 반영 후
길이 102.5초 102.5초 117.0초
숫자 밀도 7.3초당 1개 7.3초당 1개 4.9초당 1개
36자+ 비율 8% 8% 17%
격식체 94% ❌ 66% 69%

격식체 94%가 가장 큰 실패였다. 전부 ~습니다로 끝나 설명문처럼 읽혔다. ~거든요 ~죠를 섞고 짧은 명사형 문장을 박아 66%로 내렸다.

개정을 여러 차례 반복하면 길이가 계속 줄어드는 함정이 있다 (2026-08-30, ep03). "펀치감을 올리자"는 식의 압축형 개정을 4.5단계 이후 여러 차례 거치면서 초안 102.9초가 최종 88.5초까지 떨어졌다 — 목표 하한(100초) 아래로 빠진 걸 실제 녹음(97.14초, 발화가 대본 추정보다 느려서 다행히 목표에 다시 근접) 전까지 몰랐다. 매 개정판마다 이 표로 다시 측정한다. "느낌상 나아졌다"로 판단하지 말 것. 목표 하한에 가까워지면 다음 개정은 압축이 아니라 확장 방향으로 조정한다.

대본을 검토·수정할 때마다 GitHub 링크를 사장님께 전달한다 (2026-08-30, 사장님 요청). 타입캐스트 녹음 등 다음 작업을 바로 이어갈 수 있게, narration.txt가 바뀔 때마다 https://github.com/hansunghee7/shorts-lab/blob/main/channels/<채널>/ episodes/<에피소드>/01-script/narration.txt 형태의 링크를 답변에 포함한다.

narration.txt의 문단 구분은 script.json 블록과 1:1이 아니다 (2026-08-30 발견). 타입캐스트는 빈 줄마다 숨을 쉬므로, script.json의 4초/6초 블록 경계마다 그대로 빈 줄을 넣으면 뚝뚝 끊겨 읽힌다. "보기 좋은 대본"이 아니라 "필재가 맛나게 읽는 대본"이 기준이다.

2단계 호흡 규칙 (2026-08-30 수정 — 빈 줄만으로는 부족했다. 빈 줄 두 개를 계속 이어 쓰니 호흡이 너무 길어진다는 게 실측으로 확인됨):

  • 줄바꿈 한 번(엔터 1번) = 짧은 호흡. 문장이 바뀌지만 같은 흐름 안에 있을 때 — "원인은 법 조항 하나입니다."처럼 강조하는 단독 문장도 이걸로 충분하다.
  • 빈 줄(엔터 2번) = 긴 호흡. channel.json의 script_structure 대분류 (훅 / 문제 제시 / 반전1 / 반전2 / 반전3 / 엔딩)가 바뀌는 자리, 즉 에피소드 전체에서 5~6번 정도만 나와야 한다. 그보다 자주 쓰면 뚝뚝 끊겨 들린다.
  • script.json/narration_blocks.txt의 블록 단위는 씬 설계(G4)를 위해 그대로 유지한다 — 정렬(G3)은 어차피 Whisper로 실제 녹음을 텍스트와 맞춰보는 것이라, narration.txt의 줄바꿈 방식이 이후 공정에 지장을 주지 않는다.

episode.json의 g0_topic g1_script를 done으로 바꾸고 현황판을 갱신한다.

우리 채널 시그니처 표현 사전 — 벤치마크를 그대로 베끼지 않는다

channel.json의 "감정 강요 금지('충격!' 금지)" 규칙은 시청자에게 감정을 지시하는 감탄사를 막는 것이지, 상황 자체를 생생하게 묘사하는 구어체 관용구를 막는 게 아니다 — 후자는 오히려 권장한다.
