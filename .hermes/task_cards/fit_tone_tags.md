# 카드: 음성 대본 톤 태그 초안(tone_tags.json 채우기)

> 상태: 실측 1차 결과 14B 부적합(2026-09-30 탐, 핏 검토 대기). 32B 측정은 GPU가 빌 때 한다. 지금은 제미나이 API 1콜로 하고 있고 결과도 쓸 만해서, 이 카드는 "제미나이 대체"가 아니라 "무료 로컬로 초안, 제미나이는 막힐 때"의 절약용이다. 도입 전 ep25 대본으로 제미나이 결과와 줄별 비교를 해 톤 판단 품질이 떨어지지 않는지 본다.

- 호출자: 핏
- Tier: Local (왜: 미공개 대본이라 장비 밖으로 나가면 안 됨)
- 입력: 줄 나눈 대본 narration 한 편(20~35줄, 약 1500자 이내). 줄마다 번호와 원문
- 출력: 줄마다 `{i, tone, speed, pause, emph, why}` 배열(`additionalProperties: false`). `text`는 엔진이 쓰지 않고 호출자가 원문을 붙인다
- 검증기: 코드가 확인한다. ① 줄 수·번호가 입력과 같다 ② `tone`은 기존 `tone_tags.json`에서 뽑은 허용 목록 안 ③ `speed` 0.9~1.2, `pause` 0~1.0 범위 ④ `emph` true는 편당 최대 3줄 ⑤ 엔진이 원문을 고쳐 쓰지 않았다(원문은 호출자가 붙이므로 구조적으로 보장)
- 호출자의 최종 판단: 핏이 초안을 저장하고 사장님이 청취한 뒤 고칠 줄만 손으로 고친다. 톤이 맞는지는 판정 불가라 "초안 전용"
- 실패하면: 스키마·범위 위반이면 결과를 버리고 기본값(explain, 1.0, 0.3, false)으로 채워 핏에게 알린다. 5분 안에 안 돌면 종료
- 빈도: 편당 1회, 주 2~3편

참고(핏의 답): 해상도·길이·줄 글자수·파일 존재·음량은 이미 스크립트가 하므로 엔진 대상이 아니다. 조립·업스케일·음성 생성은 GPU 실행이라 헤르메스 이관이 따로 돌고 있어 카드 대상이 아니다. 엔진 후보는 판단이 들어가는 초안(톤 태그, 성과 학습 로그의 원인 가설 문장)뿐이다.

## 실측 1차 (2026-09-30 탐, `scripts/ops/delegate_tone_tags.py`, 로컬 14B, 기준본 = 제미나이가 만든 기존 tone_tags.json)
- ep25(16문장): 3회 시도 모두 검증기 반려(emph 3줄 초과), 기본값 대체됨. 기본값이 전부 explain이라 일치 6/16은 우연.
- ep26(28문장): 2회 만에 통과했지만 톤 일치 11/28(39%). 엔진 출력이 거의 전부 explain이라 hook·twist·tension·closing 구분을 못 했다. 반전 문장("그런데", "아닙니다")도 explain.
- 지연 40~50초. 개선 여지: 프롬프트에 기존 편의 예시 몇 줄을 넣는 방법(카드 입력 한도 안). 다만 톤 판단 품질이 코드 검증으로 안 잡히므로 청취 판정은 사장님.
- 결론(잠정): 14B는 톤 구분 능력이 부족해 "제미나이 대체"로 못 쓴다. 32B(19GB)로 같은 두 편을 재측정해 보고, 그래도 안 되면 이 카드는 폐기하고 제미나이 1콜을 유지한다. 32B는 핏이 GPU를 쓰지 않을 때만 돌린다(세션 메시지로 확인).
