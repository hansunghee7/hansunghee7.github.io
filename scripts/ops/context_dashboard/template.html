활동

얼마나 일하고 있는지를 보여 주는 지표입니다. 많다고 좋은 것은 아니어서 결과 지표와 함께 봅니다.

결과

일이 어떻게 끝났는지 보여 주는 지표입니다. 위에서부터 대표님이 먼저 궁금해할 순서입니다. 요청 완료 시간, 사람 개입 비율, PR 되돌림 비율은 낮을수록, 이어받기 점수는 높을수록 좋습니다.

시안 메모

바뀐 점(v4 대비): 처음 고객에게 필요 없는 것을 뺐고, 항목을 대표님이 궁금해할 순서로 다시 놓았습니다.
  • 뺀 것: "다른 고객 평균(3팀 이상부터)"와 "문서 등급을 적용했을 때" 자리. 둘 다 근거가 쌓인 뒤에 다시 넣습니다.
  • 결과 순서: 요청 완료 시간(얼마나 빨라졌나), 사람 개입 비율(내 손이 덜 가나), 이어받기 점수(담당자가 바뀌어도 이어지나), PR 되돌림 비율(망가뜨리지 않나). 활동은 그 아래 보조입니다. 순서는 제가 고객 입장에서 추정한 것이고, 월요일 질문으로 확인합니다.
  • 추가(v6): 결과 지표에 "성공 한 건당 비용(CPSO)"을 넣었습니다. 병합 PR 한 건을 끝내는 데 든 노력을 보는 지표입니다. 우리 팀에서 먼저 측정해 보고, 값이 믿을 만하면 고객이 API로 기록을 보내 분석 리포트를 받는 형태를 검토합니다.
  • 측정 현황: 금액 계산은 장부에 병합 PR 번호가 없어 하루 단위까지만 가능하고, 비용 쪽도 일부만 연결돼 있어 지금은 "측정 전"으로 둡니다. "지금"은 예시 숫자입니다.
  • "지금"은 예시 숫자입니다. 실제 화면에서는 연결된 에이전트 팀의 기록이 들어옵니다.
  • Carvit 에이전트 팀 실측: PR 되돌림 0.3%(병합 1,000건 중 제목에 되돌림 표시 3건, 근사치), 교신 가능 에이전트 3명(이번 주 GitHub 교신방에서 말머리 댓글을 쓴 탐·핏·지투, 우편으로만 교신한 에이전트는 제외), 정본 문서 186개(docs 폴더, 아카이브 제외).
  • 메뉴 순서(임시): 공개 사이트 머리 메뉴 순서(UX, Create, Pass 다음 Context)를 따랐습니다. 로그인 뒤 콘솔 구조는 지투가 설계해 사장님이 컨펌하기 전이라, 확정되면 다시 맞춥니다.
  • 추가(v7): 순서를 바꿨습니다. 활동을 먼저, 결과를 그 뒤에 둡니다(사장님 10/15). 병합 PR 수는 회사 저장소 기록으로 연결했습니다(지난 7일 168건, 그 전 7일 650건, 작성자가 봇이 아닌 PR 기준이며 자동 병합 PR도 사람 계정 이름으로 올라가 있어 완전히 걸러지지는 않습니다).
  • 측정 전으로 남은 것과 이유: 요청 완료 시간(회사 저장소가 이슈를 쓰지 않아 열림에서 닫힘을 잴 수 없습니다, 요청을 남기는 곳부터 정해야 합니다), 사람 개입 비율(`[사람]` 말머리 규칙이 있어야 계산됩니다), 이어받기 점수(5문항 시험을 돌려야 합니다), 성공 한 건당 비용(PR 댓글에 교신이 거의 없어, 교신 기록을 PR과 이어야 계산됩니다).
