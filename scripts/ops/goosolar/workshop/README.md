# 구PC 에이전트 작업실: Flow 레시피 (2026-09-24 첫 실측)

사장님 화면·브라우저와 분리된 구PC에서, 가상 모니터(Xvfb) 위 진짜 크롬을 Flow 전용 프로필로 띄워 두고
Playwright가 **캡처 없이 페이지 구조(접근성 트리)로** 조작한다. 정상 흐름에는 AI 호출이 없다.

## 구성 (구PC `~/workshop/`)
- `venv/` Playwright(파이썬), `profiles/flow-free1/` 로그인된 크롬 프로필(저장소에 넣지 않음), `out/` 결과물
- 크롬 실행: `xvfb-run -a -s "-screen 0 1366x900x24" google-chrome --user-data-dir=$HOME/workshop/profiles/flow-free1 --remote-debugging-port=9222 --remote-debugging-address=127.0.0.1 ...`
  (디버그 포트는 127.0.0.1에만 열림. 원격으로 보려면 `ssh -L 9222:127.0.0.1:9222` 터널 + 로컬 크롬 `chrome://inspect`)

## 스크립트
| 파일 | 하는 일 |
|---|---|
| `probe.py <url>` | 새 헤드리스 창으로 페이지를 열고 구조 줄 수만 확인 |
| `read_cdp.py` | 떠 있는 크롬(9222)의 Flow 페이지 구조 읽기 |
| `flow_state.py` | 설정 트리거 문구·라디오 선택 상태 확인(생성 전 점검) |
| `flow_gen.py <프롬프트파일> <저장경로>` | 설정 확인 → 입력 → 생성 시작 → 새 `<video>` src가 생길 때까지 대기 → 그 주소를 직접 받아 저장 |

## 실측 (2026-09-24, 씬01 1개)
- 설정: 동영상·소재·9:16·Omni 1.1 Flash·360p·4초·x1(4크레딧). 설정은 사장님이 원격 화면에서 맞춤, 레시피는 확인만.
- 결과: 생성 시작부터 저장까지 52초, 360x640·4.0초·오디오 포함, 사장님 품질 확인("완전 잘나왔다").
- 완료 판정: 화면 캡처가 아니라 페이지의 진행률 글자(0%→9%→17%)와 새 `<video>` 요소의 src 등장.
- 다운로드: 브라우저 다운로드 창을 쓰지 않고 src를 직접 받아 씬 이름으로 저장하므로, 병렬이어도 파일 이름이 섞이지 않는다.
