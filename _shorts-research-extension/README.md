# Simplifier 숏폼 리서치 자동화 (크롬 확장, 개인용) — 1차 버전 (v0.5.2)

숏폼 채널(신기한 아파트사전) 대본 작업 중 수치를 검증할 때, 브리프를
복붙해서 gemini.google.com에 넣고 딥리서치 결과를 다시 복붙해오던 걸
자동화합니다. `_sns-extension`과 같은 구조(팝업 + 백그라운드 + 콘텐츠
스크립트)를 재사용했지만, 성격이 다른 자동화라 **별도 확장으로 분리**했습니다
— 한쪽이 깨져도 다른 쪽까지 같이 안 깨지게 하려고요.

## v0.5.2 — 딥리서치 전환 방식 수정 (실제 화면 확인 반영)

이전 버전은 "딥 리서치"라는 글자가 화면에 바로 보이는 버튼을 찾으려
했는데, 실제로는 **입력창 영역의 "+" 버튼을 먼저 눌러야** 그 메뉴 안에
"딥 리서치" 항목이 나타나는 구조였습니다(사장님이 직접 화면 확인해주심,
2026-08-30). 그래서 v0.5.1까지는 이 단계가 계속 실패해서 딥리서치 없이
일반 채팅으로 제출되고 있었을 가능성이 큽니다(2분 반 만에 "완료"된 실행
사례로 확인 — 참고로 그 답변 자체는 출처가 붙어있어 품질은 나쁘지
않았지만, 진짜 멀티스텝 딥리서치를 탄 건 아니었을 수 있습니다).

v0.5.2부터는 "+" 클릭 → 메뉴에서 "딥 리서치" 클릭, 2단계로 찾습니다.

## ⚠️ 이 버전에서도 확실하지 않은 것 — 안 되면 확인

입력창·전송 버튼·응답 영역·계획 확인 버튼은 여전히 이 세션이 실제
화면을 못 본 채 추정한 선택자입니다. 안 되면:

1. 확장이 연 창(최소화돼 있으니 작업 표시줄에서 찾아 창을 띄우세요)에서
   F12로 개발자 도구를 엽니다
2. 콘솔 탭에서 `content-script.js` 상단 주석에 있는 확인용 코드를
   하나씩 실행해서 실제 요소가 잡히는지 봅니다
3. 안 잡히면 그 요소를 우클릭 → 검사(Inspect)해서 실제 구조를 알려주세요
   — `content-script.js` 맨 위 `SELECTORS` 객체만 고치면 됩니다

콘솔에 `[숏폼 리서치]`로 시작하는 로그가 각 단계(입력창 찾음/모드 전환/제출/
응답 감지)마다 남으니, 어디서 멈췄는지는 로그만 봐도 알 수 있습니다.

## ⚠️ 알아두어야 할 것 — 계정 자동화

이건 구글의 공식 API가 아니라 **웹 화면을 사람 대신 조작하는 방식**입니다.
제미나이 앱(소비자용 웹 서비스)의 이용약관은 이런 자동 조작을 금지할 수
있습니다. 사장님 본인 구글 계정(Gmail 등 다른 서비스와 공유)으로 쓰는
거라는 점은 인지하고 계셔야 합니다. 대량으로 돌리거나 남에게 배포하지
마세요.

**v0.5부터 판단 기준이 달라졌습니다.** 처음엔 "하루 1~2건, 사람이 매번
트리거" 전제로 리스크를 낮게 봤습니다. 이제 대본 자동 파이프라인의
필수 기본 프로세스로 쓰려는 게 목표라, 실제 사용 빈도가 그보다 늘어날
수 있습니다. 사용 빈도가 눈에 띄게 늘거나(하루 여러 건 이상), 계정에
경고/제한이 뜨면 — 그건 "조금 줄이자"가 아니라 즉시 멈추고 재검토할
신호입니다.

**계획 자동 승인의 트레이드오프**: v0.5부터 제미나이가 조사 계획을
제시해도 사람 확인 없이 즉시 승인하고 진행합니다(아래 "무인 리서치
대기열" 참고). 사람이 계획을 검토해 잘못된 방향의 리서치를 미리 막을
기회가 없어졌다는 뜻입니다 — 그 대신 계획 원문을 결과와 함께 GitHub
이슈에 남겨서, 사후에라도 뭘 조사했는지 확인할 수 있게 했습니다.

## 설치 방법

1. 크롬 주소창에 `chrome://extensions` 입력 후 이동
2. 오른쪽 위 "개발자 모드" 켜기
3. "압축해제된 확장 프로그램을 로드합니다" 버튼 클릭
4. 이 폴더(`_shorts-research-extension`)를 선택
5. 브라우저 오른쪽 위 확장 아이콘에서 "숏폼 리서치 자동화" 클릭

## 쓰는 법 (수동 실행)

1. 확장 아이콘 클릭 → 팝업의 입력창에 브리프 붙여넣기
2. "리서치 시작" 클릭 — 화면 뒤에서 조용히 창이 열립니다
3. 제미나이가 조사 계획을 제시하면 **자동으로 승인하고 바로 진행합니다**
   (사람 확인 없음 — 위 "계정 자동화" 트레이드오프 참고). 계획 단계
   자체가 없는 짧은 요청이면 이 단계는 그냥 건너뜁니다.
4. 보통 5~20분 뒤 알림이 뜨며 결과가 클립보드에 자동 복사됩니다
   (브라우저 정책으로 자동 복사가 안 될 수 있어서, 그럴 땐 팝업을 다시 열어
   "결과 다시 복사" 버튼을 쓰세요 — 결과는 저장돼 있어서 안 사라집니다)
5. 성공하면 창이 10초 뒤 자동으로 닫힙니다. **실패하면 안 닫습니다** —
   화면을 직접 보고 뭐가 막혔는지 확인할 수 있게 남겨둡니다.

⚠️ 계획 확인 버튼의 선택자(`SELECTORS.planConfirmButton`)도 실제 화면을
못 본 채 추정한 것입니다 — 계획 단계가 분명히 있었는데 로그에 "계획 확인
단계 없음"이라고 뜨면, F12 콘솔로 실제 버튼을 찾아 이 선택자를 고쳐주세요.

## 선택자 이탈 감지 (v0.3)

딥리서치 전환 버튼이나 응답 영역 선택자를 못 찾아도 지금까지는 콘솔 경고만
남기고 조용히 다른 방식으로 계속 진행했습니다 — 기능은 안 죽지만, 예를 들어
딥리서치 대신 일반 채팅으로 조용히 제출되는 것도 콘솔을 안 열면 몰랐습니다.
이제 같은 종류가 **2번 연속** 발생하면 팝업 상단에 노란 경고 배너가 뜨고
알림도 옵니다. "확인함"을 누르면 배너는 사라지지만, 실제 원인(화면 구조
변경)은 `SELECTORS`를 직접 고쳐야 없어집니다 — 배너는 문제를 고치는 게
아니라 존재를 알려주는 용도입니다.

## 결과를 자동으로 "탐(클로드)"의 프로세스로 넘기기 (v0.4)

클립보드/팝업은 이 브라우저를 벗어나면 사라져서, 지금까지는 사장님이
결과를 직접 복사해 클로드에게 전달해야 했습니다. GitHub 토큰을 연결하면
(팝업 하단 "GitHub 연결" 섹션), 완료될 때 결과가 **이 저장소에 GitHub
이슈로도 자동 등록**됩니다(제목 `[리서치 완료] ...`) — 클로드가 브라우저를
못 봐도, 저장소는 정기적으로 확인할 수 있기 때문입니다.

이슈 등록은 완전히 선택 사항이자 부가 기능입니다 — 토큰을 연결 안 해도
클립보드/팝업 결과는 그대로 동작합니다. 실패해도(권한 부족 등) 콘솔에만
로그를 남기고 조용히 넘어갑니다.

이 이슈를 정기적으로 확인해 처리하는 예약 자동화(Routine)는 **만들지
않았습니다** — 실제로는 사장님이 리서치를 걸어두고 3~10분 안에 근처에서
결과를 확인하는 패턴이라, 몇 시간 단위 폴링이 오히려 실제 완료 시점보다
늦게 반응하는 역효과가 있었습니다. 완료 알림이 뜨면 그때 클로드에게
직접 확인을 요청하는 지금 방식이, 이 사용 패턴에는 더 빠릅니다. 사람이
자리를 비운 채 여러 건을 몰아 돌리는 패턴이 생기면(바로 아래 대기열
기능), 그때 다시 검토합니다.

## 무인 리서치 대기열 (v0.5)

**목표**: 사장님이 대본 주제만 정해두면, 딥리서치가 사람 없이도 알아서
돌고 결과가 쌓이는 것. GitHub 토큰을 연결하면, 확장이 **10분마다**
`queue.json`을 확인해서 대기 중인 항목을 하나씩 자동으로 처리합니다.

### 대기열에 항목 추가하기

이 저장소의 [`_shorts-research-extension/queue.json`](queue.json) 파일을
열어(GitHub 웹 편집 또는 로컬 clone) 배열에 항목을 추가하고 커밋·푸시하면
됩니다:

```json
{
  "id": "고유한-문자열-아무거나",
  "brief": "제미나이에 그대로 넣을 리서치 브리프 전체 텍스트",
  "status": "pending"
}
```

- `id`: 항목을 구분하는 값. 겹치지만 않으면 형식은 자유입니다(예:
  `ep05-water-tank`, 또는 그냥 날짜+순번).
- `status`: 새 항목은 항상 `"pending"`으로 둡니다. 확장이 처리하면서
  `"in_progress"` → `"done"`(또는 실패 시 `"error"`)으로 자동 갱신하고,
  `startedAt`/`finishedAt`/`note` 필드를 스스로 채웁니다 — 이 필드들은
  손으로 안 건드려도 됩니다.
- 한 번에 여러 개를 추가해도 됩니다 — **한 번에 하나씩만** 순서대로
  처리합니다(겹쳐서 여러 창이 뜨지 않게).

### 동작 조건과 한계

- **크롬이 실행 중이어야 합니다.** 브라우저 창을 다 닫아도 상관없지만,
  크롬 앱 자체가 완전히 종료되면(트레이 상주 없이 꺼지면) 알람도 안
  돕니다. PC를 켜둔 채 크롬만 열려 있으면 충분합니다.
- 대기열도 GitHub 이슈 등록과 같은 토큰을 씁니다 — 연결 안 하면 대기열
  기능도 동작하지 않습니다.
- 완료된 항목의 결과는 (토큰이 연결돼 있으므로) 자동으로 GitHub 이슈에도
  등록됩니다 — 대기열과 이슈 등록은 사실상 세트로 동작합니다.
- 대기열에서 자동 실행된 항목은 팝업 최근 기록에 "대기열" 표시가 붙습니다.

### 워치독 (v0.5.1)

크롬이 메모리 절약을 위해 안 쓰는 백그라운드 탭을 정지시키면, 그 탭
안의 타이머/감시 로직이 통째로 멈춰서 "25분 넘으면 실패 처리"조차
실행이 안 될 수 있습니다(실제로 53분째 "진행 중"에 멈춘 사례로 확인됨).
그래서 background.js가 독립적으로 **30분 넘게 "진행 중"인 게 있으면
강제로 실패 처리**하고 다음 대기열 항목으로 넘어갑니다 — 탭 안에서
실제로 무슨 일이 있었는지는 알 수 없지만(관측 불가 구간), 최소한
파이프라인 전체가 영영 멈추는 건 막습니다.

## 1차 범위에서 뺀 것 (다음 단계)

- shorts-lab 저장소로의 직접 커밋(대본 파일에 바로 반영)은 아직입니다.
  그 저장소가 이 작업 세션에 연결돼 있지 않아서, 지금은 이 저장소의

## 제미나이 API 재사용은 안 씀 — 이유

`simplifier-agent` 저장소에 이미 연결된 제미나이 키가 있지만, 이 자동화엔
안 씁니다.

- 그 키는 `generateContent`(일반 채팅)용으로만 쓰이고 있고, 무료 티어로
  보입니다(코드 주석에 "무료 티어라 503이 종종 뜬다"는 메모가 있음).
  딥리서치는 별도 API(Interactions API, 2026-06 정식 출시)와 유료 Pro
  모델이 필요해서, 이 키를 그대로 넘겨도 딥리서치는 안 됩니다.
- 설령 새 키를 유료로 만들어도, 딥리서치 API 자체가 **작업당 2~5달러**입니다.
  이 확장처럼 무료 제미나이 앱을 직접 조작하는 쪽이 비용 면에서 낫습니다.

(자세한 내용: `simplifier-cxo-db` 비공개 저장소의 관련 결정 기록 참고)
