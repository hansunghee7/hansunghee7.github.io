# 세션 운영 실측과 근거 (CLAUDE.md에서 옮겨 온 원문)

> `CLAUDE.md`의 "세션 운영 교리"(id: d78e)와 "세션 중"(id: 9eaf)에 있던 실측·사례 문장을 **원문 그대로** 옮겼다(2026-09-20 슬림화 PR1). 원칙은 `CLAUDE.md`에 남아 있고, 이 문서는 왜 그렇게 정했는지의 근거다.

## 1. 비용 구조 실측 (세션 운영 교리, 2026-08-30)
토큰 비용 ≈ **컨텍스트 크기 × 도구 호출 횟수**입니다. 매 도구 호출마다 대화 전체가 다시 전송되므로, 사흘 살려둔 세션은 한 줄 질문도 사흘치 대화만큼 비쌉니다.
실측: 2026-08-28~30 스레드 5개가 $656을 썼고 최장수 세션 하나가 $303.
근거: [공식 비용 문서](https://code.claude.com/docs/en/costs) · [공식 베스트 프랙티스](https://code.claude.com/docs/en/best-practices).

## 2. 70% 셀프 체크의 세부 (세션 중, 2026-09-05 도입)
`get_usage`(session_id 생략 또는 "self")를 호출하면 `context.percentUsed`, `context.tokensUsed`, `context.contextWindow`와 계정의 `plan` 한도(5시간, 주간)가 나옵니다(2026-09-19 실측). 70%를 넘으면 "조금만 더" 하지 말고 그 자리에서 저녁 의식으로 넘어가세요. 감으로 판단하던 걸 숫자로 체크하게 한 것입니다(새 자동화·도구 불필요, 이미 있는 무료 조회).

## 3. 서브에이전트 시뮬레이션이 기본값인 이유 (세션 중)
탐(또는 진행 중인 세션)이 필요한 페르소나를 서브에이전트로 불러 1~2라운드 토론시키고 종합합니다. 근거 둘: ① 2026-09-04 마야·시안이 각자 독립 세션에서 같은 "새김 소개 페이지" 피드백을 중복 작성한 사례(진행상황.md), ② 2026-09-05 새김 세션이 이 방식으로 4인 논의를 돌려 검증 완료(비용 유한, 2라운드가 새 통찰까지 냄). 그 프로젝트를 계속 담당하며 결정하는 **지속적 소유권**이 필요할 때만 별도 세션을 새로 띄우세요.

## 4. 2026-09-05 사용량 실측 감사
계정 세션 50개 기준 누적 비용 $1,830, 상위 10개 세션이 그중 69%($1,259). 비용은 산출물(output_tokens)보다 **캐시 재전송량(cache_read_tokens, 즉 세션 길이)**과 훨씬 강하게 붙어 있음. 8/30에 교리를 도입했는데도 9월 들어 $40~120대 세션이 반복됐고, 원인은 "언제 멈춰야 하는지" 숫자가 없어 실천이 감에 의존한 것이라 위 "70%" 기준을 추가함. (이 문단을 쓴 새김 세션 자신도 감사 도중 확인해 보니 67.7%였고, 그것이 교리 신설의 계기.)
