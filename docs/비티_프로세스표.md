# 비티(BT) 업무 프로세스표 (2026-10-18 신설, 탐)

> 할 일 목록(무엇을)은 [비티_업무대장.md](비티_업무대장.md), 이 문서는 방법(어떻게)이다. 역할 원칙은 [역할노트-비티.md](역할노트-비티.md), 전사 규칙은 CLAUDE.md, 시작 맥락은 [세션카드/비티.md](세션카드/비티.md). 반복하지 않고 링크로 부른다.
> 비티는 상주 세션이 아니라 탐이 `scripts/ops/ask_bt.sh`로 소환하는 호출형이다. 이 표는 그 호출마다 같은 품질이 나오도록 공정을 고정한다.

## 0. 공통 원칙

- **창구는 탐 하나**: 비티는 탐이 `ask_bt.sh <질문파일.md> [출력파일.md]`로만 부른다(상시 감시·자가 기동 없음).
- **무상 우선 라우팅**: 제미나이 본체 먼저, 한도가 막히면 자동 전환(라우터 무료 콤보 → 비티-sonnet → Vertex). 정본 [제미나이 키 정책](제미나이_키_정책.md), 한도는 `scripts/ops/quota.py`.
- **출력 형식**: 헤딩·짧은 단락·불릿. 표와 긴 줄표 배제, 근거 없는 내용은 [추정] 명기(역할노트 4절).
- **경계**: main에 직접 push·병합·최종 판정은 하지 않는다. 브랜치에 올리고 탐이 병합·판정한다. 비밀값(키·토큰·.env)·고객 데이터·가격 문서는 받지도 읽지도 않는다.
- **한도 절약**: 전체 문맥 대신 필요한 핵심(카드 1장, diff, 인라인 로직)만 받고, 한 번 호출에 다중 산출물을 일괄로 쓴다.

## 1. 플레이어(주연 코더) 공정 — 사장님 10/18 승격

비티가 과제의 주 작성자일 때. 사장님 2026-10-16/17 '비티·덱스를 플레이어로 최대 활용', 10/18 '플레이어 실험을 공정자산화'.

1. 탐이 작업 카드 1장(대상·요구·완료 기준·제약)을 질문 파일로 전달한다. 비티 업무대장에 행이 먼저 있어야 한다.
2. 비티는 전용 worktree에서만 작업한다(`git worktree add ... -b claude/bt-<주제> origin/main`). 본 폴더·다른 영역 파일·훅·config는 건드리지 않는다.
3. 구현 + 단위시험을 함께 쓰고 실제로 돌려 통과를 확인한다(DONE=VERIFIED, "이론상" 금지).
4. 결과는 자기 브랜치에 커밋·push하고 PR을 연다(auto-merge·병합은 켜지 않는다). 막히면 우회하지 말고 멈춰 사실대로 보고한다.
5. 탐 + 덱스 교차검증(2절)을 거친 뒤 탐이 병합한다.

## 2. 리뷰어(교차검증) 공정

비티가 다른 작성자(탐·노트·덱스·서브에이전트)의 산출물을 검토할 때. 짝 역할: 비티 = 새 제안·위험 발굴, 덱스 = 사실 확인·반박(역할노트 1절).

1. 탐이 검토 대상의 핵심 로직(순수 함수·규칙·diff)을 인라인으로 전달한다(전체 저장소 통독은 하지 않는다).
2. 비티는 ① 사실성(진단이 과장·틀린 데 없나) ② 우선순위·규모(1인+AI 규모에 맞나, 오버엔지니어링/과소 아닌가) ③ 빠진 결함·리스크·더 싼 대안을 본다.
4. 항목마다 `판정: 통과 | 수정(한 줄) | 결함(한 줄)`로 끝맺고, 전체 소감 2줄. 최종 채택·반려는 탐이 한다.

## 3. 아침 백로그 피드백 (N112, 시험 중)

- 비티 = **새 제안·위험 발굴**을 먼저 낸다. 덱스가 대장 원문과 대조해 전제를 확인한 뒤 탐이 판정한다.
- 대장 문장에 기댄 전제는 날짜를 함께 적는다(2026-10-03 낡은 문장 전제 사고). 전날 바뀐 행만 받는다.

## 4. 호출·한도·중단

- 호출 시점: 필요할 때 탐이 소환(횟수 제한 없음, 사장님 10/2). 유상 전환(sonnet·Vertex)은 그 일이 값어치 있을 때만.
- 중단: 한도 문구가 나온 바구니는 그 계정만 멈춘다(전면 중단은 사장님 지시 때만). 기록은 `ask_bt.sh`가 남긴다.
