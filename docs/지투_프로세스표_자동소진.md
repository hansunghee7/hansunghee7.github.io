## 1. 예약 세션 `jitu-backlog-run`
- 하루 3번(09·14·20시) 새 세션이 열려 업무대장의 `대기`·결정자 `지투` 행을 위에서부터 진행한다. 프롬프트는 `C:\Users\PC\.claude\scheduled-tasks\jitu-backlog-run\SKILL.md`. 첫 문장이 "지투 예약 세션입니다"라서 종료 관문이 지투로 인식한다.
- **첫 실행은 도구 승인을 사람이 해야 한다**(10/5: 20:14 시작 뒤 Bash 두 번 호출하고 30분 넘게 활동 없음). 만든 직후 `run_scheduled_task`로 한 번 돌려 승인 창이 뜨는지 보고, 사장님께는 세션 링크 `[제목](#세션id)`를 드린다. 이 방식으로 만든 작업은 앱의 "루틴" 목록에 보이지 않았다.
- 예약 세션이 못 하는 것: 사장님 결정(제품·방향·돈), 계정 생성, 외부 발신. 그런 건 대장 상태를 `사장님`으로 바꾸고 이유 한 줄을 적는다.
- 효과 측정: 1주 뒤 대기 행 소진율과 주간 한도 사용량을 보고 탐·핏 확대 여부를 판단한다(대장 N58).

- 위치 `.claude/hooks/queue-gate.py`, 설정 `.claude/settings.json` Stop 목록. 지투 세션이 "정하실 것: 없음" 또는 `[실행 대기`로 끝내려는데 지투 업무대장 열린 항목에 상태 `대기`·결정자 `지투`인 행이 있으면 exit 2로 막고 그 행을 보여 준다.

## 3. 완료 확인 장치 (모니터)
- 구PC SSH·nohup 작업은 끝나도 알림이 오지 않는다. 시작 직후 `Monitor`로 진행 파일을 읽는 확인을 건다: 목표 개수·정지 문구·프로세스 종료 때 끝낸다.
- 모니터가 30분 뒤 만료되면 다시 건다. 만료 알림을 못 받으면 상태를 직접 확인한다.
- **개수는 파일 크기 기준**으로 센다(0바이트 PNG 사고). 지표 이름이 `STOP`·`ERR`일 때 성공 개수에 섞이지 않게 한다.
- 알림이 오면 이어서 할 일(자르기, 번호표 전송 등)을 바로 한다.

## 4. 대장 `대기` 행 쓰는 법
- 지투 혼자 할 수 있는 다음 일은 대장에 상태 `대기`, 결정자 `지투`로 적어 두면 예약 세션과 종료 관문이 그 행을 본다.
- 사장님이나 다른 담당을 기다리는 일은 `확인필요`·`사장님`으로 둔다(관문이 막지 않는다).
