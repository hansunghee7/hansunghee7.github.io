# 카빗DM 3차 슈퍼프로젝트: 새 에이전트 합류를 사람 입력 2회로 (정본, 사장님 지시 2026-10-23)

**한 줄 결론:** 2차가 "6명이 서로 1분 안에 주고받기"를 끝냈다면, 3차는 **새 에이전트가 합류해서 DM을 받기 시작할 때까지의 사람 개입과 막힘을 없애는 것**이다. 근거는 2차 회고 3건(카빗DM 391·392·393)과 마야·핏·지투 설치 실측이다.

일하는 방식: 슈퍼프로젝트([오케스트레이터_일하는_방식.md](오케스트레이터_일하는_방식.md)). 설계는 덱스·비티 리뷰를 거치고(공정 카드 공용-오케스트레이션 #15), 구현은 단계마다 병합 전 리뷰와 병합 후 실측을 한다. 공정 카드는 노트 #210이다.

## 이름과 범위

- **이름:** 카빗DM 3차(합류 매끄럽게).
- **대상:** 새 에이전트 한 명이 (대시보드 추가 → 설치 → 새 세션 → 수신 켬)까지 가는 길. 대상 에이전트는 이미 합류한 마야·핏·지투의 기록을 기준선으로 쓰고, 시험은 아직 없는 새 신원(예: 타미, P2A 1호 후보)으로 한다.
- **하지 않을 것:**
  - 모니터를 고객 기본 수신 방식으로 확정하지 않는다(사장님 2026-10-20: 모니터는 후보에서 제외, 세션 시작 때 기본으로 도는 방식만 후보). 30분 만료 해결은 4차 후보로 둔다.
  - 폰 승인형 에이전트 추가(P2A, 계정 생성 자동화)는 2차 별건이라 다시 설계하지 않는다.
  - 고객용 설치 문장의 방식을 사장님 결정 없이 바꾸지 않는다(결정 1).
  - 운영 데이터와 고객 데이터를 바꾸지 않는다.

## 기준선 (2026-10-22 밤 실측)

- 마야: 계정 합류 23:40 → 모니터 켬 DM 23:58, 약 18분. 막힘 2회(자동 모드가 서버 등록을 거절, 등록 전에 열린 옛 세션).
- 핏: 합류 23:41 → 모니터 켬 DM 00:08, 약 27분. 막힘 2회(앱 세션 제외 문구로 멈춤, 서버 이름 `carvit_kabit-pit`).
- 지투: 서버 이름 변경 요청 23:24 → 새 세션 확인 DM 00:12, 약 48분(사람 대기 포함). 막힘 3가지(연결 중 지연, 수신기 설정에 서버 이름이 없음, 오래된 공용 main).
- 사람 입력: 계정 추가 1 + 설치 문장 붙여넣기 1(막히면 대리 붙여넣기 +1) + 새 세션 열기 1 + 모니터 메시지 붙여넣기 1 = 4~5회.
- 서버 이름 규칙(`carvit_<영문>`) 준수: 5명 중 마야·핏이 어긋나게 생성됨(노트가 로컬 이름만 규칙대로 붙임).

## 목표 (측정 가능, 수치는 제안값이고 P1 끝에 사장님이 확정)

측정 정의: 새 에이전트 1명을 처음부터 끝까지 시험한다. 시작 = 대시보드 추가 완료 시각, 끝 = 그 에이전트의 "모니터 켬" DM 도착 시각.

1. **사람 입력 2회:** 계정 추가 1회 + 새 세션에 프롬프트 한 번 붙여넣기 1회. (기준선 4~5회)
2. **소요 10분 이내.** (기준선 18~27분)
3. **막힘 0회:** 에이전트가 멈추고 사람에게 되묻는 횟수. (기준선 2~3회)
4. **서버 이름 규칙 준수 100%:** `carvit_<영문>`. (기준선 3/5)
5. 2차 수신 지연 1분 이내를 유지한다(회귀 방지). 측정은 2차와 같다: 지연 = 받는 쪽 `read_at` − 보낸 시각(`dm_sent`), 새 에이전트에게 노트가 시험 DM 3통을 보낸다. 기준선은 2차 실측(노트→에이전트 읽힘 10~23초, 에이전트→노트 신호 7~8초).

**막힘 0회의 정의(덱스·비티 리뷰 반영):** 에이전트가 하던 일을 멈추고 사람에게 되묻거나 우회 요청을 하는 횟수만 센다. 네트워크 일시 오류의 자동 재시도, 서버 "연결 중" 대기는 막힘으로 세지 않고 별도로 기록한다. 시험이 실패하면 원인을 기록하고 같은 신원으로 다시 시험한다(아래 P6 재시험 기준).

**일반화(리뷰 반영):** 새 신원 1명 시험은 합격선이 아니라 대표 시험이다. 마야·핏·지투로 이미 확인한 막힘은 항목별 완료 기준(아래 표)으로 각각 닫고, P6에서는 앱 세션 1명과 터미널 세션 1명(가능할 때)을 시험한다.

## 회고에서 모은 개선 항목 (근거 DM 391·392·393)

1. 앱 세션 자동 받기 문장: 앱이면 stdout+Monitor 설정 본문과 실행 명령을 바로 준다. 설정 위치는 인자로 받는다(기본 `C:/work/_ops/carvit_<영문이름>`). 앱에서 중복되는 사용자 확인을 뺀다. 30분 재가동 안내를 넣는다. (세 에이전트 모두 1순위. 결정 1 필요)
2. 영문 이름 필수: 에이전트 추가 화면에서 영문 이름을 필수로 받는다. 서버 이름은 영문 이름 기준으로만 만든다(노트 #199).
3. 내부 안내 문서: 앱 세션에서 모니터를 켜는 법을 2차 정본·세션 카드에 올린다(문장 변경이 늦어도 같은 곳에서 안 멈추게).
4. 세션 카드에서 도구 접두사 빼기: "`agents`의 me로 확인"만 남긴다(지투).
5. 수신기 한 줄 스크립트: Monitor 인자를 고정한 스크립트(지투).
6. 저장 관문 훅: 출력 인코딩을 UTF-8로, 1회성 확인은 통과(탐에게 요청, DM 394).
7. 에이전트용 프롬프트 표준: 탈출 조건 맨 앞, 이름 먼저, 단계 5개 이내(노트 #201).
8. 풀 수 없는 것(안내로 줄이기): 서버 등록 뒤 새 세션 필요, 도구가 "연결 중"으로 늦게 보임, 30분 만료.
