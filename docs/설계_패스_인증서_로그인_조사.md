# 패스 과제 7: 공동·금융인증서 로그인을 금고가 대신 (조사와 설계안, 2026-10-14 노트)

> 상태: 조사 1차 + 설계안. 실사이트 인증서 비밀번호 입력 시험은 에이전트 금지 범위라 하지 않았다. 아래 "조사 사실"은 제미나이 한 번의 답이고 검색 출처가 0건이라 **미검증**이다(근거 URL은 기관 대표 주소 수준). 설계 결정 전에 기관 문서로 대조해야 한다.

## 결론

- 인증서 로그인을 금고가 "비밀번호 대신 입력"하는 길은 기술(가상 키패드·네이티브 서명 창)과 약관(법인 인증서 대리 행사 금지) 양쪽에서 막힐 가능성이 크다.
- 그래서 1순위 설계는 **금고가 비밀번호를 대신 입력하는 것이 아니라, 사람이 승인한 순간에만 보여 주거나 안전하게 보관하는 것**이다. 입력 자동화(2순위)는 사장님의 방향 결정이 필요하다.

## 조사 사실 (미검증, 제미나이 1회)

- 공동인증서는 PC의 NPKI 폴더에 인증서(signCert.der)와 비밀번호로 암호화된 개인키(signPri.key)로 있다. 로그인은 서버가 준 난수에 개인키로 전자서명한 값을 내는 구조다.
- 홈택스 등은 보안 모듈(키보드 보안, 가상 키패드, 별도 프로그램 창)로 입력을 받아 브라우저 확장의 입력 주입을 막는다.
- 금융인증서는 클라우드 저장이고 휴대폰 2차 인증과 PIN이 들어가 무인 자동화가 어렵고, 약관이 양도·대여를 금지한다.
- RPA류 대행은 화면 좌표·이미지 인식으로 키패드를 누르는 방식이고, 보안 모듈이 악성 행위로 보고 차단하거나 계정이 막힐 위험이 있다.
- 법인 인증서는 명의자 책임이라 제3자 소프트웨어의 대리 행사를 약관이 금지한다.

## 설계안 (규모 기준: 1인 회사 + 법인 인증서 1~2장)

- **A. 보관+승인 개봉(추천, 1단계)**: 인증서 비밀번호를 패스 보안 키 등급에 저장하고, 사장님이 텔레그램으로 승인한 순간 금고가 값을 화면에 짧게 보여 준다(사람이 직접 입력). 입력 자동화가 없어 약관·보안 모듈과 충돌하지 않는다. 효과는 "비밀번호를 기억·메모하지 않아도 된다"에 한정된다.
- **B. 사람 옆에서 입력 보조(2단계)**: 사람이 홈택스 로그인 화면에 있을 때만, 승인 후 로컬 도우미가 키패드 창에 입력. 보안 모듈 차단 위험과 약관 문제가 있어 **시험 전에 사장님 방향 결정 필요**(법인 약관 해석 포함, 세무사·기관 문의).
- **C. 로컬 서명 대행(비추천)**: 도우미가 개인키를 복호화해 직접 서명. 사이트별 프로토콜 역공학이 필요하고 약관 위반 소지가 가장 크다. 하지 않는다.
- 인증서 파일(signPri.key) 자체는 금고에 담지 않는다(사장님 서류 정리 방침과 일치, 파일은 PC에 두고 비밀번호만 다룬다).

## 지금 하지 말아야 할 것

- 실제 홈택스·은행에서 입력 자동화 시험(계정 제한·약관 위험, 에이전트 금지 범위).
- C안 개발.

## 다음 단계와 신호

- 조사 사실을 기관 문서(KISA 규격, 홈택스 이용약관, 인증서 발급기관 약관)로 대조: 실행 갈래(제미나이 검색 연동)로 가능.
- 사장님 결정 1건: 1단계를 A안(보관+승인 개봉)까지만 할지, B안까지 갈지. 근거: 입력 자동화는 약관 해석이 필요하다.
- 모의 시험은 B안으로 갈 때만 의미가 있다(가짜 로그인 페이지+가상 키패드로 도우미 입력 동작만 검증).
