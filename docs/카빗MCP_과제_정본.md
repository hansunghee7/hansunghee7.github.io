사장님 정리(2026-10-20)로 카빗 MCP 과제를 세 영역으로 나눠 진행한다. 이 문서는 세션이 바뀌어도 같은 질문을 되풀이하지 않게 하는 정본이다. 정본의 범위는 아래 "온보딩 2단계안"과 사장님 결정뿐이다. 거기 없는 항목은 이 문서에 넣지 않는다(10/20 밤 노트의 과거 백로그가 섞여 들어와 정리한 사고, "삭제한 항목" 참조). 상태 갱신은 공정 카드와 이 문서를 같은 세션에 같이 고친다.

- 공정 카드(수파베이스): `python scripts/ops/proc.py steps 노트-카빗MCP과제`
- 근거 카드: 노트 #99~#105(설치 배포 3종 실측·순서 확정), #142~#149(10/20 신원·수신 실측), 지투-카빗DM#1(수신 방식)
- 실측 원자료(노트 로컬): `C:/work/_ops/note/install_lab/`, `sr_mcp_*.md`
- 목표(탐-슈퍼글로벌#39): 가입 직후 받은 프롬프트를 클로드 코드에 입력하면 곧바로 통신하는 에이전트가 생긴다.
- 목표 사용자: 클로드 코드로 서비스를 만드는 스타트업 창업자와 팀(사장님 10/20). 채팅 AI만 쓰는 대표는 카빗 클래스 별도 트랙(마야#155).

이미 정한 결정은 되묻지 않고 이 문서와 카드를 먼저 읽는다. 값(코드·인증 값·신원 접두어)은 이 공개 문서에 적지 않는다. 옛 이름은 새 글·말·이름에 쓰지 않는다(이름 정책).

## 세 영역

- **1 가입**: 사용자가 carvit.ai에 로그인해 에이전트 신원(이름)을 등록하고 설치 문장을 받는다.
- **2 설치**: 사용자가 직접 카빗 MCP(와 플러그인)를 설치한다. 에이전트가 설치하는 방식이 아니다(사장님 10/20: MCP와 플러그인은 사람이 설치).
- **3 통신**: 설치한 에이전트가 Carvit Help와 소통하고, 그 소통 결과가 우리에게 전달되면 된다. 지투라는 신원은 필요 없다(사장님 10/20, 이름은 "Carvit Help" 채널).

## 온보딩 2단계안 (사장님 10/20)

- 1단계 카빗 MCP 사용자 설치: 사용자가 직접 설치(MCP와 플러그인을 하나의 묶음으로).
- 2단계 에이전트 호출 프롬프팅: 페르소나 호출 → 필수문서 세팅 → Carvit Help와 소통.
- 필수문서 5종(스탠다드, 대표용비서시연#14): 지침, 역할노트, 인수인계, 업무표, 결정. 새 세션이 역할과 직전 작업을 스스로 식별하는 수단이기도 하다.

## 정해진 결정

- 설치는 사람이 직접 한다. 에이전트 설치 문장의 자동 모드 통과는 이미 실측했다(아래).
- 배포 순서(사장님 2026-10-20, 노트#104): uvx 한 줄(PyPI 정본 패키지 하나) → 플러그인(얇은 껍데기) → zip 폴백. 섞어서 같이 설치하지 않는다. PyPI 게시는 진행 과제(노트#103, 인증 값 주입 막힘 노트#105).
- 상시 수신 방식에서 **Monitor 도구, 훅(asyncRewake), 플러그인 monitors는 모두 제외**(사장님 10/20 결정: Monitor는 에이전트 재량이라 잊고 30분 만료가 있어 후보에서 뺀다). 훅 제외의 근거는 기본 타임아웃이다. [실측: C:/work/_ops/note/install_lab/H_hook/cells — 기본값은 10분 넘게 쉰 세션에서 훅이 죽어 DM을 놓치고, 3600초 지정 시 11분 뒤에도 7초 만에 깨움] 다시 볼 신호: 훅이 타임아웃 없이 상시 유지되는 공식 방식이 나오면 재검토. 터미널은 채널(실측 완료).
- 에이전트 간 연락은 카빗DM만 쓴다. 세션메시지는 장애 때 사장님 승인으로만(PR 2490).
- 평가 기준(노트#101): 자동 모드 통과, 사람이 불안하지 않은지, 설치 단계 수.
- 실험 순서 기본(노트#132): 내부 서브에이전트 1차 → 내부 에이전트 2차 → 실측되면 외부 3차.
- 이어가기: 새 세션은 대화 기억이 없다. 사장님께 "새 세션에서 이어서 해줘만 입력하세요"라고 안내하지 않고, 역할·직전 작업·다음 단계는 공정 카드와 필수문서에 남긴다.

## 알아 둘 사실

- 알림기(도우미)의 신원은 에이전트별이다. 한 설치 폴더에 여러 신원이 섞이면 다른 에이전트의 DM만 받는다.
- 알림기의 알림은 그것을 건 세션 화면으로만 간다. 세션이 바뀌면 다시 걸어야 한다(이것이 상시 수신 방식이 필요한 이유).
- 읽기 도구 호출 거절은 이전에 한 번 재현됐으나(헤드리스 2/2) 같은 조건에서 다시 나오지 않았다. 간헐적일 수 있어 막혔을 때 안내는 필수다.
- 공식 근거를 확인하지 못한 것: 분류기가 도구 이름·설명에 영향받는지, 데스크톱 앱의 채널 지원, MCP `instructions` 길이 제한.
- 제미나이 조사에는 거짓 인용이 있었다(arXiv 2604.03211, 자동 모드 거절률 출처로 인용했으나 천체 논문). 링크가 열리는 것만으로 믿지 말고 본문을 읽는다.
