# 카빗 MCP 과제 정본 (가입·설치·통신)

사장님 정리(2026-10-20)로 카빗 MCP 과제를 세 영역으로 나눠 진행한다. 이 문서는 세션이 바뀌어도 같은 질문을 되풀이하지 않게 하는 정본이다. 상태 갱신은 아래 공정 카드와 이 문서를 같은 세션에 같이 고친다.

- 공정 카드(수파베이스): `python scripts/ops/proc.py steps 노트-카빗MCP과제`
- 근거 카드: 노트 #99~#105(설치 배포 3종 실측·순서 확정), #142~#149(10/20 신원·수신 실측), 지투-카빗DM#1(수신 방식 분기)
- 실측 원자료(노트 로컬): `C:/work/_ops/note/install_lab/비교.md`
- 목표(탐-슈퍼글로벌#39): 가입 직후 받은 프롬프트를 클로드 코드에 입력하면 곧바로 통신하는 에이전트가 생긴다.

이미 정한 결정은 되묻지 않고 이 문서와 카드를 먼저 읽는다. 값(코드·토큰·신원 접두어)은 이 공개 문서에 적지 않는다.

## 세 영역

- **1 가입**: 사용자가 carvit.ai에 로그인해 에이전트 신원(이름)을 등록하고 설치 문장을 받는다.
- **2 설치**: 사용자가 설치 문장을 클로드 코드에 입력하면 이름을 받은 에이전트가 생기고 MCP가 설치된다. 안전 검사에 막혀 에이전트가 사용자의 설치를 안내하는 형태로 바꾸는 방안을 검토 중이다(결정 전).
- **3 통신**: 설치한 에이전트가 Carvit 지투와 DM을 주고받는다. 송신은 실측 완료, 수신은 환경별로 나뉜다.

## 정해진 결정

- 도우미 설치 배포 순서(사장님 2026-10-20, 노트#104): uvx 한 줄(PyPI 정본 패키지 하나) → 플러그인(얇은 껍데기) → zip 폴백. 섞어서 같이 설치하지 않는다.
- 수신 방식 기본(사장님 2026-10-20, 지투-카빗DM#1): 터미널은 채널 1순위, 데스크톱 앱은 채널 서버를 붙일 수 없어 훅(asyncRewake) 또는 Monitor.
- 에이전트 간 연락은 카빗DM만 쓴다. 세션메시지는 장애 때 사장님 승인으로만(PR 2490).
- 평가 기준(노트#101): 자동 모드 통과 여부, 사람이 불안하지 않은지, 설치 단계 수. 셋 다 잰다.
- 실험 순서 기본(노트#132): 내부 서브에이전트 1차 → 내부 에이전트 2차 → 실측되면 외부 에이전트 3차.
- 이어가기: 새 세션은 대화 기억이 없다. 사장님께 "새 세션에서 이어서 해줘만 입력하세요"라고 안내하지 않는다. 역할·직전 작업·다음 단계는 공정 카드에 남기고 시작 훅이 식별한다.

## 실측 완료 (2026-10-20 기준)

가입
- 에이전트 신원 등록: 사장님이 대시보드에서 등록하고, 재시작한 세션의 `agents`에서 `me`가 해당 에이전트로 나온다.
- 설치 문장 발급: 대시보드 Copy message와 `autoreceive_setup`이 문장과 해시를 발급한다.

설치
- MCP 연결: `claude mcp add` 성공. 처음엔 자동 모드가 거부했고 같은 문장을 다시 붙이자 통과했다. 원인은 맥락 추정이다(노트#144·#145).
- 재시작 뒤 신원 확인, zip 내려받기·해시 대조·압축 해제: 확인됨.
- uvx 한 줄: 거절 0·0, 승인 0, 오류 0, 사람 1단계·에이전트 1단계. 한계: 헤드리스·로컬호스트·2회, 깨우기는 시험하지 않음.
- 플러그인: 거절 0, 오류 1(턴 한도), 훅이 세션 시작·종료 때 실제 실행됨. 에이전트 약 6단계, 불안 요소 2개(전역 설치, 상시 대기 훅). 같은 한계.

통신
- DM 송신: 확인됨.
- 앱에서 감시가 없을 때: 상대 답이 도착해도 세션이 알아채지 못했다(1회).
- 앱에서 도우미(Monitor)를 켠 뒤: 상대 DM이 약 7초 만에 신호로 도착했다. 한계는 감시가 최대 30분 뒤 만료되어 다시 걸어야 한다는 점이다.
- 서버 푸시로 쉬는 세션 깨우기: 헤드리스에서 4번 중 4번 실패.
- 앱 실제 세션에서 신호를 따라 `dm_read`를 불렀을 때: 거절 없이 읽힘(1회). 헤드리스에서는 2번 중 2번 거절이었다(노트#102).

## 실측 안 됨 (실험 우선순위순)

설치 없이 또는 가볍게 되는 것부터, 설치형은 뒤로 둔다(사장님 2026-10-20).

1. `dm_read` 분류기 거절 원인 분리(도구 이름 대 DM 성격). 설치 없음. 1차 서브에이전트 후 앱에서 반복.
2. 설치 문장의 자동 모드 통과 원인 분리. 가벼운 설치. 격리 폴더에서 맥락만 바꿔 시도.
3. 에이전트가 사용자의 설치를 안내하는 형태. 설계 먼저.
4. 설치 직후 자가 확인 단계(신원, 수신 방식, 다음 할 일). 설계 먼저.
5. 앱 상시 수신: 훅(SessionStart·Stop로 자동 재무장). 설정 편집 허용이 필요하므로 격리 폴더에서.
6. 앱 상시 수신: 플러그인에 훅 포함. 격리 환경에서.
7. 터미널 채널 수신 직접 재측정. 로컬 MCP 등록과 개발 채널 옵션이 있는 대화형 세션이 필요.
8. uvx·플러그인을 실제 앱·실제 주소에서 재측정(앞 시험의 헤드리스 한계 보완).
9. 내부 에이전트 옛 코드 재발급(PR 747 개명 이후). 각자 폴더·기기에서.
10. 북(노트북) 쪽 상시 수신. 노트북에 도우미 설치.
11. PyPI 게시. 토큰 주입이 막혀 있다(노트#105, envput 목적지 미등록).

## 알아 둘 사실

- 도우미 신원은 에이전트별이다. 한 설치 폴더에 여러 신원이 섞이면 다른 에이전트의 DM만 받는다. 2026-10-20 같은 저장소 폴더에서 다른 신원의 도우미가 돌고 있어 노트 DM에 신호가 없었다.
- 이 PC의 설치된 도우미는 두 곳(저장소 폴더, 노트 전용 폴더)이다. 노트의 `tools/autoreceive` 폴더들은 소스 사본이라 설치가 아니다.
- 옛 이름(`carvit_wake.py`)은 노트 전용 폴더에 10/18자 파일만 남아 있고 실행 중이 아니다.
- 도우미 알림은 그것을 건 세션 화면으로만 간다. 세션이 바뀌면 다시 걸어야 한다.
