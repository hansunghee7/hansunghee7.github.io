> 핏의 [`GENERATION_PIPELINES.md`](https://github.com/hansunghee7/shorts-lab/blob/main/GENERATION_PIPELINES.md)(shorts-lab) 형식을 벤치마킹했다: 순서/단계/상세 표 + 실측(비용·시간)·장단점 산문 + 사고는 KPT로. 절차의 정본은 `.claude/skills/ink-desk`, `ink-homepage`이며, 이 문서는 그 절차를 한 화면에서 보는 표다. 표 내용이 스킬 파일과 어긋나면 스킬 파일이 맞다.
>
> 2026-09-24 사장님 지시로 작성. 표의 7·8·13번(제미나이 API 초안 재료·검증)은 **설계만 됐고 아직 실전 글에서 돌려보지 않았다** — DONE=VERIFIED 원칙에 따라 다음 실제 글 작업에서 실측할 때까지 "적용 중"이라고 부르지 않는다.

## 파이프라인: 홈페이지 글 → SNS 파생 (화·목·토, 컨펌 3회)

| 순서 | 단계 | 담당 | 상세 |
|---|---|---|---|
| 1 | 발행 현황판 확인 | 마야 | `publish_plan.json` + 카드에서 2주 슬롯 확인, 오늘 잡을 글 하나 선정(발행일 가까운 순) |
| 2 | 주제 후보 (컨펌①) | 마야 → 사장님 | 후보 2~3개, 검색·유입 근거·뜨는 근거, 대상 하나씩 지정. `posts.json`/`publish_plan.json`으로 중복 확인 |
| 3 | 딥리서치 발주 | 헤르메스(1차) → 제미나이(보완) | 헤르메스 딥리서치 우선, 막히면 제미나이 딥리서치(서브에이전트 조작). 다이얼로그 수집(`ask_dialog.py`) 병행 |
| 4 | 리서치 검증 1차 | 제미나이 API | 열람 성공/실패 표기, 출처 원문 대조, 팩트등급 판정 |
| 5 | 원문 표본 재대조 | 마야 | 제미나이 검증 결과 중 핵심 수치·인용만 마야가 직접 재확인(DONE=VERIFIED, 자동화 결과를 그대로 믿지 않음) |
| 6 | 시놉시스 | 마야 | 7줄 흐름(훅·문제·원인·전환·처방·행동), 각 줄을 출처/다이얼로그와 연결 |
| **7** | **[신규] 초안 재료 생성** | **제미나이 API** | **`simplifier-agent/scripts/brief.py`(2026-09-03 마야 검토, 제작 완료·통합은 안 됨) 재사용 검토. 시놉시스+리서치+다이얼로그 검색 결과를 넣어 "주장 목록 → 상세 브리프"를 만들게 해서 마야가 처음부터 재료를 정리하는 시간을 줄인다. 자료 없는 곳은 `[사장님 경험 채울 곳]`으로 비워 지어내지 않게 한 설계를 그대로 따른다** |
| **8** | **[신규] 1차 초안 생성** | **제미나이 API (시험)** | **브리프를 받아 2,500자 이내 1차 초안을 제미나이가 쓰게 시험. 현재는 마야(Claude)가 처음부터 씀 → 토큰 절약 원칙(2026-09-20, 헤르메스/제미나이로 초안 우선 발주)의 실제 이행. 다만 2026-09-03 brief.py 설계 메모가 "잉크 파이프라인은 Claude로 초안을 쓴다"고 명시한 이유(작은 모델은 자료가 없으면 지어냄)가 있어, 1차 초안은 반드시 사람이 다듬는 8-1 단계를 거친다** |
| 8-1 | 본문 다듬기 (사람 검수 필수) | 마야 | 제미나이 1차 초안을 브랜딩 가이드 화법으로 다듬기, 지어낸 문장·취재기사체·전문적 숫자 제거, 분량 확인. 초안이 부실하면 마야가 처음부터 다시 씀(제미나이 초안은 참고일 뿐 그대로 쓰지 않음) |
| 9 | 제목 후보 | 마야 | 1안 + 대안 1개, 고른 이유 |
| 10 | 기계 검수 | 스크립트 | `check_ink_card.py`(준비 중): 글자수, `###`, 긴 줄표, 금지 문구 |
| **11** | **[신규] 채점 1차 스크리닝** | **제미나이 API (시험)** | **소넷 서브에이전트 채점(1건당 약 8만 토큰) 전에 제미나이로 먼저 거르기. 기준점 근처(±3점)만 소넷 서브에이전트로 재채점해 서브에이전트 호출 횟수를 줄인다** |
| 12 | 최종 채점·판정 | 마야 (+ 필요시 소넷 서브에이전트) | 제미나이 채점 결과 판정, 감점 반영. 애매하면 맥락 모르는 새 서브에이전트로 재채점 |
| 13 | 본문 컨펌 (컨펌②) | 마야 → 사장님 | 전문 + 점수 + 감점항목 + 출처목록 + 다이얼로그 수집 여부, 한 화면 |
| 14 | 이미지 후보 | 마야 | 대표 키워드 1개로 Unsplash 1회 검색(per_page 10 안팎), 조건표 채점 |
| 15 | 이미지 컨펌 (컨펌③) | 마야 → 사장님 | 후보 2~3개 + 추천 1개 |
| 16 | 예약 등록 (PR) | 마야 | 마야 worktree에서 PR, auto-merge. `date`/`scheduled: true`/`published: false` |
| 17 | 발행 확인 | 마야 | 라이브 200, 목록 카드, `posts.json`, `sitemap.xml`, 대표 이미지 직접 확인(DONE=VERIFIED) |
| 18 | SNS 파생 캡션 준비 | 마야 | 채널별 캡션 + 해시태그 + UTM 링크까지 완성해서 넘김. 게시 자체는 현재 사장님(과제2 자동화 검토 대상, 별도 문서) |

## 비용·리스크 메모 (2026-09-24 시점, 실측 아님 — 설계 근거)

- **키 배정 확인 필요**: 마야의 제미나이 키(`dialog`)는 대장(`simplifier-cxo-db/registry/gemini-keys.json`)에 "다이얼로그 Worker + `simplifier-agent` 글 만들기 계열 전용"으로 이미 지정돼 있다(2026-09-22 사장님 결정). 7·8·11번(브리프·초안·채점)이 이 키의 용도에 맞는지, 아니면 탐 소유 `hermes-verify`(role=fast) 키를 매번 빌려야 하는지는 **탐에게 확인 후 진행**한다(대여 규정: 우편함 "제미나이 키 대여 요청", 마야 키는 낮에는 대여 불가).
- **한도**: `gemini-3.6-flash`(초안 품질에 필요할 가능성) 무료 등급은 프로젝트당 하루 20회뿐(2026-09-23 실측). 글 한 편에 브리프 1회 + 초안 1회 + 검증 1회 + 채점 1~2회를 쓰면 하루 한도의 상당 부분을 쓴다. 단순 채점·분류는 `gemini-3.5-flash-lite`(하루 500회)로 내리는 것을 우선 검토.
- **품질 리스크**: 2026-09-03 `brief.py` 설계 메모가 이미 "작은 모델은 자료가 부족하면 지어낸다"고 경고했다. 8-1(사람 검수)을 생략하지 않는다.
