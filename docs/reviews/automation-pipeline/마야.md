# 숏폼 자동화 파이프라인 v2 — 마야(CMO 튜터) 크리틱

> 읽은 것: `shorts-lab/AUTOMATION_PIPELINE.md`(=`insight-7b3e9f2c/shorts-automation.html`) +
> 진행상황.md 공지의 내 항목 + 탐·노트·시안 리뷰(겹치는 지적은 반복하지 않음).
> 관점: 성과 지표 설계, 성과→주제 반영 루프, `content-insight.html`과의 데이터 중복.
> 전제: 1인+AI, S1. 이 저장소는 공개라 사업 정보(수익화·협찬·채널 운영 방침의 세부 근거)는
> 여기 적지 않고 판단이 필요한 지점만 사장님께 표시함.

## 1. 동의하는 것

- **사람은 돈 직전·밖 직전** — 마케팅 관점에서도 맞다. 취향(주제)과 공개 책임(업로드)은
  브랜드 목소리가 걸린 자리라 자동화 대상이 아니다.
- **한 계단씩** — 성과 지표처럼 나중에 바뀔 수 있는 부분을 여러 계단과 동시에 묶으면
  뭐가 잘못됐는지 못 가른다.
- **시트가 정본, 상태 열 한 칸** — 동의. 성과 데이터도 이 원칙을 그대로 따라야 한다(3절).
- **절대 조회수만으로 10편 이전 판단하지 않는 원칙**(공지에 이미 반영돼 있음) — 동의를
  넘어, 지금 설계(0·17번)가 이 원칙과 실제로 맞물리는지가 내 우려의 핵심(2-1).

## 2. 반대하거나 우려되는 것

### 2-1. 0·17번이 기록하려는 지표가 "판단하기 좋은 지표"가 아니다

지금 표는 "조회수·팔로우"를 성과로 기록한다. 그런데 편수가 한 자릿수인 지금 단계에서는
조회수 하나가 다른 것보다 100배 차이 나는 일이 흔하다(실제로 이번 세션에 확인한 두 편의
차이가 그 정도였다). 이 상태에서 조회수만 보고 "이 소재 유형이 잘 됐다"고 판단하면,
소재의 힘이 아니라 그날의 알고리즘 운을 학습하게 된다.

마케팅에서 이럴 때 더 믿을 수 있는 신호는 **완주율/평균 시청 지속시간** 같은 상대 지표다.
그런데 이번 세션에 사장님과 확인한 바로, 지금 수집 구조(유튜브는 Data API v3, 나머지는
크롬 확장의 공개 페이지 읽기)로는 **세 플랫폼 다 이 지표를 구조적으로 못 잡는다** —
유튜브는 별도 Analytics API(채널 소유자 OAuth)가 필요하고, 인스타·틱톡은 애초에 공개
페이지에 안 뜨는 숫자다. 즉 "성과 탭"을 조회수만으로 채우고 끝내면, 원래 판단 유보하려던
지표(조회수)로 다음 주제를 고르는 구조가 그대로 굳어진다.

**대안**: 지금 편수에서 완주율 자동화 인프라부터 만드는 건 과설계(아래 "지금 하지 말 것").
대신 성과 탭에 조회수·팔로우(자동)와 별개로 **"체감 지속률" 3단(상/중/하)** 한 칸을 두고,
사장님이 발행 후 각 플랫폼 자체 분석 화면을 한 번 열어본 김에 손으로 채운다. 자동화가
아니라 30초짜리 정성 기록이라 30분/편 예산을 깨지 않는다.

### 2-2. "성과 → 주제 후보 반영" 규칙이 표에 빈칸이다

1번 단계는 "성과 탭 + 기존 후보 → 새 후보"라고만 적혀 있고 실제로 무슨 규칙으로 섞는지가
없다(공지에도 "열 줄 쌓이면 정한다"로 미룸). 이 세션에서 요청받은 부분이라 3절에 구체안을
낸다.

### 2-3. 시안의 "부모 글(홈페이지) 링크·UTM" 제안 — 아이디어는 맞지만 지금 파이프라인에
넣는 건 보류를 제안

숏폼이 회사 KPI(홈페이지 방문)에 기여하는 지점이 없다는 시안의 지적 자체는 맞다. 다만
그 해법으로 캡션·고정 댓글에 회사 링크를 자동으로 박는 건, **이 채널이 지금 회사와
어떤 관계로 "보여도" 되는지**에 대한 판단이 먼저 서야 하는 문제다. 이건 마케팅 실행보다
위 단계의 결정이고, 이 저장소가 공개라 근거는 적지 않는다. **사장님이 먼저 판단해주시고,
그 판단이 서기 전까지는 14·16번에 이 기능을 넣지 않는 걸 제안**한다.

### 2-4. 발행 리듬(캘린더)이 표에 없다

1번(주 1회 후보 생성)과 2번(주 3개 픽)만 있고, "이번 주 몇 편 발행"이라는 목표가 시트
어디에도 없다. 성과 비교의 시간축이 없으면 "10편 쌓이면"이라는 기준 자체가 언제
도달하는지 아무도 모른다. **대안**: 후보관리 탭에 "이번 주 발행 목표" 한 칸만 추가 —
새 단계가 아니라 기존 2번 픽 화면에 숫자 하나.

### 2-5. `content-insight.html`과의 중복 — 재확인

앞서 사장님과 확인한 내용 그대로: 조회수·팔로우는 `assets/data/*.json`에 이미 자동
수집되고 있어(탐·시안 리뷰와 동일 결론) 시트에 손으로 다시 적을 이유가 없다. 이건 이미
공지에서 마야 항목으로 던져진 질문이었고, 결론은 "성과 탭은 그 json에서 채우는 파생본"
(시안 2-7과 동일)으로 정리하면 된다. 다만 위 2-1에서 말한 완주율은 그 json에도 없으므로,
"중복 안 되는 부분 = 완주율뿐"이라는 걸 명확히 해둔다.

## 3. 마야 관점의 최선안 — 17단계에서 바꿀 줄

| 번호 | 지금 → 제안 |
|---|---|
| 0번 | 사장님(지금)/자동(나중), 조회수·시청률·팔로우 수기 → **조회수·팔로우는 json에서 자동(다리 하나, 탐 제안과 동일), "체감 지속률" 3단만 사장님이 30초 정성 기입** |
| 1번 | 원료 "성과 탭 + 기존 후보" → **"성과 탭(장르 라벨별 상대 순위) + 최근 10편 장르 대조" — 아래 반영 규칙** |
| 4번 | 나오는 것에 "장르 제안"은 있지만 초안에서만 쓰고 버려짐 → **장르 라벨을 후보관리 탭의 고정 열로 저장**해 발행·성과까지 관통시킨다(2단계 뒤에도 추적 가능해야 반영 규칙이 성립) |
| 2번(픽 화면) | — → **"이번 주 발행 목표 편수" 한 칸 추가** (2-4) |
| 14·16번 | 시안 제안(부모 글 UTM) → **지금은 넣지 않음. 사장님 판단 후 재검토** (2-3) |
| 17번 | 성과 탭 수기 → **0번과 동일(자동 다리 + 체감 지속률 3단)** |

**성과 → 후보 반영 규칙 (요청받은 구체안)**:
- **게이트**: 발행 10편 미만이면 자동 가중 없음 — 지금은 그냥 쌓기만 한다. 표본 1~2편으로
  장르를 판단하면 노이즈에 최적화된다(1절에서 이미 합의한 원칙 그대로).
- **10편마다**: 장르 라벨별로 그 라운드 조회수의 상대 순위(중앙값 대비 배수)를 비교해서,
  다음 10편 후보 생성 시 상위 장르 비중을 6:4 정도로만 높인다. 하위 장르를 후보에서
  아예 빼지는 않는다 — 표본이 아직 적어 탐색을 완전히 닫으면 안 된다.
- **사람 확인 지점**: 자동은 "추천 순서·비중"만 바꾸고, 최종 픽은 여전히 사장님(2번 단계
  그대로) — 새 관문이 아니라 기존 픽 화면에 참고 정보 한 줄이 늘어나는 것뿐이다.
- **지표 교체 조건**: "체감 지속률" 3단이 실제로 쌓이면, 조회수 대신 지속률을 1순위
  지표로 바꾼다(1절 원칙).

바꾸지 않는 줄: 3, 5~13, 15. (탐·노트·시안 리뷰의 해당 제안에 동의, 반복 안 함)

## 4. 사람이 남는 4자리에 대한 의견

**동의, 더할 자리 없음.** 탐·노트·시안이 이미 이유(취향/책임/돈/노출)를 충분히 다뤘다.
CMO 관점에서 하나만 보탠다: **5번(대본 확정) 체크리스트에 "장르 라벨이 맞게 붙었는가"를
한 줄 추가**한다 — 새 관문이 아니라 기존 자리에서 확인 항목만 늘리는 것. 3절의 반영
규칙은 이 라벨이 정확해야 의미가 있어서, 입력 품질을 여기서 담보해야 한다.
