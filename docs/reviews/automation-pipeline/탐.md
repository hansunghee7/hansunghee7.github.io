# 숏폼 자동화 파이프라인 v2 — 탐(AI CTO 튜터) 크리틱

> 대상: `shorts-lab/AUTOMATION_PIPELINE.md` (스튜디오 읽기용 `shorts-automation.html`, 2026-09-02 사장님·숏감독 합의본)
> 관점: 아키텍처·권한 설계·자동화 단계·API 사용처. 1인 회사 + AI(S1) 규모 기준.
> 근거로 쓴 사실은 2026-09-02 shorts-lab 저장소 조사(`align_and_build.py`가 `device="cpu"`,
> `assemble_episode.py`가 1080×1920 출력, Video2X 공정은 저장소에 없음 등)입니다.

## 1. 동의하는 것

- **상태 열 하나가 신호등** — 사장님 개입 방식이 "칸 하나 바꾸기"로 통일되는 게 이 설계의 가장 좋은 점. 기계가 앞 단어를 보고 움직이고 자기 단어를 켜고 멈추는 규칙은 곧 상태 기계(state machine)라, 나중에 어떤 도구로 바꿔도 그대로 옮겨집니다.
- **시트가 유일한 정본** — 폰에서 보고 고치는 주인이 한 명일 때는 파일·DB보다 시트가 맞습니다. 뒤집을 신호(타인 접근)도 이미 적혀 있어서 좋습니다.
- **사람은 돈 나가기 직전·밖으로 나가기 직전에** — 관문 위치를 "비용"과 "되돌릴 수 없음"으로 정한 건 정확한 기준입니다. 이 원칙 하나로 나머지 자리 판단이 다 따라옵니다.
- **창작만 세션, 판단이 단순한 일은 API** — 세션(컨텍스트 전체 재전송)은 비싸고 API 호출은 싸다는 비용 구조를 정확히 반영한 분업입니다.
- **딥리서치 결과도 검증은 남긴다(ep07 오보 사례)** — 자동화가 오보를 자동으로 찍어내는 걸 막는 유일한 장치. 절대 빼지 말 것.
- **한 계단씩, 두 계단 동시 금지** — 오늘 SNS 확장에서 겪은 것처럼, 동시 변경은 원인 추적을 불가능하게 만듭니다.
- **미니PC·별도 DB·로그인 웹서비스 미도입** — S1에서 맞는 판단이고 신호가 명시돼 있습니다.

## 2. 반대하거나 우려되는 것

### 2-1. 7번(정렬)·14번(조립)을 "PC 세션"이 하는 것 — 설계 원칙 2와 충돌
정렬(faster-whisper small, CPU)과 조립(ffmpeg concat)은 **판단이 전혀 없는 결정론적 스크립트**입니다. 이걸 클로드 코드 세션 안에서 돌리면 (a) 스크립트 실행을 지켜보는 데 토큰을 쓰고, (b) 세션이 `veo/`가 찰 때까지 기다리는 구조가 되어 문서 스스로 금지한 "하루 종일 지켜보는 세션"이 됩니다. (c) 무엇보다 이 두 단계 때문에 **PC 상시 가동·절전 해제·매일 아침 `/remote-control`·드라이브 오프라인 설정**이 사장님 일과에 들어옵니다. 오늘 실제로 리모트 컨트롤 연결이 끊겨 있던 걸 확인했습니다 — 매일 아침 한 줄이 매일 아침 한 번의 고장 지점입니다.
**대안**: 두 단계를 GitHub Actions로. Apps Script가 상태 변화를 보고 `repository_dispatch`를 쏘면 Actions가 Drive에서 파일을 받아(서비스 계정) 실행하고 결과를 Drive에 올립니다. 90초 오디오 정렬·120초 1080p 합성은 CPU 러너로 수 분입니다. 이러면 **PC는 파이프라인에서 빠집니다.** (조건: shorts-lab이 공개면 Actions 무료, 비공개면 분당 과금 — 저장소 공개 여부가 `PROCESS.md` 열린 항목에 미확인으로 남아 있으니 먼저 확인.)

### 2-2. 15번 업스케일 — 자동화 여부보다 "존재 여부"를 먼저
`assemble_episode.py`는 이미 1080×1920으로 뽑고, 업스케일 근거는 취향 1건이며, 공정 자체가 저장소에 없습니다(역할 노트에만). 편당 35분 PC 점유가 유일하게 GPU를 요구하는 단계이기도 합니다. "지금 하지 않는다: 업스케일 자동화"는 맞지만, 그 전에 **업스케일 유/무로 한 편씩 A/B**해서 차이가 없으면 단계 자체를 지우는 게 자동화보다 쌉니다. 차이가 있으면 주 1회 배치(PC든 초 단위 클라우드 GPU든)로 빼서 매일 손 작업에서 제외.

### 2-3. 우편함 권한 — "액세스: 나만"으로는 숏감독이 못 씁니다
Apps Script 웹앱을 "나만"으로 배포하면 구글 로그인 없는 POST(클라우드 세션)는 거절됩니다. 숏감독이 쓰려면 "모든 사용자" 배포 + **본문에 공유 토큰**이 필요하고, 그 순간 웹앱 주소+토큰이 자격증명이 됩니다. 어디에 두는지가 설계에 없습니다. **대안**: 토큰은 세션 환경변수나 비공개 저장소에만, 공개 저장소·채팅 금지. `doPost`는 토큰 검증 → `LockService` → 처리 순.

### 2-4. 동시 쓰기 — 오늘 SNS 확장에서 터진 것과 같은 종류의 버그가 예약돼 있습니다
시트에 쓰는 손이 셋입니다(Apps Script 타이머, 숏감독 우편함, 사장님 폰). 5분 타이머가 겹치거나 사장님이 상태를 되돌리는 순간 같은 행을 두 번 처리할 수 있습니다. **대안**: 모든 자동 단계는 (1) `LockService`로 잠그고 (2) "현재 상태가 내가 기대한 단어인가"를 확인한 뒤에만 움직이며(compare-and-set) (3) 씬·행마다 **시도 횟수 열**을 두어 재실행해도 같은 결과가 나오게(멱등). 11번의 "최대 3회"는 이 열이 있어야 셀 수 있습니다.

### 2-5. API 키를 "시트에만" — 셀은 시트를 보는 모두에게 보입니다
"시트 메뉴 'API 키 등록'"이 셀에 쓰는 구조라면 공유·복사·내보내기에 키가 딸려갑니다. **대안**: 메뉴는 그대로 두되 `PropertiesService.getScriptProperties()`에 저장. 사장님 절차는 동일합니다.

### 2-6. 11번 검수 판정을 자유 문장으로 받으면 기계가 못 읽습니다
Claude API 판정은 `{scene, verdict: pass|fail, reason}` 같은 **구조화 출력**으로 고정해야 Apps Script가 분기할 수 있습니다. 검수 기준서는 매 호출 동일 접두어로 보내 프롬프트 캐싱을 받게(호출당 비용이 더 내려감).

### 2-7. 4번 아침 Routine — "할 일 없는 날"의 비용
리서치완료 행이 없는 날에도 세션이 뜨면 컨텍스트 로드 비용만 나갑니다. **대안**: 첫 동작을 "시트에서 리서치완료 행 수 확인 → 0이면 즉시 종료"로 고정. Routine은 CLAUDE.md 교리대로 매번 새 세션.

### 2-8. 0·17번 성과 기록 — 이미 자동 수집되는 데이터를 사람이 옮기고 있습니다
유튜브·인스타·틱톡 성과는 `assets/data/`에 Actions·확장이 이미 모읍니다(콘텐츠 인사이트). 시트 "성과" 탭은 **여기서 다리 하나**(Actions → 우편함 POST)로 채울 수 있어서, "사장님(지금)"을 첫 계단부터 뺄 수 있습니다. 마야가 지적한 데이터 중복도 "정본은 `assets/data/`, 시트는 사본"으로 정리됩니다.

## 3. 탐 관점의 최선안 — 17단계에서 바꿀 줄

- **0번**: 사장님(지금)/자동(나중) → **자동(지금부터)**. 발행 3일 후 Actions가 `assets/data/`의 수치를 우편함으로 시트에 씀. 사람 손 0.
- **4번**: 아침 Routine 세션 → 유지하되 **첫 동작 = 리서치완료 행 0개면 즉시 종료**. 매번 새 세션.
- **7번**: 자동(PC 세션, Whisper) → **자동(GitHub Actions, CPU)**. 트리거: `voice/` 파일 감지(Apps Script Drive 트리거) → `repository_dispatch`. PC·세션 불필요.
- **11번**: Claude API 판정 → **구조화 출력 JSON + 기준서 캐싱 + 씬별 시도 횟수 열**. 3회는 이 열로 센다.
- **13번**: 자동 → **편당 예산 상한 열(기계 관문)** 추가. 확정 씬 수 × 단가가 상한을 넘으면 영상 생성 전에 멈추고 알림. "돈 나가기 직전"을 사람 눈에만 맡기지 않는다.
- **14번**: 자동(PC 세션 ffmpeg) → **자동(GitHub Actions)**. `veo/`가 다 차면 Apps Script가 dispatch, 결과 `final/`을 Drive에 업로드.
- **15번**: 사장님(Video2X) → **A/B 1회 후 결정**. 차이 없음 → 단계 삭제. 차이 있음 → 주 1회 배치로 격리(매일 손 작업 아님).
- **16번**: 사장님 업로드 → 지금은 유지. **다음 계단 후보**: 기계가 '비공개'로 올리고 사람이 보고 '공개'로 바꾸기 — 관문은 그대로, 손만 줄어듦. 지금은 하지 않음.
- **우편함(공통)**: "나만" 배포 → **"모든 사용자" + 본문 토큰 + LockService + compare-and-set**. 토큰은 비공개 위치에만.
- **키 보관(계단 4·5)**: 시트 셀 → **Script Properties**.
- **계단 순서**: 1(우편함) → **1.5(0번 성과 다리 + 7번 Actions 정렬)** → 2(거울) → 3 → 4 → 5 → 6. 이유: 1.5는 새 판단이 필요 없고 PC를 빼는 효과가 즉시 나며, "숏감독이 시트 셀에 쓰기 성공"을 실제 데이터로 검증하는 첫 사용처가 됩니다.

바꾸지 않는 줄: 1·2·3·5·6·8·9·10·12·17.

## 4. 사람이 남는 4자리에 대한 의견

**네 자리 모두 유지**하되, 성격을 둘로 나눠서 봐야 합니다.

| 자리 | 판단 | 비고 |
|---|---|---|
| 주제 픽 | 유지, 영구 | 취향은 자동화 대상이 아님. 동의. |
| 대본 확정 | 유지, 영구 | 사실 책임이 사람 이름으로 나감. 동의. 다만 4번 초안이 "출처 있는 사실만" 규칙을 지키는지 자동 검사(출처 URL 없는 숫자 표시)를 초안 단계에 넣으면 이 10분이 더 짧아짐. |
| 이미지 확정 | 유지, **조건부** | 문서의 20장 일치율 기준에 동의. 단, 사람을 빼더라도 13번 앞의 **예산 상한 기계 관문**은 남겨야 "돈 나가기 직전" 원칙이 유지됨. |
| 확인·업로드 | 판단은 영구, **손은 줄일 것** | 되돌릴 수 없는 지점이라 사람의 "공개" 클릭은 남긴다. 파일 업로드 자체는 다음 계단에서 기계로(비공개 업로드 → 사람 공개 전환). |

**더할 자리**: 사람 자리는 없음. 대신 **기계 관문 하나**(13번 예산 상한). 사람 관문은 넷이면 충분하고, 다섯째 사람 관문은 "30분/편" 약속을 깹니다.
**뺄 자리**: 15번 업스케일은 사람 자리에서 빼는 게 아니라 A/B 뒤 단계 자체를 지울 후보.
