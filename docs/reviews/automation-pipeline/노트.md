> 관점: 시트·Apps Script·API 호출 쪽 구현 담당. 오늘 같은 시트의 대본 변환기를

## 1. 동의하는 것

- **상태 열 한 칸이 유일한 신호** — 사장님의 개입 방법이 항상 같아서(단어 바꾸기) 폰에서도 되고, 기계가 읽기도 쉽다. 색깔 금지도 맞다(오늘 시트 스크립트를 보니 색은 코드에서 읽기 지저분하다).
- **판단 단순한 일은 API, 창작은 하루 한 번 세션** — 세션은 도구 호출마다 전체 대화를 다시 보내서 비싸다(CLAUDE.md 실측 $656/3일). 시트가 직접 API를 부르면 호출당 몇십 원으로 끝난다.
- **사람은 돈 직전·밖 직전** — 이미지는 싸게 많이 찍고 영상은 확정본만. 비용 구조에 맞는 관문 배치다.
- **한 계단씩** — 오늘 대본 변환기 하나 고치는 데도 원인이 두 개(토큰 상한 + thinking 예산)였다. 두 계단을 같이 올리면 어느 쪽이 깨졌는지 못 가른다.
- **자동으로 가져온 사실도 검증** — ep07 오보 사례가 실제로 있었다. 자동화는 오보도 자동으로 만든다.
- **시트가 정본, 별도 DB 없음** — S1에서 DB를 두면 정본이 둘이 되고, 둘을 맞추는 일이 새로 생긴다.

## 2. 반대하거나 우려되는 것

**2-1. 돈 나가는 비동기 단계에 "진행중" 상태가 없다 — 이중 발주가 난다.**
원칙 3("기계는 앞 단어가 켜졌을 때만 움직이고, 자기 단어를 켜고 멈춘다")은 단계가
몇 초면 맞지만, 딥리서치(3)·이미지 생성(10)·영상 생성(13)은 몇 분~몇십 분 걸린다.
그 사이 5분 타이머가 다시 돌면 앞 단어(`픽`)가 아직 켜져 있어서 **같은 주제를 한 번
더 발주한다**($2~5가 두 번 나간다). 영상은 더 비싸다.
→ 대안: 돈 나가는 비동기 단계 셋에만 진행중 단어를 둔다 — `리서치중`·`이미지중`·
`영상중`. 발주 직후 이 단어로 바꾸고, 작업 ID를 옆 열에 적는다. 타이머는 진행중
줄만 확인한다. 사장님이 만지는 단어는 여전히 4개다(진행중은 기계만 씀).

**2-2. 우편함을 "액세스: 나만"으로 배포하면 숏감독 세션이 못 쓴다.**
Apps Script 웹앱을 "나만"으로 두면 구글 로그인 없는 요청(클로드 세션의 HTTP 호출)은
로그인 페이지를 받는다. 우편함의 목적 자체가 막힌다.
→ 대안: "액세스: 모든 사용자"로 배포하되, 본문에 **공유 비밀키**를 넣어 맞을 때만
쓴다. 지금 `ask.html`↔워커가 쓰는 방식(`X-Ask-Secret`)과 같다. 진짜 보안은
아니지만 주소를 우연히 찾은 봇을 막는 데는 충분하고, S1에서 그 이상은 과하다.

**2-3. 지금 대본 변환기는 트리거로 못 돈다 — "버튼을 상태 신호로" 하려면 손봐야 한다.**
변환기(`runGeminiWorkflow`)는 장르를 묻는 입력창과 `ui.alert`를 쓴다. 시간 트리거에는
UI가 없어서 그 줄에서 죽는다. 오늘 고친 토큰 잘림도 `alert`로만 알리는데, 무인
실행이면 아무도 못 본다.
→ 대안: 핵심 함수(입력→JSON→시트)를 UI 없는 함수로 떼고, 메뉴 버튼은 그걸 감싸는
껍데기로. 장르는 주제관리 탭의 열에서 읽고, 잘림·오류는 그 줄의 "오류" 열에
쓴다. 이건 내 소관이라 내가 한다(2-5의 파일 분리와 같이).

**2-4. 정렬(7)·조립(14)을 "PC 세션"이 하는 건 원칙 2와 어긋난다.**
Whisper 정렬과 ffmpeg 조립은 판단이 0인 일이다. 그런데 "PC 세션이 한다"고 하면
그 세션이 `voice/`·`veo/` 폴더가 찰 때까지 지켜봐야 한다 — 원칙 2가 금지한 "하루
종일 시트를 지켜보는 세션"이 폴더 버전으로 되살아난다.
→ 대안: PC에 **세션이 아닌 파이썬 스크립트** 하나(윈도우 작업 스케줄러로 10분마다).
드라이브 폴더에 새 `voice/` 파일이 있으면 정렬, `veo/`가 다 찼으면 조립. 결과와
8초 초과 같은 예외만 우편함으로 시트에 쓴다. 클로드 세션은 아침 대본처럼 판단이
있는 일에만 쓴다. `pipeline/`에 이미 정렬·조립 코드가 있으니 감시 루프만 얹으면 된다.

**2-5. 같은 Apps Script 프로젝트에 파일이 늘어난다 — 나누는 규칙이 먼저다.**
공지대로 대본 변환기(내 소관)와 우편함·폴링(숏감독이 씀)이 한 프로젝트에 들어간다.
전역 변수(`GEMINI_MODEL`, `MAX_OUTPUT_TOKENS`)와 메뉴(`onOpen`)가 파일을 넘어 공유되기
때문에 이름이 겹치면 조용히 덮어쓴다.
→ 대안: 파일 4개로 고정 — `Config.gs`(키·모델·상수, 한 곳), `Menu.gs`(`onOpen`
하나만), `Converter.gs`(변환기), `Mailbox.gs`(우편함·폴링). 새 전역 상수는
`Config.gs`에만. 오늘 대본 변환기를 이 구조로 먼저 옮겨두겠다(내용 변경 없이
파일만).

**2-6. Apps Script 트리거 하루 총량이 있다 — 5분 폴링은 그 안에서만.**
개인 계정은 트리거 실행 시간이 하루 합계 90분, 한 번에 6분까지다. 5분마다 돌면
하루 288번 — 한 번에 15초 안에 끝나면 72분이라 아슬아슬하다. 폴링이 늘어나면
(리서치+이미지+영상) 넘는다.
→ 대안: 폴링 하나로 통합(진행중 줄 전부를 한 번에 확인), 주기 15분. 딥리서치는
어차피 십몇 분 걸려서 5분과 15분의 체감 차이가 없다.

**2-7. "알림"의 경로가 안 정해져 있다.**
표의 "실패하면" 칸이 전부 "알림"인데 어디로 오는지 없다. 폰에서 상태만 바꾸는
사장님이 시트를 안 열면 못 본다.
→ 대안: Apps Script 내장 `MailApp`으로 사장님 메일에 한 줄(하루 100통 무료, 코드
두 줄). 나중에 모닝 브리핑 메일에 합치면 더 좋지만 지금은 따로.

**2-8. 편당 비용표의 숫자에 출처가 없다 — 원칙 5를 우리 계획에도 적용해야 한다.**
딥리서치 API의 존재 여부·가격·비동기 호출 방식은 착수 전에 실측으로 확인할 것.
오늘 Gemini 한도를 조사하면서 "문서상 별도"라던 thinking 예산이 실제로는 출력
예산과 합산되는 걸 봤다. 문서와 실제가 다른 경우가 있다.

**2-9. Gemini 키를 다른 도구와 나눠 쓰면 하루 한도를 같이 쓴다.**
무료 티어 한도는 키(프로젝트) 단위 합산이다. `ask.html` 워커와 같은 키면 파이프라인이
돌 때 대화 화면이 막힐 수 있다.
→ 대안: 파이프라인 전용 키(프로젝트)를 따로 만든다. 무료.

## 3. 17단계 표에서 바꿀 줄 — "N번: 지금 → 제안"

- **3번**: `픽` → 5분마다 확인 → `리서치완료` → **`픽` → 발주 즉시 `리서치중`(작업 ID 기록) → 15분 폴링 → `리서치완료`.** 진행중 줄이 없으면 발주하지 않는다(이중 발주 방지).
- **6번**: 사장님 Typecast → **그대로 두되 "사람 자리"로 정직하게 센다** (4절 참고).
- **7번**: PC 세션이 Whisper 정렬 → **PC의 감시 스크립트(세션 아님, 작업 스케줄러 10분)가 정렬. 8초 초과 블록만 우편함으로 시트 "오류" 열에.**
- **8번**: 시트 버튼을 상태 신호로 자동 실행 → **UI 없는 변환 함수로 분리한 뒤 트리거. 장르는 주제관리 탭 열에서, 잘림·오류는 "오류" 열에. (노트가 함)**
- **9번**: 별도 검사 단계 → **8번과 같은 실행 안에서 이어서 검사(트리거 하나 절약). 문제 씬 번호를 같은 줄 "문제씬" 열에.** 단계 번호는 유지, 실행만 합침.
- **10번**: 이미지 생성 → **발주 즉시 `이미지중`, 씬별 작업 ID·재시도 횟수 열 추가.**
- **13번**: 영상 생성 → **발주 즉시 `영상중`. 재시도 1회는 유지하되 두 번째 실패는 발주 금지(비싼 단계).**
- **14번**: PC 세션이 ffmpeg 조립 → **7번과 같은 감시 스크립트가 `veo/`가 다 찼을 때 조립. 세션 아님.**
- **15번**: 사장님이 Video2X → **14번 스크립트의 마지막 줄로 자동(명령줄 한 줄, 판단 0, 돈 0).** 4절 참고.
- **(계단 1, 우편함)**: 액세스 "나만" → **"모든 사용자" + 공유 비밀키. 본문 형식이 다르면 400.**
- **(계단 3)**: 아침 Routine + 딥리서치 API 한 번에 → **3a 아침 Routine(리서치는 당분간 사장님이 제미나이 앱에서 돌려 문서를 폴더에 넣음) → 한 주 굴린 뒤 3b 딥리서치 API.** 원칙 4대로.
- **(전체)**: "알림" → **MailApp 메일 한 줄.** 상태 단어에 `오류`는 넣지 않고(신호등이 복잡해짐) 별도 "오류" 열에 이유를 쓴다.

상태 단어는 이렇게 된다 — 사장님이 바꾸는 4개는 그대로:
```
후보 → 픽 → 리서치중 → 리서치완료 → 초안 → 대본 → 프롬프트 → 이미지중 → 이미지 → 이미지확정 → 영상중 → 영상 → 조립 → 발행
```

## 4. 사람이 남는 4자리에 대한 의견

**4자리 자체는 맞다.** 주제 픽·대본 확정·이미지 확정·업로드 — 취향·책임·돈·노출이라는
서로 다른 이유가 하나씩 붙어 있고, 겹치는 자리가 없다.

**다만 "4곳"은 목표이지 현재가 아니다.** 지금 표대로면 사람은 6곳이다 — 음성(6번,
Typecast)과 업스케일(15번)이 "지금은 사장님"으로 남아 있다. 이걸 4곳이라고 부르면
계단 어디에서 6→4가 되는지 안 보인다.
- **업스케일(15번)은 빼자.** 판단이 없고(모델·배율 고정), 돈이 안 나가고, 밖으로도
  안 나간다 — 원칙 2·3 어디에도 사람이 설 이유가 없다. 조립 스크립트 마지막 줄에
  붙이면 끝이라 "지금 하지 않는다" 목록에 둘 만큼 비싸지도 않다. 이유가 "화질을
  눈으로 보고 싶어서"라면 그건 16번(확인·업로드)에서 이미 본다.
- **음성(6번)은 당분간 사람으로 정직하게 센다.** 목소리 확정이 안 됐으니 자동화
  시점이 아니다. 대신 표의 "누가" 칸을 굵게 해서 5번째 사람 자리로 보이게 한다.
  Typecast API가 붙는 날 4곳이 된다.

**더할 자리는 없다.** 계단 3의 "리서치 주문서 확인"은 숨은 사람 자리인데, 원칙대로
`픽` 직후 자동 발주로 가면 사라진다(문서 9절의 추천 "전자"에 동의). 확인은 5번
대본 확정에서 출처와 같이 보면 된다.

**빼는 조건에 하나 추가**: 이미지 확정에서 사람을 빼는 기준(검수 AI 일치율 90%,
20장)에 **"반려 사유가 사장님 말과 같은가"**도 본다. 통과/반려만 맞고 이유가
다르면 기준서가 아니라 우연이다.

## 5. 지금 하지 말아야 할 것 (내 관점 추가분)

- **거울 페이지 3모드를 한 번에** — 이미지 확정 모드(돈 관문)만 먼저. 검토 모드는
  시트 셀로 충분하고, 영상 모드는 영상 모델이 정해지는 계단 5 뒤에.
- **Apps Script에서 딥리서치 결과를 파싱해 대본까지** — 리서치는 문서로 폴더에
  두고, 대본은 아침 세션이. 시트 스크립트는 "옮기기·상태 바꾸기"까지만.
- **상태 단어에 색·아이콘·이모지** — 드롭다운 칩 색은 시트가 알아서 붙인다.
- **우편함에 인증 체계(OAuth 등)** — 비밀키 한 줄이면 된다. 편집자가 생기면 그때.
- **폴링 주기 줄이기** — 15분에서 더 줄이면 트리거 총량을 먹는다. 빨라야 할
  단계는 없다.

**다음 단계 신호(내 영역)**: 트리거 실행 시간이 하루 60분을 넘기 시작하면 → 폴링을
Cloudflare Worker cron으로 옮기는 것 검토. Apps Script 프로젝트 파일이 6개를
넘으면 → 시트 밖(shorts-lab)으로 로직 이전 검토.
