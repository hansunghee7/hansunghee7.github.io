# 에이전트 왕복 표준 절차: 폴링 없는 사슬 (2026-09-20)

> 사장님 지시(2026-09-20): 마야 -> 헤르메스 의뢰(폴링 대기) -> 답변 확인(대기) -> 문제 발생 시 탐에게 의뢰(폴링 대기) -> 결과 수령 -> 사장님 컨펌(또 대기). 이 사슬의 구간마다 대기가 있는 것이 문제다. 각 구간을 이벤트로 바꾼 표준 절차다.
> 근거는 2026-09-20 실측이다. 실측하지 못한 것은 "미확인"으로 표시했다. 지표는 [탐 KPI](탐_KPI.md).

## 구간별 표준 절차

| 구간 | 예전 | 표준 절차 | 실측 |
|---|---|---|---|
| 1. 헤르메스 발주 | `tasks/pending`에 파일 푸시, 폴러가 3~4분 주기로 확인. 폴러가 하나뿐이라 긴 작업 중이면 뒤의 지시서가 대기(짧은 시험 지시서 약 19분 실측) | 세션에서 **백그라운드로** `bash scripts/hx_lite.sh ask < 지시문` 실행 | 발주 10:30:47, 응답 10:30:54(7초) |
| 2. 헤르메스 완료 확인 | 사람이나 세션이 파일·우편을 다시 확인 | 위 백그라운드 실행이 끝나면 세션이 **자동으로 깨어나** 결과를 받음. 폴링 없음 | 완료 알림이 즉시 도착 |
| 3. 다른 세션에게 의뢰·질문 | 우편함(배달원 약 11분 주기) | 같은 PC의 살아 있는 세션은 `ListAgents`로 찾고 `SendMessage`로 직접. **보낸 뒤 같은 내용을 우편함에도 한 줄 요약으로 남긴다**(사장님 모니터링 그룹은 우편함만 보여 줌) | 마야 세션(쉬는 상태)에 보낸 뒤 몇 분 안에 실질 답이 옴. 정확한 지연은 미측정 |
| 4. 사장님 컨펌 알림 | 우편함 + 배달원 크론(실제 약 11분) | `python mailbox/mailbox.py send 사장님 "<제목>" --from <이름> --ask "<할 일 한 줄>" --body "<무엇에 대한 것>"` 바로 뒤에 `bash scripts/hx_lite.sh kick` | 발송 10:31:14, 배달 완료 10:31:21(7초). 폰에 뜬 시각은 사장님 확인 대기 |
| 5. 사장님 컨펌 답 | 텔레그램 답장은 에이전트에 안 닿음 | 텔레그램은 알림만. **답은 클로드 모바일에서 해당 세션에 직접**(Remote Control 켜짐) | 사람의 응답 시간만 남음 |

## 줄 고르는 기준 (사장님 확정 2026-09-20)
헤르메스에게 일을 맡길 때 **누가 결과를 기다리는가**와 **얼마나 걸리는가** 두 가지로 줄을 고른다.

| 상황 | 줄 | 근거 |
|---|---|---|
| 세션이나 사람이 결과를 기다리는 급한 일 | **`hx ask`** (백그라운드 실행, 완료 알림이 자동으로 옴) | 7분 36초 작업이 끝까지 돌고 완료 알림이 자동으로 왔음(30분 이상은 미시험) |
| 기다리는 사람 없이 **예상 5분 이내**로 끝나는 무인 작업 | **`tasks/pending/`** (짧은 줄) | 긴 작업과 겹쳐도 1분 56초에 완료(이전 약 19분) |
| 기다리는 사람 없이 **5분을 넘거나 넘을 수 있는** 무인·야간·대량 작업 | **`tasks/pending-long/`** (긴 줄) | 긴 작업 전용 폴러라 짧은 줄을 막지 않음 |

- **애매하면 긴 줄로 보낸다**(탐 제안, 확정 기준의 세부). 짧은 줄에 긴 작업이 들어가면 그 줄의 뒤 지시서가 전부 밀린다.
- 끝나면 헤르메스가 발주자에게 우편과 즉시 배달을 한다. 보고서는 지시서에 `PUBLISH: yes`가 있을 때만 원격에 push한다.
- 다음 단계 신호: 긴 줄 안에서 긴 작업끼리 서로 막기 시작하면 병렬 작업자 방식을 검토한다([해외 사례 조사](에이전트_대기시간_해외사례_조사.md) 채택안 후보).

### 지시서 머리말 (복사해서 쓸 것)
`tasks/pending/`이나 `tasks/pending-long/`에 올리는 지시서는 맨 위에 아래를 적는다. 줄을 잘못 골랐는지 나중에 확인할 수 있게 하기 위한 것이다.

```
줄: pending 또는 pending-long
예상 소요: N분
발주자: <세션 이름>
PUBLISH: yes 또는 생략
보고서 경로: <절대 경로>
```

## 알아 둘 것 (미확인·한계)
- 백그라운드 `ask`가 **30분 이상** 작업도 끝까지 도는지는 미확인이다.
- 헤르메스가 만든 **보고서 파일은 신PC에만 남을 수 있다.** 마야 발주 3건(PM/PL 딥리서치 등)이 done으로 옮겨지기만 하고 원격 저장소에 push되지 않았다(마야 확인). 지시서에 push를 적지 않은 빈틈이다. 회수는 `hx_lite.sh read <경로>`로 한다. **공개 저장소 push는 내용이 공개 가능한지 주인이 판단**한 뒤에만 한다.
- 헤르메스 보고서의 "접속 시각"이 지시서 발주 시각보다 이른 사례가 있다(마야가 확인, 표본 대조 진행 중). 시각은 모델이 쓴 글이 아니라 도구 실행 기록에서 가져와야 한다. 검증 절차에 반영한다(백로그 0순위 "제미나이 검증 확인"과 같은 줄기).
- 세션 메시지는 **같은 PC의 세션**끼리만 확인했다. 다른 PC나 클라우드 세션은 미확인.
