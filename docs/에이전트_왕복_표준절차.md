# 에이전트 왕복 표준 절차: 폴링 없는 사슬 (2026-09-20)

> 사장님 지시(2026-09-20): 마야 -> 헤르메스 의뢰(폴링 대기) -> 답변 확인(대기) -> 문제 발생 시 탐에게 의뢰(폴링 대기) -> 결과 수령 -> 사장님 컨펌(또 대기). 이 사슬의 구간마다 대기가 있는 것이 문제다. 각 구간을 이벤트로 바꾼 표준 절차다.
> 근거는 2026-09-20 실측이다. 실측하지 못한 것은 "미확인"으로 표시했다. 지표는 [탐 KPI](탐_KPI.md).

## 알아 둘 것 (미확인·한계)
- **장시간 작업(수십 분)을 `hx_lite.sh ask` 백그라운드로 끝까지 돌릴 수 있는지는 미확인**이다. SSH 연결 유지와 세션 제한 때문에 시험이 필요하다. 그때까지 무인 야간·대량 작업은 `tasks/pending`을 쓴다.
- 헤르메스가 만든 **보고서 파일은 신PC에만 남을 수 있다.** 마야 발주 3건(PM/PL 딥리서치 등)이 done으로 옮겨지기만 하고 원격 저장소에 push되지 않았다(마야 확인). 지시서에 push를 적지 않은 빈틈이다. 회수는 `hx_lite.sh read <경로>`로 한다. **공개 저장소 push는 내용이 공개 가능한지 주인이 판단**한 뒤에만 한다.
- 헤르메스 보고서의 "접속 시각"이 지시서 발주 시각보다 이른 사례가 있다(마야가 확인, 표본 대조 진행 중). 시각은 모델이 쓴 글이 아니라 도구 실행 기록에서 가져와야 한다. 검증 절차에 반영한다(백로그 0순위 "제미나이 검증 확인"과 같은 줄기).
- 세션 메시지는 **같은 PC의 세션**끼리만 확인했다. 다른 PC나 클라우드 세션은 미확인.
