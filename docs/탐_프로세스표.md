# 탐 업무 프로세스표 (2026-09-24, 사장님 지시: 핏 표 벤치마킹)

> 핏의 생성단 파이프라인 표(shorts-lab `GENERATION_PIPELINES.md`)를 벤치마킹했다. 가져온 형식은 다섯 가지: ① 맨 위 **공통 원칙**(언제·누가 정했는지 포함) ② 업무마다 **순서·활동·상세(도구·명령·완료 증거)** 표 ③ 표 안에 "이 줄이 유일한 근거"로 결정을 박아 두기 ④ 실제로 난 **사고와 대응**을 표 바로 아래에 ⑤ 실제로 한 번 돌린 뒤 **KPT 회고**.
> 할 일 목록(무엇을)은 [탐_업무대장.md](탐_업무대장.md), 이 문서는 방법(어떻게)이다. 역할노트(업무 방식 원칙)와 CLAUDE.md(전사 규칙)에 있는 내용은 반복하지 않고 줄 번호 대신 링크로 부른다.

## 0. 공통 원칙

- **표가 유일한 근거다**(사장님 확정 2026-09-24, 핏 사례): 여러 항목의 번호·상태·매핑은 산문 대신 표부터 잡는다. 대화나 인수인계 산문에만 있는 결정은 다음 세션이 잊는다(핏: 업스케일 생략 결정이 표에 없어서 세션이 한 번 까먹음).
- **요청은 착수 전에 대장에 한 줄**: 우편·세션 메시지·감시 알림·사장님 지시가 오면 먼저 [업무대장](탐_업무대장.md)에 행을 만들고 착수한다. 대장에 없는 일은 인수인계에서 사라진다(2026-09-23~24: health-check 🔴 알림이 탐 우편함에 5번 쌓이는 동안 아무 세션도 잡지 않았음).
- **헤르메스에는 한 줄로 완결된 명령을 한 번에**(핏 확정 2026-09-23): 여러 번 묻지 않는다. 실패하면 "다시 해봐"가 아니라 원인을 코드·문서에 고친 뒤 다시 시킨다.
- **위임 전에 "정말 위임이 필요한가"부터**(핏 KPT 2026-09-24): GPU·장시간·재시도 가능성이 없는 단순 스크립트 순차 실행은 탐이 직접 한다. 헤르메스 부트스트랩(관련 없는 문서 읽기)에 막혀 아무것도 못 한 사례가 있다.
- **완료는 로그가 아니라 산출물로 확인한다**(CLAUDE.md DONE=VERIFIED, 핏 사고 2026-09-24): 위임 결과는 파일 존재·exit code·상태판 색으로 본다. "실행 중"이라는 로그는 증거가 아니다.
- **같은 자원을 여러 세션이 쓰면 경쟁이 난다**(핏 다운로드 폴더 사고 + 탐 브랜치 혼입 2026-09-24): 세션 시작 때 현재 브랜치가 내 것인지 확인하고, 작업은 전용 워크트리에서 한다.
- **토큰·PIN 같은 비밀값은 채팅·명령에 원문을 반복해서 타이핑하지 않는다**(2026-09-27, N42: 텔레그램 봇 토큰을 대화 중 여러 번 그대로 다룸 → "Credential Leakage" 안전 분류기가 세션 후반부 Bash 전체를 막아 정상 인수인계 커밋 없이 세션이 끊긴 사고가 두 세션 연달아 남). 값은 받으면 즉시 파일 하나에 한 번만 쓰고, 이후 명령은 전부 그 파일 경로로 참조한다(예: `curl ... "$(cat ~/.secrets/tg_token)"`). **토큰을 다루는 작업(예: 봇 API 왕복 테스트, `.env` 배치)을 시작하기 전에 지금까지의 업무대장·인수인계를 먼저 커밋해 둔다** — 중간에 분류기가 막혀도 그 지점까지는 남는다.
- **막힘·한도 문장은 착수 전에 1분 실측으로 갱신한다**(KPT 2026-10-01): 대장에 "한도 소진"·"막힘"이 적혀 있어도 날짜 추정을 기다림으로 설계하지 않는다. 실측이 내 권한 밖이면 사장님이 할 가장 작은 한 줄을 번호 단계로 바로 제안한다. "사장님 몫" 항목에는 항상 컴맹 가이드 단계를 붙인다.
- **"탐이 진행하는 과제"를 사장님께 시험시키지 않는다**(사장님 지적 2026-10-01): 먼저 끝까지 해 보고, 막힌 부분만 단계로 드린다.
- **사장님이 이미 정한 것을 다시 묻지 않는다. 기록 찾기는 탐의 몫이다**(사장님 지적 2026-10-03, B50 사고: 10/2 결정이 대장에 있었는데 "선택 대기"로 보고). ① 사장님 결정 대기 목록을 보고하거나 결정을 요청하기 전에 `python scripts/ops/ledger_lint.py --boss`(칸마다 결정·지시 줄 전부 출력)와 `python scripts/ops/ledger_lint.py --find <키워드>`(대장·히스토리·진행상황·아카이브 검색)를 돌리고, 대장 칸은 머리줄·끝줄만 보지 말고 전체를 읽는다(자르는 `cut`으로 읽지 않는다). ② 사장님 결정·정정이 오면 **같은 편집에서** 칸의 상태·결론·"사장님 할 일" 줄을 새 결정에 맞게 고친다(결정 줄만 덧붙이고 낡은 "선택 대기"를 남기면 모순 칸이 된다). ③ 세션 시작과 대장 PR 전에 `python scripts/ops/ledger_lint.py`를 돌려 모순 칸이 없는지 본다(있으면 종료코드 1). ④ 대장·문서에 없으면 `search_session_transcripts`로 지난 세션 대화를 검색한 뒤에야 묻는다.
- **동시 진행(WIP) 상한 5건**(사장님 승인 2026-10-01): 업무대장 `진행`이 5건을 넘으면 새 일을 올리기 전에 하나를 내린다. 세션 시작 때 `진행` 수부터 센다.
