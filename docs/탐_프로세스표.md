## 0. 공통 원칙

- **표가 유일한 근거다**(사장님 확정 2026-09-24, 핏 사례): 여러 항목의 번호·상태·매핑은 산문 대신 표부터 잡는다. 대화나 인수인계 산문에만 있는 결정은 다음 세션이 잊는다(핏: 업스케일 생략 결정이 표에 없어서 세션이 한 번 까먹음).
- **요청은 착수 전에 대장에 한 줄**: 우편·세션 메시지·감시 알림·사장님 지시가 오면 먼저 [업무대장](탐_업무대장.md)에 행을 만들고 착수한다. 대장에 없는 일은 인수인계에서 사라진다(2026-09-23~24: health-check 🔴 알림이 탐 우편함에 5번 쌓이는 동안 아무 세션도 잡지 않았음).
- **헤르메스에는 한 줄로 완결된 명령을 한 번에**(핏 확정 2026-09-23): 여러 번 묻지 않는다. 실패하면 "다시 해봐"가 아니라 원인을 코드·문서에 고친 뒤 다시 시킨다.
- **위임 전에 "정말 위임이 필요한가"부터**(핏 KPT 2026-09-24): GPU·장시간·재시도 가능성이 없는 단순 스크립트 순차 실행은 탐이 직접 한다. 헤르메스 부트스트랩(관련 없는 문서 읽기)에 막혀 아무것도 못 한 사례가 있다.
- **완료는 로그가 아니라 산출물로 확인한다**(CLAUDE.md DONE=VERIFIED, 핏 사고 2026-09-24): 위임 결과는 파일 존재·exit code·상태판 색으로 본다. "실행 중"이라는 로그는 증거가 아니다.
- **같은 자원을 여러 세션이 쓰면 경쟁이 난다**(핏 다운로드 폴더 사고 + 탐 브랜치 혼입 2026-09-24): 세션 시작 때 현재 브랜치가 내 것인지 확인하고, 작업은 새 브랜치(또는 워크트리)에서 한다.
- **토큰·PIN 같은 비밀값은 채팅·명령에 원문을 반복해서 타이핑하지 않는다**(2026-09-27, N42: 텔레그램 봇 토큰을 대화 중 여러 번 그대로 다룸 → "Credential Leakage" 안전 분류기가 세션 후반부 Bash 전체를 막아 정상 인수인계 커밋 없이 세션이 끊긴 사고가 두 세션 연달아 남). 값은 받으면 즉시 파일 하나에 한 번만 쓰고, 이후 명령은 전부 그 파일 경로로 참조한다(예: `curl ... "$(cat ~/.secrets/tg_token)"`). **토큰을 다루는 작업(예: 봇 API 왕복 테스트, `.env` 배치)을 시작하기 전에 지금까지의 업무대장·인수인계를 먼저 커밋해 둔다** — 중간에 분류기가 막혀도 그 지점까지는 남는다.

**사고와 대응(9/27, "agy CLI" 존재 여부 착오)**: 비티가 리눅스 이전 방법으로 `agy`(Antigravity CLI)를 제안하며 설치 URL을 줬는데 404였다. 탐이 "npm/pip에 없다"며 존재 자체를 의심했으나 **틀렸다** — `agy`는 Go로 만든 별도 네이티브 바이너리라 애초에 npm/pip 레지스트리에 없는 게 정상이었다(탐이 검증 경로를 잘못 골랐다). 사장님이 구글 검색으로 공식 페이지(`antigravity.google/product/antigravity-cli`)를 보여줘서 실존을 확인했고, WebFetch로 공식 문서를 직접 뒤져 올바른 설치 URL(`.../cli/install.sh`, 비티 원문은 `/cli/`가 빠진 오타)을 찾았다. **일반화**: "레지스트리에 없다"는 "존재하지 않는다"와 다르다 — 배포 방식(npm/pip/독립 바이너리/OS 패키지)부터 확인하고, 안 보이면 그 도구의 **공식 사이트를 직접** 뒤진다. 탐의 반박도 비티의 주장만큼이나 재검증 대상이다.
