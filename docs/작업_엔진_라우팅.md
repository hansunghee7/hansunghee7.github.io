# 작업 엔진 라우팅 기본 체계 (4절 1번만 확정, 나머지는 초안)

> 작성: 탐, 2026-09-20. 사장님 지시("각 모델과 헤르메스, 로컬 LLM을 적재적소에 쓰는 기본 체계"). **확정된 것은 4절 1번(무료·로컬 엔진은 판정에 쓰지 않는다)뿐이다(사장님 확정 2026-09-20).** 나머지는 제안이며 정책이 아니다. 근거는 이 저장소·solar-bible 문서와 오늘(2026-09-20) 실측만 쓰고, 측정 못 한 것은 "미측정"으로 표기했다.

## 1. 한 줄 원칙
**값싸고 되돌릴 수 있는 일은 아래 엔진으로, 판단과 되돌리기 어려운 일은 위 엔진으로.** 기준은 단가가 아니라 "틀렸을 때 되돌리는 비용"이다. 아래로 내릴수록 안전은 모델이 아니라 지시서(읽기 전용 범위, 멈춤 조건, 결과 검증)가 지킨다.

| 클로드 페이블 | 되돌리기 어려운 실행, 조직 재편 종합 | 최고가, 서브에이전트로는 안 씀 | 같은 문서 |

| 제미나이 | 딥리서치 검증, 다이얼로그 **전용**(폴백 금지) | 키당 하루 20회 | 모델 로스터 3절 |

## 3. 작업 유형별 기본 엔진 (제안)
| 작업 | 기본 | 이유와 오늘의 근거 |
|---|---|---|
| 줄 수·글자 수·문구 존재·링크 검사 | 스크립트 | 결정적이고 토큰 0. Golden Test 정적 층이 실제로 200줄 복사본의 손실을 잡았다(48/68) |
| 파일·폴더 대량 목록, 측정, 로그 수집 | 헤르메스 대장, 급하면 하이쿠 | 수집은 틀려도 부모가 다시 본다 |
| 웹 조사, 자료 수집 | 헤르메스 딥리서치 → 제미나이 검증 → 클로드 부모가 원문 표본으로 판정 | 기존 딥리서치 파이프라인 |
| 로컬 실행(빌드, 렌더, SSH), 반복 시험 | 헤르메스 | `hermes-delegate` 스킬(재시도 3회, 결과는 증거로) |
| **단순 반복 작업**(규칙이 정해져 있어 스크립트로 짜기엔 애매한 것: 형식이 제각각인 목록 정리, 정해진 기준의 1차 분류·태깅, 표 채우기, 긴 로그에서 해당 줄 뽑기). 원문은 따로 보존 | **로컬 모델**(숫자 세기보다 한 단계 높은 반복). 수집이 섞이면 헤르메스 대장 | 사장님 의견(2026-09-20): 로컬은 단순 반복이 맞다. **초안 전용.** 오늘 헤르메스 분류 초안이 절 단위로 거칠고 합계가 안 맞았으므로(STATE 0줄) 결과는 부모가 표본으로 확인한다. 로컬 모델의 반복 작업 품질은 **미측정** |
| **기준을 해석하는 판정**(채점, 통과·반려, 안전 분류) | 클로드 소넷 이상, 독립성이 필요하면 작성자와 다른 등급(오퍼스) | **무료 모델 판정 금지.** 헤르메스 채점자가 증거가 있는 답을 "근거 없음"으로 판정했고(S04, S06, S10) 같은 20문항이 12, 14, 11로 흔들렸다. 오퍼스 재채점은 19, 18, 20 |
| 코드 수정, 문서 초안, 행동 시험 실행 | 소넷 | 산출물 작업의 기본 등급 |
| 설계 검토, 개편 독립 검증 | 오퍼스 | 오늘 오퍼스가 시간 계산 오류, 안전 규칙 이탈, 훅 결함(worktree)을 잡았다. 소넷이 쓴 설계를 다른 모델이 검토하는 구조 |
| 되돌리기 어려운 실행, 조직 재편 종합 | 페이블 세션(부모) | 서브에이전트로는 쓰지 않는다 |
| 비공개 데이터를 외부 API로 보내면 안 되는 처리 | 로컬 모델 | 로스터에 "인터넷과 한도 무관"으로 명시. **비공개 처리 품질은 미측정** |
| **한국어 글 다듬기** | **소넷이 기본, 사장님의 핵심 글 마지막 손질만 오퍼스**(소넷 결과가 두 번 반려되면 올린다). **로컬·헤르메스는 다듬기용이 아니다** | 마야 보고(2026-09-20): 소넷은 초안 v2~v8과 사장님 문장 반영을 합니다체로, 지어낸 표현을 스스로 걸러 가며 했다(첫 초안은 보고서 톤 25/40). 로컬 exaone 32b는 초안 시험에서 해라체로 쓰고 재료에 없는 표현을 지어냈으며 분량이 절반이었다(다듬기는 시험하지 않아 같은 약점은 추정). 헤르메스는 열람 표기와 날짜 오류가 있었다. **소넷과 오퍼스의 직접 비교는 없다.** 다듬기는 서브에이전트를 부르지 말고 지금 대화 안에서 직접 한다(호출당 고정비가 크다: 마야 약 8만 토큰, 탐 실측 하이쿠 5.7만 토큰) |

## 4. 무료·로컬 엔진 사용 규칙 (제안)
1. **판정에 쓰지 않는다.** 수집·측정·실행·초안만. 통과·반려·안전 분류는 클로드 부모가 한다.
2. 결과는 부모가 **원문 표본**으로 확인한다(마야의 딥리서치 표본 대조와 같은 원칙).
3. 정제·요약본은 다음 단계로 넘기더라도 **원문은 별도 보존**한다(검증은 원문으로만).
4. 무료 한도(OpenRouter 계정 공유 하루 1,000회, 제미나이 키당 20회)를 의식한다. 오늘 채점처럼 20~25분 걸리는 일은 비동기로 걸고 기다리지 않는다.
5. 실패하면 로그로 원인을 진단하고 폴백 순서는 모델 로스터를 따른다. 로스터 교체는 사장님 결정이다.
6. 새 작업 유형을 무료·로컬 엔진에 맡기기 전에 **같은 시험 세트로 한 번 시험**한다(`모델_시험세트.md`). 통과한 유형만 위 표에 추가한다.

## 5. 뒤집을 신호
- 무료 엔진이 판정 유형에서 시험 세트를 통과하면(정답률과 일관성) 판정 일부를 내릴 수 있다.
- 헤르메스 대장의 하루 1,000회를 반복 소진하면 다른 무료 풀 또는 유료 모델을 검토한다.
- 로컬 모델이 특정 반복 유형(분류, 형식 정리)에서 대장과 같은 점수를 내면 그 유형은 로컬로 내린다. 한국어 글 다듬기는 로컬로 내리지 않는다(마야 보고).

## 6. 사장님이 정하실 것
1. 이 표를 **기본 체계 정본으로 확정**할지(확정되면 CLAUDE.md "모델과 서브에이전트" 절에 이 문서 링크 한 줄과 `hermes-delegate` 스킬 연결).
2. 4절 1번 "무료·로컬 엔진은 판정에 쓰지 않는다"를 규칙으로 못 박을지.
3. (선택, 마야 제안) 같은 문단을 소넷, 오퍼스, 로컬로 다듬어 사장님이 출처를 모르고 고르는 블라인드 시험을 한 번 해 볼지. 소넷과 오퍼스의 실제 차이와 로컬의 다듬기 품질을 한 번에 확인한다.

## 7. 제미나이 키 배정 (사장님 지시 2026-09-20, 키 값은 적지 않고 이름만)
| 호출자 | 키 순서 | 설정 방법 |
|---|---|---|
| 기본(마야, 헤르메스 등) | 검증 키(`GEMINI_VERIFY_KEY`) → 보조 키(`GOOGLE_API_KEY`) → 설정 파일 키 | 지정 없음(기존 순서 그대로) |
| **핏(대본 검증)** | **보조 키 우선** → 검증 키 | 호출 때 환경변수 `VERIFY_KEY_ORDER=GOOGLE_API_KEY,GEMINI_VERIFY_KEY` |
- 구현: `verify_claims.py`가 `VERIFY_KEY_ORDER`(쉼표로 키 이름 나열, `GEMINI_VERIFY_KEY`, `GOOGLE_API_KEY`, `CONFIG`)를 읽는다. 백업 `verify_claims.py.bak_0920_keyorder`. 실측: 보조 키만 지정해 2건 검증 정상.
- 한계: 무료 한도는 키당 하루 20회, 분당 5회이고 보조 키는 다른 호출자의 폴백이기도 해서 **완전 전용은 아니다.** 전용 키가 필요하면 사장님이 새 키를 발급하고 `.env`에 `GEMINI_PIT_KEY`를 추가한 뒤 순서에 넣으면 된다(미시행).
- 사용 규칙: 제미나이는 검증 전용(폴백 금지, 다이얼로그 제외), 결과는 클로드가 원문 표본으로 대조한다.
