# 슬랙 채널 실측 성공 기록 (2026-10-23, 탐-DM장애 #26~#32)

사장님 확정(2026-10-23 밤): 터미널 세션이 슬랙을 통해 에이전트끼리 메시지를 주고받는 것이 실측으로 성립했다. 성공으로 저장한다.

## 성립한 것
- 열려 있는 쉬는 터미널 세션이 슬랙 글을 0.24~0.57초에 받고 깨어난다(Claude Code Channels).
- 세션이 reply 도구로 슬랙에 글을 올린다(왕복 약 14초).
- 터미널 세션 둘(에이전트A, B)이 한 슬랙 방에서 사람 글과 서로의 글을 지명 규칙대로 주고받는다. 무한 핑퐁 없음.
- 사장님 계정(사용자 토큰)으로 올린 API 글은 Claude 앱을 깨우지 못한다(사람이 화면에서 쓴 @Claude 멘션만 클라우드 코딩 세션을 시작, 약 40초).

## 성립하지 않는 것·조건
- 닫힌 세션은 못 받고, 닫힌 동안의 글은 소급 전달되지 않는다.
- 세션마다 허용 화면 3종(폴더 신뢰, MCP 허용, 개발용 채널 경고) 사람 확인, --dangerously-load-development-channels 필요. 공식 슬랙 채널 플러그인은 없어 자체 서버를 쓴다.
- 앱 하나에 수신 접속을 둘 이상 두면 슬랙이 글을 나눠 보낸다. 수신기는 하나(slack_socket_receiver.py)만 두고 세션은 room.jsonl을 읽는다.
- 재시작한 세션이 reply 도구를 바로 못 찾을 수 있어 안내문에 도구 이름과 ToolSearch 방법을 넣었다.

## 부품
- `scripts/ops/slack_channel_server.py`: 채널 서버. AGENT_NAME 환경 변수가 있으면 room.jsonl에서 내 몫만 읽는다(사람 글은 맨 앞 @이름, 에이전트 글은 본문의 @이름·→이름).
- `scripts/ops/slack_socket_receiver.py`, `slack_room_tail.py`, `slack_post.py`: 수신기·꼬리 읽기·게시(PR 2666).
- `scripts/ops/slack_user_post.py`: 사장님 계정으로 올리되 말머리 `[발신→수신 #번호 | 목적]`을 강제하고 시험 채널로 고정.
- 시험 폴더 구성은 시험 로그 C:/work/_ops/slack_chan_lab/ (.mcp.json의 env로 AGENT_NAME 지정, settings.local.json의 enabledMcpjsonServers로 MCP 허용).
