# 지투 KPI: 고객수 (2026-10-12, 사장님 지정)

> 지투 KPI는 **UX MCP와 Carvit 전체 상품의 고객 획득과 리텐션을 높여 고객수를 확장하는 것**이다("고객수가 KPI에요", 사장님 2026-10-12). 슈퍼프로세스([슈퍼프로세스.md](슈퍼프로세스.md))의 KPI 관리 공통 공정([KPI_관리_공통공정.md](KPI_관리_공통공정.md))과 슈퍼얼라인([슈퍼얼라인.md](슈퍼얼라인.md))을 지투에 적용한 정본이다. 점검 설정은 `docs/align/지투.toml`.

## 구성 6가지 (KPI 관리 공통 공정)
1. **KPI 정의 한 줄**: 고객수 = 외부 고객 회사 수(점검 계정·내부 계정 제외). 획득(신규)과 리텐션(이탈)으로 나눠 적는다. 숫자 목표는 기준선을 본 뒤 사장님과 정한다(지어내지 않는다).
2. **수집**: 지금은 사람이 적는다(`python scripts/ops/jitu_po.py kpi add --customers N --new-customers N --lost-customers N ...`). 자동 수집은 운영 DB의 회사 표를 읽는 경로가 필요한 개선 과제다(검사 공백 원장, 노트에게 읽기 전용 요구를 취합해 요청). 기준선 K-2(2026-10-12): 외부 고객 1곳(지투시그마 5인), 셀프 가입 수 미확인.
3. **가설대장**: 지투의 `predict`가 가설대장이다. 변경마다 "무엇이 얼마나 바뀔지, 지표, 점검일"을 시작 전에 적고 점검일에 실제 값을 적는다. 선행 지표: 가입 24시간 내 첫 연결 비율, 활성 호출자, 인용, 찾지 못한 검색률, 피드백.
4. **판정 보류 규칙**: 외부 고객이 3곳 미만인 동안은 통계로 원인을 단정하지 않는다. 코호트 분석은 3곳 이상일 때 시작한다.
5. **도구 관문**: 결정 요청(`ask add`)과 예측(`predict add`)은 `--kpi`로 고객수와의 연결을 8자 이상 쓰지 않으면 기록되지 않는다. 무관한 일은 `--kpi '해당없음:이유 10자 이상'`으로 통과하되 기록이 남는다(`jitu_po.py kpi_gate`).
6. **주 1회 자동 루프**: 작업 스케줄러 `지투_주간KPI`(월 08:50)가 `scripts/ops/jitu_weekly_loop.py`를 돌려 `C:/work/_ops/jitu_po/주간_KPI.md`를 만든다(고객수 추이, 선행 지표, 열린 예측·결정·검사 공백, 슈퍼얼라인 점검). 에이전트는 제안·기록까지만 하고, 해석은 사장님·비티·덱스에게 묻는다. 감시 대장 id `file:jitu-weekly-kpi`.

## 퍼널과 공정 카드 (핏의 KPI 관리를 본뜸, 2026-10-12)
- 공정 카드(수파베이스): `지투-KPI`(KPI 관리 9단계: 정의, 퍼널 6단계, 병목 규칙, 자동 수집, 가설, 관문, 획득 행동, 오케스트레이션, 달성 모드)와 `지투-성과`(주간 루프 7단계). 보기: `python scripts/ops/proc.py steps 지투-KPI`.
- 퍼널: 방문 → 연결 시작 → 가입 → 첫 연결(가입 24시간 내) → 7일 안 재호출 → 확산. 병목 단계 하나만 고친다.
- 일일 수집: `scripts/ops/jitu_kpi_daily.py`(작업 스케줄러 `지투_일일KPI` 08:40)가 `C:/work/_ops/jitu_po/kpi_daily.jsonl`에 방문·문의·고객수를 쌓는다. 주간 루프가 이를 읽는다. 가입·첫 호출은 `customer_stats` 연결 뒤 채운다(공백 G-15).
- 한계: 방문은 Cloudflare Web Analytics의 EU 제외 값이고 탐이 주 1회 적는 `방문_주간.md`에서 읽는다(표본 16일치로 기준선으로는 작다). 고객수는 아직 손으로 적는다.

## 슈퍼얼라인 점검 5가지 (docs/align/지투.toml)
읽히는 곳(세션 카드·역할 노트·인수인계), 도구 관문(ask·predict), 자동 작업(스케줄러·감시 대장·결과 파일), 판정 장치(지표 기록의 고객수 칸), 문서 일관성(성장 루프 문서·이 문서). 실행: `python scripts/ops/align_check.py 지투`.

## 하지 않는 것
- 고객수 숫자 목표를 기준선 없이 정하지 않는다.
- 고객 1곳(5인)인 지금 North Star·코호트 분석을 하지 않는다. 신호는 외부 고객 3곳 이상이다.
- 고객 개인 이름과 사용 내용은 이 지표 기록에 넣지 않는다(회사 수와 별칭만).

## 한계
- 고객수는 아직 손으로 적는다. 자동 수집이 생기기 전까지는 주간 점검에서 "측정했는가"만 확인된다.
- 슈퍼얼라인은 "있는가"를 확인하지 "잘 쓰이는가"를 확인하지 않는다.
