# 옛 이름 소거 슈퍼프로젝트 (정본, 사장님 지시 2026-10-20·21)

일하는 방식: 슈퍼프로젝트(정본 [오케스트레이터_일하는_방식.md](오케스트레이터_일하는_방식.md)의 '슈퍼버닝과 슈퍼프로젝트' 절). 이름 처리 기준은 [이름_정책.md](이름_정책.md). 담당은 탐이고 노트는 사실 확인·시험 검토 지원이다. 진행 기록은 공정 카드 `탐-슈퍼글로벌` #61~#65와 탐 로컬 작업 폴더(`C:/work/_ops/` 아래 소거 폴더)에 있다.

## 목표와 범위
- 목표: 제품 이름은 Carvit(카빗)뿐이다. 옛 코드명이 저장소, 환경변수, 도구 이름, 훅, 클라우드 이름에 남아 에이전트가 새 조어(예: 옛 이름 DM)로 확장하는 일을 고객이 한 곳뿐인 지금 끝낸다.
- 범위: 공개 저장소, 제품 저장소(`simplifier-saegim`), 패스 저장소, 배포·실행 환경, 로컬 작업 폴더.
- 하지 않을 것: 비밀 재등록, 철자 개선, 새 이름과 옛 이름을 서로 다른 값으로 병행 운영, 날짜가 박힌 과거 기록의 문구 수정.

## 새 저장소 이름 규칙 (사장님 2026-10-21)
- 전사 제품 폴더(지금의 제품 저장소): `super-carvit`.
- 제품별 저장소: `carvit-<제품>`. 예: `carvit-pass`, `carvit-dm`, `carvit-create`, `carvit-mcp`.

## 단계와 상태
- 0 쓰기 시점 관문(옛 이름을 새로 늘리면 쓰기 전에 차단): 완료(훅 `old-name-gate`, 한글·허용 표시 처리까지).
- A 문서·주석·화면 문구 치환: 완료(공개 저장소, 패스 저장소, 제품 저장소). 남은 보류는 문자열 리터럴, 가이드 본문, 날짜 기록, SQL이고 B 이후에 다룬다.
- B1 관문 훅이 하이픈·carvit 서버 이름 인식: 완료.
- B2 프로젝트 MCP 서버 이름 변경: 보류. 공용 서버 이름에 에이전트 이름을 넣으면 모두가 한 신원으로 보이는 혼란이 생겨 되돌렸다. 에이전트별 신원 등록(노트 과제)이 끝난 뒤, 또는 호스팅 이전(D)과 함께 한다.
- B3 환경변수 별칭 병행: 설계(비티·덱스 리뷰 반영)와 P1(헬퍼, 제품 저장소 읽기 78곳) 병합·배포 검증 완료. P2(환경 이름 전환) 설계 완료, 스테이징 검증부터 시작한다. 제거 시한(제안 2026-11-30)은 사장님 확정 전.
- C 저장소 이름 변경: 사전 점검 완료, 새 이름 확정. 변경 전에 구글 클라우드 Workload Identity 허용 조건이 옛 저장소 이름에 묶였는지 확인하고 "옛 OR 새"로 먼저 넓힌다. 이 확인은 gcloud 로그인이 필요하다(사람 개입: 자격증명).
- D 구글 클라우드 프로젝트 ID·Cloud Run 서비스 이름: 이름 변경이 불가능하므로 호스팅 이전 시험(12/10 이후)과 함께 새 프로젝트로 옮긴다.
