# 제미나이 앱 이미지 생성(나노바나나) 가이드: 동료용 (2026-10-05, 지투)

제미나이 앱(웹)에서 "이미지 만들기"로 이미지를 만들어 파일로 받는 절차다. 비용 0, API 키 없이 로그인된 크롬 창만 쓴다. 지투가 Logos 후보 로고 시트를 만들며 실측했고, 바탕이 되는 상세 기록은 `docs/지투_프로세스표.md` 5절이다. 이 문서는 다른 담당(핏·마야·노트 등)이 따라 할 수 있게 요점과 함정만 모았다.

## 언제 쓰나
- 로고·아이콘·삽화 후보를 많이 뽑아 사람이 고를 때. 한 장에 여러 개를 받는 "시트" 방식이면 요청 횟수가 줄어든다.
- 쓰지 않는 것: 서비스(고객)용 대량 생성은 API 경로를 따로 검토한다(Logos는 N54). 사람 얼굴 톤은 Gem(젬)을 쓴다(핏 기록).

## 준비
- 계정: 크롬 디버그 포트가 열린 창에 로그인된 구글 계정. 어떤 계정이 어느 포트인지는 `shorts-lab/계정_현황표.md`가 정본이고, 번호는 바뀔 수 있으니 **시작할 때 화면의 「Google 계정」 이메일로 확인**한다. 로그인 화면이 뜨거나 이메일이 다르면 멈춘다. 로그인·계정 전환은 사람 몫이다.
- 허용 계정은 사장님 지정만 쓴다(2026-10-05 기준: 무료 보조 계정 둘과 사장님이 허용한 워크스페이스 둘, 이미지 생성은 거의 무제한). 계정 이메일은 공개 저장소에 적지 않는다.
- 실행 위치: 구PC 작업실 `~/workshop/logos_batch/`(SSH 별칭 `goosolar`, venv python). 공장 러너(`logs/factory.lock`)가 돌고 있으면 스크립트가 알아서 건너뛴다.

## 사람처럼 쓰기 (가장 중요, 사장님 10/5)
- 구글은 기계적 반복을 차단하고 사람 같은 속도는 막지 않는다. **횟수 상한은 두지 않지만** 아래를 지킨다.
- 시트와 시트 사이는 75~170초 무작위로 띄운다. 계정마다 시작 시각도 어긋나게 한다.
- 모든 조작은 사람이 하듯 클릭이다(생성 버튼, 다운로드 버튼). 프롬프트도 글자 사이 간격을 두고 친다(`keyboard.type` 지연). 한 번에 붙여넣기는 쓰지 않는다.
- 이미지 한도·정책 문구가 나오면 그 계정은 즉시 멈추고 재시도하지 않는다. 계정을 바꿔 두드리지 않는다(10/3 Flow 차단 교훈).

## 절차 (스크립트 `scripts/logos_gem_batch.py`, simplifier-saegim)
1. 프롬프트 파일 `prompts.json`: `[{"name":"R1_1","prompt":"...","ratio":"4:3"}]`. 영어로 쓰고, 한 이미지에 로고 6개(3열×2행)를 격자로 받는다. 흰 바탕, 검은 단색 형태, 글자·그림자·그라데이션 없음, 칸 사이 넓은 여백, 테두리·번호 없음.
2. 실행: `~/workshop/venv/bin/python logos_gem_batch.py prompts.json out/ --max 6 --accounts 포트=이메일,포트=이메일` (여러 계정이 같은 프롬프트를 각자 속도로 동시에. 가끔 이미지가 안 나오거나 이상해서 2~3계정이 안전하다). 백그라운드로 걸고 `batch_log.jsonl`·`run.log`로 본다.
3. 동선(스크립트가 하는 일): 새 채팅 → 「업로드 및 도구」 → 「이미지 만들기」(`menuitemcheckbox`) → 「가로세로 비율」 → 프롬프트 입력 → 「메시지 보내기」 → 「원본 크기 이미지 다운로드」로 저장. 한 시트 약 30~50초.
4. 자르기: `python scripts/logos_sheet_crop.py SHEET.png 3 2 접두사 cells`(로고마다 흰 바탕 1024×1024). 빈 칸·칸에 걸친 로고는 경고가 나오니 버린다.
5. 닮은 칸 걸러내기: `python scripts/logos_dedupe.py 칸폴더 --out dedupe.json`(IoU 0.85). 번호표에는 묶음 대표만 올린다.
6. 사람이 고른다: 번호표를 컨펌 방으로 보내고, 사장님 라벨(좋음 번호)을 풀에 넣는다.

## 함정 (실제로 겪은 것)
- 저장은 반드시 「원본 크기 이미지 다운로드」 버튼(PNG 고해상도). 이미지 우클릭 저장은 JPEG로 낮아진다.
- 같은 채팅을 이어 쓰면 화면이 쌓여 클릭이 깨진다. 매번 새 채팅.
- 입력창에서 엔터는 안 먹는다. 「메시지 보내기」를 클릭한다.
- 첫 클릭은 페이지가 준비되기 전엔 무시된다(약 2.5초 대기). 도구 메뉴는 첫 클릭이 안 먹을 수 있어 열렸는지 확인하며 연다.
- "닮은 변형 여러 개" 문구는 복사한 듯한 이미지를 낳는다(사장님 라벨 중단 사례). 그래서 닮은 칸 걸러내기가 필수다.
- 요소를 못 찾으면 추측하지 말고 역할별 이름을 덤프해 확인한다(`gem_diag.py`).
- Playwright가 아니라 화면 스크린샷+클릭으로 직접 하면 한 시트에 도구 호출이 약 25번 든다. 스크립트로 돌린다.

## 한계
- 계정별 정확한 생성 한도는 구글이 공개하지 않는다. 위 규칙은 우리가 안전하게 잡은 방식이고, 차단 문구가 나오면 그때 멈추는 것이 유일한 확인 수단이다.
- 이미지 품질(눈 점수)은 Krea2 로컬 생성보다 낮았다(평가기준 6절). 시트 방식은 속도·비용 장점이 있다.
