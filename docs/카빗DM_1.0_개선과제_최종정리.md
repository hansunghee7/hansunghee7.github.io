# 카빗DM 1.0 개선과제 최종 정리 (사장님 확정용 초안, 2026-10-24)

> 노트에게 보내기 전에 사장님이 이 한 장으로 확정한다(사장님 10/23 밤 지시: 노트는 주는 대로 빠르게 개발하므로 과제를 한 장으로 정리한 뒤 전달한다. 카빗DM 2차가 엉망으로 끝난 반성). 근거는 2026-10-23 밤 실측(공정 카드 탐-DM장애 #19~#44)이다.

## 한 줄 결론
수신·설치·업데이트를 "사용자나 에이전트가 기억해서 누르는 것"에 맡기면 어긋난다. 세션과 함께 자동으로 도는 부품과 안내문으로 옮긴다.

## 과제 목록 (우선순위 추천 순)
1. **구버전 MCP 업데이트 안내.** 사람이 필요했던 곳: 라이덕 사용자가 구버전을 써도 모르고 사장님이 노트에게 명령을 받아 붙이는 반복. 원인: 기술(자동 업데이트·구버전 감지 없음). 설계: 서버가 접속한 MCP 버전을 보고 오래되면 도구 결과의 notice로 한 줄 명령을 안내, 새 설치 문장은 항상 최신. 확인 필요: MCP가 버전을 알리는지, uvx가 매번 최신을 받는지. (노트-카빗MCP과제 #135)
2. **수신을 에이전트 재가동에 맡기지 않기.** 모니터는 호출당 최대 30분이고 에이전트가 다시 걸어야 해서 10/23 모든 에이전트가 같은 일을 반복하거나(소음) 다시 걸지 않고 쉬었다(무음 이탈). 설계: 세션과 함께 켜지는 채널 서버를 카빗 MCP의 기능으로 넣는다(터미널·앱 터미널 탭에서 0.24~0.57초 수신 실측). 앱 대화창은 채널을 못 붙인다(모니터만 가능, 30분 한계).
3. **설치 문장은 한 행동씩.** 실측: 일반 모드는 행동 하나당 허용 화면 1번, 자동 모드는 한 문장·한 프로그램에 0번. 설계: 설치 문장이 묶는 행동 수를 세어 줄이고 안내에 "허용 화면에서 항상 허용"을 넣는다. (현재 설치 문장의 행동 수는 아직 안 셈)
4. **에이전트 간 대화 규칙.** 사람 글은 맨 앞 @이름만 지명으로 보고, 에이전트 글은 [보낸이] @받는이로 지명한다. 재시작 세션이 reply 도구를 못 찾으니 안내문에 도구 이름과 ToolSearch 방법을 넣는다. (실측으로 결함 2건 수정 확인)
5. **닫힌 세션 소급 없음.** 슬랙은 연결 없는 앱에 지난 글을 다시 안 준다. 우편함처럼 쓰려면 접속 때 채널 기록을 읽어 따라잡는 기능이 필요하다(제안, 미구현).
6. **CarvitGuard 훅 파일 누락.** 이 PC에서 세션 종료 때마다 secret_in_reply.py 없음 오류. 막지는 않으나 점검 필요.

## 알려진 한계 (고객에게 말할 것)
- 슬랙에서 @Claude를 멘션하면 약 40초에 저장소를 읽는 클라우드 세션이 뜬다(설치 없음). 사람이 화면에서 쓴 멘션만 해당하고, 고객 요금제가 조건(Claude Tag·Projects in Claude Code)에 걸릴 수 있다.
- 채널 방식은 세션이 열려 있어야 하고 허용 화면 3종과 개발용 옵션이 필요하다.
