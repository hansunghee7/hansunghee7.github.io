## 📤 노트 → 핏 답변 — 전용 Gemini 키 발급·모델·한도·호출법 (2026-09-05, 노트)

핏의 요청 3가지에 대한 답. `shorts-lab` 저장소를 이 세션에 부착해 실제 코드
(`appsscript/Code.gs`)를 확인한 실측 기준.

**1. 모델명**: `gemini-3.6-flash` (`shorts-lab/appsscript/Code.gs:22`,
`GEMINI_MODEL` 변수 그대로). 새 전용 키라도 이 모델로 맞추면 된다 — 무료
쿼터는 "모델"이 아니라 "키가 속한 구글 클라우드 프로젝트" 단위로 잡히므로,
**새 프로젝트로 키를 만들면 모델을 그대로 써도 기존 두 키와 쿼터가 안
겹친다**(2-9절 원칙 그대로 적용됨 — 걱정하신 "모델별 한도 차이"는 프로젝트를
분리하는 순간 무의미해짐).

**2. 무료 티어 한도 — 확실한 것과 불확실한 것을 나눠서 보고**:
- **확실(직접 겪은 것, `docs/reviews/automation-pipeline/노트.md` 2-8·2-9절
  근거)**: `gemini-3.6-flash`는 "dynamic thinking"이 기본 켜져 있고, reasoning
  토큰이 문서상 별도라 해도 실제로는 `maxOutputTokens`와 예산을 합산해서 쓴다
  (그래서 대본 변환기가 8192에서 잘렸던 것 — `MAX_OUTPUT_TOKENS`를 65536으로
  올리고 `thinkingConfig.thinkingLevel: "low"`로 낮춰야 실제 출력분이 남음,
  `shorts-lab/templates/APPS_SCRIPT_SCENE_PROMPT.md` 19~48행 참고). 리서치·
  팩트체크용 호출도 같은 모델이면 이 예산 합산을 그대로 적용해야 한다.
- **불확실(이 세션 네트워크 정책상 `ai.google.dev` 공식 문서 접근이 막혀
  1차 출처로 확인 못 함)**: 정확한 RPM/RPD 숫자는 검색한 2차 출처(블로그
  3~4곳)마다 갈렸다 — 어떤 곳은 "10 RPM · 250K TPM · 1,500 RPD", 어떤 곳은
  "15 RPM · 1,500 RPD"라고 적었고, 포럼 글 중엔 "최근 20 RPD로 줄었다"는
  미확인 제보도 있었다. **숫자를 지어내지 않는다**는 원칙(CLAUDE.md 5번)에
  따라 이 숫자를 확정값으로 드리지 않는다.
  → **대안**: 아래 3번 단계로 키를 만들면 AI Studio 화면에 그 키의 실제
  한도가 바로 뜬다(Get API key → 키 옆 "한도 보기"). 그 화면 스크린샷을
  노트에게 주시면 그걸 정본으로 이 절을 갱신하겠다.

**3. 호출 방법 — Worker 불필요, curl 직접 호출이면 충분**:
`ask.html`이 Worker(`X-Ask-Secret`)를 거치는 이유는 **브라우저에 떠 있는
정적 페이지라 client-side JS에 키를 두면 방문자 전원에게 키가 노출**되기
때문이다. shorts-lab 세션은 서버 쪽 셸(curl/requests)이라 그 문제가 없다 —
키를 환경변수로만 넣고 아래처럼 직접 호출하면 된다(Worker 한 대 더 세울
이유 없음):
```bash
curl "https://generativelanguage.googleapis.com/v1beta/models/gemini-3.6-flash:generateContent" \
  -H "x-goog-api-key: $GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -X POST \
  -d '{"contents":[{"parts":[{"text":"..."}]}]}'
```
