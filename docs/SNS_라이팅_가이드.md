# SNS 라이팅 가이드 (마야, CMO)

> 왜 있나: `docs/재유통_전략.md`의 캡션 원칙은 "원문을 그대로 인용"이라 새로 쓰지
> 않는다. 하지만 숏폼 성과 공유, 실시간 소감, 링크드인 개인 포스트처럼 **원문이
> 없어서 새로 써야 하는 SNS 글**은 아직 아무 기준이 없었다. 이 문서가 그 기준이다.
> **무엇을 말할지**는 `docs/브랜딩_가이드.md`(서비스)·`docs/퍼스널_브랜딩_가이드.md`
> (개인), **어떤 문장으로**(장문 규칙)는 탐의 `docs/WRITING_GUIDE.md` 몫 — 이 문서는
> 그 둘을 **SNS라는 짧은 형식**에 맞게 압축하는 법만 다룬다.
> `docs/WRITING_GUIDE.md`를 SNS용으로 바꾸는 대신 이름을 새로 만든 이유: 그 이름은
> 탐의 질문하기 파이프라인(장문 블로그 초안 생성)에 이미 못박혀 있어서, 재사용하면
> 그 파이프라인이 가동될 때 다시 충돌한다(2026-09-03 결정).
>
> **2026-09-03 갱신**: 587편 전체를 조사해 화법 요소의 우선순위를 확정했다(3절).
> 자세한 근거는 `docs/퍼스널_브랜딩_가이드.md`를 본다 — 이 문서는 그 압축판이다.
>
> **운영 원칙**: 이 문서와 `docs/퍼스널_브랜딩_가이드.md`는 살아있는 문서다. 실제로
> 글을 써보다가(연습이든 실전이든) 새로운 판단 기준이 발견되면, 그 세션이 끝나기
> 전에 바로 이 문서에 반영한다 — 미루면 다음 세션이 같은 시행착오를 반복한다.

## 0. 쓰기 전에 먼저 정할 것 — 참여용인가 유입용인가

> 2026-09-03 발견: SNS 글 하나로 "참여"(공감·팔로우·브랜드 톤 유지)와 "유입"(홈페이지
> 방문, 회사 KPI)을 동시에 노리면 둘 다 놓친다. 실제로 샘플 글(면접 주제)을 다 쓰고
> 나서야 "이걸로 홈페이지 유입도 노려야 한다"는 요청이 들어와, 이 둘이 다른 장르라는
> 게 뒤늦게 드러났다 — 다시 이런 순서로 헛수고하지 않게 이 절을 맨 앞에 둔다.

| | 참여용 | 유입용 |
|---|---|---|
| 목적 | 공감·팔로우·브랜드 톤 유지 | 홈페이지 방문(회사 KPI) |
| 링크 | 없음(4절 "지금 하지 말 것" 그대로) | 필수 — 관련 블로그 글에 UTM(`docs/UTM_규칙.md`) |
| 전제 | 재유통할 옛 글이 있거나, 지금 겪은 일이면 바로 쓴다 | **그 내용의 블로그 글이 먼저 있어야 한다** — 없으면 SNS 글보다 블로그 발행이 먼저다 |
| SEO/GEO/AEO | 기여 없음(SNS 포스트는 크롤링 대상이 아님) | 블로그 글 쪽에서만 작동 — 발행 전 검색 콘솔로 그 주제의 검색 수요부터 확인 |
| 제목 | 클릭 유도 우선(3절 참고) | 검색 수요 있는 키워드 우선 — SNS용 제목과 다를 수 있다(`재유통_전략.md` 캘린더의 검색 콘솔 판단과 같은 방식) |

**참고**: 2026-09-03 확인 기준 사이트 전체 검색 유입이 90일간 쿼리 29개, 최고 클릭
1회(브랜드명 검색)로 아직 거의 없다(`assets/data/search-console.json`). 특정 주제가
SEO에 유리한지를 매번 재기보다, 유입용으로 쓸 때마다 그 시점 검색 콘솔로 실측할 것 —
사이트 전체 검색 유입 규모를 키우는 건 이 문서 범위 밖의 별도 과제다.

**GEO/AEO(생성형 검색·답변엔진 노출)는 아직 이 저장소 어디에도 규칙이 없다** — AI
검색엔진이 인용하려면 실제 발행된 페이지의 구조화(스키마·JSON-LD 등)가 필요한데,
그 규칙을 아직 안 만들었다. 유입용 블로그 글을 실제로 발행하기 시작하면 그때
탐·시안과 함께 정할 것(지금은 필요성만 기록, 만들지 않는다 — 4절 참고).

## 1. 신규 글이 필요한 경우 (재유통과 구분)

- 숏폼·콘텐츠 성과를 공유할 때("이번 편이 예상보다 반응이 좋았다" 류)
- 시의성 있는 짧은 소감(행사·뉴스에 대한 반응)
- 재유통할 만한 옛 글이 없는 새 주제

**원문이 있으면 항상 재유통이 먼저다** — 새로 쓰는 건 원문이 없을 때만. 매번 새로
쓰면 S1 규모에서 지속 못 한다(브랜딩_가이드.md와 같은 원칙).

## 2. 채널별 형식 차이 (`docs/재유통_전략.md`의 채널 성격 재사용)

| 채널 | 길이 | 톤 |
|---|---|---|
| 링크드인 | 3~5문단 가능 | 전문직 네트워크 — 프레임워크·경험담, 퍼스널 브랜딩 가이드 3절의 "왜→무엇→어떻게" 구조를 짧게 압축 |
| 페이스북 | 2~3문단 | 더 개인적·일상적 — 퍼스널 브랜딩 가이드의 "자기 노출" 쪽 비중을 높인다 |
| 스레드 | 1~3문장 | 캐주얼, 훅 한 줄이 전부일 때가 많다. 구조를 다 못 넣으니 "반성 한 줄"만 살린다 |

## 3. 새 글 구조 (짧은 버전의 "왜→무엇→어떻게→반성")

> 2026-09-03: 587편 전체 조사(`퍼스널_브랜딩_가이드.md` 3절)로 화법 요소의 우선순위를
> 확정했다. SNS 짧은 글엔 다 못 넣으니, 아래 넷만 지키면 이 사람 목소리로 읽힌다 —
> 나머지(번호 매기기 세부, 비유 전체 목록 등)는 장문용이라 SNS에선 생략해도 된다.

**SNS 글에 반드시 남길 4가지**(우선순위 순):

1. **전환어 하나** — "그런데"·"의외로"·"다행히" 중 하나로 훅과 본문을 잇는다. 없으면
   그냥 정보 나열로 읽힌다.
2. **질문형 마무리** — "여러분은 어떠신가요?" 류. 587편 전체에서 가장 일관된
   패턴이라 이걸 빼면 목소리가 가장 많이 흐려진다.
3. **ps. 한 줄** — 장문의 ps1·ps2 구조를 한 줄로 압축한 반성·근황.
4. **번호는 최대 2~3개까지만** — 장문에서는 5개도 흔하지만, SNS에서 5개는 스크롤이
   너무 길어진다. 압축이 안 되면 차라리 번호를 빼고 문단으로 푼다.

```
[훅 — 전환어(그런데/의외로/다행히) 또는 구체적 숫자로 한 줄]

[무엇이 있었는지 — 사실만, 2~3문장. 번호는 넣더라도 2~3개까지]

[ps. 반성/인사이트 한 줄]

[질문형 마무리 한 줄]

(링크가 있으면 마지막에, UTM 포함 — docs/UTM_규칙.md)
```

예시(숏폼 성과 공유, 링크드인):

```
편당 조회수가 이번에 처음 다섯 자리를 넘었습니다.

그런데 특별한 걸 한 게 아니라, 시청자가 댓글로 물어본 걸 그대로 다음 편으로
만들었을 뿐입니다.

ps. 콘텐츠는 만드는 게 아니라 이미 와 있는 질문을 받아 적는 일에 가깝다는
생각이 듭니다.

여러분은 어떠세요, 이미 와 있는데 못 보고 지나친 질문이 있을까요?
```

## 4. 지금 하지 말 것

- **매번 새로운 톤 실험** — 퍼스널 브랜딩 가이드의 캐릭터(가르치는 사람, 실패를 먼저
  꺼내는 사람) 밖으로 나가지 않는다.
- **해시태그 남발** — 지금 채널 성격(전문직 네트워크 위주)에서 해시태그는 도달을
  거의 안 늘리고 글만 지저분해진다.
- **모든 신규 글에 링크 붙이기** — 링크가 필요 없는 소감 글까지 UTM 링크를 억지로
  넣지 않는다. 재유통 전략의 "글이 있을 때만"과 같은 원칙(0절 "참여용" 경로).
- **참여용 글 하나로 유입까지 노리기** — 0절 참고. 링크 없이 쓴 글에 뒤늦게 "이걸로
  유입도" 요청이 오면 다시 쓰는 게 아니라, 그 내용을 블로그로 먼저 발행하고 SNS는
  홍보 글로 별도로 짠다.
- **GEO/AEO 구조화 규칙을 지금 만들기** — 필요성은 0절에 기록했지만, 유입용 블로그
  발행이 실제로 시작되기 전엔 만들지 않는다. 만들 대상(발행된 페이지)이 아직 없다.
