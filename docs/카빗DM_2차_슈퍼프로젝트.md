# 카빗DM 2차 슈퍼프로젝트: 전체 에이전트 소통 전환 (정본, 사장님 지시 2026-10-22, 담당 노트)

일하는 방식: 슈퍼프로젝트(정본 [오케스트레이터_일하는_방식.md](오케스트레이터_일하는_방식.md)의 '슈퍼버닝과 슈퍼프로젝트' 절). 설계는 덱스·비티 리뷰를 거치고(공정 카드 공용-오케스트레이션 #15), 구현은 단계마다 병합 전 리뷰·병합 후 실측을 한다. 1차의 정본은 [카빗MCP_합본스펙_초안.md](카빗MCP_합본스펙_초안.md)와 [카빗MCP_개선계획_초안.md](카빗MCP_개선계획_초안.md)다.

## 1차가 한 것과 2차가 하는 것

1차(2026-10-20~22, 끝남)는 **카빗DM이 돌아가게 만드는 장치**였다: 에이전트별 신원(서버 이름 `회사영문_에이전트영문`), 지원 에이전트(`카빗_도우미`, 영문 `Carvit_Help`), 설치 문장, 수신 알림(R-229·R-230), 출근 판정(R10), 에이전트 추가 화면. 라이브에서 한 번씩 확인됐다.

2차는 **우리 에이전트 전부가 실제로 카빗DM으로만 소통하게 바꾸는 일**이다. 1차는 노트 한 곳만 끝까지 돌아가고, 나머지는 계정이나 연결이나 자동 받기 중 하나가 빠져 있다. "장치가 있다"와 "다 쓰고 있다"는 다르다.

## 목표 (측정 가능, 수치는 사장님이 확정하기 전까지 제안값, 확정은 P1 끝에 한다)

측정 정의(덱스 리뷰 10/22 반영): **도착** = `dm_sent`의 보낸 시각, **읽음** = 같은 DM의 `read_at`(받는 에이전트가 `dm_read`로 읽은 시각), **지연** = 읽음 − 도착. 측정은 노트가 하루 1회 스크립트로 읽고(`dm_sent` 기록), 기간은 7일 연속, 표본은 그 기간의 모든 DM이다(왕복 10회 시험은 연결 직후 점검용이고 목표 판정에는 쓰지 않는다). 기록은 `C:/work/_ops/note/dm2_metrics/`에 날짜별 한 장으로 남긴다.

대상 에이전트 6명: 노트, 지투, 탐, 마야, 핏, 카빗_도우미(지원). 북·UT 북은 시험 계정이라 제외한다.

1. **연결 6/6**: 6명 모두 자기 계정으로 연결돼 `agents`의 me가 자기 이름이다. 폴더는 저장소 공용 폴더(모든 세션이 같은 폴더를 씀) 또는 전용 폴더이고, 서버 이름은 `carvit_<영문 이름>`(R13 후보 D)으로 대조한다(기대 이름표를 P1에서 만든다). 지금 연결 3/6(노트·지투·카빗_도우미), 자동 받기 1/6(노트), 계정이 이미 있는 에이전트 지투·탐·카빗_도우미, 계정이 없는 에이전트 마야·핏.
2. **핵심 목표(사장님 확정 2026-10-22)**: 6명이 서로 노트와 DM을 1분 안에 주고받는다. 노트 → 상대 DM이 상대에게 **1분 안에 읽히고**, 상대 → 노트 DM이 노트에게 **1분 안에 읽힌다**(양방향 각각 1분). 판정은 연결 직후 왕복 10회 점검에서 전부 통과이고, 이후 7일 관찰에서도 중앙값 1분 이내·24시간 넘게 안 읽힌 DM 0건이다. 상대 5명은 지투, 탐, 마야, 핏, 카빗_도우미(노트 자신이 여섯째). 자동 받기가 켜져 있는 세션만 대상이고, 앱 세션 에이전트가 있으면 별도 기준을 정한다. 지금은 자동 받기가 노트 한 곳뿐이다.
3. **우편·세션메시지 졸업**: 관문 변경(P6) **뒤** 7일 연속, 에이전트 간 연락 중 우편·세션메시지 사용 0건. 장애 예외는 카빗DM 장애를 노트가 확인해 공정 카드에 적은 날만 인정하고, 측정은 우편함 파일 목록과 세션메시지 훅 기록 두 곳을 합쳐서 센다(두 곳 밖의 경로가 있으면 P1에서 찾아 목록에 더한다).
4. **신원 안전**: 한 폴더에서 여러 에이전트를 쓰는 경우를 포함해 "이름이 섞임" 사고 0건. 시작 훅(P3 앞에서 먼저 켠다)이 연결 확인 이름과 세션 카드 이름을 비교해 다르면 멈춘다. 훅이 켜지기 전에는 어떤 에이전트도 전환하지 않는다.
5. **Help 응답**: 안정화 7일 동안 시험 가입 3회 이상(하루 한두 번, 한국어·영어 섞어서)의 인사 DM에서 답장 전달까지 중앙값 5분 이내. 시험 가입은 내부 시험이고, 외부 사용자의 온보딩 시작 신호와는 별개다(외부가 시작되면 지표를 외부 기준으로 바꾼다).

## 범위
- 대상: 에이전트 6명의 카빗 계정·폴더 연결·자동 받기, 수신 지연 측정, 신원 안전(시작 훅), 우편·세션메시지 규칙 전환, 카빗_도우미 운영 시작.
- 연결할 수 있는 도구: 이미 만든 설치 문장, 도우미(carvit-autoreceive 0.1.3), 에이전트 추가 화면. 새 서버 기능은 측정에서 필요가 확인될 때만 더한다.

## 하지 않을 것
- 카빗_도우미 자동 응답 에이전트(사람 없이 24시간 답하는 것): 첫 외부 사용자의 온보딩이 시작될 때까지 만들지 않는다.
- 앱 세션(채널 불가)에 자동 받기 붙이기 시도. 앱은 세션이 열려 있을 때만 받는 것으로 둔다.
- 옛 이름 서버 일괄 삭제: 이름 정리 프로젝트의 몫이다. 이 프로젝트는 폴더별로 안 붙게만 한다.
- 외부 고객(지투시그마 등)에게 새 기능 공개, 새 유료 서비스 결제.
- 측정 없이 "됐다"고 보고하는 것(각 단계 끝에 수치 또는 로그 증거를 붙인다).

## 단계 관문 (모든 구현 단계 공통)

## 롤백
- 에이전트별 연결: 새 서버 등록을 `claude mcp remove <서버 이름> --scope local`로 지우면 이전 경로(기존 연결, 우편)가 그대로 있다. 지운 뒤 같은 에이전트에게 우편 한 통으로 되돌렸음을 알리고, 그 사이 카빗DM에 쌓인 안 읽은 DM은 `dm_read`로 읽어 우편으로 다시 전달한다. 되돌림 검증: 그 에이전트에게 우편 한 통이 읽히고, 이름 섞임 기록이 없다.
- 관문(P6) 되돌리기: 변경 전 훅·설정을 `C:/work/_ops/note/gate_backup_<날짜>/`에 복사해 두고 시작한다. 카빗DM 장애가 확인되면(노트가 공정 카드에 적음) 백업을 복원해 우편·세션메시지를 다시 연다. 복원 뒤 7일 카운트를 0으로 되돌린다.
- 서버: 저장소 변수·설정 변경은 이전 값을 공정 카드에 적고 시작한다(1차에서 지원 에이전트 교체가 그렇게 했다).
- 중단 조건: 같은 날 이름 섞임 1건 또는 24시간 미읽음이 3건 이상 생기면 그 에이전트 전환을 멈추고 원인을 먼저 본다.

1. 마야·핏 계정 추가: 대시보드 Agents 탭에서 이름을 적고 추가(계정 생성이라 에이전트가 못 함). 2회.
2. 에이전트별 설치 문장 붙여넣기: 그 에이전트의 폴더 세션에 1회씩, 지투·탐·마야·핏 4회. 카빗_도우미는 이미 끝남. 위의 "노트가 대신할 수 있는 범위"가 실측으로 확인되면 폰 승인 1회로 바뀐다.
3. 졸업 확인(P7): 지표 한 장을 보고 우편·세션메시지 졸업을 승인.
노트가 대신할 수 있는 범위(사장님 질문 2026-10-22 "승인하면 노트가 직접 등록 가능한가"):
- **계정(에이전트) 추가는 할 수 없다.** 계정 생성은 사용자가 시켜도 에이전트 금지 규칙이고(공정 카드 노트#126·#140), 설치 코드가 서버 비밀로 계산되는 값이라 DB 행만 넣어서는 연결이 되지 않는다.
- **이미 계정이 있는 에이전트(지투·탐·카빗_도우미)의 연결은 노트가 할 수 있을 수 있다** [추정, P3 첫 실측으로 확인]: 설치 코드를 카빗 패스 발급 레시피(탐-패스개선 #31, 폰 승인 1회)로 받아 공용 폴더에 `claude mcp add --scope local`로 에이전트별 서버 이름을 등록한다. 그러면 사장님의 붙여넣기 4회가 폰 승인 1회로 줄어든다.
- 마야·핏은 계정이 없어 계정 추가 2회가 먼저 필요하다.
개선 과제로 연결: 계정 추가까지 사람 1회로 줄이는 폰 승인형 에이전트 추가(공정 카드 노트#127, 설계 초안 PR 786)를 이 프로젝트의 선택 과제로 둔다. 구현 여부는 아래 결정 3에서 정한다.

## 위험과 신호
- 위험: 자동 받기 프로세스가 죽거나 두 번 떠서 DM이 안 오거나 중복 알림이 온다. 대응: 폴더마다 한 개만 뜨게 하고(로그에 시작 시각 기록), 읽음 지연 지표가 이상하면 먼저 프로세스 수를 센다. 죽었을 때 다시 켜는 감시는 P3에서 필요한지 실측하고 넣는다.
- 위험: 설치 문장·코드가 대화에 남는다. 대응: 내부 에이전트와 사장님 화면에만 노출되는 것이라 교체 예외(2026-09-20 결정)지만, 외부 공유·공개 저장소 커밋은 하지 않는다.
