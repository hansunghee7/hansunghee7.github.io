# 토큰 저잔량 모드 (2026-09-19 초안)

Claude 사용량 한도가 빠듯할 때 "탐은 판정만, 실행은 헤르메스와 서브에이전트"로 일하는 방식을 정한다. 이 문서는 짧게 유지하고, 상세 근거는 링크로 본다. 모델 선택 원칙은 `CLAUDE.md` 모델 고르기 절(id 5e1a)을 따른다.

## 1. 잔량을 숫자로 확인하는 법 (2026-09-19 실측)
- `get_usage`(도구, `session_id` 생략)를 호출한다. 두 가지가 나온다.
  - `plan`: 계정의 **5시간 한도**와 **주간 한도**의 사용 비율(`percentUsed`)과 초기화 시각(`resetsAt`). 모델별 주간 한도(예: Fable)도 따로 나온다.
  - `context`: 이 세션의 컨텍스트 창 사용 비율(`percentUsed`), 자동 압축 시작 지점(`autoCompactsAtPercent`), 큰 항목별 토큰.
- 참고: `get_session`은 메타데이터만 주고 사용량은 주지 않는다(예전 문서의 `context_usage` 서술은 틀렸다).

## 2. 모드 전환 기준 (초안, 사장님 조정 가능)
| 상태 | 기준 | 하는 일 |
|---|---|---|
| 보통 | 5시간과 주간 한도 모두 70% 미만 | 평소대로. 세션 컨텍스트가 70%를 넘으면 마감 절차로(저녁 의식) |
| 주의 | 5시간 또는 주간이 70% 이상 | 조사·표 만들기·초안은 전부 서브에이전트(하이쿠, 소넷)와 헤르메스로. 탐은 판정과 지시서만 |
| 저잔량 | 5시간 또는 주간이 90% 이상 | **탐은 도구 호출을 최소화**한다. 실행과 조사는 헤르메스가 전부 하고, 탐은 결과 판정 1회와 사장님 보고만 한다. 새 큰 작업은 시작하지 않고 초기화 시각(`resetsAt`)을 사장님께 알린다 |

- 오퍼스와 페이블(고가 모델)은 주의 단계부터 사장님 컨펌 없이 쓰지 않는다(이미 있는 원칙 강화).
- 사장님이 모드를 직접 지정하면("저잔량 모드로") 위 표보다 그 지시가 먼저다.

## 3. 저잔량 모드에서 하지 않는 것
- 긴 파일 통째 읽기, 새 세션 여러 개 띄우기, 오퍼스 서브에이전트 사용.
- 사장님께 복사·붙여넣기 요청(원칙 그대로. 헤르메스가 파일로 넘긴다).

## 4. 측정과 개선 (다음 단계 신호)
- 사용량 조사는 `get_usage` 호출 1회로 끝나므로 세션 시작 때와 큰 작업 사이에만 확인한다.
- 이 기준이 실제로 일을 멈추지 않게 했는지 2주 뒤 사장님이 체감으로 판단한다. 체감이 나쁘면 기준(70%, 90%)을 조정하고, 필요하면 야간 큐(백로그 6번)를 앞당긴다.

## 5. 실측 메모
- 2026-09-19 밤 탐 세션: 컨텍스트 창 39% 사용(약 39만 토큰 / 100만), 5시간 한도 24%, 주간 4%. Messages가 33%로 가장 크고 시스템 도구, MCP 도구, 메모리 파일, 스킬을 합친 값은 약 7%.
- 긴 세션이라도 한도가 여유로우면 서브에이전트 사용이 성능을 높인다. 이 표는 "빠듯할 때의 방어선"이다.
