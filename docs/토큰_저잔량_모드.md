# 토큰 저잔량 모드 (백로그 7번)

> 목적: 사장님 토큰 제한으로 일이 멈추는 것을 막는다. 잔량이 낮을 때 탐은 판정만 하고 실행은 싸고 무료인 쪽(헤르메스, 로컬 모델, 하이쿠 서브에이전트)에 맡긴다. 2026-09-21 작성, 기준선은 **제안**이라 실측으로 조정한다.

## 1. 잔량을 어떻게 보나

세션 시작(하이~)과 **큰 작업을 시작하기 전**에 `get_usage`(MCP `ccd_session_mgmt`)를 한 번 부른다. 볼 값은 셋이다.
- `plan.windows`의 **5-hour limit** `percentUsed`와 `resetsIn`
- `plan.windows`의 **Weekly · all models** `percentUsed`와 `resetsIn`
- `context.percentUsed`(이 세션의 컨텍스트 창)

## 2. 기준선 (제안)

| 상태 | 조건 | 탐이 하는 것 |
|---|---|---|
| 평소 | 5시간 80% 미만이고 주간 85% 미만 | 지금처럼. 다만 조사·탐색은 서브에이전트에 위임하고 요약만 받는다 |
| **저잔량 모드** | 5시간 80% 이상 **또는** 주간 85% 이상 | 아래 3절 |
| 컨텍스트 경고 | 세션 컨텍스트 70% 이상 | **그 자리에서 저녁 의식**(기존 규칙, CLAUDE.md §d78e). 새 작업을 시작하지 않는다 |

오늘(2026-09-21) 측정 예: Max 플랜, 5시간 5%, 주간 39%, 이 세션 컨텍스트 59%(하루 종일 열려 있던 세션이라 비쌌다).

## 3. 저잔량 모드에서의 행동

1. **판정과 설계만** 한다. 파일 수집, 측정, 로그 조사, 초안, 반복 실행은 헤르메스(`hermes-delegate`), 로컬 모델(`docs/작업_엔진_라우팅.md`), 하이쿠 서브에이전트에 맡긴다.
2. 새 큰 작업(여러 파일 읽기, 새 설계)은 **시작하지 않는다.** 진행 중인 것을 끝내거나 인수인계 블록으로 넘긴다.
3. 큰 파일은 필요한 범위만 읽는다. 스크린샷이 많이 들어가는 화면 조작은 서브에이전트에 맡긴다.
4. 사장님께는 **한 줄로 알린다**: 저잔량 모드 진입, 이유(어느 창이 몇 %), 풀리는 시각(`resetsIn`), 그동안 무엇을 헤르메스에 맡겼는지. 결정 요청이 아니면 폰 알림은 보내지 않는다.
5. 모델을 올리는 결정(오퍼스·페이블)은 하지 않는다(CLAUDE.md §5e1a, 사장님 컨펌 필요).

## 4. 풀리는 조건

`resetsIn`이 지나 창이 초기화되면 평소로 돌아간다. 헤르메스에 맡긴 결과는 그때 원문 표본으로 검수한다(판정은 부모).

## 5. 아직 모르는 것

- 80%·85% 기준이 사장님 일정에 맞는지는 실측 전이다. 저잔량 모드로 들어간 횟수와 그때 멈춘 일 수를 2주 기록해서 조정한다.
- `get_usage`가 API 키·게이트웨이 환경에서는 "해당 없음"을 돌려준다. 그런 세션은 컨텍스트 값만 쓴다.
