# AI 라우팅 정책 (2026-09-21, 탐, 사장님 지시로 작성)

> 업무를 Claude / 서브에이전트 / 헤르메스 / 4090 로컬 LLM / 스크립트 / 제미나이 중 어디로 보낼지 정하는 **전 에이전트 공통** 기준이다. 고정된 순서가 아니라 **작업별 선택 + 막히면 상위로 승격**하는 정책이다. 기존 [작업 엔진 라우팅](작업_엔진_라우팅.md)(초안)을 이 문서가 대체한다. 이미 확정된 규칙은 그대로 유지한다: 무료·로컬 엔진은 판정에 쓰지 않는다, 오퍼스·페이블은 사장님 컨펌 뒤에만, 한국어 글 다듬기는 소넷.

표기: **[공식]** 제조사 문서로 지원됨 / **[커스텀]** 우리가 만들어 운영 중 / **[미검증]** 이 환경에서 아직 시험 안 됨.

## 2. 라우팅 표 (기본 경로 → 막히면 승격)
| 작업 | 기본 | 막히면 |
|---|---|---|
| 줄·글자 수, 문구·링크·상태 검사, 파일 이동·변환, 감시, 알림 | **스크립트/훅** | 스크립트 실패 → 원인 진단(소넷) |
| 큰 로그·목록·문서의 1차 요약·분류, 형식 정리(정해진 기준, 저위험, 비공개 데이터) | **4090 로컬**(작은 모델부터) | 실패·품질 미달 → 헤르메스 → 하이쿠 서브에이전트 |
| 웹 검색·자료 수집(출처 원문 필요) | **`collector`(하이쿠)** 또는 헤르메스 웹 조사 + **코드 대조** | 인용 불일치·근거 부족 → 소넷 서브에이전트 → 제미나이 딥리서치 |
| 여러 출처 종합이 필요한 장시간 조사 | **헤르메스 → 제미나이 딥리서치**(검증 뒤에만, 지금은 Claude 브라우저 서브에이전트가 대신) | 헤르메스 미검증인 동안은 서브에이전트(소넷)가 실행, 거부 시 새 채팅 3~5회 |
| 파일·코드 탐색(읽기 전용) | **`explorer`(하이쿠)** | 결과 부족 → 소넷 서브에이전트 |
| 브라우저 화면 조작(수집, 확인) | **서브에이전트**(본 세션은 직접 하지 않는다) | 헤르메스 브라우저 PoC 성공 뒤에 이관 검토 |
| 코드·문서 초안, 시험 실행 | 소넷(서브에이전트 또는 본 세션) | 두 번 반려 → Claude 본 세션 |
| 독립적인 추론·설계 검토 | 서브에이전트(소넷, 독립성 필요 시 오퍼스=컨펌) | — |
| 아키텍처, 복잡한 판단, 통과·반려·안전 판정, 최종 통합, 사장님 보고 | **Claude 본 세션** | — |

## 3. 폴백·승격 규칙
1. **4090 실패**(응답 없음, 형식 위반, 오류) → 헤르메스 → 하이쿠. 로컬 결과의 판정은 하지 않는다.
2. **헤르메스 웹 조사 부족**(인용 불일치, 결과 파일 없음, 하루 한도 소진) → 소넷 서브에이전트 수집 → 그래도 부족하면 제미나이 딥리서치.
3. **하이쿠 부족**(요약이 근거를 빼먹음, 원인을 놓침) → 소넷. 이번 세션 실측: 하이쿠 진단이 2차 원인을 놓쳐 부모가 이어 확인함(표본 1건).
4. **소넷으로 해결 안 됨**(2회 반려) → Claude 본 세션. 오퍼스·페이블은 사장님 컨펌 뒤에만.
5. **승격 신호는 결과로 판단**한다: 원문 표본 대조 실패, 형식 위반, 같은 실패 재발. 처음부터 상위 모델을 쓰는 것은 되돌리기 어려운 일과 판정에 한정한다.
6. 모든 무료·로컬 결과는 원문과 함께 보존하고 채택은 부모가 원문 표본으로 확인한다.

## 4. P0 (이번에 적용)
1. **웹 조사·수집을 Claude 본 세션이 직접 하지 않는다.** 로그 기준 WebSearch·WebFetch 결과 566건, 브라우저 조작 4,560호출(도구 결과의 52%)이 본 세션 또는 소넷 서브에이전트에서 나갔다. 수집은 `collector`(하이쿠)나 헤르메스, 화면 조작은 서브에이전트가 한다. 적용: 이 문서 + CLAUDE.md 링크 1줄.
2. **읽기 전용 탐색·큰 파일 훑기는 `explorer`(하이쿠)에 맡긴다.** 서브에이전트 호출의 79%가 소넷이던 것을 하이쿠 기본으로 바꾼다. 적용: 이미 병합된 `explorer` 사용을 이 정책으로 의무화. 효과는 사용 후 측정(측정 대기).

## 5. 백로그
- **P1**: ① 헤르메스 브라우저가 실제로 페이지를 여는지 확인(수집 프로필 창을 닫고 재시도) 후 제미나이 딥리서치 PoC 재개. ② 헤르메스 `delegation`에 로컬 모델 연결 시험(작은 반복 작업 1종으로). ③ 로컬 14B 생성 속도(9.6 tok/s)가 GPU 공유 때문인지 확인(측정만).
- **P2(측정으로 필요성이 확인될 때만)**: llama.cpp 직접 서버, 추측 디코딩, 컨텍스트 128K/256K, 헤르메스 프로필 4분할, Agent Teams 구조, 대규모 로컬 오케스트레이션.

## 6. 지원 구분 요약
- **[공식]**: Claude 서브에이전트의 모델 지정·`.claude/agents`, 훅, 헤르메스 delegation·브라우저·real profile.
- **[커스텀]**: 감시·알림 스크립트, 로컬 가공 주간 작업, 수집 결과 코드 대조, 제미나이 웹 UI 브라우저 조작(공식 통합 아님, 구글 약관 확인은 PoC 보고서에서).
- **[미검증]**: 헤르메스→제미나이 딥리서치, 헤르메스→로컬 delegation, 헤르메스 브라우저의 실제 페이지 열기, 하이쿠 서브에이전트의 실사용 품질.

## 7. 외부 고사용자 사례 반영 (사장님 제공 2026-09-21)
목표: **비슷한 성능(같은 업무량, 원문 표본 검수 통과)을 유지하면서 Claude 사용량을 줄인다.** 아래 사례는 외부 경험이라 **이 환경에서 1회 시험을 통과해야** 위 2절 표의 기본 경로로 올린다(시험 전은 [미검증]). 이미 2절에 있는 것은 중복하지 않는다.
