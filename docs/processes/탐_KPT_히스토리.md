# 탐 KPT 회고 히스토리 (2026-09-28, 탐_프로세스표.md 8절에서 JIT 분리)

> [탐_프로세스표.md](../탐_프로세스표.md)를 실제로 돌린 뒤 남긴 KPT(Keep-Problem-Try) 회고. 세션 종료 의식에서 회고를 남길 때, 또는 과거 결정의 배경을 찾을 때만 연다.

## 2026-10-01 밤 (carvit.ai 개편 사이트맵 요청 + 사장님 과제 4건 세션)

**Keep**
- 병합 전에 스테이징을 만들고 링크 12개 200·로그인 연결을 실측한 것. 코드를 읽어 `/login`이 비밀키를 회전시킨다는 걸 찾아 버튼 대상을 고친 것.
- 크롬 확장 퇴역 질문을 느낌이 아니라 데이터 시각 형식·구PC 로그·시스템 로그로 대조해 "3일 안 돌았다"는 원인(크론 `%`)을 찾은 것.

**Problem**
- **비티 한도를 실측하지 않고 업무대장의 "한도 소진, 10/2 리셋 예상"을 사실처럼 받아 "10/2 낮에 확인하겠다"고 답했다.** 사장님이 방법을 물으셔서야 재 봤고, 결과는 비티 계정(`bt-agent`)이 이미 응답했다(10/1 21시, `agy -p`가 `OK`). 확인 한 번(1분)으로 바꿀 수 있는 추정을 기다림으로 설계했다. 사장님 마음을 쓰이게 한 근본 원인이다.
- 권한이 없는 부분(bt-agent 계정)을 "읽기 권한 없어 미확인"으로 두고 끝냈다. 그 한계를 사장님 손(sudo 한 줄)으로 풀 수 있다는 걸 먼저 제안하지 않았다.
- 대기 중인 과제가 "사장님 몫"이라는 이유로 멈춰 있는데, 사장님 몫을 가장 작은 단계로 쪼개 드리지 않았다(로그인·한도 확인이 그 예).
- 크론 줄을 등록할 때 수동 1회 실행만 확인하고 크론이 직접 돌린 첫 결과를 확인하지 않아 3일 누락(cxo-db #296).

**Try**
1. 업무대장의 "한도 소진"·"막힘" 같은 문장은 날짜가 붙어 있어도 착수 전에 1분짜리 실측으로 갱신한다. 실측 방법이 내 권한 밖이면 사장님이 할 가장 작은 한 줄을 바로 제안한다.
2. "사장님 몫"으로 둔 항목에는 반드시 번호 단계(컴맹 가이드)를 같이 붙인다.
3. 주기 작업 등록의 증거에 "크론이 직접 돌린 첫 결과"를 넣는다(CLAUDE.md 진입점 표의 주기 작업 행 보강 여부는 사장님 결정).

## 2026-09-24 (9/21~24 탐 세션들 되돌아보기 + 이번 표 첫 실행)

**Keep**
- 감시 대장·상태판으로 주기 작업을 한 화면에서 본 것. 이번에도 health-check가 이미 초록이라는 걸 바로 알았다.
- 헤르메스 스크립트를 고칠 때 백업을 남기는 습관(원복 경로가 항상 있음).
- 지투·노트 요청에 우편으로 바로 회신한 것.

**Problem**
- 할 일이 인수인계 산문, 백로그 문서의 날짜별 표 7개(열 모양이 제각각), 우편함에 흩어져 있었다. 무엇이 열려 있는지 세려면 서브에이전트를 돌려야 했다(이번에 63건을 정리해 보니 열린 것 44건, 닫힌 것 19건, 상태 불명 10건).
- 감시 알림이 탐 자신에게 5번 쌓였는데 아무 세션도 잡지 않았다. 알림이 대장으로 들어가는 길이 없었다.
- 세션이 길어졌다(9/22 72%, 9/24 새벽 "매우 긴 세션"). 한 세션에서 여러 줄기를 동시에 잡으면 인수인계가 산문으로 길어진다.
- 공유 작업 트리에서 다른 세션 브랜치 위에 커밋한 사고(9/24).

**Try**
1. 우편·알림을 읽으면 그 자리에서 대장 행부터 만든다(탐_프로세스표.md 2절 0번). 다음 세션에서 지켜졌는지 KPT로 본다.
2. 인수인계의 "탐 단독 진행 큐"를 대장 필터로 대체한다(탐_프로세스표.md 6절 0번).
3. 세션 시작 때 브랜치부터 새로 딴다(탐_프로세스표.md 1절 0번).
4. `hx.sh`의 SSH 별칭이 Git Bash에서 안 풀리는 문제: 같은 PC면 로컬 실행, 다른 PC면 별칭 설정 확인(대장에 등록).
