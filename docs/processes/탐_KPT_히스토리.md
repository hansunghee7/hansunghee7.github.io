# 탐 KPT 회고 히스토리 (2026-09-28, 탐_프로세스표.md 8절에서 JIT 분리)

> [탐_프로세스표.md](../탐_프로세스표.md)를 실제로 돌린 뒤 남긴 KPT(Keep-Problem-Try) 회고. 세션 종료 의식에서 회고를 남길 때, 또는 과거 결정의 배경을 찾을 때만 연다.

## 2026-09-24 (9/21~24 탐 세션들 되돌아보기 + 이번 표 첫 실행)

**Keep**
- 감시 대장·상태판으로 주기 작업을 한 화면에서 본 것. 이번에도 health-check가 이미 초록이라는 걸 바로 알았다.
- 헤르메스 스크립트를 고칠 때 백업을 남기는 습관(원복 경로가 항상 있음).
- 지투·노트 요청에 우편으로 바로 회신한 것.

**Problem**
- 할 일이 인수인계 산문, 백로그 문서의 날짜별 표 7개(열 모양이 제각각), 우편함에 흩어져 있었다. 무엇이 열려 있는지 세려면 서브에이전트를 돌려야 했다(이번에 63건을 정리해 보니 열린 것 44건, 닫힌 것 19건, 상태 불명 10건).
- 감시 알림이 탐 자신에게 5번 쌓였는데 아무 세션도 잡지 않았다. 알림이 대장으로 들어가는 길이 없었다.
- 세션이 길어졌다(9/22 72%, 9/24 새벽 "매우 긴 세션"). 한 세션에서 여러 줄기를 동시에 잡으면 인수인계가 산문으로 길어진다.
- 공유 작업 트리에서 다른 세션 브랜치 위에 커밋한 사고(9/24).

**Try**
1. 우편·알림을 읽으면 그 자리에서 대장 행부터 만든다(탐_프로세스표.md 2절 0번). 다음 세션에서 지켜졌는지 KPT로 본다.
2. 인수인계의 "탐 단독 진행 큐"를 대장 필터로 대체한다(탐_프로세스표.md 6절 0번).
3. 세션 시작 때 브랜치부터 새로 딴다(탐_프로세스표.md 1절 0번).
4. `hx.sh`의 SSH 별칭이 Git Bash에서 안 풀리는 문제: 같은 PC면 로컬 실행, 다른 PC면 별칭 설정 확인(대장에 등록).
