## 1. 세부 항목별 구체적 지적 (위치, 심각도, 조치 방안)

### [지적 1] 구PC 헤드리스 브라우저를 통한 유튜브 스튜디오·인스타 프로페셔널 로그인 시도
- **대상 위치**: `## 알려진 문제` - *"숏폼 채널 로그인(유튜브 스튜디오, 인스타 프로페셔널)이 구PC 크롬 프로필에 아직 안 돼 있다."* 및 `## 핏(숏폼 담당)이 정한 완료 조건` - *"클립 영상별 지표(로그인 벽)."*
- **심각도**: **높음**
- **내용**: Playwright 원격 디버깅 포트 기반 헤드리스 크롬으로 Google 계정(유튜브 스튜디오) 및 Meta 계정(인스타 프로페셔널 웹)의 로그인 세션을 지속 유지하는 것은 플랫폼의 봇 탐지(AutomationControlled 플래그, 캔버스 핑거프린팅)에 즉각 노출됩니다. 로그인 챌린지(CAPTCHA, SMS 2FA)가 발생해 무터치가 즉시 깨질 뿐 아니라, 반복 적발 시 채널 섀도우밴 또는 영구 계정 정지(TOS 위반)를 초래합니다.
- **고치는 방법**: 유튜브 스튜디오와 인스타 프로페셔널 웹 화면 스크래핑 계획을 전면 취소하고, 공식 무료 API(YouTube Analytics/Data API, Meta Graph API) 기반 GitHub Actions 수집으로 전환한다.

### [지적 2] 공개 저장소 환경에서의 성과 상세 데이터(JSON) 영구 노출 위험
- **대상 위치**: `## 지금 구조` - *"3. GitHub Actions: 하루 2~3회 fetch_*.py가 유튜브 채널·영상 통계... 인스타 콘텐츠 기록을 assets/data/*.json에 커밋. 이 JSON 14개를 스튜디오가 fetch()로 직접 읽는다(DB 아님)."*
- **심각도**: **높음**
- **내용**: 스튜디오 정적 사이트가 호스팅되는 저장소가 공개(Public, 예: `hansunghee7.github.io`)일 경우, 유튜브 시청 유지율 곡선, 댓글 원문, 구독 전환수, 인스타 릴스별 팔로우 유입수 등 1인 회사의 핵심 영업 자산인 콘텐츠 퍼널 지표가 Git 커밋 기록을 통해 외부에 무방비로 공개됩니다.
- **고치는 방법**: 스튜디오 호스팅 저장소의 공개(Public) 여부를 확인하고, 공개 저장소라면 상세 지표 JSON 커밋을 중단하거나 비공개 저장소 또는 접근 토큰이 필요한 스토리지로 분리한다.

### [지적 3] rclone 구글드라이브 공유 Client ID 만료로 인한 백업 파이프라인 중단 확정
- **대상 위치**: `## 알려진 문제` - *"구글드라이브 공유 client_id를 rclone이 쓰고 있어 2026년 중 중단 예정 공지."*
- **심각도**: **중간**
- **내용**: 2026년 Google의 정책 변경으로 rclone 기본 공유 client_id가 차단되면, 구PC에서 수집된 SQLite DB의 드라이브 업로드가 사전 경고 없이 즉각 실패하게 됩니다.
- **고치는 방법**: Google Cloud Console에서 무료로 자체 OAuth 2.0 Client ID/Secret을 발급받아 구PC rclone 설정에 등록한다.

### [지적 4] 구PC SQLite와 스튜디오 JSON 간 파이프라인 단절(데이터 사일로)
- **대상 위치**: `## 알려진 문제` - *"구PC DB(드라이브)와 스튜디오 JSON(저장소)이 이어져 있지 않다. 스튜디오는 아직 확장이 채운 값을 읽는다."*
- **심각도**: **중간**
- **내용**: 구PC는 데이터를 SQLite DB로 압축해 구글 드라이브로 쏘고, 정적 웹인 스튜디오는 저장소의 JSON만 읽을 수 있는 구조적 단절 상태입니다. 이 상태에서 확장을 끄면 스튜디오 데이터 갱신이 즉시 중단됩니다.
- **고치는 방법**: 구PC의 `build_insight_db.py` 완료 시점에 스튜디오 호환용 경량 JSON 파일을 함께 생성하여 Git 저장소로 푸시하거나 GHA와 동기화한다.

### [지적 5] 물리 구PC 크론 단일 실행 환경의 취약성
- **대상 위치**: `## 지금 구조` - *"2. 구PC 수집(새 방식): 리눅스 PC에서 크론이 매일 01:00 UTC에 run_sns_daily.sh를 실행. ... 9/29~10/1은 크론 줄의 % 이스케이프 오류로 3일 안 돌았고"*
- **심각도**: **중간**
- **내용**: *(가설)* 구PC의 하드웨어 전원 단절, 네트워크 순단, 재부팅 시 원격 복구 수단이 없을 가능성이 큽니다. 크론 구문 오류 하나로 3일간 중단된 사례처럼, 물리 단일 머신에 의존하는 구조는 무터치 원칙을 쉽게 무너뜨립니다.
- **고치는 방법**: 스크립트 실행을 crontab 대신 systemd timer로 전환해 실패 시 자동 재시도 및 로깅을 보장하고, 공식 API 수집은 100% GitHub Actions로 분리 이관한다.

### [지적 6] 네이버 클립 `following` 필드 부재로 인한 확장 퇴역 지연
- **대상 위치**: `## 알려진 문제` - *"사장님 조건: 네이버 클립 following 필드가 구PC 수집에 아직 없음(확인되면 확장 퇴역)."*
- **심각도**: **낮음**
- **내용**: 확장을 퇴역시키기 위한 유일한 기능적 블로커인데, 1개 필드 파싱 누락으로 인해 불안정한 크롬 확장 수집 파이프라인을 계속 병행 운영하고 있습니다.
- **고치는 방법**: 구PC Playwright 스크립트에 네이버 클립 모바일 프로필 페이지의 `following` DOM 셀렉터를 추가하고 실측 검증하여 확장을 즉시 퇴역시킨다.

## 2. 핏(Fit)의 완료 조건 달성을 위한 최적 아키텍처 및 실행 순서

### 핵심 구조 원칙 (무터치 · 무료 · 계정 안전)
- **공식 API는 GitHub Actions(클라우드)로 완전 일원화**: 계정 정지 위험이 있는 로그인 스크래핑을 배제하고, 무료 공식 API의 리프레시 토큰(OAuth 2.0)을 GitHub Actions Secrets에 보관하여 매일 정기 수집합니다.
- **구PC는 '비로그인/공개 웹 스크래핑' 전용으로 축소**: 링크드인, 리멤버, 로켓펀치, 네이버 클립 등 공식 API가 없는 채널만 최소 주기로 수집합니다.

| 데이터 항목 (핏의 완료 조건) | 수집 경로 및 방식 | 비용 / 제약 |
| :--- | :--- | :--- |
| **유튜브 시청 유지율 곡선** | **GitHub Actions** + YouTube Analytics API (`dimensions=elapsedVideoTimeRatio`, `metrics=audienceWatchRatio`) | 무료 (OAuth 토큰 필요) |
| **유튜브 구독 전환** | **GitHub Actions** + YouTube Analytics API (`dimensions=video`, `metrics=subscribersGained,subscribersLost`) | 무료 (할당량 극소) |
| **유튜브 댓글 본문** | **GitHub Actions** + YouTube Data API v3 (`commentThreads.list`) | 무료 (일일 10,000 쿼터 내 충분) |
| **인스타 릴스별 팔로우** (1순위) | **GitHub Actions** + Meta Graph API (`/{media-id}/insights?metric=follows,reach,saved,shares`) | 무료 (크리에이터 계정 전환 필수) |
| **편별 한 장 표 출력** | GitHub Actions가 매일 수집 데이터를 취합해 `shortform_summary.json` (또는 마크다운) 자동 커밋 | 스튜디오 및 핏(에이전트) 즉시 열람 |

### 실행 순서 (권장 로드맵)
1. **1단계 (기반 보안·백업 조치)**: Google Cloud Console에서 자체 OAuth Client ID를 발급해 rclone의 만료 예정 client_id를 교체합니다.
2. **2단계 (유튜브 공식 API 수집 파이프라인 구축 - GHA)**: YouTube Analytics API 및 Data API v3 OAuth 인증을 설정하고, 유지율·댓글·구독전환을 JSON으로 뽑아내는 `fetch_youtube_deep.py`를 GHA에 등록합니다.
3. **3단계 (인스타그램 Meta Graph API 전환 - GHA)**: 인스타 계정을 크리에이터 계정(무료)으로 전환하고 Facebook 페이지에 연결한 뒤, 릴스별 `follows` 메트릭을 수집하는 GHA 워크플로를 추가합니다. *(가설: 현재 계정이 개인 계정이라면 1회 수동 전환 설정 필요)*
4. **4단계 (구PC 수집기 수정 및 확장 퇴역)**: 구PC 스크립트에 네이버 클립 `following` 파싱을 추가하고 실측 검증 후, 사장님 PC 크롬 확장을 완전 삭제(퇴역)합니다.
5. **5단계 (핏용 피드백 표 자동 생성)**: GHA에서 수집된 유튜브·인스타 데이터를 병합하여 핏이 바로 읽고 다음 주 가설을 쓸 수 있는 "편별 단일 요약표"를 매일 자동 생성합니다.

## 3. 핵심 위험 분석 (심각도 순)

### 1위. 계정 정지 위험 (심각도: 높음)
- **위험 내용**: 구PC 헤드리스 Playwright로 유튜브 스튜디오 및 인스타그램 프로페셔널 웹에 로그인 세션을 붙여 지속 스크래핑하는 설계.
- **영향**: Google과 Meta의 보안 시스템은 브라우저 핑거프린트와 자동화 신호를 탐지하여 캡차/로그인 락을 걸며, 비공식 접근 지속 시 브랜드 공식 채널이 일시 정지되거나 섀도우밴(노출 제한) 처리될 수 있습니다.

### 2위. 단일 장애점 (SPOF) 위험 (심각도: 높음)
- **위험 내용**:
  1. **물리 구PC**: 가정/사무실 리눅스 PC의 하드웨어 고장, 전원 차단, OS 먹통 발생 시 수집 전면 중단.
  2. **rclone 기본 client_id**: 2026년 예고된 Google 차단 시 드라이브 업로드 전면 실패.
  3. **파이프라인 미연결**: 구PC DB와 스튜디오 간 데이터 전달 통로가 없어 확장을 끄면 스튜디오가 즉시 멈춤.

### 3위. 데이터 정확성 및 정시성 위험 (심각도: 중간)
- **위험 내용**:
  1. **플랫폼 DOM 변경(Silent Failure)**: 틱톡 팔로워/좋아요 필드가 뒤바뀐 사례처럼, 웹 스크래핑은 UI 변경 시 에러 없이 잘못된 값이 DB에 쌓여 에이전트(핏)가 왜곡된 가설을 세울 위험이 있습니다.
  2. **API 집계 시차 (가설)**: YouTube Analytics API의 유지율 및 구독 전환 데이터는 실시간이 아니라 24~48시간 정산 지연이 존재합니다. 핏이 "발행 당일 유지율 0"을 실패로 오판하지 않도록 파이프라인에서 데이터 기준 시점(Date lag)을 명시해야 합니다.
