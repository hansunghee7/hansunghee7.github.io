# 비티 한도 조건 (2026-10-01, 비티 본인 답 + 탐 실측)

> 사장님이 "비티의 하루 또는 시간당 한도 조건도 비티에게 확인하라"고 해서 `ask_bt.sh`로 물었다. 비티의 숫자는 **일반 Gemini API 지식이며 이 계정의 실제 한도가 아니다**(비티도 [추측]이라고 구분함). 실제 한도는 탐이 호출 기록으로 측정한다.

## 비티의 답 (요지, 원문 근거 없음)
- 사실로 말한 것: 환경은 Antigravity CLI(`agy`) + Gemini 계열. 공개 Gemini API 무료 티어 표준은 분당 15회·분당 100만 토큰·일 1,500회, 일일 리셋은 태평양 자정(한국 시간 오후 4~5시). 한도 초과 오류는 `429`/`RESOURCE_EXHAUSTED`, 분당 한도는 롤링.
- 추측으로 말한 것: Antigravity 구독 환경은 위보다 여유가 있을 수 있음, 일일 한도가 24시간 롤링일 수 있음.
- 비티 제안: 정기 소환은 3~5분 이상 간격, 입력은 1만~2만 토큰 이하, 세션 누적 금지(작업마다 새 세션).

## 탐 실측과 판정
- 지금까지 하루(10/1) 구PC `agy -p` 호출 8회 안팎(1단어 확인 3·역할 질문 1·시험 1·B1·B2·한도 질문 2)에 **한도 오류 0건**. 입력은 최대 약 7KB.
- 비티가 알려 준 실측 방법 중 "대화 기록의 `usage_metadata`로 토큰 확인"은 **틀렸다**: 구PC 대화 기록(`transcript.jsonl`)에는 토큰 필드가 없다(10/1 실측). 비티 오류 사례 1건으로 채택률에 반영.
- 그래서 안전 가드는 보수적으로: `bt_loop.py`는 7일 2회·간격 36시간·실패 시 24시간 쉼. 비티 제안(3~5분 간격)보다 훨씬 느슨한 사용이라 충분히 안전하다고 본다.
- 실제 한도를 알려면 한도 오류가 나올 때까지 밀어 볼 필요는 없다(무료 한도를 소진해 다른 일을 막는다). 실패 문구가 처음 나오면 그 원문을 `state.json`과 이 문서에 남겨 정의한다.


## 2026-10-02 변경

- 사장님 지시로 7일 2회·간격 36시간 가드를 없앴다. 남은 장치는 실제 실패(한도 문구·빈 답) 뒤 24시간 쉬기 하나. 한도는 호출 기록(`agent_calls.csv`)과 첫 한도 오류 원문으로 정의한다.

## 2026-10-03 실측: 첫 한도 오류 원문(주 단위 개인 한도)

- 원문: `Individual quota reached. Please upgrade your subscription to increase your limits. Resets in 131h9m17s.` (`RESOURCE_EXHAUSTED`, HTTP 429, retryable). stderr에만 나오고 stdout은 비며 종료 코드 3.
- 그날 쓴 양: 같은 날 08:34~10:27 사이 호출 7회(검토 1, 출제 1, AB 역할노트 1, 주제 추천 시도 4). 그중 웹 검색·웹페이지 읽기가 든 주제 추천(447초) 직후 소진. 검색이 든 긴 작업이 한도를 크게 먹는 것으로 보인다[추정].
- 리셋: 131시간 뒤(약 10/8 저녁). 일 단위가 아니라 주 단위 창으로 보인다.
- 영향: `bt_loop.py`(매일 10:00)는 실패 시 24시간 쉼으로 자동 대기. N112 아침 피드백 시험·N113 주제 추천(핏 도구 `tools/topic/recommend_topics.py`)은 그동안 덱스 단독.
- 운영 규칙(제안, 10/10 N112 판정 때 확정): 비티는 웹 검색이 필요 없는 검토·출제에 우선 쓰고, 검색이 필요한 일은 덱스 먼저.

## 2026-10-03 사장님 결정: 비티 제미나이 한도 나누기

- **핏 주 3회**(주제 추천 도구, 핏이 도구에 주간 상한 관문으로 넣는다), **나머지는 탐이 알아서**.
- 같은 날 실측: 한도는 제미나이 계열 전체 공유(3.8·3.6 Flash, 3.1 Pro 모두 같은 "Resets in 130h"). 비티 안의 다른 회사 모델은 별도로 돈다(`--model claude-sonnet-4-6` 성공, `gpt-oss-120b-medium`은 혼잡 503 잦음). Sonnet은 웹 검색 때 원문 URL 대신 요약을 주는 경향.
- 탐 운영: 출처 URL이 필요 없는 검토·출제·아침 피드백은 `--model claude-sonnet-4-6`을 먼저 써서 제미나이 한도를 아낀다. 제미나이는 웹 출처가 꼭 필요한 일에만.
