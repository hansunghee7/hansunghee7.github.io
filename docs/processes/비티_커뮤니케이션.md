**협업 원칙(사장님 2026-09-27)**: 비티는 도구가 아니라 다른 사고방식을 가진 동료로 대한다. ① **비티가 우리보다 나은 방식을 보여주면 검토 후 우리 것(스킬·프로세스표·훅)으로 채택한다**(예: 아래 감시 자동화가 비티의 File Watcher를 보고 만든 것). ② **개발하다 막히면 비티에게도 조언을 구한다** — 답을 억지로 혼자 찾지 않는다. ③ **비티에게 기술적 사실을 물을 땐 검증 가능한 공식 출처(URL)까지 요청하고, 비티 스스로도 답하기 전에 팩트체크하도록 요청한다.** ④ **그래도 탐이 직접 재확인한다** — 비티의 답, 탐의 확인 둘 다 완전히 못 믿는다(아래 사고 참고). ⑤ **큰 과제를 받으면 앞으로는 비티와 협업해서 진행한다(사장님 지시 2026-09-27)** — 탐 혼자 다 하지 않고, 병렬로 나눠서 과제 품질을 올린다. 방법: `TASK.md`(할 일)·`COMMUNICATION.md`(요청/보고)로 넘기고, 결과는 탐이 채점(코드 대조·실행 증거 확인) 후 반영 여부를 정한다.

**사고와 대응(9/27, "agy CLI" 존재 여부 착오)**: 비티가 리눅스 이전 방법으로 `agy`(Antigravity CLI)를 제안하며 설치 URL을 줬는데 404였다. 탐이 "npm/pip에 없다"며 존재 자체를 의심했으나 **틀렸다** — `agy`는 Go로 만든 별도 네이티브 바이너리라 애초에 npm/pip 레지스트리에 없는 게 정상이었다(탐이 검증 경로를 잘못 골랐다). 사장님이 구글 검색으로 공식 페이지(`antigravity.google/product/antigravity-cli`)를 보여줘서 실존을 확인했고, WebFetch로 공식 문서를 직접 뒤져 올바른 설치 URL(`.../cli/install.sh`, 비티 원문은 `/cli/`가 빠진 오타)을 찾았다. **일반화**: "레지스트리에 없다"는 "존재하지 않는다"와 다르다 — 배포 방식(npm/pip/독립 바이너리/OS 패키지)부터 확인하고, 안 보이면 그 도구의 **공식 사이트를 직접** 뒤진다. 탐의 반박도 비티의 주장만큼이나 재검증 대상이다.

**실측 사례(2026-09-27, 이 표로 처음 정리)**: `COMMUNICATION.md`에 `[보고]` 1건 작성 → 비티가 5분 뒤 `[보고]`로 회신(수신 확인 + Watchdog 개선 알림) → 별도로 텔레그램 Bot API 직접 호출(urllib, 토큰은 파일에서만 읽음)로 실제 메시지 전송 → 사장님이 텔레그램 앱 화면으로 도착 확인(왕복 총 소요 약 5분). 이어서 `vault.js` 보안구조를 "정답을 좁히지 않고" 자유 검토해 달라는 과제를 냈더니, 비티가 감사 60%+개선설계 40% 하이브리드 접근으로 5개 발견(4개 타당, 1개는 실측 없이 단정한 것으로 판단돼 탐이 반려)을 코드 무변경으로 제출 — 접근 방법 자체를 관찰하는 시험이 실제로 유의미한 차이를 보여줬다. 이후 비티의 File Watcher(자기 쪽 실시간 감지)를 보고 **같은 걸 우리 쪽에도 만듦**(`communication_watcher.py`, 위 3번) — 협업 원칙 ①의 첫 사례.

**사고와 대응**: 코드 검토 중 발견 — 비밀값을 작업 폴더 밖(`carvit-bot-secrets/.env`)으로 옮기는 보안 패치는 코드(로딩 순서)에 반영돼 있었지만, **패치 전 옛 `.env`(작업 폴더 안, 비티가 읽을 수 있는 위치)가 실제 값이 든 채 안 지워지고 남아 있었다**(길이로만 확인, 내용은 안 엶). 사장님 판단: 텔레그램 봇 토큰은 "비티 자신의 봇이라 본인 것을 본 것"이라 재발급 불필요, Gemini 키도 이미 이 용도 전용 별도 키라 영향 제한적 — 재발급·삭제 둘 다 보류. **일반화**: 비밀값 위치를 옮기는 패치는 "새 위치에서 읽는 코드"만으로 안 끝난다 — **옛 위치의 실물 파일을 지우는 것까지가 패치**다. 다음에 비슷한 이동을 하면 옛 파일 삭제를 체크리스트에 넣는다.

## 호출 순서와 한도 표시 읽는 법 (2026-10-08, 근거 `scripts/ops/ask_bt.sh`, AI_ROUTING_POLICY.md, PR 2028)

- **기록된 호출 순서**: 비티 직통(본체) → 옴니라우터 무료 풀 → 비티-sonnet → Vertex(GCP 크레딧). 정식 `scripts/ops/ask_bt.sh`가 이 순서로 자동 전환한다.
- **직통의 한도 표시(429, `RESOURCE_EXHAUSTED`)는 "비티 불가"가 아니라 다음 경로로 넘어가라는 신호다.** 일이 멈출 이유가 아니다. 직통 한도가 풀리는 시각을 기다리지 않는다.
- **사고(2026-10-08)**: 로컬 세션이 `ask_bt.sh`의 옛 복사본으로 직접 호출해 429를 받고 "약 3시간 35분 뒤 풀림, 검증 미실시"로 보고했다. 저장소 최신 정식 스크립트로 다시 발주하자 옴니라우터 무료 콤보가 답해 검증이 끝났다. 탐도 그 보고를 그대로 전달해 한도 정보를 틀리게 말했다.
- **규칙**: ① 복사본이 아니라 저장소 최신 `ask_bt.sh`를 쓴다(호출 전에 pull). ② 한도 표시를 보고하기 전에 정식 스크립트의 자동 전환까지 거쳤는지 확인한다. ③ 모든 경로가 막혔을 때만 "검증 미실시"로 보고하고, 그때 어느 경로가 어떤 문구로 막혔는지 원문을 적는다.
