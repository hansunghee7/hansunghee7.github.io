# 나노바나나(제미나이 앱 이미지 만들기) 이미지 생성 프로세스표 (2026-10-05 지투, 동료 공용)

> **DB 이관 완료(2026-10-06)**: 단계 카드는 운영 DB 공정 `공용-나노바나나이미지`에도 있다(`python scripts/ops/proc.py steps 공용-나노바나나이미지`). 새로 배운 것은 `proc.py add`로 DB에도 쓴다.

> 제미나이 앱(웹)의 "이미지 만들기"로 이미지를 한 장에 여러 개(시트) 받아 파일로 쓰는 공정이다. 사장님 지시(10/5): 다른 동료도 쓸 수 있게 프로세스표로 둔다. 지투가 Logos 로고 시트 90여 장을 만들며 실측했고, 상세 가이드는 [제미나이_앱_이미지_생성_가이드.md](제미나이_앱_이미지_생성_가이드.md), 로고 공정은 [지투_프로세스표_로고.md](지투_프로세스표_로고.md). 영상(Flow) 생성은 이 문서의 범위가 아니다(핏 기록).

## 언제 쓰고 언제 쓰지 않나
- 쓴다: 로고·아이콘·삽화 **후보를 많이 뽑아 사람이 고를 때**. 시트 방식은 한 번 요청에 6개를 받아 요청 횟수가 6분의 1이다.
- 쓰지 않는다: 서비스(고객)용 대량 생성은 API 경로를 따로 검토한다. 사람 얼굴 톤은 Gem을 쓴다(핏). 이미지 품질은 로컬 Krea2보다 낮았다(평가기준 6절), 속도·비용(0원)이 장점이다.

## 0. 시작 전에 지킬 것
- **계정**: 사장님이 허용한 계정만 쓴다(무료 보조 계정, 허용한 워크스페이스 계정, 정본은 `shorts-lab/계정_현황표.md`). 크롬 창의 「Google 계정」 표시 이메일로 계정을 **눈으로 확인한 뒤** 시작한다. 로그인 화면이 뜨거나 이메일이 다르면 멈춘다. 로그인·계정 전환·계정 생성은 사람 몫이다. 계정 이메일은 공개 저장소에 적지 않는다.
- **사람처럼 쓴다**(사장님 10/5): 횟수 상한은 없지만 시트 사이를 75~170초 무작위로 띄우고, 생성·다운로드는 마우스 클릭, 프롬프트는 글자 간격을 두고 입력한다. 키 입력 연타·붙여넣기·스크립트 연속 호출 금지.
- **한도·정책 문구가 나오면 그 계정은 즉시 멈춘다.** 계정을 바꿔 다시 두드리지 않는다(10/3 Flow 차단 교훈).
- 실행 위치는 구PC 작업실 `~/workshop/logos_batch/`(SSH 별칭 `goosolar`, venv python). 공장 러너가 돌고 있으면 스크립트가 건너뛴다(`factory.lock`).

## 1. 프롬프트 파일 만들기
- `prompts.json`: `[{"name":"R1_1","prompt":"...","ratio":"4:3"}]`. 이름은 폴더·번호표 접두사로 이어진다.
- 시트 프롬프트(영어): `A sheet of 6 DIFFERENT <대상> arranged in a clean grid of 3 columns by 2 rows on one plain pure white background. ... Solid pure black shapes only, thick bold shapes, flat 2D, no text/letters/shadow/gradient/thin lines, simple smooth outline, at most 3 distinct parts, fills about half of its cell. Wide empty white space between the marks, no borders, no grid lines, no labels, no numbers.`
- **무엇을 그릴지는 이 문서가 아니라 대상 공정**이 정한다(로고는 설명서 카드 → 동작을 담은 의도, 지투_프로세스표_로고.md A절).
- 같은 프롬프트를 두세 계정이 각자 속도로 만든다(가끔 이미지가 안 나오거나 이상해서).

## 2. 실행
- `~/workshop/venv/bin/python logos_gem_batch.py prompts.json out/ --max 6 --accounts 포트=이메일,포트=이메일`
- 스크립트의 동선: 새 채팅 → 「업로드 및 도구」 → 「이미지 만들기」(`menuitemcheckbox`) → 「가로세로 비율」 → 프롬프트 입력 → 「메시지 보내기」 → 「원본 크기 이미지 다운로드」. 한 시트 약 30~60초. 같은 채팅을 이어 쓰지 않는다(화면이 쌓여 클릭이 깨진다).
- 백그라운드로 걸고(`nohup ... &`) 로그는 `batch_log.jsonl`, `run_*.log`.

## 3. 완료 확인 장치 (시작하자마자)
- 구PC에서 SSH로 따로 도는 작업은 끝나도 이 세션에 알림이 오지 않는다. **시작 직후 `Monitor`**로 1분마다 진행 파일을 읽는다. 종료 조건: 목표 개수·`STOP`·프로세스 종료.
- **완료 개수는 파일 개수가 아니라 크기 100KB 이상인 PNG 개수**로 센다(10/5 사고: 22/24장이 0바이트인데 로그는 `ok`).
- 모니터는 30분 뒤 만료되므로 다시 건다. 알림이 오면 이어서 할 일을 바로 한다.

## 4. 저장 검증과 복구
- 스크립트는 저장 후 0바이트면 `~/Downloads/Gemini_Generated_Image_*.png`에서 최근 60초 안의 파일로 복구하고, 없으면 실패로 멈춘다(PR #553). 옛 실행분은 로그 시각(UTC)과 파일 수정 시각이 8초 안에 맞는 것끼리 짝지어 복구한다.
- 시트 이미지는 약 1200×896, 사람이 저장하는 우클릭 저장은 JPEG로 낮아지니 쓰지 않는다(원본 크기 다운로드 버튼만).

## 5. 자르기
- `python scripts/logos_sheet_crop.py SHEET.png 3 2 접두사 cells` → 칸마다 1024×1024 흰 바탕 PNG와 경고(빈 칸·칸에 걸친 대상은 버린다).

## 6. 걸러내기와 번호표
- `python scripts/logos_tray.py <시트폴더> <접두사> --thr 0.5`: 닮은 칸을 묶어 대표만 번호를 붙인 `contact_sheet.png`와 `numbers.json`. 임계값 0.85는 칸이 많이 남아 0.5를 쓴다.

## 7. 전달과 기록
- 결과물(번호표)은 컨펌 방으로 `python scripts/ops/tg_boss.py photo ... --persona <내 이름>`, 대상 설명서와 질문을 캡션에 같이 쓴다.
- 시트·칸·번호표는 대상 공정 폴더(예: `docs/logos_poc/<라운드>/`)에 PR로 남기고 CI 통과 뒤 병합한다.
- 대장에 한 줄(몇 장, 어느 계정, 결과)과 `worklog.py add`.

## 함정 (실제로 겪은 것)
- 입력창에서 엔터가 안 먹는다. 「메시지 보내기」를 클릭한다.
- 첫 클릭은 페이지가 준비되기 전엔 무시된다(약 2.5초 대기). 도구 메뉴는 첫 클릭이 안 먹을 수 있어 열렸는지 확인하며 연다.
- "닮은 변형 여러 개" 문구는 복사한 듯한 이미지를 낳는다. 걸러내기(6번)가 필수다.
- 요소를 못 찾으면 추측하지 말고 역할별 이름을 덤프해 확인한다(`gem_diag.py`).
- 화면을 보며 직접 클릭하면 한 시트에 도구 호출이 약 25번 든다. 스크립트로 돌린다.
- 공용 main 폴더가 뒤처져 있으면 그 폴더의 스크립트는 옛 버전이다(지투_프로세스표.md 0절).

## 채워 나갈 빈칸
- 계정별 정확한 생성 한도는 구글이 공개하지 않는다. 위 규칙은 우리가 안전하게 잡은 방식이고, 한도 문구가 나오면 그때 멈추는 것이 유일한 확인 수단이다.
- 로고 외 용도(삽화, 썸네일)의 프롬프트 문구는 아직 정리하지 않았다. 쓰는 동료가 해당 용도 절을 이 문서에 덧붙인다.
