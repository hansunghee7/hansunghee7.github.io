## 1. 최종 아키텍처

```
assets/data/sns_publish_queue.json (마야가 게시할 항목을 채워 둠, status: "pending")
  → GitHub Actions 워크플로(.github/workflows/publish-sns.yml, 하루 2회)
  → scripts/publish_sns_queue.py 가 AItoEarn 발행 흐름 API(POST /api/v2/channels/publish-flows) 호출
    (실제 게시 시각은 각 항목의 publishAt, AItoEarn 서버가 그 시각에 게시한다)
  → 결과(flowId 또는 에러)를 큐 파일에 다시 커밋
  → 다음 날 _sns-extension 수집 결과(팔로워·조회수)와 대조해 완료 확인(탐이 준 재사용 자산 a)
```

**왜 GitHub Actions인가**: 정해진 시각에 맞춰야 하는 반복 작업(예약 게시)은 사람이 매번 지켜보며 누르는 것보다, 그 시각에 도는 서버가 대신 하는 편이 안전하고 확실하다. 이 저장소의 `fetch-analytics.yml`(GA4)·`fetch-sns-public.yml`과 완전히 같은 구조라 새 기술이 아니라 기존 패턴의 재사용이다. 실행은 사장님이 채팅에서 승인한 항목(`approved_by`)에만 한정한다(2026-09-24, 탐의 검토 반영: 처음 이 문서를 "Claude Code 세션이 못 하니 다른 경로로 실행한다"는 식으로 썼다가 우회 설계로 판정받아 고쳤다).

시크릿 이름: `AITOEARN_API_KEY` (GitHub 저장소 Settings → Secrets and variables → Actions에 사장님이 직접 붙여넣기, 1회).


## 부록 A. 채널별 게시 절차 (확장 이식용 실측 기록)

### 브런치 (2026-09-28 실측·게시 완료, DONE=VERIFIED)
- `https://brunch.co.kr/write` 이동 시 사장님 크롬 로그인 세션 그대로 에디터 진입(별도 로그인 불필요). 제목·본문은 contenteditable, 본문에 URL을 그대로 넣으면 해당 페이지의 OG 이미지를 자동으로 카드/이미지로 붙여준다(대표 이미지 문제를 사실상 자동 해결).
