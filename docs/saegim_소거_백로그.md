# saegim 소거 걸림돌 백로그 (어려운 순)

사장님 지시(2026-10-20): saegim 이름 변경의 걸림돌을 백로그로, 어려운 순으로 정렬한다. 근거는 노트의 전수 조사(이 저장소 1252줄, 제품 저장소 1380줄, 패스 저장소 78줄)와 워크플로·패스 코드 확인이다. 표시 `[추정]`은 아직 직접 확인하지 못한 부분이다. 단계 정책은 [이름_정책](이름_정책.md), 재발 방지 검사는 `scripts/check_saegim_names.py`.

**변경 주체는 탐이다**(사장님 지시 2026-10-20). 아래 각 항목의 "담당 후보"는 지원 역할 참고용이고, 순서·일정·실행의 지휘와 변경은 탐이 한다. 노트는 제품 저장소 사실 확인, 시험 작성·검토, 요청받은 초안 PR, 전수 조사 갱신을 지원한다.

## 0. 바꿀 수 없음 (영구 예외)
- 커밋 이력과 공개 저장소에 이미 올라간 옛 기록, 진행상황 아카이브. 다시 쓰지 않고 검사의 제외 목록에 둔다.

## 1. 가장 어려움: GCP 프로젝트 ID `saegim-mcp`와 Cloud Run 서비스 이름
- 왜 어려운가: GCP 프로젝트 ID는 이름을 바꿀 수 없어 새 프로젝트로 옮겨야 한다. 서비스 이름 `SERVICE_NAME: saegim-mcp`가 배포 워크플로 5곳에 있다. 옮길 것은 Cloud Run, Secret Manager, 권한, 도메인 연결(`mcp.carvit.ai`), 로그인 연동의 되돌아오는 주소, 예약 작업이다.
- 일정 제약: GCP 크레딧 만료가 회사 12/10, 개인 12/23(탐 N164). 크레딧 라우팅 설계와 함께 12/10 전에 이전 설계를 시작한다.
- 고객 영향: 고객은 `mcp.carvit.ai`를 쓰므로 도메인만 지키면 거의 없다. 옛 `run.app` 주소는 별도 호스트로 남아 있다.
- 담당 후보: 탐(N164)과 노트.

## 2. 패스의 네이티브 호스트 이름과 확장 ID
- 왜 어려운가: 네이티브 호스트 `kr.simplifier.saegim_pass`, `…_direct`가 사용자 PC 레지스트리에 등록돼 있어 바꾸면 설치된 모든 PC에서 다시 등록해야 한다. 확장 ID는 매니페스트 키로 정해져 바뀌지 않는다(표시 이름만 변경 가능). 스토어 심사가 얽힌다. [추정]
- 판단: 설치 수가 적은 지금이 가장 싸다. 확장 ID는 영구 예외로 두고, 호스트 이름은 이중 등록 기간을 두고 옮긴다.
- 담당 후보: 탐(패스).

## 3. 자체 실행기 이름표와 Actions 변수
- 걸림돌: 실행기 이름표 `saegim-test`, 변수 `SAEGIM_DEPLOY_RUNNER`·`SAEGIM_CI_RUNNER`, 이 이름을 읽는 유료 실행기 관문 시험. 바꾸면 실행기 재등록과 워크플로 수정이 같은 날 맞아야 하고, 어긋나면 배포가 멈춘다.
- 선행: 실행기 두 이름표를 동시에 받게 하는 과도기 설정, 관문 시험 갱신.
- 담당 후보: 탐.

## 4. 환경변수 `SAEGIM_*` (65종)
- 걸림돌: 제품 676줄, 배포 워크플로 64줄, 서버 환경, Secret Manager, 깃허브 시크릿, PC의 설정 파일. 고객은 전혀 모르는 이름이라 고객 영향은 없다.
- 방법: 새 이름을 먼저 읽고 없으면 옛 이름을 읽는 과도기 코드 → 배포 설정 이전 → 옛 이름 읽기 삭제. 값 자체는 옮기지 않는다.
- 담당 후보: 노트(제품 쪽), 탐(배포 설정).

## 5. 저장소 이름과 작업 폴더 경로
- 걸림돌: 저장소 `simplifier-saegim`, 패스 저장소. GitHub가 옛 주소를 자동 연결해 주지만 이 저장소만 경로 참조가 62개 파일 313곳이고 노트 작업 폴더가 89개다. 스크립트, 예약 작업, 감시 대장 경로, 안내 문서의 실행 경로도 같이 바뀐다.
- 특징: 시간이 갈수록 참조가 늘어 "나중이 더 큰일"인 항목.
- 담당 후보: 탐과 노트가 같은 날.

## 6. 프로젝트 서버 이름과 신원 분리, 관문 훅·권한
- 걸림돌: 루트 `.mcp.json`의 서버 이름 `saegim`, 도구 이름 `mcp__saegim__*`(19줄), 이름에 묶인 관문 훅 파일(209줄)과 시험, 권한 문자열. 같은 세션에 사용자 범위 `carvit`(다른 신원)이 있어 이름만 겹치면 신원이 섞인다.
- 선행: 신원별 서버 이름 규칙 결정(예: `carvit-<에이전트>`), 훅·권한·시험을 한 PR에서 같이 변경(카빗DM#20, 사장님 10/18 결정).
- 담당 후보: 탐(훅·설정)과 노트.
