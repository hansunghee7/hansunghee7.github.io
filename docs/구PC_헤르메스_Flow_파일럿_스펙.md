# Hermes × Google Flow 파일럿 테스트 (구PC, 사장님 지시 2026-09-22)

> 백로그 [에이전트_퍼포먼스_백로그.md](에이전트_퍼포먼스_백로그.md) 49번의 전체 스펙. 착수 전 이 문서를 읽는다.

## 목표
현재 구PC의 Hermes 환경에서 Google Flow 영상 생성 자동화가 실제 가능한지 최소 범위로 검증한다. 구조 설계나 본격 자동화 개발이 아니라 **1회 성공 여부 확인**이 목적이다.

## 테스트 범위 (다음 순서만 검증)
1. 현재 Hermes 환경에서 Flow 접속
2. Google 로그인 상태 확인
3. Flow에서 이미지 1장 업로드
4. 간단한 영상 생성 프롬프트 입력
5. 영상 생성 실행
6. 생성된 MP4 다운로드
7. 지정 폴더에 정상 저장됐는지 확인

## 중요 원칙
- 현재 설치된 Hermes v0.21.2 환경을 우선 그대로 사용한다.
- 업그레이드, 대규모 설정 변경, 운영 환경 변경은 하지 않는다.
- 테스트 성공을 가정하지 말고 실제 실행 결과로 판단한다.
- **핵심 검증 대상**: Claude Browser Control에서 발생한 OS 파일 선택창 문제(`window.showOpenFilePicker`, 2026-09-22 핏 세션에서 확인)를 Hermes가 실제로 해결할 수 있는가.
- Playwright의 `set_input_files()` 등을 쓸 경우, 실제 Flow 업로드 구조가 그 방식으로 동작하는지 먼저 확인한다.
- 확인되지 않은 기능은 가능하다고 가정하지 않는다.
- 공식 문서에서 확인된 내용과 실제 테스트 결과를 분리해서 기록한다.

## 우선 검증할 것

**A. 브라우저 접근**
- Hermes가 현재 환경에서 Flow를 정상 열 수 있는가?
- 기존 Google 로그인 세션을 사용할 수 있는가?

**B. 파일 업로드**
- Flow의 이미지 업로드 방식이 무엇인지 확인한다.
- `<input type="file">` 또는 Playwright file chooser 방식으로 접근 가능한지 확인한다.
- 가능하면 OS 파일 선택창을 직접 조작하지 않고 파일을 전달한다.
- 불가능하면 정확히 어느 단계에서 막히는지 기록한다.

**C. 영상 생성**
- 이미지 업로드 후 실제 영상 생성까지 진행한다.
- 생성 완료 여부를 Hermes가 확인할 수 있는지 검증한다.

**D. 다운로드**
- 생성된 MP4를 자동 다운로드할 수 있는지 확인한다.
- 파일이 실제 로컬 폴더에 존재하는지 검증한다.

## 성공 기준
아래 4개가 모두 실제로 성공하면 파일럿 성공으로 판정한다: **이미지 업로드 → 영상 생성 → MP4 다운로드 → 로컬 파일 확인.** 중간 단계가 하나라도 실패하면 성공으로 판단하지 않는다.
