# 슈퍼 용어집 (이름, 뜻, 별칭)

사장님이 명명한 "슈퍼" 계열 이름과 옛 이름을 한곳에 모은다. 새 이름과 옛 이름은 같은 뜻이고, `recall.py`가 둘을 같은 뜻으로 찾는다. 문서는 고칠 때마다 새 이름으로 바꾸고 일괄 수정은 하지 않는다(별칭 방식, 슈퍼색인관리의 첫 정본).

## 우산과 부품

- **슈퍼프로세스** (사장님 10/11): 전체 공정을 카드로 만들고 수파베이스(DB)로 관리하는 방식. 공정 카드, 장부, 컨펌 대장, 자동 단계표, 사고 회수 루프를 한 세트로 쓴다. 정본 [슈퍼프로세스.md](슈퍼프로세스.md).
  - **슈퍼얼라인** (10/11): 목표 정렬 점검. 슈퍼프로세스의 여덟째 부품.
  - **슈퍼백로그** (10/11): 백로그 분류, 관리, 진행을 에이전트가 스스로 순환하는 방식. 공정 카드 공용-백로그관리 #10.
  - **슈퍼인덱싱** (사장님 10/16 명명) = **슈퍼색인관리**(10/15, 찾는 순서: 1차 공정 카드와 최신 결정, 2차 정본 문서, 나머지는 히스토리) + **업무구조문서 리팩토링**(10/16, 일할 때 여는 길에서 닿는 핵심 구조문서만 남기고 나머지는 `docs/_이력/`으로). 목적: 에이전트가 건망증 없이 자기 최신 기록과 의사결정으로 일하고, 원하는 자료를 쉽게 찾는다. 정본 [슈퍼색인관리.md](슈퍼색인관리.md), 공정 카드 공용-슈퍼색인관리.
    - **슈퍼사서** (10/16, 옛 이름 **컨텍스트 감수 에이전트**, 크론 이름 `context-audit`): 슈퍼인덱싱을 관리하는 감사. 사서처럼 최신 정본은 서가(1차)에 꽂고, 대체된 옛 판본은 서고(`_이력`)로 내리고, 찾는 자료를 바로 꺼내 준다. 매일 08:50 판정과 실행(숨김·재작성·대체 표시), 재발 대장(`ctxfix.py`) 판정.

## 모델 이름 (사장님 10/8·10/15·10/19 정정, 재발방지)

- **비티** = 안티그래비티 제미나이 풀 + **Vertex(GCP 크레딧) 제미나이 풀**. 안티그래비티 풀이 한도로 막혀도 Vertex 풀로 받은 검수는 정식 비티 검수이고 보고에는 `비티(GCP 풀)`로 적는다. `비티 한도로 없음`·`비티 없음`이라고 쓰지 않는다(안티그래비티만 막힌 것을 비티 전체로 읽은 10/19 사고, 근거 탐 #71·사장님 10/8). 막힘 확인은 상태판의 `비티(안티그래비티 풀)` 줄이고, 호출은 `BT_MODEL=vertex bash scripts/ops/ask_bt.sh <카드> <출력>`.
- **비티-sonnet**: Claude 계열이라 작성자와 같은 계열이다. 이종 검수로 인정하지 않고 참고로도 쓰지 않는다.
- **덱스** = Azure OpenAI 풀의 코드 검수 모델(탐 #71). PR 검수는 덱스와 비티를 같은 머리에서 한 번씩 받는다(사장님 10/19).
