# 슈퍼 용어집 (이름, 뜻, 별칭)

사장님이 명명한 "슈퍼" 계열 이름과 옛 이름을 한곳에 모은다. 새 이름과 옛 이름은 같은 뜻이고, `recall.py`가 둘을 같은 뜻으로 찾는다. 문서는 고칠 때마다 새 이름으로 바꾸고 일괄 수정은 하지 않는다(별칭 방식, 슈퍼색인관리의 첫 정본).

## 우산과 부품

- **슈퍼프로세스** (사장님 10/11): 전체 공정을 카드로 만들고 수파베이스(DB)로 관리하는 방식. 공정 카드, 장부, 컨펌 대장, 자동 단계표, 사고 회수 루프를 한 세트로 쓴다. 정본 [슈퍼프로세스.md](슈퍼프로세스.md).
  - **슈퍼얼라인** (10/11): 목표 정렬 점검. 슈퍼프로세스의 여덟째 부품.
  - **슈퍼백로그** (10/11): 백로그 분류, 관리, 진행을 에이전트가 스스로 순환하는 방식. 공정 카드 공용-백로그관리 #10.
  - **슈퍼색인관리** (10/15, 별칭 **슈퍼인덱싱**): 기록을 찾는 순서(1차 공정 카드와 최신 결정, 2차 정본 문서, 나머지는 히스토리). 정본 [슈퍼색인관리.md](슈퍼색인관리.md).

## 일하는 방식의 이름

- **슈퍼오케스트라** (사장님 10/15 제안, 옛 이름 **오케스트레이션 2.0**, 그 앞은 환상의 오케스트레이션·탐비상모드): 본체는 지휘와 판정만 하고 모든 자원으로 일을 나눠 맡기는 상시 모드.
- **슈퍼버닝** (사장님 10/15 제안, 옛 이름 **백로그 버닝모드**, 10/12 공식명칭): 크레딧과 모든 갈래를 써서 백로그를 공격적으로 줄이는 모드.
- **슈퍼리서치** (10/11): 제미나이 검색, 링크 대조, 비티 의견, 덱스 의견, 사장님께 20줄 보고의 5단계 리서치.
- **슈퍼글로벌** (10/12): 해외 지원사업·투자 준비 과제.
- **슈퍼테마**: 주제를 추천받는 방식(덱스·비티 API 활용 갈래).
- **슈퍼에이전트(슈퍼에이전츠)**: 브랜드 이름.

## 아직 정하지 않은 것

- 등급 이름 스탠다드, 프리미엄, "슈퍼"와 프로그램 접두사 "슈퍼"가 겹친다. 어느 쪽을 구분할지는 사장님 결정.
- 라이브러리 목록은 비공개 저장소 `simplifier-cxo-db/standards/INDEX.md`에 둔다(차별성 근거는 측정 전까지 외부에 쓰지 않는다).
