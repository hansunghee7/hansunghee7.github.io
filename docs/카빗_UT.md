# 카빗 UT (유저빌리티테스트)

> 사장님 2026-10-18 명명·정규화 지시: "북처럼 새로운 세션 깨워서 경로 체험하고 피드백 듣고 개선하는 걸 카빗 유저빌리티테스트(UT)로". 기록 도구는 `scripts/ops/jitu_po.py ut`, 공정 카드는 `지투-카빗UT`.

## 무엇인가

맥락이 없는 새 세션(또는 다른 기기의 세션)을 실제 사용자로 세워, 정해진 경로를 처음부터 끝까지 직접 겪게 하고, 막힌 곳과 의견을 받아 개선하는 시험이다. 만드는 쪽 세션은 자기가 만든 흐름의 빈칸을 못 본다. 처음 보는 세션은 사람과 에이전트가 실제로 막히는 곳을 그대로 밟는다.

## 언제 하나

- 화면 흐름·붙여넣는 문장·초대 메일을 바꾸는 요구를 노트에게 보내기 전(지금 흐름의 막힌 곳 찾기)
- 그 개선이 배포된 뒤(같은 경로 재측정, 행동 수와 걸린 초 비교)
- 고객이 막혔다는 신호가 왔을 때(같은 경로를 재현)

## 순서

1. **경로 정하기**: 진입 경로별로 나눈다(초대 메일, carvit.ai 홈, SNS 글 링크, 재방문). 한 UT에 경로 하나.
2. **테스터 고르기**: 그 경로를 처음 겪는 세션. 우리 크루 대화 맥락이 없는 새 세션이 기본이고, 다른 기기 세션(북)이 가장 실제에 가깝다. 사전 설명은 주지 않고 사용자가 받는 것(메일·링크·문장)만 준다.
3. **기록 열기**: `python scripts/ops/jitu_po.py ut add --path "경로" --tester "세션 이름" --task "과제 한 줄"`
4. **과제 주기**: 사용자가 받는 그대로 건넨다. 묻는 것은 표준 네 가지로 고정한다.
   - A. 가장 막힌 곳 1~2개
   - B. 받은 안내(화면·문장)로 충분했나, 빠지면 곤란한 것은
   - C. 빼도 되는 것
   - D. 꼭 남길 것
   - 숫자: 사람 행동 수, 시작부터 끝까지 걸린 초
5. **결과 기록**: `ut result UT-n --text "요약" --blocks "막힌 곳" --actions N --seconds N --reqs "R-..."`
6. **요구로 옮기기**: 의견은 `req add --source "UT-n"`으로 영역에 넣는다. 사장님이 이미 정한 것과 부딪히는 의견은 넣지 않고, 이유를 테스터에게 회신한다.
7. **재측정**: 개선이 배포되면 같은 경로를 새 테스터(또는 같은 테스터)로 `ut add --retest UT-n`. 행동 수·초가 줄었는지로 완료를 판정한다. 결과 없이 2일 지난 UT와 반영 뒤 재측정 안 한 UT는 `due`에 뜬다.

## 지키는 것

- 테스터에게 계정 만들기·비밀번호 입력을 시키지 않는다(에이전트 금지 행동). 가입이 필요한 경로는 시험 계정을 쓰거나 사람 단계로 표시한다.
- 고객 이름·주소는 기록에 넣지 않는다.
- 테스터 의견도 판정 근거는 화면 원칙(UX 가이드 1.59: 1번 행동만 남기기)이다.
