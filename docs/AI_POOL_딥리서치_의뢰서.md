# AI Pool 프로젝트 Phase 2 딥리서치 의뢰서

> 2026-09-16 작성. 이 파일을 그대로 복사해서 딥리서치 도구(제미나이 등)에
> 붙여넣어 사용합니다. 결과를 반입할 때는 `multi-llm-handoff` 규약대로
> "[반입용 요약]" 문단이 있는지 확인하고, 출처 없는 수치는 미검증으로
> 표시해서 반영합니다.

---

## 의뢰 배경

우리는 1인 회사(심플리파이어)의 에이전트 팀(클로드 코드 여러 페르소나 +
헤르메스 상시 에이전트)이 리서치·검증 작업에 쓸 외부 LLM 자원을
넓히려 합니다. 이미 제미나이 공식 무료 API를 1단계로 도입했고,
다음 단계로 어떤 다른 공식 API를 추가할 만한지 조사해주세요.

## 절대 지켜야 할 전제

다음은 이미 검토했다가 반려한 방법입니다. **이 리서치에서 다시 제안하지
마세요**:

- 웹 서비스의 로그인 세션 쿠키를 추출해 로컬 API처럼 위장하는 방법
- 봇 탐지 회피(스텔스 브라우저, TLS 지문 변조), CAPTCHA 우회
- 무료 한도를 늘릴 목적으로 새 계정을 여러 개 만드는 방법

**공식으로 발급받는 API 키, 이미 존재하는 유료/무료 구독 계정의 정식
API 접근권만** 조사 대상입니다.

## 조사해줄 것

1. **아래 제공자들의 공식 무료 또는 저비용 API 티어 조건**을 표로
   정리해주세요(제공자별: 무료 여부, 분당/일일 요청 한도, 컨텍스트
   크기, 가입 방법, 신용카드 요구 여부):
   - OpenRouter
   - Nous Research (Nous Portal)
   - Z.AI (GLM)
   - Moonshot/Kimi (Kimi Coding, 중국/글로벌 버전 각각)
   - MiniMax (중국/글로벌 버전 각각)
   - AWS Bedrock (무료 크레딧·저비용 옵션이 있다면)
   - 그 외 위 목록에 없지만 소규모 팀이 실제로 쓸 만한 공식 무료/저비용
     API가 있다면 추가로 제안(단, 위 "절대 지켜야 할 전제"를 지키는
     것만)
2. **LiteLLM(오픈소스 프록시)로 여러 제공자를 한 풀에 묶는 모범 사례**:
   - 여러 제공자를 섞어 쓸 때(같은 제공자 키 여러 개가 아니라 제공자
     자체가 다를 때) 라우팅 전략을 어떻게 짜는지
   - 요청 실패·한도 초과 시 자동 재시도/쿨다운 설정의 실제 권장값
   - 비용·사용량을 제공자별로 추적하는 방법
3. **"여러 LLM을 풀로 묶어 쓰는 것"이 실제로 팀 성과에 도움이 되는지
   측정하는 방법**: 업계에서 쓰는 지표나 방법론이 있다면 정리(예: 검증
   단계에서 오류 검출률, 응답 지연시간, 토큰당 비용 등)

## 결과 형식

> 결과는 목적에 맞는 최소 표현으로 작성해줘. 산문·설명은 순수 마크다운,
> 표·레코드 데이터는 JSON(납작한 표는 CSV), 코드는 원본 코드 그대로,
> API 스키마는 JSON/OpenAPI. HTML이나 장식용 포맷은 쓰지 마.
> 맨 앞에 "[반입용 요약]" 한 문단(결론 우선, 5문장 이내)을 두고,
> 본문은 근거와 출처 위주로.
> 특정 회사·플랫폼의 자체 통계(가입자 수, 카테고리별 정확한 개수·비율
> 등)는 출처 URL이나 발표 문서명을 못 대면 절대 인용하지 마. 숫자
> 대신 "다수", "상당수" 같은 정성적 표현을 써.
