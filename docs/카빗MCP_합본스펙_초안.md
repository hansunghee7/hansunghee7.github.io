# 카빗MCP 합본 개발 스펙 (초안, 사장님 검토 전)

작성: 노트, 2026-10-22. 방식: [슈퍼실측.md](슈퍼실측.md) 7~8단계(실측과 설계를 합쳐 한 장으로). 근거 정본: [카빗MCP_과제_정본.md](카빗MCP_과제_정본.md).

**이 문서의 상태:** 실측은 끝났다(카빗DM 기술검증 백로그 완료, 공정 카드 노트-카빗MCP과제 #115). 아직 지투와 협의하지 않았고 구현도 시작하지 않았다. 사장님이 검토해 순서를 정한 뒤에 지투 협의로 넘어간다.

## 1. 목표와 대상

- 목표(사장님 10/20): 가입 직후 받은 프롬프트를 클로드 코드에 입력하면 통신하는 에이전트가 생긴다.
- 대상: 클로드 코드로 서비스를 만드는 스타트업 창업자와 팀.
- 흐름: 1단계 사용자가 카빗 MCP를 직접 설치(번들), 2단계 에이전트 호출 프롬프팅(페르소나 호출, 필수 문서 세팅, Help 안내).

## 2. 실측으로 확정된 사실 (스펙의 전제)

- 터미널: 설치·새 세션 호출·채널 수신이 실측으로 확인됐다.
- 앱: 설정 > 커넥터 추가, 설치 문장으로 설치(북 노트북), 새 세션 호출 프롬프팅이 확인됐다. 앱 세션 자체는 채널을 못 붙인다. 앱 터미널 탭에서 채널 세션을 따로 띄우면 즉시 깨어난다.
- 같은 세션에서는 새로 설치한 서버 도구가 로드되지 않는다. 새 세션이 필요하다.
- 같은 세션에서 계정 커넥터를 추가하면 기존 카빗 도구가 끊긴 사례가 있다(1회).
- 설치 직후 에이전트가 스스로 `agents`의 `me`를 확인하게 하면 5/5, 안 하면 2/5.
- 설치 배포 순서는 사장님이 정했다: uvx 한 줄(PyPI `carvit-autoreceive` 0.1.2 게시 완료). 2026-10-22 사장님 정정으로 zip 폴백은 폐기하고, uv가 없으면 같은 PyPI 패키지를 pip로 설치한다. 플러그인은 보류. 섞어서 설치하지 않는다.
- 수신 방식은 사장님이 정했다: 세션이 열려 수신 확인이 되면 출근으로 보고 DM, 아니면 우편함 저장.
- 막힘 진단표 8행(정본 B4 절)이 있다. S2는 부분 확인, S4 재현 절차와 S8 원인은 미확정이다.

## 3. 요구사항 목록 (번호, 내용, 근거, 담당 후보)

설치 단계
- R1. 설치 전에 같은 주소의 계정 커넥터가 있는지 점검하거나 안내한다. 같은 세션에서 커넥터를 추가했다면 새 세션을 열게 한다. 근거: 시사점 1, S2 재현. 담당 후보: 안내 문구(지투), 서버 지침(노트).
- R2. 설치한 에이전트가 자기 신원을 `agents`의 `me`로 스스로 확인한다. 근거: 시사점 2(5/5 대 2/5). 담당: 서버 지침(노트).
- R3. 안내 문구를 "재시작 후 이어서"가 아니라 "새 세션을 연다"로 바꾼다. 근거: 시사점 3, 사장님 10/20 결정. 담당: 안내 문구(지투).
- R4. 환경 선택(앱·터미널·그 밖)에 따라 다른 설치 문장을 보여 준다. 근거: 클릭형 시안(10/22), 앱과 터미널 경로가 다름. 담당: 화면(지투).
- R5. 설치 문장 복사: 설치 코드는 가리고(••••) 보기 토글, 복사는 항상 전체, 복사 뒤 "복사됨"과 다음 행동 한 줄("새 세션을 열고 붙여넣으세요"). 근거: 시안, 가이드 UX_GUIDE_CARVIT. 담당: 화면(지투).
- R6. 막혔을 때 대체 경로: 진단표 8행을 사용자에게 보이는 증상 기준으로 안내한다(Help 챗봇은 보류이므로 우선 정적 안내). 근거: B4. 담당: 안내 문구(지투), 내용(노트).
- R7. 알림기 배포는 PyPI 정본 하나(uv가 있으면 uvx, 없으면 pip). zip은 폐기(사장님 10/22, 사용자에게 zip 명칭 비노출). 플러그인은 보류. 근거: 3종 실측과 사장님 결정(노트#104, #158). 담당: 서버·패키지(노트). 상태: 문장 반영 완료(PR 813).

호출 단계
- R8. 호출 프롬프트 복사 화면과, 첫 세션에서 사람이 입력하는 질문(MCP 승인, 폴더 신뢰, 최초 1회 "Pending approval")의 안내. 근거: 호출 프롬프팅 앱 실세션 1/1. 담당: 화면(지투).
- R9. 에이전트끼리 대화가 오갈 때 Help가 "여기서 확인하세요"라며 관전방(Agents 탭) 링크를 안내한다. 근거: 설계 항목(PR 2524). 담당: Help 안내 문구(지투).

통신 단계
- R10. 출근 판정: 세션이 열려 수신 확인(에이전트의 확인 또는 시스템 안의 설정)이 되면 DM으로, 아니면 우편함에 저장한다. 근거: 사장님 10/21 확정. 담당: 서버(노트), 구현 설계는 아래 4절.
- R11. 앱 상시 수신은 R10으로 갈음하고, 터미널 채널 사용은 안내로만 한다(앱 터미널 탭 채널 세션이 깨어남). 담당: 안내 문구(지투).
- R12. 설정 > 커넥터 목록이 기대와 다를 때 화면을 새로 고쳐 실제 목록을 확인하라는 안내(S8). 근거: 관측 2건. 담당: 안내 문구(지투).

## 4. 지투에게 물을 구현 설계 질문 (실측 뒤 협의할 것)

카빗DM 181로 보낸 세 가지(회신은 보류 상태)다.
1. 출근 신호: 무엇을 신호로 볼 것인가(`last_seen_at`, 읽힘 표시, 알림기 확인 중 무엇을 쓰나).
2. 판정 시간 설정: 몇 분 안이면 출근인가, 고객이 바꿀 수 있나.
3. 보낸 쪽 표시: 보내는 사람에게 상대가 출근인지 우편함으로 갔는지 어떻게 보여 주나.

정본의 다른 재료로 `act_as` 신원 전환과 세션 매핑이 있다. 질문 협의 때 함께 다룬다.

## 5. MCP 서브메뉴 구조 변경안

지투가 이미 올린 안이고 사장님이 홀드해 둔 상태다. 노트는 원문을 이 초안에 옮기지 않았다. 협의 때 지투의 원문을 이 스펙의 R4~R9와 맞춘다(화면 구조가 겹치는 부분만 조정).

## 6. 구현 순서 제안

1. 문구와 서버 지침으로 끝나는 것부터: R2, R3, R1(문구 부분), R11. 위험이 작고 바로 효과를 잴 수 있다.
2. 패키지 배포: R7(PyPI 0.1.2 게시 완료, 문장은 uvx·pip 두 갈래로 정리, zip 폐기, 플러그인 보류).
3. 화면: R4, R5, R8, R9 (지투 시안, 노트 서버 연동).
4. 출근 판정 구현: R10 (서버 계산 가능 여부 확인이 선행).
5. 진단표 안내: R6, R12.

원칙: 각 단계는 구현 전에 사장님 확인을 받고, 구현 뒤 실제 환경에서 한 번 더 돌려 본다.

## 7. 사장님이 정하실 것

- 5절의 서브메뉴 변경안을 이 스펙에 합칠지(합친다면 협의 때 지투 원문을 보고 조정).
- 4절의 질문 3가지를 지금 지투에게 보낼지(사장님 허용 뒤에만 보낸다).

## 8. 한계

## 9. 진행 현황 (2026-10-22 오후, 사장님 "순서대로 진행")

지투·탐 회신 반영과 1단계 확인 결과다. 구현 PR은 아직 없다.

- R2(설치 후 `me` 자가 확인): **이미 구현돼 있다.** R-196(#776)이 첫 호출에 "연결 확인: 회사 공간, 내 에이전트 이름, 동료 수, 문서"를 붙인다. 10/22 앱 실세션 캡처에서 실제로 나왔다. 추가 코드는 필요 없다.
- R3·R1(안내 문구): 사용자 화면 문구라 지투 소관이다(사장님 10/6). 현재 `agent_prompt.py`의 `RESTART_KO`와 추가 에이전트 프롬프트에 "세션을 다시 시작"으로 적혀 있어 실측("재시작 선택은 새 서버를 못 읽음, 같은 폴더에 새 세션은 읽음")과 다르다. 문구 제안을 지투에게 전달했다(카빗DM 188). 지투가 문구를 정하면 노트가 코드를 바꾼다. 영어판(`RESTART_EN`, 추가 프롬프트 영어)도 같이 바꾼다.
- R10(출근 판정) 서버 계산 가능 여부(노트 영역 확인 결과):
  - `last_seen_at`은 에이전트가 카빗 도구를 부를 때 5분에 한 번(`SEEN_REFRESH`) 갱신된다. 알림기가 기다리는 것만으로는 갱신하지 않는다(의도적).
  - 그래서 "최근 N분 안에 도구를 불렀다"는 서버가 지금 값으로 계산할 수 있다. 새 칸은 필요 없다. 판정 시간 기준은 갱신 간격(5분)보다 길어야 한다.
  - "받았다"의 정의 후보는 DM의 읽힘 표시(`dm_sent`의 읽은 시각)다. 알림 쪽지(`dm_notice`) 지연은 평균 약 4분이다.
  - 아직 정해야 할 것: 판정 시간(몇 분), 터미널 채널 세션처럼 도구를 안 부르고 쉬는 세션을 출근으로 볼지(알림기 신호를 `last_seen_at`에 반영하지 않는 현재 설계를 바꿀지).
- R13(신규): 같은 폴더에서 여러 에이전트(예: 탐·노트·마야)가 세션을 열면 카빗MCP 신원이 폴더 하나로 정해져 모두 같은 이름으로 나온다(탐 세션이 지금도 노트로 나옴, 탐 10/22 11:20 실측). 사용자 쪽에서는 "한 폴더 = 한 에이전트" 안내가 필요하고, 한 팀이 여러 페르소나를 한 저장소에서 쓰는 경우 폴더별 설치(`--scope local`)나 신원 선택 기능이 필요하다. 설계 항목으로 올린다.
- 병행: 바이블 통합 2단계는 지투가 이름 `BIBLE_UX_PLAYBOOK` 유지와 시험 4개 선행에 동의했다(카빗DM 185·186). 운영 DB를 바꾸는 단계는 사장님이 그 세션에서 직접 승인한다.
- 제약(탐 11:01 우편): 10/23 13~17시 제품 저장소 배포 금지. 새 코드는 옛 환경변수 이름 대신 `CARVIT_` 새 이름만 쓴다.

## 10. 지투 답 반영 (2026-10-22 오후, 카빗DM 189·190)

- R3·R1 문구: 지투가 한·영 문구를 확정했다(노트는 코드만 변경). 제품 저장소 PR 800(`agent_prompt.py`의 `RESTART_KO/EN`, 에이전트 추가 문장 한·영, 첫 연결 안내에 R1 문장). 지투 검토·병합 대기.
- R10 출근 판정(지투 제안, 노트 서버 확인과 일치):
  - 신호: `agents`의 `last_seen_at`(최근 도구 호출). 새 칸 없음. 읽힘 표시는 보조 정보. 알림기 확인을 `last_seen_at`에 반영하는 설계 변경은 이번에 하지 않는다(쉬는 터미널 채널 세션은 DM 수신 확인이 오면 출근으로 보는 R10 문장 그대로).
  - 판정 시간: 갱신 간격(5분)보다 길어야 하므로 기본 15분(설계값, 실측 뒤 조정). 고객 설정은 처음엔 두지 않고 요청이 생기면 설정에 추가(기본값은 흔한 선택, 바이블 27절).
  - 보낸 쪽 표시: 글자 한 줄로 두 상태만. "상대가 지금 열려 있어요" / "우편함에 두었어요. 열면 바로 읽어요". 색으로만 구분하지 않는다(바이블 2절).
- 서브메뉴 구조 변경안 원문: 아티팩트 "Carvit Home 제안"(10/20 마지막 갱신). 내용은 홈을 없애고 대시보드를 첫 화면으로, 막대 그래프 중심(기본 7일), 메뉴 4개(대시보드, DM 방 새 창, UX 가이드, 설정). 지투 요구 장부 R-238~R-246(R-239 DM 방 새 창, R-243 대시보드 그래프, R-244·245 기존 지표 유지). 10/18 "로그인 후 화면 시안"은 구버전이라 무시한다. 합본의 R4~R9 화면 요구는 이 안에 맞춘다.
- 화면 시안(R4·R5·R8·R9·R12): 담당 지투. 가이드에 부품 규칙(탭, 설치 코드 칸, 문장 상자, 복사 버튼, 다음 행동 한 줄)을 먼저 올린 뒤 시안. 10/23은 13~17시 배포 금지와 대표 미팅이 있어 착수는 10/24 이후 제안(사장님 순서 확인 대기).
- R-203·R-204(지투 요구): 착수 전, 병합된 PR 없음. R-203은 가이드에 상태 절이 있는지 확인이 선행. A-159는 폴 답 대기(10/27까지 답 없으면 "회사 문서 올리고 조회하는 도구"로 안내하는 기본값).
- 바이블 통합 2단계: 이름 `BIBLE_UX_PLAYBOOK` 유지, 시험 4개 선행에 동의. 구현 분담(지투와 서브에이전트가 시험·코드 PR, 노트 리뷰, DB 적용은 노트·탐)은 사장님 확인 대기.
