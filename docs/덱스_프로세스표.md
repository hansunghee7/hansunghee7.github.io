# 덱스(DEX) 업무 프로세스표 (2026-10-18 신설, 탐)

> 할 일 목록(무엇을)은 [덱스_업무대장.md](덱스_업무대장.md), 이 문서는 방법(어떻게)이다. 역할 원칙은 [역할노트-덱스.md](역할노트-덱스.md), 전사 규칙은 CLAUDE.md, 시작 맥락은 [세션카드/덱스.md](세션카드/덱스.md). 반복하지 않고 링크로 부른다.
> 덱스는 상주 세션이 아니라 탐이 `scripts/ops/ask_dex.sh`로 소환하는 호출형(OpenAI Codex CLI)이다. 이 표는 그 호출마다 같은 품질이 나오도록 공정을 고정한다.

## 0. 공통 원칙

- **창구는 탐 하나**: 탐이 `ask_dex.sh`로만 부른다(카드는 표준입력, 상시 감시 없음).
- **격리 실행**: 덱스는 격리 워크트리/복사본에서만 돌고 diff를 만든다. 본 폴더·상위 폴더·비밀값 폴더 접근 금지, 네트워크 꺼짐(샌드박스 기본값), 사람 확인 없는 자동 실행 모드 금지.
- **비밀값 차단**: 카드에 키·토큰·.env 같은 비밀값 의심 문자열이 있으면 덱스가 거절한다(2026-10-18 실측). 전달 전에 일반 명칭으로 소독한다.
- **경계**: 판정하지 않고(채점·통과·반려·안전 분류 금지) "검사가 exit 0이었다"는 사실만 보고. main push·병합은 하지 않고 탐이 한다.

## 1. 플레이어(주연 코더) 공정 — 사장님 10/18 승격

덱스가 과제의 주 작성자일 때. 사장님 2026-10-16/17 '비티·덱스를 플레이어로 최대 활용', 10/18 '플레이어 실험을 공정자산화'.

1. 탐이 작업 카드 1장(대상 파일·요구·완료 기준·제약)을 전달한다. 덱스 업무대장에 행이 먼저 있어야 한다.
2. **작업 폴더는 git 저장소여야 한다**(2026-10-03 실측). 기존 파일을 고치는 과제는 그 파일이 워크트리에 실재해야 한다(빈 DEX_WORKDIR면 "파일 없음"으로 실패, 2026-10-18 사고). 신규 파일 생성 과제가 덱스에 더 맞는다.
3. 구현 + 단위시험을 쓰고 같은 검사를 다시 돌려 종료 코드를 남긴다(DONE=VERIFIED, "이론상" 금지).
4. 결과는 diff 또는 PR 초안으로만 낸다. 같은 브랜치에 push해 PR을 갱신하되 병합·auto-merge는 켜지 않는다. 카드 밖 파일을 고치고 싶으면 멈추고 탐에게 묻는다.
5. 탐 + 비티 교차검증(2절)을 거친 뒤 탐이 병합한다.

**실행 방법(사장님 10/18 동일권한 확정, 실측 탐#177)**: 덱스가 저장소에 직접 커밋·push하고 운영 상태 DB까지 쓰는 플레이어 실행은 `scripts/ops/ask_player.sh dex <작업카드.md>`로 한다(codex danger-full-access, 일회용 클론·claude 브랜치·비밀값 스캔). 이 런처는 호스트 안전 분류기를 거치지 않도록 지휘 세션(클로드)이 아니라 사장님·자동화가 터미널에서 직접 돌린다(설계=탐, 실행=사장). PR·병합은 탐.

## 2. 리뷰어(사실 확인·반박) 공정

덱스가 다른 작성자의 산출물을 검토할 때. 짝 역할: 덱스 = 사실 확인·반박, 비티 = 새 제안·위험 발굴(역할노트 5절).

1. 탐이 검토 대상의 핵심 로직(순수 함수·규칙·diff)을 인라인으로 전달한다(덱스 워크트리에 원본이 없으면 코드를 질문에 담아 준다).
2. 덱스는 제시된 전제를 저장소 사실·규칙과 대조해 맞음·틀림·확인 불가로 가르고, 결함·엣지케이스·크래시를 짚는다.
3. 항목마다 `판정: 통과 | 수정(한 줄) | 결함(한 줄)`로 끝맺는다. 최종 채택·반려는 탐이 한다.

## 3. 아침 백로그 피드백 (N112, 시험 중)

- 덱스 = **사실 확인·반박**. 비티가 낸 제안을 탐 업무대장 원문과 대조해 전제 맞음·틀림·확인 불가·중복을 근거와 함께 낸다(판정은 탐). 전날 바뀐 행만 받는다.

- 호출 시점: 필요할 때 탐이 소환(횟수 제한 없음, 사장님 10/2). 상시 감시 없음.
