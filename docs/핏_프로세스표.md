> 핏이 반복하는 업무의 "어떻게"만 모은다. 할 일의 상태는 [핏_업무대장.md](핏_업무대장.md). 아래 절차는 10/4에 실제로 돌려 확인한 것이다. 확인하지 못한 것은 "미확인"으로 적는다.

## 원칙(사장님 10/4)
- 고정 주기로 반복해서 날리는 핑·조회·작업은 기계로 읽힌다. 주기는 무작위로 흔들고, 상태 확인은 사람처럼 화면으로 한다.
- 생성은 딱딱 맞추지 않고 가끔 살짝 쉬되, 너무 긴 휴식은 두지 않는다. 한 편이 끝나면 약 20분 쉬거나 다른 계정으로 넘어간다.
- 차단이나 정책 실패가 보이면 같은 프롬프트를 바로 다른 계정에 던지지 않는다. 장소를 옮기고(신PC) 사람이 확인한다.
- 사장님께 절차를 드리기 전에 기록을 먼저 찾고, 기록이 없으면 내가 끝까지 시험한다.

## 1. Flow로 한 컷 만들기 (신PC, 검증 10/4)
- 어디서: 신PC 크롬(Claude in Chrome 탭 그룹), 계정 슬롯 `flow.google.com/u/N/`(0 simon@simplifier, 1 myloveplanning, 2 hansunghee7 프로, 3 mylovesimplifying, 4 hansunghee7777).

- 프롬프트는 `execCommand('insertText')`로 넣는다(줄바꿈을 키보드 입력으로 치면 일부만 들어간다). 화살표는 한 번만 누른다.
- 생성은 약 40~60초. 컷 사이는 20~60초 불규칙. 크레딧이 모자라면 팝업이 뜨니 계정을 바꾼다.

## 2. Flow 영상 내려받기 (검증 10/4)
- 프로젝트 화면에서 영상 타일을 **우클릭 → 아래에 뜨는 메뉴의 "다운로드"**. 파일 이름이 영상 제목으로 저장되어 씬 구분이 쉽다.
- 영상을 연 뒤 `⋮ → 미디어 다운로드 → 360p 원본 크기`도 된다.
- 막히는 경우: 화면 위 검색창이 포커스를 가지면 다른 클릭이 먹히지 않는다. 먼저 빈 곳을 누르고, 영상은 다 로드된 뒤에 누른다.

## 3. Vids로 한 컷 만들기 (신PC, 가로, 검증 10/4)
- 계정: hansunghee7777(u/4)은 9/24 이후 사용 안 해 한도가 열려 있다. hansunghee7 프로(u/2)는 한도. 구PC 5개 계정은 모두 한도(10/4).
- 새 문서(`docs.google.com/videos/u/4/` 의 `+`) → 시작 창에서 가로 모드(기본) → "AI 동영상 만들기" → 프롬프트(**순수 영어**, 한글·대괄호 금지) → 생성 → 약 1분 → 미리보기에 `720p • 0:10`과 **"삽입"**이 뜨면 → **삽입을 눌러야** 문서에 들어간다.
- 내려받기: **파일 → 다운로드 → MP4 동영상(.mp4)**. 결과는 1920x1080·10초·오디오. 렌더링에 1분 안팎.
- 한 문서에 한 컷(여러 컷을 이어 삽입하면 재생헤드가 0초로 리셋되는 알려진 버그).
- 예전 기록(구PC 자동화, 9/24)은 `<video>` src를 직접 받는 방식(`docs/구PC_작업실_영상레시피.md` 2절). 신PC 수동 경로는 그것과 다르다.

- **스크립트 방식(10/4 lf02 46컷 실측, 정본 shorts-lab `tools/factory/vids_page_runner.js` 주석)**: 새 문서는 `https://docs.google.com/videos/u/N/create`. 생성 뒤 미리보기 영상(1280x720)을 페이지 스크립트가 로컬 서버(`vids_save_server.py`, 127.0.0.1:8790)로 저장한다. 파일>다운로드 MP4는 합성 클릭으로는 "문제가 발생했습니다"로 실패한다(실제 클릭만 됨, 파일은 `D:\Downloads`). 컷당 호출 2개(다음 컷 시작+직전 컷 저장 확인, 사이에 45초 대기). 가려진 탭은 호출 안에서 오래 기다리면 시간 초과되므로 대기는 호출 사이에서 한다. 같은 번호를 다시 시작하면 중복 생성된다.
- **계정별 한도 실측(10/4)**: simon@simplifier(u/0, 워크스페이스)는 약 50회 생성에도 한도에 닿지 않았다. hansunghee7777(u/4, 무료)은 하루 5회 안팎 뒤 "생성 한도에 도달했습니다"(21:55경). 나머지(u/1·u/3·u/2)는 미측정.
- 720p 미리보기본은 `tools/sheet/upscale_clips_1080.py`(Video2X ×2 후 1080p, 컷당 약 15초)로 맞춘 뒤 조립한다.

- **제작 완료 때 시트 갱신(10/5 사장님 지시)**: 대본 컨펌 뒤 `sheet_update_ep.py <편ID> --status 제작중`, 조립 뒤 `--status 영상제작완료`(에피소드ID·최종파일 자동), 조회수·팔로워 증가수는 `sheet_push_perf.py --apply`. 상세는 shorts-lab `LONGFORM_PROCESS.md` 7절.

## 4. 롱폼 조립 (로컬, 검증 10/4)
- 클립을 `04-scenes/flow_clips/씬NN.mp4`로 모으고 `tools/sheet/verify_clips.py <폴더> --expect <씬수>`가 통과해야 한다.
- 자막은 `pipeline/build_srt.py <편폴더> 10`.
- `tools/sheet/build_final.py <클립폴더> 04-scenes/timing_scenes.json narration.mp3 05-assemble/captions.srt 05-assemble <이름> --assembler assemble_ep3.py --w 1280 --h 720 --no-upscale`.
- 화질이 섞일 때(Flow 360p + Vids 1080p, 10/4 lf01 실측): 360p 컷을 컷마다 Video2X ×3(realesrgan animevideov3)으로 1920x1080까지 올린 폴더(`flow_clips_1080`)를 위 명령에 넣고 `--w 1920 --h 1080 --no-upscale`로 조립한다(조립 뒤 통째 업스케일 안 함). 컷당 약 5초, 49컷 약 4분. 스크립트·유튜브 등록·시트 미러링은 shorts-lab `LONGFORM_PROCESS.md`가 정본이다.

- 주의: 로컬 시험(`apt_local_build.py`)이 `timing_scenes.json`을 덮어쓴다. 시험 전에 백업한다.
