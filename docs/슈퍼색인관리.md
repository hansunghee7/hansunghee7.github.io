# 슈퍼색인관리 (사장님 명명 2026-10-15)

기록을 찾는 순서와 어떤 기록이 1차 검색에 걸리게 할지 정한 정본이다. 공정 카드: 공용-슈퍼색인관리 #1.

## 찾는 순서

- **1차 검색**: 정본 프로세스(공정 카드, 사장님 결정 칸 포함)와 최신 의사결정(사장님 최근 14일 발화). 답하기 전에 `python scripts/ops/recall.py "<사장님 말>"`을 먼저 본다. 사장님 메시지마다 UserPromptSubmit 훅이 같은 검색을 자동으로 보여 준다.
- **2차 검색**: 정본 문서(정본 문서 지도 `canonical_map`의 14개 주제, docs 표의 정본 역할). 4단계에서 recall에 연결한다.
- **히스토리**: 업무 기록(worklog, handoff, closed, open, fact, history)과 대체된 옛 카드·옛 문서. 1차 결과에 섞지 않는다. 필요할 때만 `recall.py --history "<말>"`로 찾는다.

## 결정은 카드로 올린다

업무 기록에만 남은 결정은 1차 검색에 걸리지 않는다. 사장님이 정한 것, 에이전트끼리 합의해 사장님께 보고한 것은 같은 세션 안에 공정 카드(`proc.py add`)로 올린다. 올렸는지 점검하는 후보 도구가 `python scripts/ops/promote_queue.py --days 7`이다(읽기 전용).

## 정본은 하나

같은 규칙이 카드, 문서, 스킬에 다르게 적혀 있으면 한쪽을 정본으로 정하고 나머지는 그쪽을 가리키게 고친다(CLAUDE.md 도구 관문 절과 같은 원칙). 3단계에서 충돌 점검 도구를 만든다.

## 단계

1. 완료: recall.py 계층화, 동의어 확장(예: 깃배포와 Actions 분 절감을 같은 뜻으로 찾음), `--history`.
2. 승격 큐: `promote_queue.py`로 업무 기록 결정 중 카드가 없는 행을 찾아 카드로 올린다.
3. 정본 충돌 점검, 4. 2차 검색에 정본 문서 지도 연결, 5. 대체된 카드·문서의 히스토리 이동.

측정: 기억을 못 찾은 실제 사례를 시험 세트로 쌓고 1차 적중률을 잰다.
