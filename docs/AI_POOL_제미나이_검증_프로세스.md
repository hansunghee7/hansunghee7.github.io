# AI Pool: 제미나이 검증 프로세스

> 2026-09-16 도입. AI_POOL_프로젝트.md 원칙4(제미나이는 검증 전용)를
> 실제로 어떻게 돌리는지 정의한다.

**역할 정의**: 1차 판정 기준은 헤르메스가 확보한 원본 출처 자체다(4번
원칙). 제미나이 무료 API는 그 위에 얹는 **2중 안전장치**다 - 헤르메스가
출처를 잘못 요약했는지, 출처 자체가 없는 주장이 있는지를 잡아내는
보조 역할이지, 제미나이가 1차 판정자가 아니다.

## 초기 방식과 문제 (정확도 70%)

사장님이 처음 시도한 순서:

1. 제미나이에게 딥리서치(자체 조사)를 먼저 시킴
2. 헤르메스에게 같은 주제를 독립적으로 조사시킴
3. 1번 결과를 이미 가진 제미나이에게 2번(헤르메스 결과)을 평가시킴

**원인**: 3번에서 제미나이는 1번(자기 자신의 리서치)을 정답으로 놓고
헤르메스를 채점한다. 1번은 정답이 아니라 또 다른 AI 리서치 결과일 뿐이라,
이 구조는 "헤르메스 대 실제 사실"이 아니라 "헤르메스 대 제미나이의 의견"을
비교한 것이다. 두 가지 실패가 동시에 생긴다.

- 헤르메스가 맞았는데 제미나이 자기 리서치와 달라 오답 처리(자기 편향).
- 제미나이 자기 리서치가 틀렸는데 헤르메스도 같은 실수를 하면 "일치"로
  통과(공통 오류를 못 잡음).

부수 효과: 1번(제미나이 딥리서치)은 원칙4가 금지한 "제미나이를 1차 조사에
쓰는 것"에 해당해, 그라운딩(웹검색) 호출량도 늘어난다.

## 개선된 프로세스

1. **헤르메스가 1차 조사한다**(그대로 유지, 원칙4). 주장뿐 아니라
   출처(URL·인용문)까지 같이 정리한다.
2. 결과를 **개별 사실 주장 단위**로 쪼갠다.
3. 제미나이에게 **자체 리서치를 시키지 않는다.** 헤르메스가 가져온 출처
   자료를 그대로 컨텍스트로 주고, "이 주장이 이 자료와 일치하는가"만
   판정시킨다. 출력은 구조화된 형식으로 강제한다:
   ```json
   {"claim": "...", "verdict": "confirmed|unsupported|contradicted", "evidence_quote": "...", "source": "..."}
   ```
4. **원본 출처가 확보된 자료는 그 자체로 정답 처리한다**(2026-09-16
   사장님 지시). 헤르메스가 가져온 출처가 실제로 존재하고 확인 가능하면,
   그 출처의 신뢰도를 다시 의심하지 않고 `confirmed`로 진행한다.
   그라운딩 재확인은 **출처 자체가 없거나(`unsupported`) 확인이 안 되는
   경우에만** 그 건 하나에 한해 실행한다. 전체를 다시 리서치시키지
   않는다.

이러면 "제미나이 의견 대 헤르메스 의견" 대결이 아니라 "헤르메스 주장 대
헤르메스가 직접 가져온 자료"를 체크하는 팩트체크가 된다.

## 남은 한계

이 프로세스는 "헤르메스가 자기 출처를 정확히 요약했는가"를 검증한다.
"출처 자체가 맞는 원본인가"는 별도로 의심하지 않는다(4번 원칙) - 출처가
확보돼 있으면 정답으로 간주하고 진행 속도를 우선한다.

## 이 워크플로가 마야·탐 블로커에 미치는 영향

- **그라운딩 할당량 블로커**: 제미나이가 더 이상 자체 리서치를 안 하므로
  대부분 해소된다. 남은 그라운딩 호출(4번, 의심 건 재확인)만 저빈도로
  필요하다.
- **외부 뉴스·블로그 직접 접근 블로커**: 헤르메스(로컬 탐 또는 로컬
  마야가 실행)가 원문을 가져와 저장소·진행상황.md에 남기면, 클라우드
  세션(마야·탐)은 그 결과물만 읽으면 되므로 외부 사이트에 직접 접속할
  필요가 줄어든다.
- **심플리파이어 다이얼로그 Ask API 블로커**: 이 워크플로와 무관한 별개
  문제다(내부 API 호출이지 리서치가 아님). 클라우드 환경 네트워크 정책에
  도메인을 추가하는 기존 조치로 별도 해결한다.
