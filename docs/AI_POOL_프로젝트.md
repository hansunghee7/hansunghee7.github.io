# AI Pool 프로젝트

> 2026-09-16 신설(사장님 지시). 우리 에이전트(헤르메스·클로드 코드·페르소나
> 세션들)가 다양한 외부 AI의 토큰을 풍부하게 활용해서 퍼포먼스를 극대화하는
> 것이 목표. 개별 작업 지시서가 아니라 **지속되는 프로젝트**라 이 문서에
> 정본을 두고, 단계(phase)가 늘 때마다 이 파일에 절을 추가한다.

## 원칙

1. **공식 API·정식 계정만.** 스크래핑, 세션 쿠키 추출, 봇 탐지 회피, 한도
   회피 목적의 신규 계정 생성은 하지 않는다(`multi-llm-handoff` 규약의
   영구 금지 항목과 동일 경계). 이 프로젝트가 "토큰을 풍부하게 쓴다"고 해서
   이 경계가 바뀌지 않는다.
2. **이미 보유한 자산부터.** 새 구독·새 계정을 늘리기 전에, 사장님이 이미
   갖고 있는 유료 계정의 API 접근권부터 활용한다.
3. **1인 회사 규모가 아니라 공정자산·확장성 기준으로 설계한다**
   (CLAUDE.md §8649). 지금 당장 필요한 만큼만 만들지 않고, 프로젝트가
   커질 걸 감안한 구조를 처음부터 잡는다. 단, 검증되지 않은 실험을 그대로
   운영에 앉히지는 않는다(CLAUDE.md §f3a9, DONE=VERIFIED).
4. **호출량 자체를 줄이는 설계를 우선한다.** 외부 AI를 1차 조사 계층에
   두지 않고, 헤르메스·클로드 코드가 자체적으로 할 수 있는 건 자체적으로
   하고 외부 AI는 검증·보강 용도로 쓴다.

## Phase 1: 제미나이 무료 API 풀 (2026-09-16, 진행 중)

- **목표**: 잉크 프로젝트(마야)와 쇼츠랩(핏)의 검증 단계에 제미나이를
  붙인다. 그라운딩(웹검색)은 원칙4에 따라 기본 경로가 아니다 (아래 검증
  프로세스 참고).
- **경위**: 제미나이 딥리서치가 제안한 스크래핑 기반 3계정 풀(세션 쿠키
  추출 + 봇 탐지 회피)을 반려하고, 공식 무료 API로 재설계. 이후 역할을
  "1차 조사"에서 "검증 전용"으로 축소해 호출량을 낮췄다. 계정 3개를
  프로젝트별(잉크/쇼츠랩) 전담 배정하는 안을 한 차례 검토했으나, 이 풀이
  특정 프로젝트 2개가 아니라 전 에이전트 공용 자원이라는 지적에 따라
  **단일 LiteLLM 풀(`gemini-pool`, 3키 + 자동 재시도)**로 최종 확정.
- **구조**: `docs/지시서/2026-09-16_로컬탐_헤르메스모델라우팅.md` 0절에
  LiteLLM 설정 전문. 설계 배경·비교표는 아티팩트
  (https://claude.ai/artifact/FM86igrvHaA6H5ztKM6g2G).
- **현재 상태**: 서로 다른 구글 계정 3개(project 번호 `100742441770`,
  `1030756466986`, `911161170287`) 확보, LiteLLM 프록시 실행 및 실제
  chat completion 성공까지 검증 완료(2026-09-16, 로컬 탐).
  `--host 127.0.0.1` 로컬 전용 바인딩 + `LITELLM_MASTER_KEY` 인증으로
  외부 유출 방지. 키 값은 로컬 `.env`에만, 저장소·문서에는 값을 남기지
  않는다. **한계**: 클라우드 세션(탐·마야)은 이 프록시가 있는 신PC의
  localhost에 물리적으로 도달할 수 없어 접속 불가하다 (아래 검증
  프로세스 절 참고).
- **미확인**: 무료 티어 정확한 분당/일일 한도, Hermes가
  `router_settings.fallbacks` 구문을 지원하는지.
- **검증 프로세스(2026-09-16)**: 제미나이에게 자체 딥리서치를 먼저 시키고
  그 결과로 헤르메스 조사를 채점하는 초기 방식은 정확도 70%에 그쳤다(제미나이
  자신의 리서치를 정답으로 놓고 채점하는 자기 편향 문제). 헤르메스가 가져온
  출처 자료를 그대로 제미나이에게 주고 주장 단위로 대조시키는 방식으로
  교정했다. 상세: [docs/AI_POOL_제미나이_검증_프로세스.md](AI_POOL_제미나이_검증_프로세스.md).

## Phase 2 조사 (딥리서치 반입 완료, 미채택 · 2026-09-16)

- 의뢰서: [docs/AI_POOL_딥리서치_의뢰서.md](AI_POOL_딥리서치_의뢰서.md).
  결과 전문은 비공개 저장소
  `simplifier-cxo-db/research/2026-09-16_AI_Pool_Phase2_멀티프로바이더_딥리서치.md`에
  보관(공개 저장소에는 전문을 안 올림, multi-llm-handoff 규약 1원칙).
- **채택하지 않음.** 이유 셋:
  1. 보고서의 RPM/RPD/가격/컨텍스트 수치는 전부 출처 없이 정밀하게
     제시됨. 이 세션은 `generativelanguage.googleapis.com`(제미나이) 외
     다른 제공자 도메인이 전부 네트워크 차단이라 하나도 직접 검증 못 함.
  2. 제안된 YAML에 원본 딥리서치의 인용 태그(`[span_NNN]`)가 단어
     중간에 그대로 섞여 있어 실제로는 문법이 깨진 텍스트(예:
     `mod[span_171]el_list:`). 정리 전엔 그대로 못 쓴다.
  3. 제안 아키텍처(Redis 기반 usage-based-routing, PostgreSQL
     spend_logs, Prometheus, 에이전트별 가상 키+예산)가 지금 규모에
     과함(`multi-llm-handoff`의 "다중 LLM 병렬 파이프라인은 S1 규모에
     과함" 원칙과 충돌). Phase 1(제미나이)조차 아직 실사용 검증 전인데
     Phase 2 제공자를 더 늘리자는 순서도 이미 합의한 "Phase 1 검증 후
     판단" 원칙과 어긋남.
- **잘된 점**: 스크래핑·봇 탐지 회피 등 의뢰서에서 금지한 항목은 안
  건드림.
- **후보로만 기록**(실제 채택 시 사장님이 직접 콘솔에서 재확인 필수):
  카드 등록 불필요·무료라고 주장된 Z.AI(GLM-4-Flash), Groq, Cerebras가
  1순위 확인 후보. Phase 1이 실사용으로 검증되기 전까지는 착수하지
  않는다.

## Phase 2 착수 (2026-09-17, 사장님 지시: 우선순위 높게)

Phase 1 게이트가 실제로 풀렸다. `gemini-pool`이 delegation 실사용
DONE=VERIFIED까지 확인됐고(헤르메스 모델 라우팅 지시서 9절), 밤새 실제
fallback·delegation 호출에도 쓰였다. **위 Phase 2 조사 절의 반려 사유
셋(출처 없는 수치, 깨진 YAML, 과한 아키텍처)은 그대로 유효하다.** 그
딥리서치 결과물을 다시 꺼내 쓰지 않는다. 대신 같은 원칙(공식 API, 이미
보유한 자산, 호출량 자체를 줄이는 설계)으로 처음부터 가볍게 다시 한다.

할 일(로컬 탐):
1. 후보 3개(Z.AI GLM-4-Flash, Groq, Cerebras)를 순서대로, **딥리서치
   수치를 믿지 말고 직접** 공식 가입 화면에서 무료 티어 여부·카드 등록
   필요 여부·실제 한도를 확인한다. 카드 등록이 필요하면 그 후보는 이번
   단계에서 제외(무료·카드 불필요 조건은 원칙2의 "이미 보유한 자산부터"
   정신과 맞지 않으면 보류).
2. 되는 후보부터 실제 키를 발급해 chat completion 1건을 성공시킨다
   (DONE 기준, Phase 1 때와 동일한 검증 수준).
3. 아키텍처는 새로 만들지 않는다. 기존 `litellm_config.gemini-pool.yaml`에
   `model_list` 항목만 추가하거나(다른 이름의 풀로 분리할지, 같은
   `gemini-pool`에 합칠지는 라우팅 성격이 다르면 분리, 비슷하면 합치는
   쪽으로 로컬 탐이 판단), Redis/PostgreSQL/Prometheus 같은 새 인프라는
   추가하지 않는다(위 반려 사유 3번과 동일 원칙).
4. 완료 후 이 문서에 새 절("Phase 2: 실사용", 날짜 포함)을 추가해서
   기록한다.
