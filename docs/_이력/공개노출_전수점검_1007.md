# 공개 저장소 노출 전수 점검 (읽기 전용, 2026-10-07)

## 왜 했나

`scripts/check_public_leaks.py`는 PR의 **새로 추가된 줄만** 본다. 그 전부터
저장소에 있던 줄은 못 잡는다. 이번 점검은 같은 네 가지 패턴을 저장소
**전체**에 수동으로 돌려, 이미 들어가 있는 노출이 있는지 목록만 만드는
작업이다. 아무 파일도 고치거나 지우지 않았다.

## 점검 방법

- 대상 확장자: `.md .py .sh .yml .yaml .toml .json .html .txt` (git으로
  추적되는 파일 전체, 3,893개 파일 중 해당 확장자 421개)
- 제외: `.git/`, 그리고 파일명에 "업무대장"·"진행상황"·"프로세스표"가 들어간
  문서(열지도 않았다). `node_modules`·빌드 산출물 디렉터리는 이 저장소에
  해당 파일 유형으로 커밋된 것이 없어 실질적으로 해당 없음을 확인했다.
- 이메일 허용 목록·도메인은 `check_public_leaks.py`의 `ALLOWED_EMAILS`·
  `ALLOWED_DOMAINS`를 그대로 가져와 썼다(사장님 본인 주소, `simplifier.co.kr`,
  `anthropic.com`, `users.noreply.github.com`, `example.com/org`,
  새김 MCP 서비스 계정).
- (b)는 "숫자열 근처에 project/billing/account/프로젝트/결제/계정 단어"
  조건과, GCP 결제계정 형식(`XXXXXX-XXXXXX-XXXXXX`)·`project(s)=숫자` 형식
  두 가지를 추가로 더 넓게 돌려 교차 확인했다.
- 실제 값(이메일, 숫자열, 전화번호, 경로의 사용자명)은 이 문서에 절대
  적지 않았다. 아래는 위치와 판단만 적는다.

**허용 목록 밖 이메일은 찾지 못했다.**

## (b) 구글 클라우드 프로젝트 번호·결제 계정 번호로 보이는 숫자열 — 0건

## (c) 전화번호 형태 문자열 — 142건, 전부 "허용 가능"(오탐)

정규식이 느슨해 숫자가 일정 패턴으로 이어지면 다 걸리는데, 실제로 열어보니
전화번호가 아니라 다음 유형뿐이었다. 같은 이유로 몰린 것은 묶어서 적는다.

- **헤르메스 타임스탬프 파일명**(`scripts/hermes_courier/tstate.json` 84건,
  `scripts/hermes_courier/test_courier.py` 1건): `YYYYMMDD-HHMM-이름-일련번호`
  형식의 내부 작업 파일명. 전화번호 아님 — 허용 가능.
- **교보문고 상품코드·분류코드**(`scripts/fetch_book_insight.py`,
  `insight-7b3e9f2c/book-insight.html`, `llms.txt`, `_layouts/default.html`,
  `_includes/home-body.html`, `_data/books.yml`, 합계 약 25건): 공개
  서점 URL에 들어가는 상품 식별자(`S0002...`)와 국내도서 분류코드. 공개
  정보이고 전화번호 형식과 무관 — 허용 가능.
- **SNS/분석 데이터의 계정 ID·콘텐츠 ID**(`assets/data/sns_publish_queue.json`,
  `assets/data/naver-content.json`, `scripts/sns_queue_draft.py`, 합계 약
  12건): 인스타그램 `accountId`, 틱톡 `content_id`처럼 플랫폼이 부여한
  내부 식별자. 개인 전화번호 아님 — 허용 가능.
- **클래리티 분석 지표값**(`assets/data/clarity.json`, 8건): 세션 비율
  같은 소수점 통계 수치가 우연히 패턴에 걸림 — 허용 가능.
- **외부 뉴스·공문 URL의 날짜·게시글 번호**(`insight-7b3e9f2c/shorts-visual-grammar.html`,
  4건): 신문사·정부기관 공개 URL에 박힌 게시일자/파일번호 — 허용 가능.
- **연락처 폼의 자리표시자(placeholder)와 그 설명 주석**
  (`_includes/contact_modal.html`, 2건): `placeholder="010-1234-5678"`
  입력칸 예시 문구와, 자릿수 허용 범위를 설명하는 코드 주석. **실제 고객
  전화번호가 아니라 UI에서 보여주는 예시 형식**이라 허용 가능하나, 검색
  패턴상 "진짜처럼 보이는 전화번호" 문자열이 소스에 그대로 있다는 점은
  사람이 한 번 더 보는 게 안전하다 — **의심(경미)**으로 분류.

**의심으로 분류한 것은 없음** — 둘 다 사람의 실명이 아닌 범용/서비스
계정명이라 (d)의 "개인정보 노출" 취지에는 해당하지 않는다고 본다.
