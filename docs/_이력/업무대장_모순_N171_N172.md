# 업무대장 N171·N172 모순 분석 보고

`python scripts/ops/ledger_lint.py` 실행 결과 "모순 2건"(N171, N172)이 나온 원인을 분석한다. 대장 본문(docs/탐_업무대장.md)과 린트 스크립트(scripts/ops/ledger_lint.py)는 DB와 동기화돼 있어 이 세션에서 고치지 않는다 — 원인 분석과 고칠 문구 제안까지만 담는다.

## 1. 어떤 규칙이 걸렸나

`scripts/ops/ledger_lint.py` 64~68줄의 "측정 먼저 규칙"(사장님 2026-10-05 지시: "탐과 일할 때는 측정(정답지)을 먼저 만드는 작업이 1번, 그 뒤에 설계")이 걸렸다.

- 규칙 한 줄 설명: **상태가 [진행]이고 항목 번호가 N160 이상인 칸에서, 그 칸 본문 전체(헤딩 아래 모든 줄)에 "측정" 또는 "정답지"라는 글자가 단 한 번도 안 나오면 모순으로 찍는다.**
- N171·N172 둘 다 "선택 대기 낡음" 검사(DECIDED/WAITING 정규식, main() 44~63줄)에는 걸리지 않았다. 이 두 건은 오직 "측정 먼저 규칙" 하나 때문에 찍혔다.

## 2. N171 — 무엇이 빠졌나

- 위치: docs/탐_업무대장.md 514~518줄, 상태 [진행].
- 인용(514줄): "### [진행] N171: 클라우드 세션 크레딧 파일럿(US$164 남음, 11/5 16:59 만료, 사장님 승인 10/6 'A만 먼저, B를 더하겠습니다')"
- 515~518줄 전체를 확인했지만 "측정"·"정답지" 글자가 한 번도 없다.
- 가장 가까운 대체 문구는 518줄의 완료 증거 줄이다: "완료 증거: 클라우드 세션이 만든 PR이 CI를 통과해 병합되고 실제 소모 US$가 기록됨." — 이건 **끝났는지 아닌지 판정 기준**이지, 사장님이 말한 "설계보다 먼저 만드는 측정(정답지)", 즉 **결과물의 품질을 잴 잣대**는 아니다. 특히 B(515줄의 "마야 주간 성과표 초안")의 "좋은 초안"을 무엇으로 판단할지는 어디에도 적혀 있지 않다.

## 3. N172 — 무엇이 빠졌나

- 위치: docs/탐_업무대장.md 520~524줄, 상태 [진행].
- 인용(520줄): "### [진행] N172: 대표용 AI 비서(CPO) 월요일 시연(사장님 코칭 회사 대표, 사장님 10/6 '급하지 않게, 10/12(월) 대형 모니터 시연')"
- 521~524줄 전체를 확인했지만 "측정"·"정답지" 글자가 한 번도 없다.
- 524줄의 완료 증거 줄: "완료 증거: 월요일 시연 후 대표님 답(맡길 일·설치 여부)이 기록됨." 역시 이진 결과(답을 받았는지 여부)이지, 정답지 기반 측정이 아니다.

## 4. 고치는 문구 제안 (수치를 모르는 부분은 '미확인')

- N171, 515줄 뒤에 추가 제안: "측정: A(인프라 하드닝)는 '완료 증거'와 같은 PR 병합 여부를 정답지로 쓴다. B(마야 주간 성과표 초안)의 품질 정답지는 미확인 — 사장님께 확인 필요."
- N172, 521줄 뒤에 추가 제안: "측정: 이 항목은 수치 정답지가 아니라 사장님·대표님의 의사결정(진행 여부·맡길 일) 자체가 완료 기준이다. 정량 측정 대상 미확인(이런 유형엔 해당 없을 수 있음 — 사장님 확인 필요)."
- 두 문구 모두 실제 수치나 사장님이 말한 적 없는 기준을 지어내지 않았다. 대장 반영은 이 세션이 직접 하지 않으므로, 로컬 탐 세션이 대장을 고칠 때 참고용으로만 쓴다.

## 5. ledger_lint.py의 거짓 양성(false positive) 소지

- 규칙이 "상태=진행 & 번호≥N160"이면 업무 종류를 가리지 않고 전부 "측정"·"정답지" 글자를 요구한다. N172처럼 **사람 대상 의사결정·이벤트(시연)**에는 애초에 "정답지" 개념이 잘 안 맞는다 — 성공 기준이 숫자가 아니라 "대표님이 예/아니오로 답했는가"다. 이런 항목까지 "측정:" 줄을 강제하면, 실제 측정 없이 "측정: 해당 없음"처럼 형식만 채우는 줄이 늘어나 규칙의 원래 취지("설계 전에 잣대부터 만든다")를 오히려 약화시킬 위험이 있다.
- 규칙은 "측정"·"정답지" 글자가 블록 어디에 있는지, 문맥과 관련 있는지는 가리지 않는다(`any(re.search(r"측정|정답지", l) for l in ls)`로 순서·문맥 무관 단순 포함 검사). 반대로, 실제로는 측정 기준이 있지만 "정답지"·"측정" 대신 "기준"·"판정 방법"·"평가 방법" 같은 동의어만 썼다면 똑같이 걸린다. 이번 N171·N172는 동의어도 없는 경우라 오탐은 아니지만, 동의어를 쓴 다른 칸이 있다면 그건 억울한 오탐이 될 수 있다.
- 완화 아이디어(제안만, 이번 범위에서 스크립트를 고치지는 않음): ① "완료 증거" 줄이 있는 칸은 그 줄도 측정 후보로 같이 인정하거나, ② 칸 머리글에 업무 종류(기술 구현 vs 사람 의사결정) 태그를 달아 사람 의사결정형은 이 규칙에서 빼는 방안.
