# 마야 채널 도구 리서치: 게시·좋아요 수집·홈페이지 유입 (2026-10-06, 마야)

> 사장님 지시 10/6: 제미나이 API 리서치로 Composio, 공식 API, AItoEarn 등 마야가 필요한 일을 할 수 있는 사이트와 방법을 찾는다. 목적은 마야 KPI([마야_KPI.md](마야_KPI.md)): 게시물별 좋아요·조회수를 모으고 홈페이지 유입과 묶는다.
> 방법: 구글 검색 연동 제미나이(Vertex 경로, 질문 6개를 API 1회로 묶음, 토큰 16,767). 원문 JSON은 마야 세션 임시 폴더. 탐의 Composio 조사(N150·N152 보고서, simplifier-cxo-db/reports)와 대조했다.
> 판정 표기: 확인됨 = 공식 문서 원문을 직접 열어 대조 / 미검증 = 제미나이 답에만 근거.

## 1. 결론

- 글을 올리는 일은 지금 방식(AItoEarn 큐 + 크롬 직접 등록)으로 충분하다. 막힌 것은 올리기가 아니라 **게시물별 좋아요·조회수를 모으는 일**이다.
- 링크드인은 공식 API로 글별 반응(REACTION)·노출(IMPRESSION)을 읽을 수 있는 길이 **문서에 존재한다**(확인됨). 다만 권한 `r_member_postAnalytics`를 개인 개발자가 받을 수 있는지는 확인 못 했다.
- 페이스북 개인 프로필은 공식 API로 게시도 수집도 안 된다(미검증이나 Page 전용이라는 설명이 일관됨). 개인 프로필 수집은 화면 읽기(크롬)가 유일한 길이다.
- 인스타·페이스북 Page·스레드는 Meta 공식 API로 글별 좋아요·조회수를 읽을 수 있다(미검증). 본인 계정만 쓰는 개발 모드로 앱 검수 없이 가능하다는 설명이다.
- 홈페이지 유입 쪽은 UTM에 글 번호(`utm_content`)를 넣고 GA4 Data API로 글별 세션을 읽으면 된다. 지금은 UTM 규칙이 글별로 안 들어가 있어 글 단위 유입이 안 쪼개진다.
- Composio는 도입하지 않는다는 탐의 결정(N152)을 따른다. 마야 용도로도 링크드인·페이스북 Page·인스타·GA4·서치콘솔 툴킷이 있고 무료 월 도구 호출 10만 회이지만(공식 가격 페이지는 탐이 대조함), 페이스북 개인 프로필은 지원하지 않고 우리 자격증명을 외부 금고에 맡기는 구조라 맞지 않는다. 가입은 해 두었으니 벤치마크와 시험용으로만 쓴다.

## 2. 채널별 표 (게시 / 글별 좋아요·조회수 읽기)

링크드인(개인 한성희)
- 게시: Share on LinkedIn(`w_member_social`)은 개인 개발자 앱으로 검수 없이 가능(미검증). 예약 파라미터는 없어 우리 큐가 시각에 호출해야 한다.
- 글별 수치: `memberCreatorPostAnalytics`, 권한 `r_member_postAnalytics`, 지표 IMPRESSION·MEMBERS_REACHED·RESHARE·REACTION·COMMENT(확인됨, learn.microsoft.com/en-us/linkedin/marketing/community-management/members/post-statistics). `r_member_social`은 신규 접수 중단(확인됨, Community Management API 개요 FAQ). 제미나이는 "개인은 불가"라 했으나 위 문서와 다르다.
- 지금 쓰는 길: 활동 페이지 화면 읽기(오늘 실제 수집 성공).

페이스북
- 개인 프로필: 공식 API 게시·수집 불가(미검증). 크롬 화면 조작이 유일(오늘 게시 성공, 수집은 가상 스크롤이라 부분만).
- Page(Simplifier, 팔로워 0): Graph API로 게시·예약·글별 반응 읽기 가능(미검증). 단 사장님 신원 확인(Meta 368) 해제 여부는 아직 모름.

인스타그램(비즈니스·크리에이터)
- 글별 `likes`, `views`, `reach` 등 insights 읽기 가능(미검증, developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-media/insights). AItoEarn이 이미 연결한 계정과 같은 종류다.

스레드
- Threads API로 게시와 글별 `views`·`likes`·`replies` 읽기 가능(미검증, developers.facebook.com/docs/threads). 지금 AItoEarn 스레드 자동화(N17)가 대기 중이라 이 API가 대안이 될 수 있다.

리멤버 커넥트
- 공식 API 없음(미검증). 글별 좋아요는 내 게시물 목록 화면 읽기(오늘 성공).

로켓펀치
- 제미나이는 "Open API로 게시글 조회 가능"이라 했으나 공식 개발자 문서를 찾지 못했고 문서 주소가 403이라 **믿지 않는다**. 화면 읽기가 현실 경로.

네이버 블로그·브런치
- 글쓰기 공식 API 없음, 자체 예약·통계 화면만(미검증). 지금 Playwright 예약 스크립트가 있다. 통계는 화면 읽기.

## 3. AItoEarn

- 지원 채널은 TikTok, YouTube, Instagram, X, LinkedIn, Threads, Facebook과 중국 채널 다수(미검증, github.com/yikart/AiToEarn).
- 게시 후 글별 좋아요·조회수를 API로 주는 기능은 없거나 제한적이라는 답이다(미검증). 우리가 쓰는 범위(큐 등록)는 되지만 수집 용도로는 기대하지 않는다. 링크드인 이미지 1장 거부는 우리가 이미 겪은 것(링크드인은 크롬 예약으로 우회 중).

## 4. 통합 도구(예약+분석)

- Buffer 무료: 채널 3개, 채널당 대기 글 10개, 링크드인 개인 지원, 페이스북 개인 미지원(미검증).
- Publer 무료: 계정 3개, 계정당 예약 10개, 링크드인 개인 지원(미검증).
- Postiz(셀프호스팅, AGPL): 25개 이상 채널, 각 공식 Insights API를 연결해 글별 조회·좋아요를 한 대시보드에 모아 준다(미검증). 본인 서버에 OAuth 앱을 직접 만들어 연결하는 방식이라 설치·운영 부담이 있다.
- Mixpost(Lite, MIT): 12개 채널, 노출·도달·반응 차트(미검증).
- 어느 도구도 페이스북 개인 프로필, 리멤버, 로켓펀치는 못 한다. 이 셋은 어차피 화면 읽기로 남는다.

## 5. 마야 추천 (규모 원칙: 지금 1인+AI 기준, 공정자산이 되는 것 먼저)

1. **하지 않는 것**: Composio 도입, 통합 도구 유료 구독, Postiz 셀프호스팅(운영 부담이 이득보다 크다. 신호: 채널별 API 연결이 3개를 넘고 화면 읽기가 병목일 때 재검토).
2. **먼저 할 것 A (비용 0)**: 글 링크에 `utm_source=채널&utm_medium=social&utm_content=글번호`를 붙이는 규칙을 큐 초안(`sns_queue_draft.py`)에 넣는다. 그러면 GA4에서 글별 유입이 쪼개진다. 현재는 링크가 관련글 1개뿐이고 UTM이 없다.
3. **먼저 할 것 B**: 글별 좋아요·조회수 수집(N14)을 탐 자동화에 맡기되, 크롬 화면 읽기로 5개 채널(링크드인, 리멤버, 로켓펀치, 페이스북 개인, 인스타)을 하루 1회 모으는 레시피를 마야가 만든다. 오늘 3개 채널은 실제로 모았다.
4. **시험할 것**: 링크드인 `r_member_postAnalytics` 신청이 개인에게 열려 있는지(개발자 포털 앱 생성 후 제품 추가 화면에서 확인). 열리면 링크드인은 화면 읽기에서 API로 바뀐다. 사장님 개발자 계정 로그인이 필요한 단계라 사람 개입 ①이다.
5. **시험할 것**: Meta 개발 모드 앱으로 인스타·스레드 insights 읽기. 역시 앱 생성에 사장님 로그인이 필요하다.

## 5-1. 후속 확인 (10/6 마야, 사장님 "확인해 봐 주세요")

링크드인 개발자 포털 실사(사장님 로그인된 크롬, 읽기만 함, 앱 생성·신청은 안 함)
- 내 앱 0개. `r_member_postAnalytics`는 Community Management API 프로그램 소속이고, Development Tier 신청(심사) 뒤 Standard Tier 승인을 거치는 검증형 제품이다. Standard 신청에는 사용 사례 시연 영상이 필요하고, 앱은 회사 페이지(Simplifier)와 묶인다(공식: learn.microsoft.com/en-us/linkedin/marketing/community-management/community-management-overview, 확인됨).
- 판단: 개인이 즉시 켜는 권한이 아니다. 신청서 제출은 외부 발신이라 사장님 컨펌 사안이고, 승인 보장도 없다. 자동 수집의 1순위로 삼지 않는다.

Composio로 링크드인 수집이 되는가: **안 된다**(탐 실측 정정, 2026-10-06 우편)
- 공식 문서 페이지(docs.composio.dev/toolkits/linkedin)에는 `LINKEDIN_LIST_REACTIONS`, `LINKEDIN_GET_SHARE_STATS` 등이 적혀 있었으나, 탐이 같은 날 API로 조회한 실제 도구 목록에는 링크드인 툴이 글 올리기·삭제·내 정보·회사 정보 4개뿐이다. 문서와 실제가 다르며, 실제 목록을 따른다.
- 결론: 링크드인 글별 좋아요는 Composio로 불가. 활동 페이지 화면 읽기를 유지한다.
- Composio로 가능한 것(탐): 인스타그램 글별 인사이트·미디어, 페이스북 Page 글별 반응·인사이트(개인 프로필 불가). 인스타·페이스북 연결 링크는 탐이 사장님께 텔레그램으로 보냈고 동의 클릭 대기 중이다. 결과는 `C:/work/_ops/n152/maya_result.json`.
- GA4는 이미 우리 자동 수집(`analytics.json`)이 있어 Composio가 필요 없다.
- 화면 읽기 대상은 링크드인·리멤버·로켓펀치·페이스북 개인 4곳으로 좁혀졌다.

UTM 정정
- 앞 절의 "UTM이 없다"는 틀렸다. `UTM_규칙.md`에 규칙이 있다. 남은 일은 (a) 규칙에 글 번호(`utm_content`)가 있는지 확인, (b) 이번에 올린 글의 링크에 UTM이 실제로 붙었는지 확인(오늘 본문은 UTM 없이 올림).
