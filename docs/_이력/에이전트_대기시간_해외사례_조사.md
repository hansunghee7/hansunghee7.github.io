# 에이전트 대기 시간: 해외 사례 조사와 우리 솔루션 (2026-09-20)

> 사장님 지시(2026-09-20): 해외 고수들은 이 문제를 어떻게 푸는지 조사하고 솔루션을 제시한다.
> 방법: 독립 서브에이전트 3개가 공식 문서·저장소를 직접 열어 조사(멀티 LLM 규약의 "자체 자동화 파이프라인을 짓기 위한 리서치는 직접 한다" 예외). 서브에이전트 보고는 **웹 조회 도구의 요약을 거친 것**이라 원문과 다를 수 있다. 결정 전 핵심 문단은 원문으로 다시 볼 것.
> 규약 3원칙 적용: 정밀 수치, 고유명사는 "미검증"으로 표시했다. 도구 설치는 공급망 위험을 함께 적었다.

## 결론 한 줄
해외에서도 **폴링은 여전히 흔하다**(Cursor, Devin, LangChain의 비동기 서브에이전트가 폴링). 다만 잘 하는 곳은 (1) 완료·알림을 이벤트로 받고, (2) 큰 산출물은 파일에 두고 참조만 넘기고, (3) 사람에게는 "할 일 있는 것만" 알린다. 우리는 Claude Code 공식 기능만으로 사슬의 대부분을 이벤트로 바꿀 수 있고, 새 도구를 들일 필요는 지금 없다.

## 1. 프론티어 팀의 통신 패턴 (출처: 공식 문서)
| 패턴 | 누가 | 지연 특성 | 우리 적합도 |
|---|---|---|---|
| 세션 간 메시지(`SendMessage`), 같은 PC는 소켓·named pipe. 받는 세션이 쉬는 중이면 새 턴 시작 | Claude Code (cross-session-messaging) | 즉시 | **이미 사용 중.** 네이티브 Windows는 문서상 v2.1.234 이상 |
| `notify_when_idle`: 상대가 한가해지면 1회 알림, 폴링 없음 | Claude Code (v2.1.236 이상 양쪽) | 유휴 즉시 | 같은 PC 한정. 시험해 볼 만함 |
| 다른 PC 세션과 메시징 | Claude Code + Remote Control(서버 경유) | 미확인 | 로그인 필요, 인바운드 개방 없음 |
| 백그라운드 명령·서브에이전트 완료 알림 | Claude Code | 완료 즉시(실측 7초) | **이미 사용 중** |
| Monitor 도구: 백그라운드 스크립트의 출력 줄을 도착하는 대로 세션에 전달 | Claude Code (tools-reference) | 즉시. 기본 5분, 최대 30분, 세션 재개 시 복원 안 됨 | 파일·메일 도착 감지에 적합 |
| 훅 `asyncRewake`: 종료 코드 2로 세션을 깨움 | Claude Code (hooks) | 즉시 | Windows 동작은 미확인 |
| 채널(Channels): 외부 이벤트를 열린 세션에 주입, 텔레그램 플러그인 공식 제공 | Claude Code (research preview) | 즉시 | **보류.** Windows·데스크톱 앱 동작 미확인, Bun 필요 |
| 웹훅 푸시 | OpenAI, A2A, Cursor(예고) | 즉시 | **제약 위반.** 공개 URL 필요 |
| 폴링(감독자가 부를 때 확인) | LangChain 비동기 서브에이전트, Devin, Cursor v1 | 호출 주기에 좌우 | 해외도 폴링이 흔하다는 근거 |
| 동기 대기 + 큰 산출물은 파일에 두고 참조만 전달 | Anthropic 자체 리서치 시스템 | 가장 느린 작업에 묶임 | 우리 "파일=메시지 저장소"와 같은 발상 |
| Hermes no-agent 크론 + `{"wakeAgent": false}` 게이트 | Hermes 공식 문서 | 크론 주기 | 폴러를 값싼 스크립트 게이트로 바꿀 근거 |

## 2. 사람의 승인·대기를 줄이는 패턴
| 패턴 | 출처 | 근거의 강도 | 우리 적합도 |
|---|---|---|---|
| 승인이 필요 없게 만들기(샌드박스 경계) | Anthropic 샌드박싱 글 | 프롬프트 감소 수치는 Anthropic 내부 데이터(미검증) | 높으나 Windows 지원 미확인 |
| auto 모드 분류기 | Anthropic auto 모드 글 | 승인율 93%라는 낭비를 대체. 미탐 17%라는 대가도 함께 공개 | PC 세션에서만 선택 가능(모바일 앱에서는 못 고름) |
| Remote Control 폰 푸시 두 종류 토글, `CLAUDE_CLIENT_PRESENCE_FILE`(PC 앞에 있으면 푸시 생략) | Claude Code remote-control 문서 | 공식 기능 | **높음. 지금 설정만으로 가능** |
| 알림은 "행동 필요하고 긴급한 것만" | Google SRE 책 | 원칙 | 우리 "요청 있는 우편만 폰으로" 정책과 일치 |
| 알림·질문·검토 3분류 | LangChain 앰비언트 에이전트 글 | 개념 | 알림은 답을 요구하지 않는다는 구분을 차용 |
| 텔레그램 인라인 버튼으로 승인 | Telegram 공식 문서, 커뮤니티 훅 도구 | 정량 근거 없음 | **보류.** 봇 업데이트를 이미 다른 프로세스가 소비 중이라 충돌 위험 |
| ntfy 푸시 버튼 | ntfy 문서, 커뮤니티 도구 | 정량 근거 없음 | 낮음. 공개 토픽 이름이 사실상 비밀번호, Windows 동작 미확인 |
| LangGraph interrupt와 묶음 재개, Agent Inbox | LangChain 문서 | 구조는 문서에 있음. 타임아웃 후 자동 진행은 미확인 | 낮음. 새 런타임이 필요해 과함 |

## 3. 파워유저 도구
| 도구 | 판단 | 이유 |
|---|---|---|
| 공식 기능(세션 메시지, 훅, Remote Control) | **먼저 쓴다** | 새 설치 없음, 공급망 위험 낮음 |
| mcp_agent_mail 계열(우편함 MCP) | 채택 안 함 | 받는 쪽이 `fetch_inbox`를 호출하는 폴링 방식이라 지금 문제를 못 풂. 설치가 `curl\|bash` 방식이라 공급망 위험 |
| claude-peers-mcp | **채택 안 함** | 조사 요약에 따르면 권한 우회 플래그(`--dangerously-skip-permissions`)를 요구. 권한 측면 위험이 가장 큼(원문 확인 필요) |
| workmux, dmux, Claude Squad 등 tmux 기반 | 채택 안 함 | tmux 전제라 네이티브 Windows에서 안 되고, WSL 세션과 네이티브 세션은 서로 닿지 않음 |
| ntfy(공개·셀프호스트)와 훅 | 보류 | 위 표와 같은 이유. 셀프호스트는 Docker와 Tailscale 사이드카가 필요해 운영 부담 큼 |

## 4. 우리 솔루션 (규모 최적화: 1인 회사, Windows, 월 몇 만원 이하)
### 지금 한다 (대부분 이미 완료)
1. 헤르메스 발주는 백그라운드 `hx_lite.sh ask`(발주와 완료 통지가 이벤트, 실측 7초).
2. 살아 있는 세션끼리는 `SendMessage`(마야 실측 회신 도착).
3. 사장님 알림은 우편 뒤 `hx kick`(실측 7초). 답은 클로드 모바일에서 해당 세션에.
4. 폴러 줄 분리(짧은 줄과 긴 줄): 시험 중. 결과는 [왕복 표준 절차](에이전트_왕복_표준절차.md)와 백로그 28에 기록.
5. 신규: Remote Control 폰 푸시 설정 점검(`Push when actions required` 등)과 `CLAUDE_CLIENT_PRESENCE_FILE`. **사장님 기기 설정이라 사장님이 확인하실 부분.**

### 다음
6. 헤르메스가 끝냈다는 신호를 세션이 **기다리는 스크립트**로 받기: 백그라운드 명령이나 Monitor로 "내 앞 우편 도착"이나 "보고서 파일 생김"을 감지하면 세션이 깨어난다. 모델이 폴링하지 않고 값싼 스크립트가 본다. (Monitor 최대 30분, 재개 시 복원 안 됨 -> 다시 걸어야 함)
7. 폴러를 `wakeAgent` 게이트 방식으로: 일이 없을 때 AI를 아예 호출하지 않는다(현재 하루 약 480회 호출).
8. `notify_when_idle` 시험(같은 PC 세션끼리).

### 보류 (넘어갈 신호 포함)
| 보류 | 신호 |
|---|---|
| 채널(Channels), 텔레그램 답장을 세션에 주입 | Windows·데스크톱 앱 지원이 문서에 명시되고 프리뷰가 끝날 때 |
| 텔레그램 인라인 버튼 승인 | 봇 업데이트를 한 곳에서 받아 나눠 주는 구조를 만들 만큼 승인 건수가 늘 때 |
| 병렬 작업자 + 결정적 마무리 래퍼(폴러 대체) | 줄 분리로도 긴 작업끼리 서로 막을 때 |
| mcp_agent_mail, ntfy, tmux 도구 | 다른 PC나 다른 도구(Codex 등)의 에이전트와 소통해야 할 때 |
| 신PC 공개 웹훅 | 도입하지 않음(원칙: 외부 접속은 Tailscale만) |

## 5. 미확인 목록
- 채널의 Windows·데스크톱 앱 동작과 최소 버전. `asyncRewake`의 Windows 동작.
- 백그라운드 세션(`--bg`)에서 훅이 도는지. 데스크톱 앱에서 Remote Control이 정확히 어떤 플랜 조건인지(문서끼리 어긋남).
- Hermes 크론의 최소 주기와 동시 실행 정책(공식 문서에 명시 없음, 우리 관찰로는 서로 다른 크론은 동시에 돎).
- 외부 스크립트가 소켓으로 쉬는 세션을 깨우는 절차의 실제 동작.
- 서드파티 도구의 Windows 지원과 성숙도(서브에이전트가 스타 수, 커밋 수를 출처 불안정으로 뺐다).
- 서드파티 도구는 서브에이전트가 README 요약으로 본 것이라 채택 전 원문 확인 필수.
