# G2 표 이전 메모: 한도 대장·컷 큐를 운영 DB 표로 (설계만, 2026-10-12)

사장님 목표 G2 "에이전트 스스로 DB 조회"의 마지막 미이전 두 파일. 운영 DB 쓰기·마이그레이션은 이번에 하지 않았다.

## 현재 위치와 형식
- 한도 대장: `quota_ledger.json`이라는 파일은 없다. 실제 정본은 `C:\work\shorts-lab\pilot-shorts2\account_quota.json`(shorts-lab 저장소 추적, 도구는 `tools/factory/quota_ledger.py`). 형태는 `{updated, note, accounts: {u0..: {email, kind, flow:{credits,reset,read_at,note,state}, gemini:{...}, vids:{...}}}}`. 쓰는 쪽은 `quota_ledger.py set/use`뿐.
- 컷 큐: `C:\work\shorts-lab\pilot-shorts2\cut_queue.json`(추적). 형태는 `{generated, order[ep], tag_rule, stats{ep:{total,done[],remaining,by_tag}}, pending[{ep,status,note}], queue[]}`. 스크립트가 통째로 다시 만든다.
- `C:\work\_ops`에는 둘 다 없다(`quota_state.json`은 에이전트별 차단 시각이라 별개).

## 대상 표 이름 후보
- `account_quota`: 행 = (계정, 엔진). 열 = account, engine, credits, remaining, reset_at, reuse_at, read_at, state, note.
- `cut_queue`: 행 = 컷 하나. 열 = ep, cut_no, tag, status(done/pending), note, updated_at. `stats`는 저장하지 않고 뷰로 계산.
- 이미 있는 `fit_cut_ledger`(cut_ledger_db.py)와 겹치는지 먼저 대조하고, 겹치면 새 표 대신 열만 추가한다.

## 위험
- 한도 대장은 사람 속도로 읽은 값이라 DB가 정본이 되면 `set`과 DB가 어긋날 수 있다. 쓰기 경로를 하나로 정해야 한다.
- `stats`와 `done[]`은 파생값이라 이중 저장하면 불일치가 생긴다.
- 파일 인코딩이 깨져 보이는 환경이 있어(CP949 콘솔) 이전 스크립트는 반드시 utf-8로 읽는다.
- 계정 이메일이 들어 있어 표 접근 권한(RLS)과 공개 저장소 유출을 확인한다. 값은 로그·PR에 싣지 않는다.
- 이중 차감: `use`가 파일과 DB에 두 번 깎지 않게 한다(`quota_ledger.py` 사용법 문서 참조).

## 옮기는 순서
- 1) 읽기 전용 이전: 기존 `import_ops_tables.py` 패턴으로 두 JSON을 표에 단방향 동기화(파일이 정본, DB는 거울). 1회 실행해 행 수가 파일과 같은지 대조.
- 2) 에이전트가 `opsdb.py select`로 조회하게 하고 `opsdb_access_report.py`로 조회 횟수가 늘었는지 확인.
- 3) 안정되면 `quota_ledger.py`의 `set/use`가 DB에 먼저 쓰고 파일은 거울로 뒤집는다(되돌릴 수 있게 파일 백업 유지).
- 4) 주기 작업이 되면 `scripts/ops/jobs.toml`에 등록하고 첫 자동 실행까지 확인.
- 제품·방향 결정(정본 뒤집는 시점)은 사장님 몫.
