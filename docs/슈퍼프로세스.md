# 슈퍼프로세스 (전 에이전트 필수 적용 정본)

**한 줄 정의**: 한 영역의 일을 처음부터 끝까지 **공정 카드(수파베이스) + 장부(수파베이스 표) + 컨펌 대장 + 자동 단계표 + 오케스트레이션 2.0 적용 + 사고 회수 루프**로 묶어, 세션이 바뀌어도 빠짐·환각·망각 없이 돌게 하는 운영 방식이다.

**출처·지시**: 핏이 영상 공장 전체(주제 → 대본 → 음성 → 컷 → 조립 → 쇼츠 → 발행 → 성과)를 이 방식으로 만들었고, 사장님이 2026-10-11에 "핏이 만든 전체 공정 프로세스화 및 수파베이스 활용을 **슈퍼프로세스**로 명명, 다른 에이전트도 필수 적용"하도록 지시했다. 앞선 지시(2026-10-07, 영역별 프로세스표 필수)와 오케스트레이션 2.0 정본([오케스트레이터_일하는_방식.md](오케스트레이터_일하는_방식.md))을 이 문서가 한 장으로 묶는다.

## 슈퍼프로세스의 일곱 부품

1. **영역 목차**: 내 일을 영역(예: 대본·음성·영상생성·조립·발행·장부관리)으로 나눠 이름 붙인다. 영역마다 공정 이름이 하나다(`핏-대본` 식).
2. **공정 카드(수파베이스 tasks, `proc.py`)**: 영역마다 단계 카드. `python scripts/ops/proc.py add <공정> "제목" --do "무엇을 어떻게(도구·명령·분기·증거)" --boss "사장님 말(날짜 포함)" --tool "도구"`. 일을 시작하기 전에 `proc.py steps <공정>`을 먼저 읽는다. 고칠 땐 `amend`(이력 보존), 삭제는 없고 `retire`.
3. **장부(수파베이스 표 + 로컬 정본)**: 일의 단위(에피소드·건·계정)마다 한 줄이 남는 표. 사람이 손으로 쓰지 않고 **스크립트가 증거에서 적재**한다(예: 컷 대장 `cut_ledger.py` → `fit_cut_ledger`, 에피소드 단계표 `episode_stages.py`). 표가 필요하면 DDL은 탐에게 요청한다(탐이 실행).
4. **컨펌 대장**: 사장님 컨펌 관문마다 요청 → 응답 → 무효/수정 반영을 한 줄로 남긴다(`confirm_ledger.py request|reply|void|pending`). 응답 없는 요청은 `pending`으로 보고 직접 읽는다. 컨펌 댓글이 세션을 못 깨울 수 있다(자동 응답 승인 거부, 중단 시 일시정지, 감시 10개 상한).
5. **자동 단계표(빈칸 점검)**: 단위마다 단계별 증거 파일을 읽어 `-`(빈칸)를 보여 주는 읽기 전용 표를 만든다. 사람이 "했다"고 쓰는 표가 아니라 증거가 있어야 채워지는 표다. 30분 동기화 작업에 연결한다.
6. **오케스트레이션 2.0 적용 단계**: 영역마다 "무엇을 스크립트·타미·Vertex·덱스·비티·API·서브에이전트에 맡기고 무엇을 직접 하는지" 카드 한 장을 둔다. 긴 읽기는 서브에이전트에 맡기고 요약만 받는다. 본 세션은 판정과 조율만 한다.
7. **사고 회수 루프**: 사고·오류·사장님 지적이 나오면 그 턴에 카드(증상·원인·조치·재발방지)로 남기고, 가능하면 도구 관문(훅·스크립트 검사)에 넣는다. 문서만 고치면 세션이 바뀌어 빠진다(CLAUDE.md 4e7b).

## 자동화 원칙(핏이 겪고 정한 것)

- **알림은 조치 뒤 결과로**: 같은 문제 알림이 반복되면 버그 신호다. 알림 빈도를 줄이는 것이 아니라 다른 시도를 하고 그 결과를 알린다(예: 풀이 막히면 자동 전환 후 "전환했다" 알림).
- **막힌 단위는 그 단위만 멈춘다**(계정 하나, 컷 하나). 전체 정지는 사장님 지시 때만.
- **판정이 필요한 곳은 사람 전에 도구 관문**: 규칙을 어기면 멈추는 코드를 먼저 넣는다.
- **증거 없는 완료 금지**: 완료 = 파일·수치·응답 같은 증거(CLAUDE.md f3a9).

## 새 에이전트가 적용하는 순서(필수)

1. 내 일의 영역 목차를 만든다(10줄 이내).
2. 영역별 공정 카드를 `proc.py add`로 올린다. 이미 있으면 읽고 빠진 단계만 추가한다.
3. 영역마다 단위(건)가 있는 장부를 정한다. 기존 표가 있으면 재사용하고, 새 표가 필요하면 DDL 요청을 탐에게 보낸다.
4. 사장님 컨펌 관문이 있으면 컨펌 대장을 쓴다(`confirm_ledger.py`를 본보기로, 다른 영역은 같은 형식으로 복제해도 된다).
5. 증거 파일을 읽는 자동 단계표를 만들어 30분 동기화에 연결한다.
6. 영역마다 "오케스트레이션 2.0 적용" 카드 한 장을 둔다(정본은 [오케스트레이터_일하는_방식.md](오케스트레이터_일하는_방식.md), API 갈래 포함).
7. 완료 보고는 "카드 N장·장부 M개·단계표 빈칸 K개"를 숫자로 한다. 주 1회 빈칸을 점검한다.

## 본보기(핏 영상 공장)

- 공정 카드: `핏-대본`·`핏-음성`·`핏-영상생성`·`핏-조립`·`핏-발행`·`발행장부관리`(각 20~50단계, 마지막에 오케스트레이션 2.0 적용 카드).
- 장부: 컷 대장(`fit_cut_ledger`·`fit_assembly_items`), 에피소드·대본·조립·발행(`fit_*` 표 7개와 뷰 `v_fit_pipeline`), 컨펌(`fit_confirmations`, 요청·응답 컬럼 확장), 단계표(`pilot-shorts2/에피소드_단계표.md`).
- 도구(shorts-lab `tools/factory/`): `cut_ledger.py`, `confirm_ledger.py`, `episode_stages.py`, `fit_db_sync.py`(30분 동기화).
- 감사 결과(2026-10-11): 영상 에피소드 15단계 중 카드 빈칸은 성과 확인 1개, 장부 칸 빈칸은 7개(자료·팩트체크 결과, 정본/읽기 분리, 정책 거절 컷, 쇼츠 조립, 설명, 관련 동영상·성과 DB) → 이런 감사를 영역마다 한 번 한다.

## 하지 않는 것

- 카드·장부를 "만들어 놓기"만 하고 실제 일에 쓰지 않는 것(CLAUDE.md 원칙 5: 검증되지 않은 설계는 자산이 아니다).
- 장부를 손으로 쓰는 것(자동 적재가 안 되면 그 한계를 개선 과제로 올린다).
- 같은 일을 하는 새 표·도구를 따로 만드는 것(기존 것을 먼저 찾는다).
