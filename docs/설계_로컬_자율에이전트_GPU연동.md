# 설계: 로컬 자율 에이전트 (헤르메스 + 로컬 LLM + 4090 GPU + 외부 검증기) — 클라우드 탐 작성, 2026-10-07, v1 초안

상태: **설계 초안**(구현 없음). 클라우드는 로컬 PC·GPU·헤르메스 설정을 못 봐서, 아래 "확인할 것"으로 로컬이 대조한다. 공개 저장소 문서이므로 PC 이름·경로 중 비밀이 될 것과 고객 정보는 쓰지 않았다.

## 한 줄 결론
"무제한 렌더링"은 GPU 한 장(4090, 24GB)을 핏·탐·마야가 나눠 쓰는 한 불가능하다. 대신 **사람이 없는 시간에 허용된 작업만 밤새 순서대로 돌리고, 결과를 결정적 코드로 검사하고, 막히면 멈추고 알리는 무인 큐**는 만들 수 있다. 판단은 코드가 하고, 타미는 호출·감시만 하고, 주관 품질 판정은 사장님 컨펌 3곳(주제·음성·조립본)과 검증 채널이 맡는다.

## 먼저 바로잡을 것 (자원의 정체)
- **덱스·비티는 GPU가 아니다.** 덱스는 외부 코드 에이전트(Codex), 비티는 외부 서비스(Antigravity)로 각자 구독 한도가 있다(비티 본체 10-08 21:39, sonnet 10-11 01:01에 풀림). 로컬 GPU(4090)는 ComfyUI(이미지·영상)와 Ollama(로컬 LLM)가 쓴다. 이 둘을 한 덩어리로 부르면 한도 계획이 틀어진다.
- **로컬 LLM은 판정자가 아니다.** 무료·로컬 엔진은 수집·측정·실행·초안에만 쓰고 통과·반려·안전 분류는 하지 않는다(사장님 확정 2026-09-20, 이미지 검수 예외 2026-09-22). 이 설계도 그대로 따른다.
- **"스스로 판단"의 범위**: 정해진 규칙(코드) 안의 선택(재시도, 파라미터 낮추기, 순서 정하기)은 자율, 기준을 해석하는 판정은 사람·검증 채널이다.

## 지금 있는 부품 (저장소 근거)
- `scripts/ops/gpu_gate.py`: GPU 공용 관문. 5GB 미만은 확인만, 20GB 이상은 새벽 01~06시만(`--now`는 사유 기록), 예약과 ttl, 기록 `gpu_gate_log.csv`(DB에도 직접 기록).
- `scripts/ops/ollama_ask.py`: 로컬 Ollama 호출기(호출 전 관문 통과, 외부 전송 없음). 모델: qwen2.5-coder:14b(실측 생성 9.6 tok/s, 콜드 18.6초), qwen2.5:32b, exaone3.5 32b·7.8b, 비전(qwen2.5vl:7b 화면 글자 읽기 실측 완료), 임베딩.
- `scripts/ops/local_llm/`: 주간 가공 스크립트(요약·보관 후보).
- 타미(헤르메스) 폴러: `tasks/pending` 카드를 1~2분 안에 집어 가고 `tasks/done`으로 옮긴다(오늘 실측 2~5분 처리). 감시 대장 `jobs.toml`, 상태판, 감시 `watch.py`.
- `scripts/ops/browser_lease.py`: GUI 직접 조작 작업의 서브에이전트 임대(별도 예외). 이 설계의 대상이 아니다.
- 린트 위임 패턴 `delegate_lint.py`: 검증기가 통과시킨 diff만 제안하고 적용은 호출자가 한다. 코드 수정 자율화의 본보기.
- 핏의 조립: 결정적 스크립트(`build_final.py` 등)가 전담, 타미·로컬은 호출·파라미터 전달·종료 코드와 로그 감시만(사장님 확정 2026-10-07).

## 목표 구조 (네 부분)
1. **작업 명세(접수)**: 일은 자유 문장이 아니라 작은 JSON 명세로 접수한다. 칸: `id`, `kind`(render / encode_check / test), `action`(허용 목록의 이름), `params`, `gpu_gb`, `deadline`, `max_retries`(기본 3), `owner`, `evidence_path`. 접수 경로는 두 가지다: ① `tasks/pending` 카드(클라우드·핏이 올림) ② 로컬 큐 폴더(로컬 스크립트가 올림).
2. **실행기(결정적 스크립트)**: `gpu_gate need` → 허용 명령 실행 → 종료 코드 확인 → 산출물 검사 → 결과 JSON → `gpu_gate release`. LLM이 명령을 만들어 실행하지 않는다. `action`은 코드에 박힌 허용 목록(예: 조립, 업스케일, 자막 입히기, 영상 검사)에서만 고른다.
3. **검사기(결정적 검증)**: 1차는 코드가 참·거짓을 판정한다. 영상은 `ffprobe`로 해상도·길이(목표 대비 오차)·코덱·오디오 유무·파일 크기 하한, `ffmpeg`의 `blackdetect`·`silencedetect`로 검은 화면·무음 구간, 자막 파일은 글자 수·줄 길이 규칙(대본 약 20자, 자막 10자 이내 등 기존 확정 규칙). 화면 글자 일치 같은 **객관 검사**는 로컬 비전 모델을 써도 된다(통과·반려 판정이 아니라 글자 읽기). 주관 품질은 이 단계의 몫이 아니다.
4. **감시자(타미)**: 큐를 보고 실행기를 부르고 종료 코드·로그를 본다. 판단은 하지 않는다(핏 조립 원칙과 같다). 사람 개입이 필요하면 마야 형식 텔레그램 1건. 완료는 `tasks/done` 이동과 이벤트 신호(`docs/설계_N180_에이전트_통신망.md`)로 클라우드에 알린다.

## 자동 테스트 루프 (코드 수정 쪽)
- 저장소 테스트(`unittest`)와 린트를 무인으로 돌린다. 실패하면 ① 로그에서 실패 시험 이름·마지막 줄을 뽑고(스크립트) ② 로컬 LLM(qwen2.5-coder:14b)이 원인 후보와 수정 diff **초안**을 만들고 ③ 검증기가 통과시킨 것만 제안으로 남기고 ④ 덱스(코드 1차)에게 검토 지시서를 던진 뒤 ⑤ 적용은 사람 또는 본체가 한다(`delegate_lint.py`와 같은 구조). 자동으로 main에 반영하지 않는다.
- 같은 실패가 2회 이어지면 로컬 LLM 시도를 멈추고 "무상 자원 연속 2회 실패" 예외 관문(SOP)으로 올린다.

## 자율 범위 (누가 정하나)
- **자율(기록만)**: 같은 명세의 재시도(최대 3회), 파라미터 한 단계 낮춰 재시도(해상도·길이), 마감순 큐 정렬, 자기 산출물의 임시 파일 정리.
- **알림 후 계속**: 3회 실패한 건을 보류로 옮김, 모델을 내려 VRAM을 확보하는 `gpu_gate` 새벽 회수 규칙, 하루 상한 도달.
- **사람 승인**: 허용 명령 목록에 새 `action` 추가, 상한 변경, 외부 산출물 삭제·발행, 돈이 드는 것, 계정·결제·외부 발신(기존 사람 개입 4종 그대로). 사장님 컨펌 3곳(주제·음성·조립본)은 건너뛰지 않는다.

## 안전장치 (무인이 가능하려면 필수)
- 킬 스위치: 파일 하나(`STOP_AUTONOMY`)가 있으면 실행기와 감시자가 새 일을 시작하지 않고 진행 중인 일을 안전하게 마친다. 사장님·본체가 파일 하나로 끌 수 있다.
- 쓰기 범위: 지정한 작업 폴더 밖에는 쓰지 않는다. 비밀값·키 폴더는 읽지도 않는다. 호스팅 모델에는 고객·비공개 내용을 보내지 않는다(로컬 모델만).
- 상한: 하루 작업 수, 하루 GPU 시간, 연속 실패 수. 온도(`nvidia-smi`) 임계 초과 시 일시정지, 디스크 여유 하한 미만이면 새 일 시작 안 함, 밤 창(새벽 01~06시)에만 큰 작업.
- 사용자 화면 무영향: 창이 뜨지 않게 실행한다(`CREATE_NO_WINDOW`, 헤드리스). 낮에 사장님이 GPU를 쓰는 중이면 관문이 막는다.
- 감사 기록: 모든 실행을 덧붙이기 전용으로 남긴다(`gpu_gate_log`, `agent_calls`, N156의 `ingest_runs` 계열). 클로드 호출이 기록에 없어야 "토큰 0"이라고 말할 수 있다.
- 훅 차단은 우회하지 않는다. 막히면 멈추고 보고한다(공정 탐비상모드 #15).

## 측정 (성공 판정)
- 무인 완료율(사람 개입 없이 끝난 명세 / 전체), 건당 사람 개입 횟수, 재시도율, 보류 비율과 원인 분류, GPU 가동률(`gpu_gate_log`), 클로드 호출 수(0이어야 함), 검사기가 놓친 결함 수(사람이 나중에 발견한 것).
- 다음 단계 신호: 무인 완료율이 2주 연속 80% 이상이고 사람 개입이 건당 0.2회 이하면 야간 창을 넓힌다. 낮 GPU 사용 충돌이 주 2회를 넘으면 큐를 새벽 전용으로 되돌린다. (이 숫자는 제안이고 사장님이 정한다.)

## 단계적 롤아웃 (한 단계씩, 증거와 되돌리기)
- **P0 검사만**: 이미 만든 영상에 검사기를 매일 한 번 돌려 결과를 DB·파일에 남긴다(쓰기·렌더 없음). 증거: 일주일 결과표, 사람이 보기에 맞는지 표본 대조. 되돌리기: 크론 끄기.
- **P1 결정적 실행기 1종**: 조립 한 가지(`build_final.py` 호출)만 허용 명령으로 등록, `gpu_gate`·검사기와 연결. 증거: 같은 입력 3회 동일 결과, 종료 코드 처리. 되돌리기: 허용 목록에서 제거.
- **P2 큐와 타미 감시**: 명세 접수·감시·완료 신호. 증거: 명세 10건 무인 완료. 되돌리기: 폴러에서 이 큐 제외.
- **P3 자동 테스트 루프**: 로컬 LLM 초안 + 덱스 검토 지시서. 증거: 실패 5건 중 제안 채택률. 되돌리기: 제안만 남기고 끔.
- **P4 야간 렌더 창**: 새벽 01~06시 큐. 증거: 낮 충돌 0, 온도·디스크 상한 지킴.

## 성공 결과와 시행착오 (오늘까지의 근거, 누적)
- 성공: ① 타미 폴러가 카드를 2~5분에 처리하고 완료 신호가 `tasks/done`으로 오는 경로가 실제로 돈다. ② 핏 조립의 해석이 확정됐다(결정적 스크립트 전담 + 타미 감시). ③ GPU 관문 규칙은 측정 1,450건에 근거했다(5GB 초과는 6%, 24GB까지 찬 겹침 2번). ④ 카드→텔레그램 경로가 작동했다.
- 시행착오: ① 9/20 폴러가 한 줄 구조라 긴 작업 하나가 뒤를 막았다(줄 서기 막힘). 큐를 짧은 줄·긴 줄로 나눈 결정이 이 설계의 전제다. ② 약한 모델(타미)이 카드의 폴더 지시를 어겨 다른 곳에 복사했다. 명세를 JSON 칸으로 고정하고 결과를 이름·개수로 사후 점검하는 이유다. ③ 카드가 원격이 아닌 로컬 작업 폴더를 세어 "0건"을 알렸다. 명세는 "어디를 기준으로 세는가"까지 적는다. ④ 클라우드는 로컬 파이프라인을 직접 볼 수 없어 이 문서의 실행 부분은 모두 미검증이다(구현·실측이 없는 산출물은 공정자산이 아니라는 원칙에 따라, P0부터 실제로 돌려 증거를 남기기 전에는 "설계 초안"으로만 취급한다).
