# 로컬 에이전트 작업영역

> 2026-09-16 신설(사장님 지시). 신PC에서 로컬 에이전트(페르소나) 여러 개가
> 동시에 돌 수 있게 되면서, 서로 다른 에이전트가 같은 파일·프로세스·포트를
> 건드려 충돌하는 걸 막기 위해 각자의 작업영역을 명시해둔다. 새 로컬
> 에이전트를 추가하거나 담당 범위가 바뀌면 이 표를 그 자리에서 갱신한다.

| 에이전트 | 담당 영역 | 손대지 않는 것 |
|---|---|---|
| 로컬 탐 | 헤르메스 `config.yaml`, AI Pool 로컬 인프라(LiteLLM 프록시 `localhost:4000`, 크론 설정) | 잉크 프로젝트 콘텐츠, shorts-lab 파이프라인 |
| 로컬 마야 | 잉크 프로젝트 콘텐츠·리서치(헤르메스 브라우저 도구로 1차 조사), 제미나이 풀로 검증 호출 | 헤르메스 `config.yaml`, 크론 설정, shorts-lab 파이프라인 |
| 로컬 핏 | shorts-lab 파이프라인·에피소드 폴더 | 헤르메스 `config.yaml`, 잉크 프로젝트 콘텐츠 |

## 원칙

- 자기 담당 영역 밖의 파일을 고쳐야 하면, 먼저 그 담당 에이전트에게
  진행상황.md `📥`/`📤` 절로 요청한다. 직접 고치지 않는다.
- 같은 지시서로 같은 에이전트의 로컬 세션이 두 개 동시에 뜨는 걸 피한다
  (2026-09-16 밤 중복 실행 사고, cxo-db #106 참고).
- 이 표에 없는 새 로컬 에이전트를 추가할 때는 기존 담당 영역과 겹치지
  않는지 먼저 확인하고 이 표에 행을 추가한다.

## 워킹 디렉토리 공유 문제 (cxo-db #106, #113)

위 표는 "누가 어떤 파일을 건드리는가"만 정하고, "여러 에이전트가 같은
git 워킹 디렉토리(물리 폴더)를 공유해서 생기는 문제"는 다루지 않는다.
둘은 다른 문제다 — 담당 영역이 안 겹쳐도, 같은 폴더를 쓰면 서로의
**미커밋 변경**이 부딪힌다.

**왜 위험한가**: 로컬 세션은 보통 이 저장소를 한 번 clone한 폴더를
그대로 재사용한다. 로컬 탐·로컬 마야·로컬 핏이 동시에 뜨면 셋 다 같은
폴더에서 `git checkout <자기 브랜치>`를 실행하는 셈이라, 한 세션이
`git checkout .`·`git reset --hard`·`git clean`처럼 워킹트리 상태를
되돌리는 명령을 돌리면 **다른 세션이 아직 커밋 안 한 작업이 그대로
날아간다.** 실측 사례: 2026-09-16 같은 지시서로 로컬 탐 세션 2개가
동시에 떠서 브랜치가 충돌(cxo-db #106), 2026-09-17 로컬 탐 세션이
작업 중 폴더에 로컬 마야의 미커밋 노인덱스 작업(195편)이 섞여 있는 걸
발견 — 이번엔 우연히 특정 파일만 `git add`해서 피해는 없었지만, 재발
위험은 그대로 남아 있다.

**적용 완료(2026-09-17, 로컬 탐)**: 원안은 수동 `git worktree add`였는데,
실제로 셋업하려 보니 **Claude Code 자체에 이미 `EnterWorktree`/
`ExitWorktree` 내장 도구가 있었다**(Inspect → Reuse — 수동 명령보다 이걸
우선 쓴다). 수동 `git worktree add`보다 나은 점: 세션이 다른 워크트리로
`git -C <다른 경로>`처럼 리디렉션하려 하면 **Claude Code가 도구 차원에서
거부한다**("a worktree-isolated session's git operations must target its
own worktree") — 순수 git 격리보다 한 단계 더 강한 보장이다.

**세션 시작 시 각 페르소나가 할 일**:
```
EnterWorktree(name: "탐-workspace")   # 로컬 탐
EnterWorktree(name: "마야-workspace") # 로컬 마야
EnterWorktree(name: "핏-workspace")   # 로컬 핏
```
(도구 이름 제약상 한글은 안 되고 영문·숫자·`.`/`_`/`-`만 허용 — 예:
`tam-workspace`, `maya-workspace`, `fit-workspace`.) 워크트리는
`.claude/worktrees/<name>/`에 새 브랜치로 생성되고, 세션 종료 시
"keep"을 선택하면 다음 세션이 `EnterWorktree(path: "<그 경로>")`로 같은
워크트리를 재사용할 수 있다.

**검증한 것(DONE=VERIFIED)**: 실제로 `tam-workspace` 워크트리 생성 →
`git worktree list`로 메인 체크아웃·기존 워크트리(`goofy-kalam-46d202`)와
함께 3개가 독립적으로 등록됨을 확인 → 각자 다른 브랜치, 격리된
작업 디렉토리 확인. **검증 못 한 것**: 실제로 두 로컬 세션(탐+마야)을
동시에 띄워 미커밋 변경이 안 섞이는지 라이브로 재현하는 것 — 이건 각
세션이 위 방식을 실제로 채택해서 며칠 쓰다 보면 자연히 확인된다(억지로
동시 실행을 만들 필요는 없음, 다음에 마야가 세션 시작 시 이 방식을
쓰면 그 자체가 검증이 됨).

**수동 `git worktree add`가 여전히 필요한 경우**: Claude Code 세션이
아니라 순수 스크립트·크론(예: 헤르메스)이 이 저장소를 건드릴 때는
`EnterWorktree`를 못 쓰므로 원안의 수동 명령(`git worktree add ../repo-X
-b claude/X-작업용`)을 그대로 쓴다.
