# 이름 정책: saegim(새김) → Carvit 리브랜딩 (2026-10-02, 사장님 확정)

브랜드는 Carvit으로 바뀌었지만 `saegim`은 저장소·서버·확장 곳곳에 남아 있다. 한 번에 바꾸지도, 그냥 두지도 않고 **이름이 놓인 층에 따라** 다르게 다룬다.

## 1층: 지금 바꾼다 (고객이 보는 이름)
- 화면 문구, 페이지 제목, 확장 이름·설명, 메일, OAuth 앱 이름처럼 고객 눈에 보이는 곳.
- 고객 설정에 박히는 주소(MCP 서버 주소 등)는 이름을 바꾸지 않고 **우리 도메인을 앞에 씌운다**(예: `mcp.carvit.ai` → 실제 서버). 뒤의 서버 이름이 무엇이든 고객과 무관해진다. 도메인 전환은 기존 고객 설정을 깨지 않게 옛 주소를 계속 살려 두는 것이 조건이다.

## 2층: 손댈 때 바꾼다 (내부 코드·문서)
- 코드 안 변수·함수·주석, 내부 문서 제목. 그 파일을 어차피 고칠 때 같이 바꾼다. 이름만 바꾸는 일괄 PR은 만들지 않는다.

## 3층: 바꾸지 않는다 (시스템 ID)
- (사장님 2026-10-21: 새 프로젝트를 만들어 이전하면 사라지므로 D단계에서 처리, 아래는 그 전까지의 현황) GCP 프로젝트 ID(`saegim-mcp`), Cloud Run 서비스 이름, Supabase 프로젝트, 저장소 이름(`simplifier-saegim`, `saegim-pass`), 로컬 폴더 경로, 크롬 확장 ID(manifest `key`로 고정).
- 이유: 바꿀 수 없거나, 바꾸면 고객 설정·저장된 Key·감시 대장·스크립트 경로가 동시에 끊긴다(2026-10-02 실측: 확장 ID가 폴더가 아니라 manifest key에 묶여 있어, 옛 ID로 시험하자 운영 로그인이 거부됨).

## 다음 단계 신호

## 2026-10-20 개정 (사장님): 사용자에게 노출되는 saegim은 지금 바꾼다

- 기존(2026-10-02 확정): 고객이 보는 이름만 즉시 바꾸고, 내부 코드·문서는 손댈 때, 시스템 ID는 바꾸지 않는다. 이름만 바꾸는 일괄 PR은 만들지 않는다.
- 개정 근거(북 실측 2026-10-20): 새 세션 첫 화면에서 저장소 `.mcp.json`의 `saegim` 서버를 쓸지 묻는 질문이 떠 사람 입력이 필요했고, 외부 사람이 공개 저장소를 열어도 같은 이름이 보인다. 고객이 적을수록 바꾸는 비용이 작다(사장님: 나중에 바꾸면 더 큰일).
- 개정 내용: 사용자의 첫 화면·설정·질문 창에 보이는 `saegim`(프로젝트 `.mcp.json`의 서버 이름, 안내문, 공개 문서의 안내 문구)은 최소한으로 지금 `carvit`으로 바꾼다. 환경변수 `SAEGIM_*`, 배포·GCP·저장소 ID 같은 시스템 ID는 그대로 둔다(3층 유지).
- 현황 조사(2026-10-20): 제품 저장소(simplifier-saegim)의 `saegim`은 환경변수·주석·시험·배포 ID가 대부분이라 사용자 노출은 사실상 없다(옛 이름으로 연결한 고객용 안내 문구만 의도적으로 남김). 노출 지점은 이 저장소의 루트 `.mcp.json`과 그 이름에 묶인 관문 훅(`saegim-gate.py`, `cite-note-gate.py`)·`settings.json` 권한 문자열 `mcp__saegim__*`이다.
- 주의: 같은 세션에 사용자 범위 `carvit`(다른 에이전트 신원)과 프로젝트 범위 `saegim`(탐 신원)이 함께 있다. 이름을 바꿀 때 같은 이름이 겹쳐 신원이 섞이지 않게 신원 분리를 같이 정한다. 관문 훅과 권한은 같은 PR에서 바꾼다.
