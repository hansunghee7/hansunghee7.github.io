## 위험이 낮은 이유와 한계

- 이 코드는 **알림 전용**이다. 새 DM이 왔다는 신호만 받을 수 있고 DM 본문을 읽거나 보낼 수 없다(도구 안내 문구 기준).
- 그래도 원칙(값은 에이전트와 대화에 남기지 않는다)은 지키는 쪽이 낫다. 같은 구조가 더 강한 코드(설치 코드)에서 되풀이되면 위험이 커진다.
- 이 PC의 설정 파일은 평문이다. 안내에는 파일 권한을 본인만 읽게 하라고 되어 있으나 Windows에서 실제로 적용되는지는 확인하지 않았다.

## 비교한 길

- **가. 에이전트가 파일에 쓴다(현재).** 구현 비용 0, 값이 대화에 남는다. 알림 전용이라 지금은 허용.
- **나. `pass.py envput`으로 에이전트가 값을 금고에 넣고 파일에는 참조만 둔다.** 값이 이미 에이전트에게 보인 뒤라 대화에 남는 문제는 없앨 수 없다. 효과는 파일 평문 제거뿐이고 금고 코드 수정이 필요할 수 있어 이번 범위에서는 제외한다.
- **다. 서버가 코드를 금고 도우미로 직접 보낸다(권장).** `autoreceive_setup`이 코드를 결과 글에 싣지 않고 "금고에 담았다, 설정 파일 위치는 이것"만 돌려준다. 값은 서버→금고→설정 파일로만 흐르고 에이전트는 보지 못한다. 설치 코드 재발급 설계(공정 카드 탐-패스개선 #30 ①: 금고가 서버에 재발급을 요청하고 코드는 서버→금고 직행)와 같은 뿌리라 한 번에 만들면 둘 다 풀린다.

다시 볼 신호: 서버가 금고 직행 전달을 지원하게 되는 시점(노트 확인), 또는 수신 코드의 권한이 알림 전용에서 넓어지는 변경이 생길 때.

## 제안하는 순서

1. 지금: 현재 방식 유지. 안내 문장은 "코드 값을 대화에 다시 적지 마라"로 낮춰 사실과 맞춘다(노트, 3차 항목 1과 함께).
2. 개선 과제: 노트에 "수신 코드를 결과 글에 싣지 않고 금고 도우미로 직접 전달" 요청(제품 변경, 서버 쪽). 근거는 이 문서. 완료 기준은 새 에이전트 설정에서 코드 값이 대화 기록에 나타나지 않는 것.
3. 금고 쪽: 서버 변경이 정해지면 도우미가 코드를 받아 설정 파일을 쓰는 기능이 필요하다. 이때 금고 코드 수정 허용 문장을 사장님께 따로 받는다(이번 승인 범위 밖).
4. 코드가 대화에 노출됐다고 판단되면: 알림 전용이라 교체는 필수가 아니다. 노출이 외부로 번졌을 때만 재발급한다(CLAUDE.md 자격증명 노출 예외 원칙).
