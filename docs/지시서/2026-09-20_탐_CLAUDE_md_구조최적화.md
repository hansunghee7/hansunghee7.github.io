## 0. 작업 목적

이번 작업의 목적은 `CLAUDE.md`를 단순히 짧게 만드는 것이 아니다.

현재 Claude Code 운영 규칙을 다음 계층으로 재구성하여, **상시 컨텍스트를 줄이면서도 에이전트의 규칙 준수율과 팀 전체 실행 안정성을 높이는 것**이 목적이다.

```text
CLAUDE.md
→ 모든 세션에서 항상 필요한 핵심 규칙

.claude/rules/
→ 특정 파일/경로에서만 필요한 규칙

.claude/skills/
→ 특정 업무를 수행할 때 필요한 절차

Hooks / CI
→ 모델의 기억에 맡기지 않고 기계적으로 강제해야 하는 규칙

Subagents
→ 독립적인 탐색·조사·검토·검증

docs / backlog / cxo-db
→ 현재 상태, 운영 기록, 사고, 의사결정의 역사
```

### 최종 목표

1. `CLAUDE.md`를 **200줄 이하**로 만든다.
2. 120~180줄은 **최적화 목표**이지 강제 기준으로 사용하지 않는다.
3. 현재 정책과 역할의 의미를 임의로 변경하지 않는다.
4. 중복 규칙을 하나의 정본으로 통합한다.
5. 업무별 절차를 적절한 Skill로 이동한다.
6. 특정 경로에만 필요한 규칙을 path-scoped Rule로 이동한다.
7. 반복 실패가 확인되고 기계적으로 판정 가능한 규칙만 Hook/CI 승격을 검토한다.
8. 독립 검증으로 리팩터링 전후 행동을 비교한다.
9. 문서가 줄었다는 사실이 아니라 **동일하거나 더 적은 컨텍스트로 더 안정적으로 동작하는지**를 최종 기준으로 삼는다.

# 1. 핵심 원칙

## 1-1. 이번 작업은 정책 변경이 아니라 정책 실행 위치 리팩터링이다

기존 정책을 다음처럼 임의로 바꾸지 않는다.

```text

```

다음은 기본적으로 허용된다.

```text
CLAUDE.md → Skill
CLAUDE.md → Rule
CLAUDE.md → Hook
CLAUDE.md → 현재 상태 문서
```

단, 내용을 삭제하거나 의미를 변경하는 경우에는 반드시 그 이유를 기록한다.

> 이 문장은 모든 세션에서 항상 필요한가?

### 예

* 예 → `CLAUDE.md`
* 특정 업무에서만 → `Skill`
* 특정 파일/경로에서만 → `Rule`

* 과거 사고 → 실수 대장 / history

“혹시 필요할지도 모른다”는 이유로 `CLAUDE.md`에 남기지 않는다.

7. Shorts 작업

## B. Skill 이동

다음에 해당하면 Skill로 이동한다.

* 여러 단계의 업무 절차
* 특정 업무에서만 필요

* 배포
* 글쓰기
* 검수

* 특정 운영 의식

---

## C. Rule 이동

다음이면 `.claude/rules/`를 검토한다.

* 특정 파일/디렉터리에서만 필요
* 특정 코드/문서 유형에만 적용
* 여러 업무에서 쓰지만 전체 세션에서는 불필요

가능하면 `paths:`로 범위를 제한한다.

---

## D. Hook/CI 검토

다음 조건을 모두 또는 대부분 만족하면 장치화를 검토한다.

* 반복적으로 실패하는 규칙
* 사람이 기억하지 않아도 항상 지켜야 함
* 기계적으로 판정 가능
* 실패하면 작업을 막는 것이 유리함

우선 검토 후보:

```text
main 직접 push
금지 문자
필수 검사
특정 파일 변경 시 검사
보안 검사
노출 변경
build/test gate
```

단,

> “Skill을 반드시 읽어야 한다”처럼 의미 해석이 필요한 규칙은 Hook으로 억지로 만들지 않는다.

Hook은 **결정적 통제**가 필요할 때만 사용한다.

```text
120~180줄
```

단, 다음 상황에서는 180줄을 넘겨도 된다.

> 중요한 공통 규칙을 삭제하거나 다른 계층에 부자연스럽게 넣어야만 180줄 이하가 되는 경우

그 경우 180줄 목표보다 **행동 안정성**을 우선한다.

---

# 16. Hook은 “필요할 때만” 만든다

Hook 후보를 발견했다고 반드시 구현하지 않는다.

다음 네 가지를 평가한다.

```text
1. 반복 실패가 실제로 확인되었는가
2. 기계적으로 판정 가능한가
3. Hook 구현 비용이 합리적인가
4. 유지보수 복잡도가 줄어드는가
```

예:

### Hook에 적합

```text
main 직접 push
금지 문자
필수 테스트
보안 검사
특정 변경 시 검사
```

### Skill에 더 적합

```text
글쓰기 workflow
마케팅 판단
문서 작성 순서
어떤 자료를 먼저 볼지
어떤 Skill이 필요한지 의미 해석
```

---

# 17. Skill 설계 원칙

Skill은 실제 workflow를 담는다.

가능하면:

```text
.claude/skills/<name>/
├── SKILL.md
├── scripts/
├── references/
└── examples/
```

구조를 사용한다.

`SKILL.md`에는 다음을 중심으로 둔다.

1. 언제 쓰는가
2. 입력
3. 절차
4. 멈춤 조건
5. 완료 조건
6. 참조 문서

장문의 배경자료는 references로 이동한다.

---

# 18. Subagent 설계 원칙

Subagent는 메인 컨텍스트를 보호하기 위해 사용한다.

우선 대상:

```text
탐색
수집
웹 조사
로그 분석
독립 리뷰
독립 검증
```

부모 세션보다 높은 모델을 자동 사용하지 않는다.

판단이 필요한 경우 결과 원문/근거를 부모 세션이 검토한다.

# 28. 가장 중요한 최종 원칙

이번 작업에서 성공의 정의는:

> `CLAUDE.md`가 짧아졌다는 것보다, 에이전트가 더 적은 상시 컨텍스트로 같은 일을 더 안정적으로 수행하게 되는 것이다.

따라서 다음 우선순위를 유지한다.

```text
행동 안정성
>
정책 보존
>
중복 제거
>
상시 컨텍스트 감소
>
문서 줄 수 최소화
```

문서가 짧아지는 과정에서 행동 안정성이 떨어진다면 되돌린다.

이번 작업은 “규칙 삭제 프로젝트”가 아니라:

> **심플리파이어 에이전트 운영체계의 실행 계층을 재배치하는 리팩터링**

으로 수행한다.
