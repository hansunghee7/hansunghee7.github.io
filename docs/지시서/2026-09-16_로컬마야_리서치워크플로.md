# 로컬 마야 도입: 리서치 워크플로 지시서 (2026-09-16)

발신: 탐(클라우드 세션) / 수신: 마야(신PC 로컬 전환) / 승인: 사장님

## 배경

클라우드 마야가 보고한 3개 블로커(심플리파이어 다이얼로그 Ask API 차단,
제미나이 그라운딩 할당량 0, 외부 뉴스·블로그 접근 차단) 중 2·3번은
클라우드 세션의 network egress 제한이 근본 원인이다. 로컬 세션은 이
제한이 없으므로, 마야를 신PC의 로컬 세션으로 전환한다(사장님 결정,
2026-09-16).

## 워크플로

1. **1차 조사는 헤르메스로.** 헤르메스의 `/browser`(CDP 연결 또는
   Browser Use 모드)로 실제 웹사이트를 직접 읽는다. 제미나이 그라운딩은
   쓰지 않는다(AI_POOL_프로젝트.md 원칙4, 호출량 최소화).
2. 조사 결과를 **개별 사실 주장 + 출처(URL·인용문)** 형태로 정리한다.
3. **검증은 제미나이 풀(gemini-pool)로, 2중 안전장치로만.**
   `docs/AI_POOL_제미나이_검증_프로세스.md`의 프로세스를 그대로 따른다:
   원본 출처가 확보된 주장은 그 자체로 정답 처리하고, 제미나이는
   "헤르메스가 출처를 정확히 요약했는가"만 대조 확인한다.
4. 검증까지 끝난 자료로 글을 쓴다.

## 실행

- 로컬 마야 세션 기동 방법은 로컬 탐·로컬 핏과 동일(신PC에서 직접 실행).
- 담당 영역은 `docs/로컬_에이전트_작업영역.md` 표를 따른다(헤르메스
  `config.yaml`·크론 설정은 손대지 않는다, 로컬 탐 담당).
- 제미나이 풀 호출법·마스터키 취급은 `docs/진행상황.md`의 "📥 탐(클라우드)
  → 마야: 제미나이 API로 질의하고 답 받는 법" 절 그대로.

## DONE 기준

1. 헤르메스 브라우저 도구로 외부 사이트 1건 실제 조회 성공.
2. 그 결과를 이 워크플로대로 제미나이 풀에 검증 호출, 실제 응답 수신.
3. 심플리파이어 다이얼로그 Ask API를 로컬에서 직접 호출해 답변 수신
   (클라우드에서 막혔던 것과 대조 확인).

세 가지가 다 되면 클라우드 마야의 3개 블로커가 로컬 전환만으로 전부
해소됐다고 최종 확인하고 진행상황.md에 기록한다.
