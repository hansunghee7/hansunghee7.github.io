# 덱스 영입 준비 (OpenAI Codex CLI)

> 문서만 준비한 단계다. 설치, 로그인, 실행은 아직 아무것도 하지 않았다(2026-10-02, 탐). 역할은 [역할노트-덱스.md](역할노트-덱스.md), 근거는 [B3 기록](processes/비티_검토_기록/B3_덱스도입.md).
> 비티의 답은 가설이었다. 10/2 탐이 공식 문서를 직접 열어 대조했다(아래 "공식 문서 대조" 절). 아직 확인 못 한 것만 [확인 필요]로 남긴다.

## 1. 영입 전 관문 체크리스트

네 가지가 모두 증거와 함께 채워져야 첫 시험을 한다. 하나라도 비면 멈춘다.

- [ ] 학습 제외: 사장님이 쓸 ChatGPT 계정에서 "내 대화·코드를 모델 학습에 쓰지 않게" 하는 설정이 켜져 있다. 화면 사진으로 확인한다. 무료 계정에서 이 설정이 가능한지 자체가 [확인 필요]다. 불가능하면 도입하지 않는다(B3 중단 기준).
- [ ] 격리 실행: 덱스는 저장소 본 폴더가 아닌 새 워크트리 또는 복사본에서만 돈다. 그 위 폴더에 비밀값 파일이 없다는 것을 `ls`로 본다.
- [ ] 비밀값 접근 차단: 작업 폴더에 `.env`, 키 파일, 고객 데이터가 없다. 덱스에게 줄 파일 무시 목록(B3의 `.codexignore`)이 실제로 있는지, 그 이름이 맞는지 [확인 필요].
- [ ] 한도와 요금: 무료(Free) 플랜에도 Codex가 포함된다. 공식 요금 문서의 무료 설명은 "Explore Codex capabilities on quick coding tasks"이고 정확한 횟수 한도는 문서에 없다(작업 크기에 따라 소모가 다름). 결제 수단은 등록하지 않는다.
- 네트워크: 공식 문서 "By default, the agent runs with network access turned off." 샌드박스 기본값으로 꺼져 있다. 켜는 옵션(`danger-full-access`, `--yolo`)은 쓰지 않는다.

## 2. 사장님이 직접 할 단계

계정 로그인과 설정 변경은 에이전트가 대신하지 않는다(계정 인증, 설정 변경은 사장님 몫). 각 단계는 한 동작이다. 어디서 막히면 그 화면 사진을 탐에게 보내 주시면 된다.

### 2-1. 설치 (사장님 PC, PowerShell 창)

1. 키보드의 Windows 키를 누르고 "PowerShell"을 입력해 "Windows PowerShell"을 연다. 성공: 파란 또는 검은 창에 `PS C:\...>`가 보인다.
2. 아래 한 줄을 입력하기 전에 Node.js가 있는지 본다: `node --version`을 붙여넣고 엔터. 성공: `v숫자.숫자.숫자`가 나온다. 실패("인식되지 않습니다"): 여기서 멈추고 탐에게 알린다(Node 설치 단계는 탐이 따로 안내한다).
3. 설치 명령을 붙여넣고 엔터: `npm install -g @openai/codex`. 공식 저장소(github.com/openai/codex) README의 명령과 같다. Node.js가 필요하다. Windows는 공식 PowerShell 설치 스크립트도 있지만 우리는 npm 방식 하나로 통일한다.
4. `codex --version`을 붙여넣고 엔터. 성공: 버전 숫자가 나온다. 실패: 화면 사진을 탐에게 보낸다.

### 2-2. 로그인 (ChatGPT 계정)

1. 2-1이 끝난 PowerShell 창에서 `codex`를 입력하고 엔터. 로그인 방식을 고르는 화면이 뜬다(공식 README: "Run codex and select Sign in with ChatGPT").
2. `Sign in with ChatGPT`를 고른다. 성공: 브라우저가 열려 ChatGPT 로그인 화면이 나온다. 실패(브라우저가 안 열림): 화면에 나온 주소를 탐에게 보낸다.
3. 브라우저에서 사장님이 직접 로그인한다. 비밀번호는 어디에도 복사하지 않고 탐에게도 보내지 않는다.
4. 터미널로 돌아와 "로그인 완료" 비슷한 문구가 보이면 성공. 실패: 사진을 탐에게 보낸다.
5. 결제 정보를 입력하라는 화면이 나오면 입력하지 말고 닫는다.

### 2-3. 학습 제외 설정

1. 브라우저에서 ChatGPT에 로그인한 상태로 화면 오른쪽 위 프로필 아이콘을 누른다.
2. "설정"에 해당하는 메뉴를 고른다. 이어서 `Data controls`(데이터 제어)를 고른다. 메뉴 이름은 제미나이 조사 결과이고 탐이 원문을 아직 열어 보지 못했다[확인 필요].
3. `Improve the model for everyone`(모두를 위한 모델 개선) 스위치를 끈다(제미나이 조사, [확인 필요]: 이 설정이 Codex 사용분에도 적용되는지 공식 원문 미확인). 성공: 스위치가 꺼진 상태로 보인다. 그 화면 사진을 탐에게 보낸다.
4. 스위치가 없거나 무료 계정에서 끌 수 없으면 그대로 두고 탐에게 알린다. 이 경우 도입은 중단이다.

## 3. 첫 시험 과제 1건과 합격 기준

B3의 비티 제안(`notify.py` 재시도 추가)은 대상 파일이 이 저장소에 있다는 증거가 없어 쓰지 않는다. 대신 이 저장소에서 실제로 가능한 더 작은 과제를 쓴다(2026-10-02 `ruff` 실측으로 확인).

- 과제: `scripts/ops/yt_oauth_once.py`의 ruff F401(쓰지 않는 import `os`) 지적을 고친다. 검사 명령: `python -m ruff check scripts/ops/yt_oauth_once.py --select F401,F841`. 현재 결과는 지적 1건이다. 이 파일은 일회성 스크립트라 시험 대상으로 안전하다.
- 입력: 위 파일 한 개의 복사본과 위 검사 출력(작업 카드 1장). 비밀값 파일은 복사하지 않는다.
- 합격 기준 (모두 만족):
  - 위 검사 명령이 종료 코드 0(`$?`가 0)이다.
  - `python -m py_compile` 통과.
  - diff가 그 파일 하나뿐이고 실제 사용하는 import는 지워지지 않았다.
  - 덱스 작업 폴더 밖 파일 접근 0건(작업 폴더 구성으로 확인).
  - 탐이 중간에 고쳐 보낸 횟수 0회. 덱스 사용 후 탐 토큰 사용량을 기록해 직접 고칠 때와 비교한다.
- 이 시험은 쉬워서 "덱스가 똑똑한가"는 알려 주지 못한다. 도입 관문(격리, 호출 방식, 한도)이 실제로 돌아가는지 보는 시험이다. 두 번째 시험으로 pytest 실패 1건 수정을 넣는다.

## 4. 호출 방식 초안

- 파일: `scripts/ops/ask_dex.sh`(만들어 두었고 실행한 적 없음). 형태는 `ask_bt.sh`와 같다: 카드 파일을 넣으면 답이 파일로 나오고 끝난다. 상시 감시 없음.
- 다른 점: 비티는 구PC 원격이지만 덱스는 로컬의 격리 폴더에서 돈다. 환경변수 `DEX_WORKDIR`로 격리 폴더를 반드시 지정하고, 저장소 본 폴더나 비밀 폴더이면 스크립트가 멈춘다.
- 비대화형: `codex exec`. 샌드박스 이름은 `read-only`, `workspace-write`, `danger-full-access`, 승인 정책은 `on-request`, `never`(공식 문서 "Agent approvals & security"). 덱스는 검토만 할 땐 `read-only`, 고칠 땐 `workspace-write`, `danger-full-access`와 `--dangerously-bypass-approvals-and-sandbox`는 금지.
- 결과는 파일로만 받고 탐이 diff를 읽는다. 사장님 손을 거치지 않는다.
