# Azure gpt-5-mini 사용법

우리 Azure 배포 gpt-5-mini를 쓰는 두 가지 길이다. 키는 카빗 패스 금고가 비밀 파일에 넣어 두며, 이 문서와 코드는 키 값을 다루지 않는다.

## 누가 언제 쓰나

- 마야·핏은 **아이디어 주제가 없을 때** `python scripts/ops/ask_gpt.py --who 마야 --task ideas "프롬프트"`로 부른다. 긴 카드는 `--file 카드.md`, 결과를 파일로 받으려면 `--out 답.md`를 붙인다.
- `--task ideas`는 주제·흐름 아이디어를 번호 목록 5개, 각 한 줄 근거로 돌려준다.
- 덱스 리뷰 검수는 `DEX_PROVIDER=azure`를 주고 `ask_dex.sh`를 부르면 Azure로 간다. `review_queue.py`는 이를 기본으로 넘긴다.
- 판정(통과·반려)은 여전히 탐이 한다. 이 모델의 답은 초안·의견이다.

## 한도와 기록

- 하루 호출 상한은 환경변수 `AZURE_GPT_DAILY_CALLS`(기본 300)이다. 넘으면 종료 코드 5로 거부한다.
- 호출 기록은 `C:/work/_ops/azure/usage.jsonl`에 한 줄씩 남는다(시각, 누가, 작업, 입력·출력·추론 토큰, 성공 여부). 답 본문은 기록하지 않는다.
- 이 모델은 추론에 토큰을 쓰므로 `--max-tokens` 기본값은 4000이다. 너무 낮추면 답이 빈다.
- 타임아웃은 90초이고, 실패는 종료 코드와 한 줄 사유로 나온다(2 입력, 3 비밀값 의심, 4 키 없음, 5 상한, 6 호출 실패).

## 롤백

- 덱스 검수를 예전 방식으로 되돌리려면 `REVIEW_DEX_PROVIDER=default`를 주고 `review_queue.py`를 돌린다. `DEX_PROVIDER`를 넘기지 않으므로 기본 동작과 같다.
- `DEX_PROVIDER`가 없으면 `ask_dex.sh`는 이전과 완전히 같게 동작한다.

## 하지 말 것

- 프롬프트·카드에 비밀값(키, 토큰, 비밀번호)을 넣지 않는다. 의심 문자열이 있으면 래퍼가 거부한다.
- 고객 정보, 가격, 사업 전략을 프롬프트에 넣지 않는다. 래퍼의 거부는 1차 관문일 뿐 완전한 검사가 아니다.
- 키 파일을 열어 출력하지 않는다. 키가 필요한 일은 코드가 파일에서 직접 읽는다.
