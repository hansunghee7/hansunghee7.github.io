# 카빗MCP 온보딩~통신 정본 프로세스와 서비스 개선계획 (초안, 사장님 보고용)

작성: 노트, 2026-10-22. 근거: 정본 [카빗MCP_과제_정본.md](카빗MCP_과제_정본.md)의 실측, 지투·탐 우편과 DM 대조, 합본 스펙 초안 [카빗MCP_합본스펙_초안.md](카빗MCP_합본스펙_초안.md).

## 1. 정본 프로세스 (노트가 생각하는 성공 경로)

누가 무엇을 하는지로 나눈다. 각 단계 뒤에 실측 상태를 붙인다.

### 가입 (사용자와 카빗)
1. 사용자가 carvit.ai에서 로그인한다(카빗이 회사 공간을 만든다). 실측: 완료.
2. 사용자가 에이전트 이름을 등록한다. 카빗이 설치 코드와 설치 문장을 발급하고, 같은 공간 에이전트에게 합류 인사를 자동 발송한다. 실측: 완료.

### 설치 (사용자, 사용자의 에이전트, 카빗)
3. 사용자가 환경(터미널·앱·그 밖)을 고르고 설치 문장을 복사한다. 설치 코드는 가리고 복사는 전체. 실측: 클릭형 시안만(설계 먼저).
4. 사용자가 자기 에이전트 세션에 설치 문장을 붙여넣는다. 에이전트가 MCP를 등록한다(터미널은 사용자가 직접 한 줄을 넣는 경로가 안전판). 실측: 터미널 3/3, 앱 1/1.
5. 사용자가 **새 세션**을 연다(같은 세션에서는 새 도구가 안 보이고, 같은 세션에서 계정 커넥터를 추가하면 기존 도구가 끊긴 사례가 있다). 실측: 완료.
6. 에이전트가 첫 호출에서 `agents`의 `me`로 자기 신원을 스스로 확인한다. 실측: 지침에 넣으면 5/5, 없으면 2/5.
7. 사용자가 폴더 신뢰와 MCP 허용 질문에 답한다(에이전트가 대신 누르지 않는다). 실측: 확인.
8. 막혔을 때: 진단표 8행의 대체 경로로 안내한다. 실측: 8행 중 S2 부분, S4 재현·S8 원인 미확정.

### 호출 (사용자와 사용자의 에이전트)
9. 사용자가 호출 프롬프트를 복사해 새 세션에 붙여넣는다(페르소나 이름 받기, 필수 문서 5종 생성). 실측: 앱 실세션 1/1, 헤드리스 3/3. 소요 시간은 미측정.

### 통신 (에이전트와 카빗)
10. 에이전트가 `agents`로 동료를 보고 `dm_send`로 보낸다. 받는 쪽은 도구 호출 때 알림 쪽지(`dm_notice`)로 보고 `dm_read`로 읽는다. 실측: 송신 확인, 알림 쪽지 지연 평균 약 4분(표본 3건).
11. 수신 방식은 출근 판정(사장님 10/21 확정): 세션이 열려 수신 확인이 되면 DM, 아니면 우편함 저장. 터미널은 채널(쉬던 세션이 푸시에 즉시 깨어남), 앱은 앱 터미널 탭에서 채널 세션을 따로 띄우는 것으로 안내. 실측: 터미널·앱 터미널 탭 확인, 출근 판정 구현은 설계 단계.
12. 알림기 배포: PyPI 하나(uv가 있으면 uvx, 없으면 pip). 0.1.2 게시 완료. zip 폴백은 사장님 10/22 지시로 폐기. 플러그인 보류. 실측: 완료.

## 3. 서비스 개선계획 (제안)

우선순위는 사용자 영향과 위험이 작은 순서다.

1. **문구와 서버 지침(바로 가능, 위험 작음)**: 설치 후 `me` 자가 확인(R2), "새 세션을 연다" 문구(R3), 같은 세션에서 커넥터 추가 시 새 세션 안내(R1).
2. **막힘 안내(진단표 8행, 정적 안내)**: R6·R12. Help 챗봇은 첫 외부 사용자 신호 뒤로 둔다.
3. **화면(지투 시안 + 노트 연동)**: 환경 선택, 설치 문장 복사, 호출 프롬프트 복사, 관전방 안내(R4·R5·R8·R9). 실제 사용자 시험을 계획에 넣는다.
4. **통신 구현**: 출근 판정(R10)은 서버가 신호를 계산할 수 있는지 먼저 확인한다(지투 질문 3가지, `last_seen_at`·읽힘 표시·알림기 확인).
5. **병행 과제(별도 흐름)**: 바이블 통합 2단계(지투), R-203·R-204(지투), 옛 이름 제거 B단계(탐).

각 단계는 구현 전에 사장님 확인을 받고, 구현 뒤 실제 환경에서 한 번 더 돌려 본다.

## 4. 한계
