# 마야 글쓰기 고도화 루프 ("글로벌 탑급 라이터 되기" 프로젝트)

> 정본 문서. 사장님 지시 2026-10-06: "마야가 카피라이팅·UX라이팅·테크니컬라이팅·브랜드라이팅·네이밍 등 글과 관련된 전문 에이전트가 되고, 1회성으로 끝나지 않고 루프로 고도화되며 돌게 하라. 글 종류에 따라 라우팅되어 전문화된 글을 쓰고, 측정지표와 셀프 피드백 루프를 개발하라."
> 데이터 정본: `scripts/ops/maya_write_rubrics.json`(종류, 라우팅 단서, 평가표, 린트 규칙). 도구: `scripts/ops/maya_write.py`. 평가 기록: `C:/work/_ops/maya_writing/eval_log.jsonl`.
> 역할 노트의 권한표가 우선한다. 제목·대외 메시지·네이밍의 확정은 항상 사장님 컨펌이다.

## 1. 탑급의 정의 (측정할 수 있어야 탑급이다)

더 큰 모델이 아니라 **기준표, 독립 평가, 실측 성과**를 갖추는 것이다. "탑급"이라는 말은 아래 지표가 기준선 대비 오르고, 외부 블라인드 평가에서 확인될 때만 쓴다. 지금은 기준선을 재는 단계이고 목표 수치는 기준선을 잰 뒤에 정한다(수치를 먼저 만들면 오늘 마야가 한 과장과 같은 실수가 된다).

## 2. 루프 (글 한 편마다, 그리고 매주)

1. **판별**: `python scripts/ops/maya_write.py route "<요청 문장>"`. 종류(카피·UX·테크니컬·브랜드·네이밍)와 작업 순서(가이드, 작성 도구, 린트 맥락, 독립 평가, 컨펌)가 나온다. 판별이 애매하면 한 줄 질문. 판별이 틀렸으면 고치기 **전에** `routecase "<발화>" <종류>`로 먼저 기록한다(보류 시험이 된다).
2. **가이드 조회**: 플레이북의 `mcp:` 항목은 `lookup(doc=UX_GUIDE_CARVIT, ...)`로 받고, 쓴 절은 `cite`(note는 `[마야]` 시작). 파일 항목은 열어서 읽는다.
3. **작성**: 제미나이 3.8 flash(`ask_vertex.py --model gemini-3.8-flash`, 조사는 `--search`, 가이드 1.48). 후보는 서로 다른 전략 3~5개.
4. **린트**: `maya_write.py lint <파일> --context carvit|home|generic [--title --sub]`. 오류 0이 될 때까지 고친다. 길이·문체·금지어는 모델이 아니라 이 도구가 센다.
5. **독립 평가**: `maya_write.py card <종류> <파일>`로 평가 카드를 만들고 `scripts/ops/ask_dex.sh`(덱스 우선, 비티는 한도 확인)로 채점시킨다. 쓴 쪽(마야)과 채점하는 쪽은 분리한다. 평가자가 센 길이·숫자는 믿지 않고 린트·산술로 다시 센다.
6. **기록**: `maya_write.py log add --type ... --scores <덱스 답 파일> --evaluator 덱스 --title ... --sub ... --notes "한계"`. 자기 평가는 기록은 되지만 평균에서 빠진다.
7. **주간 점검(토요일 CMO 세션)**: `maya_write.py report`. 기록 없는 영역과 점수 낮은 항목이 "다음 개선 후보 3개"로 나온다.
8. **반영**: 후보 하나를 골라 가이드 절, 린트 규칙, 라우팅 단서, 평가표 항목 중 한 곳에 반영한다(문서만 고치는 것은 첫 선택이 아니다, CLAUDE#4e7b). 가이드 변경은 지투·노트 경로.
9. **확인**: 반영 뒤 같은 입력을 다시 린트·평가해 점수가 올랐는지 기록한다. 안 올랐으면 반영을 되돌리거나 고친다.

## 3. 측정지표

- M1 **기준선 커버리지**: 영역별 독립 평가 기록 수. 지금 UX 1건, 나머지 0건. 영역마다 3건 이상을 첫 목표로 한다(숫자는 기준선 뒤에 다시 정함).
- M2 **독립 평가 항목별 평균과 추세**(1~5점, 공통 3개 + 영역별 5개). 정본은 평가표 JSON.
- M3 **린트 통과율**(오류 0 비율)과 경고 종류별 건수.
- M4 **라우터 정확도**: 만든 시험 20건(고치는 데 쓴 것), 그리고 `routecase`로 쌓이는 보류 시험 정확도를 따로 본다.
- M5 **컨펌 재작업률**(사장님 반려·수정 지시 횟수): 아직 수집 방법이 없다. 사장님 말 원장(`boss_said.py`)에서 글별로 세는 방법을 설계 과제로 둔다.
- M6 **성과**: 글별 좋아요·조회·홈페이지 유입([마야_KPI.md](마야_KPI.md)). 글의 속성(제목 길이, 형용사 유무, 구조)과 묶어 보되, 표본이 모일 때까지 통계를 말하지 않는다.
- M7 **외부 블라인드 평가**(분기): 마야 글, 기본 모델 글, 외부 우수 글을 이름 가리고 사람이 비교. 탑급이라는 말은 여기서만 나온다.

## 4. 기준선 (2026-10-06 첫 측정)

- 도구 시험: 라우터 20/20, 린트 7/7, 플레이북 파일 경로 정상(`maya_write.py selftest`). **라우터는 제가 만든 시험 14건은 만점이었으나, 사장님의 실제 발화 6건은 고치기 전 2/6**이었고 키워드를 고쳐 5/6(남은 1건은 라벨이 임의였음)이다. 앞으로의 정확도는 `routecase`로 쌓는 보류 시험으로 본다.
- 린트 기준선(13건): carvit.ai 한국어 3페이지(홈·UX MCP·브랜드)와 영어 홈은 통과, 테크리포트 4편은 2편 통과, 1편 경고 1(평어체 2문장, 단계 이름표라 오탐 가능), 3편 경고 1(내부 용어 "서랍", 첫 문단에 대응 설명 있음), 4편 경고 1(평어체 4문장: 남은 원칙 목록이 합니다체 본문에 평어체로 섞임, 실제 결함). 마야 최근 홈페이지 글 5편(634~638)은 모두 통과.
- 독립 평가 1건(UX, 덱스): 낮은 항목 근거일치 2, 용어일관 2, 첫10초 2. 덱스 최우선 개선안은 "가이드 절", "조회·인용" 같은 핵심 용어를 쉬운 말로 통일하는 것. 평가자의 한계 둘을 같이 기록: 부제를 40자 안팎이라 판정했지만 린트 실측은 49자(길이는 기계 검사가 우선), 평가 입력에 버튼이 없어 다음행동 1점은 해석에 주의.
- 이 기준선이 알려 준 실제 결함 둘: ① 라이브 홈 부제가 49자로 가이드 기준(40자 안팎)보다 길다. ② 테크리포트 4편에 평어체 4문장. 둘 다 사장님·지투 컨펌 항목이라 마야가 직접 고치지 않고 올렸다.
- **영역별 독립 평가 기준선(2026-10-06, 덱스, 1~5점, 기록 13건)**: 카피 3건 전체 평균 2.96, 테크 3건(1·2·4편) 3.33, 브랜드 3건 3.17, 네이밍 3건 3.04, UX 1건. 영역마다 가장 낮은 항목은 카피 행동명확 2.0·신뢰증거 2.0, 테크 방법재현 2.7·용어정의 2.7, 브랜드 실제기록 2.0·차별구분 2.3, 네이밍 발음철자 2.0·고유검색 2.0. 가장 높은 항목은 카피 후킹 4.0·첫10초 4.0, 테크 한계공개 4.0, 브랜드 금지표현 4.3, 네이밍 구체간결 4.0·상표도메인 4.0(미확인을 미확인이라 적었기 때문). 테크의 약점은 마야가 앞서 한 사람 분석(방법 재현, 용어 정의)과 같아, 평가자가 달라도 같은 결론이 나왔다. 한계: 영역별 3건이고 입력은 본문 앞 6~7천 자까지이며, 네이밍 입력은 마야가 쓴 짧은 설명이라 "근거 없음"으로 낮게 나온 면이 있다(발음·검색을 실제로 재 본 적이 없다는 뜻이기도 하다). 테크리포트 3편(Carvit Pass)은 덱스 전송 관문의 낱말 검사(password·secret·API 키)에 걸려 평가하지 못했고 4편으로 대체했다.
- **반영 → 재확인 첫 사례(루프 8·9단계, 같은 날)**: 카피 '신뢰증거' 2.0(연구에 출처가 없다는 평가)을 보고 린트에 규칙 `출처없는근거`를 추가했다(연구·조사·논문·통계 낱말과 숫자가 있는 문장에 같은 문장 안 출처 표시가 없으면 경고). 같은 글로 재확인하니 636·637·638 세 편에서 각 1문장씩 실제로 잡혔고(외부 연구·통계를 인용하면서 출처는 자기 사이트 링크뿐), 테크 4편에서는 "우리가 한 조사"를 잡는 오탐 2건이 나왔다. 아홉 파일 기준 적중 3건, 오탐 2건이라 지금 정밀도는 약 60%이며, 낱말을 넓히지 않고 오탐 사례를 모아 다음 반영에서 좁힌다.

## 5. 영역 순서와 하지 않을 것

- 순서(추천): ① UX·테크니컬 라이팅(Carvit 직결, 이미 가이드 1.47~1.50이 있음) → ② 브랜드·네이밍(네이밍은 상표 검색 도구가 아직 없어 "미확인"으로 표시) → ③ 카피(전환을 재려면 외부 사용자가 필요).
- 지금 하지 않는 것: 파인튜닝(표본 부족, 비용), 글쓰기 SaaS 구독, 에이전트 증설, 근거 없는 목표 수치, 자기 평가만으로 점수 올리기.
- 다음 단계 신호: 영역별 독립 평가 3건 이상이 쌓임, 외부 사용자 발생(카피 전환 측정), 글 성과 표본이 영역별로 통계를 말할 만큼 모임.

## 6. 장치로 굳히는 계획 (문서에만 두지 않는다)

- `report`를 `scripts/ops/jobs.toml`에 주간 작업으로 등록하는 것은 수동으로 세 번 돌려 본 뒤, 첫 자동 실행 결과까지 확인해야 완료다(c7e4 규칙). 아직 등록하지 않았다.
- carvit.ai 저장소 CI에 `maya_write.py lint`를 검사로 넣는 것은 지투·노트에게 개선 과제로 올린다(오탐 경험이 쌓인 뒤).
- 평가표를 바꾸면 JSON의 `version`을 올리고 아래 이력에 한 줄 적는다. 평가 기록에는 `rubric_version`이 같이 남아 버전이 다른 점수를 섞지 않는다.
