# 주기 작업·서비스 신뢰성 체계 (감시 대장, 2026-09-20)

> 사장님 지시(2026-09-20): 주기 작업이 자꾸 "동작을 안 한다"는 문제의 원인과 재발방지. 조건은 **토큰 비용과 사장님 손이 들지 않을 것**. 그래서 AI 없이 스크립트로 점검한다. 소스는 `scripts/ops/`, 실행본은 `C:\work\_ops\`, 상태판은 `C:\work\_ops\STATUS.md`.

## 1. 원인 (2026-09-20 실측)
1. **성공 표시가 거짓**: 헤르메스 크론의 "ok"는 AI 실행 종료일 뿐 작업 성공이 아니다(폴러가 마무리를 빼먹은 날도 ok).
2. **실패가 조용히 쌓임**: 홈페이지 저장소 예약 자동화 7개가 보호 규칙 도입 뒤 `GH013 push 거절`로 실패한 채였다. 발견은 사람이 했다.
3. **등록만 하고 첫 실행을 검증하지 않음**: `model-roster-review`는 한 번도 실행 기록이 없다. 자동화 12개 중 8개는 실제 실행 확인이 없었다.
4. **환경이 바뀌면 조용히 죽음**: 모델 종료(404), 구글 인증 만료, 제미나이 풀 프로세스 미기동.
5. **"안 돌았다"를 알아채는 곳이 없음**: 헬스체크는 폴러만 봤고, 주기 작업 목록이 흩어져 있었다.
6. **GitHub 예약 실행 자체가 누락됨**(오늘 발견): 예약 발행 워크플로는 15분 간격 설정인데 실제로는 약 2시간 간격이고 4시간 48분째 실행이 없었다. 공식 문서도 부하 시 예약 실행의 지연을 명시한다(최소 주기 5분).

## 3. 점검 주기와 근거
원칙: **주기는 "탐지 지연을 얼마까지 허용하는가"로 정한다**(주기가 탐지 지연의 하한). 오탐을 줄이려고 서비스는 연속 2회 실패에 알린다.
| 대상 | 주기 | 알림 | 이유 |
|---|---|---|---|
| 에이전트가 일하다가 부딪히는 것(서비스, 헤르메스 크론, 기능 점검) | 30분 | 연속 2회(약 1시간 안) | 하루에 한 번만 보면 어제의 고장을 오늘 아는 셈이라 "일하다가 안 된다"가 그대로 남는다 |
| 예약 발행 | 2시간 | 1회 | 글 발행 시각에 직결 |
| GitHub 예약 작업, 명령 점검 | 6시간 | 1회 | 작업 주기가 하루~2시간이고 실패는 한 번에 확정 |
| PC 보안 상태 | 하루 1회 | 1회 | 상태 변화가 느림 |
근거와 한계: 조사(2026-09-20, 하이쿠 수집)에서 확인한 것은 "주기가 탐지 지연의 하한", "연속 2~3회 실패 후 알림 권장", "GitHub 예약 최소 5분과 부하 시 지연"이다. 조사가 인용한 세부 수치(예: SRE 책의 분당 횟수)는 출처와 맞는지 확인하지 못해 쓰지 않았다.

## 4. 등록 절차 (DONE=VERIFIED)
새 주기 작업(헤르메스 크론, 예약 워크플로, 작업 스케줄러)은 다음이 모두 끝나야 "등록 완료"다.
1. **지금 1회 실행**해 성공 증거(출력, 산출물)를 확인한다.
2. `scripts/ops/jobs.toml`에 항목을 추가하고 성공 기준(결과물)을 적는다.
3. 보호 규칙, 토큰, 모델, 인증을 바꿀 때는 대장에서 영향받는 작업을 찾아 즉시 1회 실행한다.

## 5. 경량 보안 설계 (AI 시대 위협, 마찰 최소)
원칙: 방어는 **길목**에 둔다(권한 최소화, 되돌릴 수 없는 행동 앞의 확인, 비밀 격리). 일상 마찰이 큰 통제는 하지 않는다.
- **이미 있는 것**: 위임 금지 목록과 사장님 승인 게이트, 공개/비공개 경계, main 보호 규칙, 사장님 보고 훅, 키 값 출력 금지(마스킹), 내부 노출은 교체 예외 규정.
- **감시에 편입(추가 비용 0)**: 방화벽, 디펜더, 디스크, 열린 포트 변화(기준선 비교).
- **오늘 확인한 위험(마찰 낮은 순)**: 새김 배포 계정 권한 과다(백로그 39), 외부 액션의 SHA 미고정(새김 저장소 13회 사용, 고정 0건), 올라마(11434)와 Open WebUI(3000), n8n(5678)이 모든 인터페이스에 열림(`OLLAMA_HOST=0.0.0.0` 설정 확인, 사용처는 미확인).
- **참고 자료의 위협 분류**(OWASP LLM 2025: 프롬프트 인젝션 LLM01, 과도한 권한 LLM06, 시스템 프롬프트 유출 LLM07, GitHub Actions 최소 권한과 서드파티 액션 고정). 세부 요약은 조사 결과가 부정확한 부분이 있어 분류와 방향만 썼다.
- **하지 않는 것(마찰이 커서)**: 모든 명령 수동 승인, MCP 전수 수기 심사, 키 자동 교체, 세션 전면 샌드박스. **넘어갈 신호**: 외부인 합류, 고객 데이터를 다루는 에이전트 도입.
