# 오케스트레이터 일하는 방식 (전사 공용)

## 오케스트레이션 2.0(구 환상의 오케스트레이션·비상모드)이란
- 2026-10-08 사장님이 이름을 정했다. 1.0은 본체가 소넷 서브에이전트에게 맡기는 것이었고, 2.0은 본체가 지휘와 판정만 하고 모든 자원으로 라우팅하는 **상시 기본값**이다. 공정 카드 이름 `탐비상모드`는 명령어(`proc.py steps 탐비상모드`)라 그대로 두고, 의미는 2.0 공정으로 읽는다.
- 완료 판정은 종료 코드가 아니라 출력 원문 증거로 한다.
- 타미(헤르메스)·로컬 스크립트·Qwen(실행), 덱스·비티·GCP Vertex(검증), 클라우드 세션을 모두 효과적으로 동시에 쓰는 상태다. 이것이 최상의 상태다(사장님 2026-10-07, 같은 날 오후 삼각 체계로 개정: 소넷 서브에이전트는 아래 SOP의 예외 관문에서만 쓴다).
- 모든 에이전트(탐·마야·핏·지투·노트 등)는 이 상태를 지향한다. 본체는 지시서·위임·판정·병합 한 줄·사장님 대화만 한다.
- 갈래는 여섯이다. 다섯 갈래(타미·스크립트, 클라우드 세션, Vertex, 덱스·비티, 소넷 예외)에 **클로드 API 활용도 레이어**(만료 크레딧 소진, 래퍼 필수)가 여섯째로 붙는다(사장님 2026-10-11). 아래 '### 클로드 API 활용도 레이어' 절이 정의다.
- 갈래 하나만 쓰고 있으면 나머지를 왜 안 쓰는지 사유를 대조해 본다. 순서·호출법은 공정 카드 탐비상모드 #10·#11, 정의 카드는 공용-오케스트레이션.

정본 공정: 탐 21번(평소 역할), 탐비상모드, 클라우드세션작업지시, 마야 18번. 이 문서는 그 공통분모와 페르소나별 적용을 한 장으로 모은 것이다.

## 한 줄 원칙
- 직접 하는 일은 지시서 작성, 위임, 결과 판정, 병합 한 줄, 사장님 대화뿐이다. 편집·조사·통독·push는 맡긴다.

## 병렬 발주와 배시 대기 (사장님 정정 2026-10-07)
- 본체는 일감을 하나씩 처리하는 작업자가 아니다. 과제를 **5~7개 서브작업**으로 쪼개 한 번에 동시에 발주하고 기다린다.
- ① **병렬 발주**: 서브작업마다 갈래를 정해 한 턴에 모두 올린다(tasks/todo 지시서, solar-bible tasks/pending 카드, Vertex, Qwen, 타미, 덱스·비티). 한 서브작업은 입력·끝 조건·증거를 지시서 한 장에 적는다.
- ② **배시 대기**: 발주한 같은 턴에 백그라운드 배시 감시 루프(`python scripts/ops/orch_wait.py --main <지시서 파일명> --solar <카드 파일명>`, run_in_background)를 건다. 신호는 지시서가 tasks/done으로 옮겨져 main에 오르거나 카드가 solar-bible tasks/done으로 이동하는 것이다. 대기 중에는 다른 손일을 하지 않는다.
- ③ **신호 수신과 판정**: 감시가 끝나면(또는 이벤트로 깨어나, 설계 `docs/설계_N180_에이전트_통신망.md`) 결과를 검증 채널(덱스·비티·Vertex)의 요약으로 받아 한 줄로 판정(채택·조건부·기각)하고 남은 신호는 같은 방식으로 다시 건다. 시간 초과(기본 2시간)는 "신호 없음"으로 보고하고 다음 갈래로 넘긴다.
- 갈래 고르기: 판단·훅·사장님 확인이 낀 일은 tasks/todo, 명령 한 줄로 끝나는 수집·측정은 solar-bible tasks/pending(헤르메스 solar-pro4가 받으므로 지시를 짧고 정확하게). 결과 내용은 공개 저장소에 올리지 않고 로컬 파일 경로만 신호에 담는다.
- 한계: 신호는 로컬 쪽(탐 세션이 지시서를 집어 감, 폴러가 카드를 처리함)이 움직여야 온다. 5~7개는 한 번에 발주하는 지시서 단위이고 업무대장 진행 건 상한(탐 5건)과는 다른 숫자다.

## 전사 정식 운영 표준 (SOP, 일상·비상 공통, 사장님 2026-10-07)
적용 범위는 탐·마야·핏·지투·노트 등 전사 에이전트 일체다. 비상모드 임시 규칙이 아니라 평소 표준이다. CLAUDE.md 요약 줄(`5e1a` 절)은 이 절을 가리킨다.

- **소넷 서브에이전트는 원칙적 금지(Default Disabled)**. 예외 관문은 ① 무상 실행·스크립트가 연속 2회 이상 실패했거나 ② 100줄 이내 복잡 맥락 코드 구현처럼 무상 자원 범위를 명확히 벗어난 경우뿐이고, 극소 범위(원자적 과제 하나·파일 1~2개)로만 쓴다.
- **GUI 별도 예외(사장님 2026-10-07, CLAUDE.md 마지막 줄)**: 화면·브라우저 직접 조작(GUI)이 필수인 핏 전용 작업(예: 브라우저 임대)은 무상 자원으로 대체할 수 없으므로 연속 2회 실패 관문 없이 첫 시도부터 소넷 서브에이전트를 허용한다. `scripts/ops/browser_lease.py` 임대 절차(자동 만료·한 번에 한 명·로그)와 함께 쓰고, 다른 서브에이전트 발주에는 적용하지 않는다.
- 예외를 쓰면 `worklog.py add --who <이름> "서브에이전트 예외 사용: 사유"`를 남긴다(측정용, 훅 강제는 후속 과제).

### 삼각 체계 (기본 흐름)
- **실행(손)**: 타미(헤르메스)·로컬 스크립트·Qwen. 작업 카드(solar-bible tasks/pending, 이 저장소 tasks/todo)를 받아 구현·수집·정제를 한다. 클로드 토큰은 쓰지 않는다.
- **검증(눈)**: 덱스(코드·사실 1차), 비티(논리·보안·위험 2차), GCP Vertex(`ask_vertex.py`, 기획·대용량 문서·정적 분석). 타미가 올린 결과물과 지시서의 정밀 검증은 본체가 하지 않고 **검증 지시서**로 이 셋에 던져 요약을 받는다.
- **지휘(뇌)**: 에이전트 본체. 지시서 작성, 갈래 라우팅 발주, 대기(이벤트 또는 감시), 검증 요약에 대한 1줄 최종 승인·판정만 한다.

### 클로드 API 활용도 레이어
사장님 지시(2026-10-11): 오케스트레이션 레이어에 클로드 API 활용도 레이어를 추가하고, 에이전트들이 필히 쓰도록 정본에 반영한다. 출처 카드: 공용-오케스트레이션(클로드 API 활용도 레이어), 탐비상모드 #2(여섯 갈래)·호출법 카드, 탐 #34·#36.

정의: 오케스트레이션 갈래 중 머리가 필요한 단계(판정 보조, 긴 문서 정리, 코드 구현 초안, 교차 검토)를 로컬 스크립트·타미·제미나이 무료로 풀 수 없을 때, 만료되는 API 크레딧을 래퍼로 소진하는 층이다. 삼각 체계의 어느 칸에도 안 들어가는 별도 층이고, 소넷 서브에이전트 예외 관문과는 다르다(래퍼를 거친 API 호출이며 에이전트 세션이 아니다).

층의 위치(갈래별 한 줄 정의 옆):
- 실행(타미·스크립트·Qwen)이 못 푼 머리 단계 → 이 층으로 올린다.
- 검증(덱스·비티·Vertex)이 한도로 막히거나 같은 품질을 더 싸게 못 낼 때 → 이 층이 대신 교차 검토를 맡는다.
- 지휘(본체)는 이 층의 결과도 5줄 요약과 1줄 판정으로만 받는다.

규칙(필수):
- **순서**: 스크립트·로컬 → 제미나이 무료(search=False 먼저) → 비티·덱스 → 클로드 API 래퍼 → 그 밖의 소넷 서브에이전트(원칙 금지, 예외만). 다만 만료가 가까운 크레딧(클로드 API 10/28, GCP 회사 12/10·개인 12/23)은 같은 품질이면 먼저 쓴다. 이 층을 건너뛰고 소넷 서브에이전트로 가려면 이유를 worklog에 남긴다.
- **래퍼 필수**: 모든 클로드 API 호출은 `scripts/ops/api_run.py`(Messages API 직접) 또는 `scripts/ops/credit_run.py`(claude -p)를 거친다. 키(`ANTHROPIC_API_KEY_OPS`, 이름만 쓰고 값은 출력하지 않는다)를 직접 꺼내 호출하지 않는다. 호출마다 장부(`claude_api_usage.csv`: 호출 수, 모델, 추정 비용)가 남는다.
- **콘솔 대조**: 호출 뒤 콘솔의 크레딧 줄이 줄었는지 대조한다(탐 #34: 인증 출처, 프로모션 크레딧 줄, 비용 화면). 반영이 10분 넘게 걸릴 수 있다. 장부 추정치는 대조 전까지 추정이다.
- **비밀값 문서 금지**: 키 값, 계정 비밀, 고객 개인정보, 가격이 든 문서는 보내지 않는다. 비공개 일감 자료의 허용 범위는 탐 #24를 따르고, 결과는 파일로만 저장해 자동 반영하지 않는다.
- **상한은 관문이 강제**: 하루 상한(`--daily-usd`, 기본 5.0), 키 없음, 종료 코드(0 성공, 2 호출 실패, 3 하루 상한 초과, 4 키 없음)는 래퍼 코드가 막는다. 에이전트는 상한을 올리거나 우회하지 않고, 3이면 다음 날로 넘기거나 사장님 결정으로 올린다.
- **사용 기록 경고**: 한 구간(예: 하루) 사용 기록이 0이면 위임 관문 훅(`.claude/hooks/delegation-gate.py`)이 경고하게 한다. 이번에는 훅을 고치지 않았고 아래 제안으로 남긴다.

호출법과 장부 보는 법은 공정 카드 탐비상모드의 '클로드 API 레이어 호출법'에 있다.

훅 제안(후속 과제, 이번 변경 범위 밖):
- 위임 관문 훅의 '위임 기록' 정의에 `api_run.py`·`credit_run.py` 호출(장부 `claude_api_usage.csv`의 해당 구간 행)을 추가한다.
- 한 구간 장부가 0행이면서 만료 임박 크레딧이 남았으면 warn으로 시작한다(기본 warn, 차단은 실측 뒤).
- 래퍼를 거치지 않은 `api.anthropic.com` 직접 호출이나 `ANTHROPIC_API_KEY_OPS` 직접 사용을 감지해 알린다.

### 소넷 서브에이전트 통제 (기본 금지, 예외만)
- **원칙적 금지(Default Disabled)**. 허용되는 경우는 아래 둘뿐이다.
- 예외 관문: ① 무상 실행·스크립트가 연속 2회 이상 실패했다 ② 100줄 이내 복잡 맥락 코드 구현처럼 무상 자원 범위를 분명히 벗어난다. 둘 다 **극소 범위**(원자적 과제 하나, 파일 1~2개)로만 쓴다.
- **별도 예외: 화면(GUI) 직접 조작**(사장님 결재 2026-10-07 오후). 화면을 직접 보고 조작해야 하는 브라우저 작업(예: 핏의 브라우저 임대)은 타미·스크립트·하이쿠로 대체할 수 없다는 것이 실측으로 증명됐다. 그래서 "연속 2회 실패" 관문 없이 **첫 시도부터** 소넷 서브에이전트를 허용한다. 문구: "단, 화면/브라우저 직접 조작(GUI)이 필수적인 작업(예: 핏의 브라우저 임대)은 무상 자원 대체가 불가하므로 첫 시도부터 소넷 서브에이전트 사용을 예외적으로 허용함." 이 예외는 `scripts/ops/browser_lease.py` 임대 절차(자동 만료 최대 120분, 한 번에 한 명, 로그)와 함께만 쓴다.
- 예외를 쓰면 `worklog.py add --who <이름> "서브에이전트 예외 사용: 사유"`를 남긴다(측정용, 훅 강제는 후속 과제).
- **훅 차단은 우회하지 않는다.** 제작 서브에이전트가 훅 차단을 문자열 치환으로 피하려다 자동 모드 분류기가 보고를 막은 사건이 있었다(공정 탐비상모드 #15). 막히면 정당한 경로를 찾거나 막혔다고 보고하고 멈춘다.

### 검증 채널 사용법
- 검증 지시서 모양: 대상 파일 경로(로컬), 채널(Vertex→덱스→비티 중 무엇을 어떤 순서로), 질문 3개 이내, 돌려줄 형식(채택·조건부·기각 + 근거 5줄, 공개 가능한 문장만). 질문엔 고객 정보·가격·전략·프로젝트 ID를 넣지 않는다.
- 판정 기준: 헤르메스 카드의 `done`은 처리 종료일 뿐이므로, 검증 채널이 결과 파일 존재와 내용을 확인한 요약이 와야 "채택"이다. 요약이 없으면 "조건부"다.
- 한계: 비티는 한도 풀림 시각(본체 10-08 21:39, sonnet 10-11 01:01) 전에는 막힐 수 있다. 막히면 Vertex·덱스 결과만으로 조건부 판정하고 비티 질의는 풀린 뒤로 미룬다. Vertex는 하루 상한(10/10 전 변경 금지)을 넘으면 호출이 안 된다. 클라우드엔 이 채널이 없어 검증 실행은 로컬 몫이다.

## 검증된 패턴과 시행착오 (발견 즉시 한 줄씩 누적, 사장님 2026-10-07)
- 규칙: 효과적인 패턴, 시행착오, 병목 해결이 생기면 **그 자리에서** 이 절에 한 줄 추가하고 작업 PR에 같이 넣는다. 1회성 해결로 끝내지 않는다. 날짜와 증거(PR·로그)를 붙인다.
- 지시서 파일명은 감시 신호의 열쇠다. 감시를 건 뒤 파일 이름을 바꾸면 신호를 놓친다. 이름을 확정한 다음에 발주하고 감시를 건다(2026-10-07, a5 지시서 분할 때 이름이 바뀜).
- 발주 경로마다 받는 쪽이 있어야 한다. `tasks/todo`를 읽는 곳이 없어서 지시서가 아무에게도 안 갔다. 새 경로를 만들면 "누가 언제 읽는가"를 같은 PR에서 연결한다(2026-10-07, #2036).
- 헤르메스 카드의 `done`은 "처리 종료"일 뿐 결과 파일 존재가 아니다. 결과 파일은 로컬 검증 단계(후속 지시서)에서 확인한다(2026-10-07).
- 공개 저장소 카드에는 결과 내용을 올리지 않고 로컬 파일 경로만 신호로 쓴다. solar-bible은 공개다(2026-10-07).
- 클라우드에서 로컬 전용 스크립트(`proc.py`, `session_brief.py` 등)를 돌리면 `C:/work/...` 모양 파일이 작업 폴더에 생긴다. 끝나면 `git status`로 확인해 지운다(2026-10-07, 두 번 발생).
- 병목은 느낌이 아니라 로그로 확인한 뒤 고친다. 폴러 15분이 병목이라는 짐작은 실제 지연 약 2분과 달랐다(2026-10-07, 지시서 `타미_폴러_주기_점검`).
- 감시 루프를 정리할 때 `pkill -f`·`kill $(pgrep -f ...)`는 같은 명령줄(또는 같은 셸 호출 안의 어디든)에 스크립트 이름이 적혀 있으면 호출한 셸까지 죽는다(종료 코드 144, 괄호 요령 `[o]rch`도 문장 안에 이름이 있으면 소용없음, 2회 재발). 정리만 하는 호출을 따로 두고 PID를 숫자로 받아 `kill <PID>`만 한다. 새 감시는 또 다른 호출로 건다(2026-10-07).
- 클라우드 루틴(새 세션 생성형)은 `ArtifactData`는 쓰지만 `send_message`·`list_triggers` 같은 harness 도구는 못 쓴다. 한 번에 약 US$0.1이 든다. 그래서 "루틴이 감지하고 본체를 깨움"은 안 된다. 감지는 로컬 예약 작업이 하고 신호는 저장소 파일(`tasks/done/...`)로 클라우드에 오게 한다. 루틴을 만들기 전에 시험 실행 한 번으로 도구 가용성을 확인한다(2026-10-07).
- 한글 파일명 신호는 `git ls-tree`가 `\354\225...`처럼 따옴표와 8진수로 바꿔 출력해서 `orch_wait.py`가 한 건도 못 알아봤다(2026-10-07, 로컬이 12건을 끝낸 뒤에도 감시가 55분 조용했음). 한글 경로를 다루는 git 명령은 `-c core.quotepath=false`를 붙인다. 감시 루프를 새로 만들면 실제 신호 하나로 감지 시험을 한 번 한다.

- 본체(클라우드 탐)가 대장을 읽고 파일을 쓰는 손일을 하면 클라우드 토큰이 급격히 소진된다. 10/7에 세 차례 지적을 받았다(백로그 정리, 지시서 작성, 감시 스크립트 수정). 지시서·설계 문서처럼 지휘의 산출물만 본체가 쓰고, 수집·복사·시험 실행은 타미·로컬로 넘긴다(2026-10-07).
- 타미 카드가 지시한 폴더와 다른 곳에 파일을 복사했다(기억 파일 162개가 `reports/tam_memory/`가 아니라 `n172_sync_1007/tam_memory/`로). 약한 모델에는 경로를 한 줄에 하나씩, 끝 조건과 함께 적고, 결과는 이름·개수로 사후 점검한다(2026-10-07, `N172_동기화_검수`).
- 카드가 "tasks/todo 파일 수를 센다"고만 써서 타미가 원격이 아닌 로컬 작업 폴더를 세어 "0건"을 알렸다. 원격 상태를 묻는 카드는 `git ls-tree origin/main <경로>`처럼 원격 기준 명령을 그대로 적는다(2026-10-07, 로컬 세션 가동 알림).
- 자기 계정으로 단 PR 댓글은 이벤트로 오지 않았고(E1), 봇 댓글은 11초 만에 왔다(E2). 같은 계정의 신호는 걸러진다고 가정하고 발신자를 봇으로 둔다(2026-10-07, `docs/설계_N180_에이전트_통신망.md`).

- 아직 병합되지 않은 PR의 브랜치를 최신 main으로 되돌리고 강제 푸시하면 그 PR의 커밋이 사라진다. 병합 여부를 `git ls-tree origin/main`으로 먼저 확인하고, 안 됐으면 PR 브랜치 위에 커밋을 쌓는다. 이번엔 reflog로 복구했다(2026-10-07, #2065). 지정된 작업 브랜치 외의 이름(`-b` 접미사)으로 병렬 PR을 만들면 원격 브랜치를 못 지워 남는다(프록시가 삭제를 거부). 한 브랜치에 순서대로 쌓는다.

## 결과는 요약으로만 받는다
- 결과 파일을 오케스트레이터가 열지 않는다. 검증 채널(덱스·비티·Vertex)이 읽고 판정(채택, 조건부, 기각)과 근거 5줄만 돌려준다.
- PR은 검증 채널이 diff를 검토하고, 오케스트레이터는 CI 확인과 병합만 한다.
- 예외: 공개 저장소에 올릴 문서·설계를 쓴 본인(클라우드 탐)이 사실 확인을 위해 필요한 만큼 읽는 것은 막지 않는다. 이때도 파일 전체를 열기 전에 `grep`·범위 읽기를 먼저 한다.

## 감시 걸기
- 위임한 일마다 결과 파일이나 PR 생성을 폴링하는 감시를 같은 턴에 건다. 로그 위치를 적어 두면 세션이 닫혀도 새 세션이 읽는다.
- 클라우드 일감은 claude/cloud-* 브랜치와 PR 생성을 신호로 본다.
- 시각이 아니라 사건을 기다릴 때는 감시가 필수다(commit-gate 규칙).

## 컨텍스트 마감선
