# ops_query 도구 설계 초안: 에이전트가 운영 DB를 스스로 조회하게 만들기 (2026-10-06)

> 기존 초안(10/6, 탐)을 이어 고쳐 쓴 2판이다. 아래는 코드(`opsdb.py`, `session_brief.py`, `worklog.py`, `proc.py`, `db-gate.py`)에서 확인한 것만 적었다. 실제 DB 호출은 하지 않았다.

## 결론

- 조회 길은 이미 4개 있고 모두 `opsdb.py`를 거친다. 모자란 것은 두 가지다. 에이전트가 DB를 먼저 쓰게 하는 길안내와, 호출자·횟수를 입구에서 자동으로 재는 장치다.
- 해법은 읽기 전용 MCP 도구 `ops_query` 하나를 먼저 만들고, 막힘 안내문과 보고 스크립트를 그 이름에 맞추는 것이다.

## 현재 조회 경로 4개의 역할

- `opsdb.py`: 공통 도서관. `select`·`count` 명령과 모듈 함수(`insert`·`upsert`·`patch`·`delete`)를 가진다. 조건은 PostgREST 문법이고 필요한 열·행만 읽는 것이 목적이다. 호출마다 시각·방식·표·호출자를 `opsdb_access.jsonl`에 남긴다. 호출자는 환경변수 `OPSDB_WHO`나 명령줄 `--who`가 있을 때만 구분된다.
- `session_brief.py`: 하이 때 한 번 쓰는 묶음 조회. 내 최신 인수인계 원문, 열린 건 목록(사람 확인·진행·확인필요·대기), 감시 상태판의 문제 줄, DB 기준 시각을 출력한다. md가 DB보다 새로우면 가져오기 스크립트를 돌려 먼저 동기화한다.
- `worklog.py`: 에이전트가 자기 작업 기록을 한 줄씩 추가하고(`add`) 읽는다(`list`·`today`). `--who` 필수와 허용 이름 목록, 300자 제한, 비밀값 모양 거부, 삭제 명령 없음.
- `proc.py`: 공정 단계 카드와 작업별 체크리스트. 읽기(`steps`·`show`·`list`)와 추가·고치기(`add`·`amend`)·숨기기(`retire`)·진행(`run`)이 한 명령에 있다. 삭제는 없고 고친 이력은 남는다. 완료 처리에는 증거 경로가 필요하다.
- 한 줄로 비교하면, 임의의 표를 자유롭게 읽는 것은 `opsdb.py`뿐이고, 나머지 셋은 정해진 목적(하이 브리핑, 기록, 공정)에 맞춘 좁은 길이다. 쓰기까지 가진 것은 `worklog.py`·`proc.py`다.

## 에이전트가 md 통읽기 대신 DB를 먼저 보게 하는 방법

- 이미 있는 것: `db-gate.py`(PreToolUse 훅)가 업무대장·진행상황 md의 통읽기·grep을 막고 DB 명령을 안내한다. limit 150 이하 읽기, `sed -n`, `head`·`tail`, `git`, 편집용 python 스크립트는 통과한다. "[DB 불가: 이유]"를 적으면 예외로 통과하고 막힘·통과는 `db_gate_log.jsonl`에 남는다.
- 제안 1: 막힘 안내문의 첫 줄을 "`ops_query`로 묻는다"로 바꾼다. 지금은 `opsdb.py` 명령 문장이라 도구 호출로 이어지지 않는다.
- 제안 2: `ops_query`의 도구 설명에 "큰 업무 문서를 읽기 전에 이 도구로 먼저 찾는다"와 자주 쓰는 질의 예(번호로 한 건, 키워드로 목록)를 적는다. 에이전트는 도구를 고를 때 이 설명을 본다.
- 제안 3: 하이 브리핑(`session_brief.py`)은 그대로 두고 출력 끝에 "더 필요하면 `ops_query`"를 한 줄 붙인다.
- 훅은 막기만 하고 가르치지 못하므로, 막힌 자리에 올바른 도구 이름을 보여 주는 것이 핵심이다.

## 조회 한 번의 입출력 (JSON 제안)

- 입력: `{"who": "핏", "table": "tasks", "where": {"owner": "eq.핏", "status": "eq.진행"}, "cols": "no,title,status", "order": "id.desc", "limit": 20}`
- 출력(성공): `{"ok": true, "table": "tasks", "count": 3, "rows": [...], "truncated": false, "as_of": "<마지막 동기화 시각>"}`
- 출력(실패): `{"ok": false, "error": "who 필수", "hint": "who에 에이전트 이름을 쓰세요"}`
- `where` 값은 `opsdb.select`가 받는 형식 그대로(`eq.`·`neq.`·`gte.`·`lte.`·`in.(a,b)`·`like.*글자*`)라 새 문법이 없다.
- `limit` 기본 20·최대 100, `cols` 기본은 `*`가 아닌 표별 짧은 열 목록(토큰 절약). 숫자는 기존 초안 값이고 실측 뒤 조정한다.
- `as_of`는 DB가 최대 1시간 뒤처질 수 있다는 것을 응답에서 바로 알리기 위한 값이다(`session_brief.py`가 같은 이유로 기준 시각을 출력한다).

## 읽기 전용 원칙과 비밀값 비노출

- 도구는 `opsdb.select`·`count`만 부른다. `insert`·`upsert`·`patch`·`delete`는 불러오지 않는다. 쓰기는 `worklog.py`·`proc.py`가 추가 전용으로 맡는 현재 구조를 유지한다.
- DB 키는 도구 서버가 `.env`에서 읽어 쓰고 에이전트 입출력에 나오지 않는다. 오류 메시지에서 키를 `[키]`로 가리는 처리가 `opsdb.py`에 이미 있다.
- 허용 표는 코드에서 실제로 쓰이는 `tasks`·`docs`·`content_items`·`channels`·`metrics_snapshots`·`account_snapshots`로 시작한다(기존 초안과 같음). 목록 밖 표는 거절한다.
- 결과 행에도 `worklog.py`의 비밀값 모양 검사(키·토큰 접두어)를 적용해 걸리면 그 행을 가린다.
- `who`는 허용 이름 목록(`worklog.py`의 목록)과 대조한다. 내부 에이전트용이라 거짓 이름을 막을 수는 없고 구분 용도로만 쓴다.

## MCP 도구로 만들 때의 최소 목록

- `ops_query`(필수): 위 입출력대로 한 표를 읽는다.
- `ops_tables`(권장): 허용 표와 열 이름을 알려 준다. 에이전트가 열 이름을 추측해 실패하는 것을 줄인다.
- `ops_brief`(선택): `session_brief.py`를 감싸 `who`만 받아 인수인계와 열린 건을 준다. 하이 의식을 도구 한 번으로 바꾸고 싶을 때 쓴다.
- 쓰기 도구는 넣지 않는다. 지금 `.mcp.json`에는 `saegim` 서버만 있어서 새 서버 등록이 필요하다.

## 측정 지표

- 에이전트별 일일 조회 수: `opsdb_access.jsonl`에서 방식이 GET이고 호출자가 있는 행을 날짜·호출자별로 센다. `db_adoption_report.py`가 이미 G2 기준(하루 3명 이상)으로 보여 준다. 도구 호출도 같은 파일에 남기고 `cmd`로 구분하게 한다.
- md 통읽기 시도 감소: `db_gate_log.jsonl`에서 `decision`이 block인 줄을 날짜별로 센다. 10/5 시험 호출이 섞여 있으니 10/6부터 본다.
- 호출자 미지정 비율: 0에 가까워져야 한다. 도구가 `who`를 필수로 받으므로 도구 경로는 0이 된다.
- 남용 점검: "[DB 불가:" 예외 통과 비율이 오르면 DB가 낡았거나 예외를 우회로로 쓰는 신호다.
- 기존 초안이 인용한 10/6 실측은 호출 1,581건 중 호출자가 구분된 것이 탐 17건·마야 1건이다. 이 값이 도입 전 기준선이다(이 세션에서는 다시 확인하지 못했다).
