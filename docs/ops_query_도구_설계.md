# ops_query 도구 설계: 에이전트가 운영 DB를 안전하게 묻는 한 입구 (2026-10-06, 탐)

> 목표 G2(사장님 10/5): 에이전트들이 운영 상태 DB(도서관)를 실제로 쓰게 하고, 누가 얼마나 쓰는지 잰다. 대장 N156·N162.

## 결론

- 지금은 `opsdb.py`·`proc.py`·`worklog.py` 명령을 에이전트가 각자 쓴다. 호출 1,581건 중 호출자가 구분된 것은 탐 17건·마야 1건뿐이다(`db_adoption_report.py` 10/6 실측). G2의 "에이전트 3명 이상의 일일 조회"를 재려면 **호출자가 도구 입구에서 자동으로 붙어야** 한다.
- 해법은 MCP 도구 한 개 `ops_query`다. 읽기 전용, 허용 표만, 결과 크기 상한, 호출자 필수. 명령줄 `--who`에 기대는 방식은 에이전트가 빼먹으면 끝이라 안정적이지 않다.

## 도구 모양

- 입력: `who`(에이전트 이름, 필수), `table`(허용 목록: tasks·docs·channels·content_items·metrics_snapshots·account_snapshots), `where`·`cols`·`order`·`limit`(기본 20, 최대 100).
- 출력: 행 JSON과 건수. 값이 비밀 모양이면 거부(기존 `worklog.py` 규칙과 같다).
- 쓰기는 이 도구에 넣지 않는다. 쓰기는 `proc.py add`·`worklog.py add`가 이미 추가 전용으로 맡는다.
- 기록: 호출마다 `opsdb_access.jsonl`에 who·표·건수를 남긴다(지금 형식 그대로라 보고 스크립트가 바로 쓴다).

## 호출자를 붙이는 방법 (선택지)

- ① 도구 입력의 `who`를 필수로 한다. 빼먹으면 도구가 거절하고 "who에 에이전트 이름을 쓰라"고 안내한다. 가장 단순하고 지금 규모에 맞다. 에이전트가 거짓 이름을 쓸 수는 있으나 내부 에이전트라 위험이 낮다.
- ② 세션 시작 훅이 에이전트 이름을 환경에 기록. 이름은 사장님이 "하이~ 이름"으로 알려 줄 때 정해져서 훅 시점에는 모른다. 지금은 불가.
- 추천은 ①. ②는 세션이 이름을 시작 때 선언하게 되면 재검토한다.

## 단계

- 1단계(탐, 사장님 행동 없음): MCP 서버 스켈레톤을 `scripts/ops/ops_query_mcp.py`로 만들고, 이 저장소의 `.mcp.json`에 등록해 모든 세션이 같은 도구를 쓰게 한다. 1회 실행 증거 후 감시 대장 점검 항목을 추가한다.
- 2단계: DB 관문 훅의 안내 문구를 "`ops_query`를 쓰라"로 바꾸고, 통읽기 막힘 횟수와 `ops_query` 호출 수를 `db_adoption_report.py`에 함께 보여 준다.
- 3단계: 핏·마야·지투·노트에게 우편으로 알리고 일주일 뒤 보고서의 호출자별 수로 G2를 판정한다.

## 하지 않을 것

- 에이전트에게 DB 열쇠를 직접 주는 것(도구가 금고 경유 `envput` 값을 읽어 호출하고 값은 에이전트에 안 보인다).
- 쓰기 기능을 이 도구에 합치는 것(추가 전용 도구의 안전이 깨진다).
- 크레딧 장부·컷 큐의 DB 이관(핏의 제작 도구가 쓰는 파일이고 새 표 DDL이 필요해 별도 과제로 둔다).

## 한계

- MCP 서버가 세션마다 뜨는 방식(`.mcp.json`)이 원격·구PC 세션에서도 되는지는 아직 시험하지 않았다.
- 허용 표 목록과 `limit` 상한은 초안이며 1단계 실측으로 조정한다.
