# 리서치 체계 (모듈형 공정표 DB)

제미나이 리서치, 슈퍼리서치 같은 리서치 방법을 **모듈로 쪼개 운영 DB(simplifier-ops-data)에 연관 표로 둔 체계**다. 이 문서는 사용법만 가리키고, **내용의 정본은 DB**다. 문서와 DB가 다르면 DB가 맞다.

## 모듈 종류

- 체계: 여러 모듈을 순서대로 묶은 큰 단위(예: 슈퍼리서치).
- 모듈: 체계의 한 단계를 맡는 부품(예: 제미나이 검색 연동 질의).
- 도구: 실제로 돌리는 스크립트나 서비스.
- 규칙: 지켜야 할 조건(예: 출처 링크 원문 대조).
- 경로: 막혔을 때 갈아타는 대체 길(예: 버텍스 대체).

모듈 상태는 작동, 부분, 막힘, 계획, 폐기 다섯 가지다. 모듈끼리의 관계는 링크 표에 단계(step), 대체(fallback), 관문(gate)으로 적는다.

## 명령 5개 (PowerShell 기준)

- `python scripts/ops/research_db.py status`: 모듈별 상태, 최근 실행, 열린 이슈를 한 장으로 본다.
- `python scripts/ops/research_db.py howto <slug>`: 그 모듈의 실행 명령, 방법, 한계, 관련 공정 카드, 열린 이슈를 본다.
- `python scripts/ops/research_db.py tree <slug>`: 체계의 구성 모듈을 단계 순서로, 대체 경로까지 들여쓰기로 본다.
- `python scripts/ops/research_db.py add-run <slug> --who 탐 --question "..." --route "..." --ok yes --cost 0 --path <결과 파일>`: 리서치를 돌릴 때마다 한 줄 남긴다.
- `python scripts/ops/research_db.py add-issue <slug> --symptom "..." --cause "..." --fix "..." --status 열림`: 막힌 일이나 사고를 남긴다.

보조 명령: `issues [slug]`(이슈 목록), `set-status <slug> <상태> --note "..." [--verified]`(상태 변경), `link-check <run_id> <url> <http> <확인|부분|미확인|불일치>`(인용 링크 대조 결과), `seed <폴더>`(JSON 일괄 반영).

## 새 모듈 추가 방법

1. `C:/work/_ops/research_db/seed_modules.json`에 항목을 더한다. 필수는 slug, name, status이고 kind, entry(실행 명령), how_to, limits, process_ref도 채운다.
2. 체계에 붙이려면 `seed_links.json`에 parent, child, seq, role 한 줄을 더한다.
3. `python scripts/ops/research_db.py seed C:/work/_ops/research_db`로 반영한다(같은 slug는 덮어쓴다).
4. `status`와 `tree <체계 slug>`로 들어갔는지 확인한다.

## 안전 규칙

- 쓰기는 모두 길이 제한과 비밀값 모양(키 접두어, 주소 속 키 인자) 거부 관문을 지난다. 키 값은 DB에도 문서에도 쓰지 않는다.
- 표가 아직 없으면 "표 미생성: research_schema.sql 실행 필요"가 나온다. 표 정의는 `tools/db/research_schema.sql`이고, 운영 DB 실행은 별도 승인 절차를 거친다.
- 접속은 `scripts/ops/opsdb.py`를 쓴다(키는 카빗 패스 금고가 넣어 준 것을 읽기만 한다).
