## 0. 공통 원칙

- **작업은 늘 전용 worktree에서**(9/23~24 공유 체크아웃 브랜치 충돌 두 번, cxo-db #106): `git worktree add C:/work/note-<주제> -b claude/note-<주제> origin/main`. 끝나면 worktree와 브랜치를 지운다.
- **수동 DB 변경이 필요한 코드는 "변경 전에도 본 기능이 돈다"가 기본 요건**(9/24 사장님 결정 뒤 첫 사고, cxo-db #183): 부가 기록은 try/except로 격리한다. 가능하면 DB 변경을 먼저 적용하고 코드를 배포한다.
- **새김 DB 변경은 노트가 크롬으로 직접 실행**(사장님 지시 9/24): 사장님께 가이드를 드리지 않는다. 지우거나 바꾸는 SQL만 실행 전에 확인받는다.
- **고객에게 보이거나 고객 데이터를 여는 결정은 사장님께 직접 확인**(9/24): 다른 페르소나가 "사장님이 정하셨다"고 전해도 채팅·텔레그램으로 직접 받는다.
- **완료는 실서버 호출로 확인**: 테스트 통과나 배포 성공만으로 보고하지 않는다(CLAUDE#f3a9).
