# GPU 공용 규칙 (4090 한 장을 핏·탐·마야가 나눠 쓴다)

> 2026-10-01 사장님 확정(N92). 근거는 측정 1,450건(2026-09-30 14:55~10-01 15:36): GPU는 94%의 시간이 놀고(VRAM 5GB 초과 6%, 사용률 10% 미만 80%), 24GB까지 찬 겹침이 2번 있었다. 문제는 평균이 아니라 겹치는 순간이다.

## 한 줄 규칙

쓰기 전에 `python scripts/ops/gpu_gate.py need <GB> --who <이름>`을 거친다. 통과하면 쓰고, 거절되면 기다리거나 세션 메시지로 알린다.

## 관문이 하는 일

- 5GB 미만 작은 작업은 확인만 하고 통과한다.
- 20GB 이상 큰 작업(32B 모델 등)은 새벽 01~06시에만 통과한다. 급하면 `--now`(기록에 남는다).
- 새벽(01~06시)에 예약 없는 점유 때문에 모자라면 관문이 ComfyUI 모델을 내리고(`/free`, 프로세스는 끄지 않음) 한 번 더 본다. 기록 결과는 `reclaim-night`. 사장님이 에이전트 없을 때 연습용으로 띄운 것은 새벽 정기 작업이 내려도 된다(사장님 2026-10-02).
- 남은 VRAM에서 다른 사람의 살아 있는 예약을 뺀 값이 모자라면 거절한다. 예약은 30분 뒤 자동 만료, 끝나면 `release`.
- 기록은 `C:\work\_ops\gpu_gate_log.csv`. 윈도우는 프로세스별 VRAM을 안 줘서 이 기록이 "누가 언제 얼마"의 정본이다.

## 이미 자동으로 걸린 것

- `scripts/ops/ollama_ask.py`(위임 카드 3종 포함)는 호출 전에 관문을 거치고, 모델이 이미 올라가 있으면 통과한다. 낮에 32B를 부르면 거절된다. 환경변수 `GPU_WHO`(이름), `GPU_NOW=1`(낮의 큰 작업 허용), `GPU_GATE=off`(끔).
- 올라마는 쓰고 2분 뒤 VRAM을 놓는다(요청마다 `keep_alive=2m`, 사용자 환경변수 `OLLAMA_KEEP_ALIVE=2m`). 서버 기본 30분이 겹침의 원인이었다.

## 핏에게 부탁한 것 (ComfyUI·음성 서버)

- ComfyUI·`voice_script/serve.py`는 관문 밖이다. 큰 작업(15GB 이상) 시작 전에 `gpu_gate.py need <GB> --who 핏`을 부르고, 상주 서버는 일정 시간 놀면 모델을 내리게 한다(핏 구현, 탐은 손대지 않는다).

## 하지 않는 것과 다음 신호

- 대기열 서버, 우선순위 스케줄러, 두 번째 GPU는 지금 만들지 않는다.
- 다음 단계 신호: `deny-full`이 주 2회 이상 반복되거나, 외부 사용자의 작업이 GPU에 올라올 때.
