# 콘솔 창 깜빡임 범인 색출 절차 (핏, 2026-10-22)

사장님 화면에 CMD 창이 떴다 사라질 때 쓰는 절차다. 사장님이 다시 신고하면 이 순서로 바로 적용한다.

## 원인의 정체
- 창 없는 부모(`pythonw.exe`, 서비스, 예약 작업)가 `ffprobe`·`git`·`ffmpeg`·`cmd`·`powershell` 같은 콘솔 프로그램을 `creationflags=CREATE_NO_WINDOW` 없이 부르면 호출 하나마다 창이 한 번 뜬다.
- `DETACHED_PROCESS`는 쓰지 않는다. 가상환경 실행기가 자식에서 콘솔을 새로 만든다. 답은 `CREATE_NO_WINDOW`(필요하면 `CREATE_NEW_PROCESS_GROUP` 추가)다.
- 작업이 시작되는 무렵에 몰려 뜬다(편마다·문서마다 반복 호출).

## 상시 기록기 (2026-10-22 추가, 사장님은 키보드를 칠 수 없어 신고 시각도 못 남기므로)
- `scripts/ops/console_flash_logger.py`가 예약 작업 `핏_창기록`(로그온 때 시작, 창 없음)으로 상시 돈다. 창이 뜰 때마다 시각과 직전 3초의 새 프로세스(부모→자식)를 `C:/work/_ops/flash_log.jsonl`에 남기고 3일 지난 줄은 지운다.
- 읽기: `python scripts/ops/console_flash_logger.py --report 10`. 사장님 신고는 "ㄱㄱ"이나 "창" 한 단어면 되고 늦게 보내도 된다(스킬 console-flash-hunt).

## 절차
1. **신고 시각 잡기.** 사장님이 "떴다"고 한 시각 직전 3분이 범위다. 창이 더 안 뜨는 시점이 신고 시점이다.
2. **프로세스 생성 집계.** 90~150초 동안 새로 생긴 프로세스를 부모별로 센다(`Get-CimInstance Win32_Process` 반복 조회, WMI 이벤트는 접근 거부될 수 있음). `pythonw`·서비스가 부모인데 `ffprobe`·`git`·`cmd`가 자식이면 용의자다.
3. **용의 코드 확인.** 그 부모 스크립트에서 `subprocess` 호출에 `creationflags`가 있는지 본다. 없으면 `CREATE_NO_WINDOW`를 넣는다. 파일이 많으면 `subprocess.run` 등을 기본값으로 감싸는 보호막(shorts-lab 도구 86개에 적용, 커밋 f15b99c)을 쓴다.
4. **재현 시험.** `python scripts/ops/console_flash_watch.py 200 결과.json`을 띄워 두고, 의심 예약 작업을 `Start-ScheduledTask`로 12초 간격 순차 실행한다. 감시기는 새로 보이는 창을 시각·소유 프로그램과 함께 기록한다. 기본 터미널이 Windows Terminal이면 소유자가 `WindowsTerminal.exe`로 찍힌다.
5. **대조 시험.** 먼저 일부러 창을 띄워 감시기가 잡는지 확인한다(이번엔 잡혔다).
6. **기록.** 원인 목록과 고친 파일을 공정 카드 `핏-영상생성`에 남긴다.
