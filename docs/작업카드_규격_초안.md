# 작업 카드 규격 (초안, 2026-09-20, 사장님 승인 대기)

> 목적: 글 한 편이 마야, 헤르메스, 제미나이, 탐을 거쳐 끝까지 흐르는 동안 **누가 무엇을 하고 있는지 한 장에 남고**, 한 단계가 끝나면 **다음 담당이 자동으로 깨어나며**, 사장님은 **세 번만** 알림을 받는다.
> 이 문서는 설계 초안이다. 아직 만들지 않았다. 승인되면 1건으로 시험한 뒤 넓힌다(튜터 원칙 5: 검증 없는 설계는 자산이 아니다).
> 공개 저장소이므로 카드에는 비밀값·고객 정보·사업 전략을 쓰지 않는다. 산출물은 내용을 복사하지 않고 경로만 적는다.

## 1. 카드는 파일 한 장이다
- 글 한 편 = 카드 한 장. 위치: `solar-bible/cards/<날짜>-<짧은이름>.md`(제안. 위치는 미결정 1번).
- git이 이력·백업·동기화를 해 준다. 이미 쓰는 경로(`tasks/`, `mailbox/`)와 같은 방식이라 새로 운영할 것이 없다.

```
---
id: 20260921-핵심인재이탈
제목: 핵심 인재는 왜 말없이 떠날까
상태: 진행          # 접수 / 진행 / 사장님차례 / 완료 / 실패 / 취소
단계: 수집          # 의뢰 / 수집 / 검증 / 질의 / 수정 / 집필 / 확정
담당: 헤르메스
다음: 제미나이
막힘: 없음          # 있으면 이유 한 줄
사장님 할 일: 없음  # 있으면 무엇을 결정할지 한 줄
산출물:
  - reports/maya-628-claims.md
---
## 이력 (도구가 자동 기록. 손으로 고치지 않는다)
2026-09-21 09:00:12 접수 마야
2026-09-21 09:00:40 수집 시작 헤르메스
```

## 2. 상태 말은 표준을 빌린다
구글 A2A 규격의 작업 상태 7종에서 우리에게 필요한 6개만 쓴다(하이쿠 수집분, 원문 미확인).

| 우리 말 | A2A | 뜻 |
|---|---|---|
| 접수 | submitted | 카드가 만들어짐 |
| 진행 | working | 담당이 일하는 중 |
| **사장님차례** | input-required | 사장님이 결정해야 다음으로 감 |
| 완료 | completed | 끝 |
| 실패 | failed | 막혀서 사람이 봐야 함 |
| 취소 | canceled | 중단 |

## 3. 단계 7개 (마야가 말한 흐름 그대로)
의뢰(마야 → 헤르메스) → 수집(헤르메스) → 검증(제미나이) → 질의(마야가 심플리파이어 다이얼로그에 질의) → 수정(에러 나면 탐) → 집필(마야, 두 결과를 합쳐 글쓰기) → 확정(사장님 컨펌).
- **검증 단계의 담당은 지금은 사람이 잇는다.** 제미나이 검증을 자동으로 돌리는 도구가 아직 없다(9/19 확인). 카드에는 "검증 단계 미실행 또는 수동"으로 적는다.

## 4. 갱신 규칙 (충돌과 거짓 기록을 막는 장치)
1. 에이전트는 카드 파일을 직접 고치지 않고 **`card.py`(만들 것)** 로만 갱신한다: `new`, `advance`, `block`, `ask-boss`, `done`, `show`.
2. **시각은 도구가 기록한다.** 모델이 시각을 적으면 안 된다(지원사업 보고서에서 접속 시각이 어긋난 사고).
3. 자기 단계만 갱신한다. 남의 단계를 대신 넘기지 않는다.
4. 산출물은 경로만 적는다. 내용은 복사하지 않는다.

## 5. 다음 담당을 깨우는 법 (이미 실측한 부품)
| 대상 | 방법 | 실측 |
|---|---|---|
| 헤르메스 | 카드 갱신 → 지시서가 `tasks/pending`에 올라감 → 감지기 → 폴러 | 지시서 push부터 완료 폴더 도착 56초(감지기 수정 후 1건) |
| 열린 세션(마야, 탐) | 카드 폴더 감시 프로그램이 이벤트로 감지하고 종료하며 세션을 깨움 | 감지 12밀리초, 깨움 6~11초 |
| 닫힌 세션 | 깨울 수 없음. 우편함에 남기고 다음에 열 때 읽음 | 한계 |
- 단계 하나의 인계 오버헤드는 약 1분 이내로 예상한다. 각 부품은 쟀지만 **전체를 이어서 잰 적은 없다.** 시험으로 재는 것이 이 초안의 첫 검증이다.

## 6. 사장님 알림은 세 번
| 시점 | 내용 | 사장님 할 일 |
|---|---|---|
| 접수 | "무엇을 시작했고 예상 언제 끝나는지" 한 줄 | 없음 |
| 막힘 또는 사장님차례 | "어디서 막혔고 무엇을 결정해 주세요" 한 줄 | 있음 |
| 완료 | "결과 위치" 한 줄 | 없음 |
- 카드 상태가 바뀔 때 도구가 자동으로 보낸다. 단계마다 알리지 않는다(알림 피로).
- "지금 어디까지 왔나"는 `card.py show`로 한 줄에 보인다. 스튜디오 화면 표시는 만들지 않는다(아래 신호 참고).

## 7. 지금 하지 않는 것과 넘어갈 신호
| 하지 않는 것 | 넘어갈 신호 |
|---|---|
| Temporal, Inngest, LangGraph 등 워크플로 엔진 | 동시에 도는 카드가 하루 여러 건이 될 때 |
| Claude Code 에이전트 팀 | 한 세션 안에서만 작동해 우리 구조(별도 세션)와 안 맞음. 공유 작업 목록이 세션 간으로 확장될 때 |
| 스튜디오 실시간 진행 화면 | 사장님이 "알림 세 번으로 부족하다"고 하실 때 |
| 채널·웹훅·메시지 서버(NATS 등) | 다른 PC 세션과 즉시 통신이 필요해질 때 |

## 8. 시험 계획 (승인 후)
1. `card.py`를 최소 기능(`new`, `advance`, `show`)으로 만든다. 테스트를 같이 만든다.
2. 실제 글 한 편 또는 그에 준하는 작업 하나를 카드로 흘려, **접수부터 확정까지 구간별 시각을 자동 기록**한다.
3. 결과(전체 소요, 구간별 인계 시간, 막힌 곳)를 [탐 KPI](탐_KPI.md)에 남기고 규격을 고친다.

## 9. 미결정 (사장님 확인)
1. 카드 위치: `solar-bible/cards/`(헤르메스와 같은 저장소, 신PC 로컬 감시가 쉬움)로 갈지, 이 저장소 `docs/`로 갈지.
2. 시험 대상: 마야의 다음 글 한 편이 좋다. 어느 글로 할지는 마야와 정한다.
3. 알림 채널: 카드 알림도 "사장님 할 일이 있을 때만" 원칙(요청이 있는 우편만 폰으로)과 충돌하지 않게, 접수·완료 알림은 폰이 아니라 에이전트 채널로 보낼지.
