# 지투 프로세스표: 고객에게 메일 보내는 과정 (2026-10-05 신설)

> **DB 이관 완료(2026-10-06)**: 단계 카드는 운영 DB 공정 `지투-고객메일`에도 있다(`python scripts/ops/proc.py steps 지투-고객메일`). 새로 배운 것은 `proc.py add`로 DB에도 쓴다.

> 고객에게 서비스 개편·런칭을 알리는 메일 한 통을 **조사 → 사실 확인 → 초안 → 컨펌 → 렌더 확인 → 발송 → 회신** 순서로 보낸다. 새로 배운 것은 해당 단계에 덧붙인다. 사례: 10/5 외부 고객 1호(Carvit 사용 5인) 개편 안내 메일. 목차: [지투_프로세스표.md](지투_프로세스표.md).

## 지켜야 할 규칙 (어기면 멈춘다)
- **사장님 컨펌 없이 고객에게 보내지 않는다.** 컨펌 뒤에 지투가 직접 발송한다(사장님 9/24 확대 결정). 컨펌은 채팅 또는 컨펌-지투 방 번호로 받는다.
- 한국 명절 연휴에는 급하지 않은 외부 연락을 하지 않는다.
- 고객 데이터(실명, 실제 사용 내용)는 공개 저장소에 쓰지 않는다. 초안은 비공개 저장소 `simplifier-saegim`에 둔다.
- Carvit 화면·메일에는 회사 이름 Simplifier와 로고를 보이지 않는다(UX 가이드 1.34). 연결에 쓰는 값은 **설치 코드** 한 이름으로만 부른다.

## 1. 알릴 일이 생겼는지 판단
- 이용 방법·이름·주소·로그인 방식이 바뀌어 고객이 알아야 하면 보낸다. 내부 구현만 바뀌면 보내지 않는다.
- 사례(10/5): 새김이 Carvit으로 이름이 바뀌었고, 새 사이트(carvit.ai)·구글·깃허브 로그인·새 주소가 생겼는데 고객이 모를 수 있었다(사장님: "우리 사이트도 만들었는데 안 보내도 되나요?").

## 2. 사실 확인 (주장마다 근거)
- 메일에 쓰는 문장마다 **라이브 실측이나 기록**이 있어야 한다. 예: 소셜 로그인은 대장 N19 실측, 이메일 링크 종료는 백로그 P12, 옛 주소 유지는 `MCP_Carvit_도메인_산정.md`.
- 확인하지 못한 것은 약속하지 않고 초안 아래 "발송 전 지울 메모"에 적는다. 사례: 구글·깃허브 계정이 기존 계정에 연결되는지는 5인 계정으로 확인 못 해서 "같은 메일 주소의 계정으로"라는 조건만 넣었다.

## 3. 작성법 조사 (제미나이 검색 연동)
- 명령(최신 origin/main 워크트리에서, 공용 main이 뒤처졌으면 옛 스크립트가 돈다): `python scripts/ops/ask_vertex.py <질문파일> <출력파일> --who 지투 --model gemini-3.8-flash --search`.
- 질문에 넣을 것: 구조·제목 예시·반드시 담을 정보·톤·한국어 B2B 관례·광고성 정보 표기 필요 여부, **항목마다 전체 URL 요구**.
- 받은 링크는 `curl -m 30`으로 열어 대조한다. 안 열린 링크의 주장은 "직접 확인 전"으로 표기한다(10/5: KISA 안내서 링크 400). 결과 원문은 `docs/mailcopy/`에 보존.
- 10/5 조사 결과 요약: 소수 기존 고객에게는 **1:1 파트너 서신** 성격. 제목에 변경 성격과 조치 필요 여부, 본문은 요약 → 바뀐 것 → 그대로인 것 → 지금 할 일(없으면 없다고) → 문의(답장 한 줄) 순서. 길이 A4 반 장~한 장, 불릿. 모호한 수식어와 판촉 문구를 피한다. 기존 계약 관계의 이용 방법·기능 변경 안내는 정보성이라 광고 표기가 필수가 아님(KISA 근거는 미확인).

## 4. 초안 쓰기
- 제목: `[Carvit] 새 사이트와 로그인 개편 안내 (바꾸실 설정은 없습니다)`처럼 **무엇이 바뀌었고 고객이 할 일이 있는지**를 한 줄에.
- 본문 순서: 감사 → 요약 한 줄 → 바뀐 것 → 그대로인 것 → 지금 하실 일 → 답장 요청 → 발신. 이름이 바뀌었으면(새김→Carvit) 반드시 첫 단락에.
- 첫 초안이 4줄로 너무 짧아 사장님이 보완을 요구했다(10/5). 정보 목록(바뀐 것·달라지는 점·안 바뀌는 것·지금 할 일·문의)을 채운 뒤 길이를 줄인다.
- 초안은 `docs/mailcopy/<고객>_notice_vN.md`에 저장한다(예: `ztosigma_notice_v2.md`).

## 5. 컨펌 요청
- 컨펌받을 결과물 자체를 텔레그램 컨펌-지투 방으로: `python scripts/ops/tg_boss.py text --file 초안.md --persona 지투`.
- 채팅에는 마야 형식(결정 하나, 선택지 번호와 이름, 추천)으로 "발송해도 되는지"와 정해야 할 선택(발신자 표기 등)을 묻는다. 고쳐서 다시 보내면 "이전 초안은 무효"를 적는다.

## 6. 발송 전 렌더 확인
- HTML 메일은 저장 → 브라우저에서 렌더 → 다시 조회해 세 단계를 거친 뒤 발송한다(9/28 깨진 메일 사고). 수신자 목록을 한 번 더 읽는다.

## 7. 발송과 기록
- 발송은 hello@carvit.ai(Resend)로, 회신은 hello@carvit.ai가 지투에게 텔레그램으로 알린다(백로그 M1 완료).
- 발송 후 대장에 한 줄(누구에게, 언제, 회신 대기)과 `worklog.py add`로 기록. 회신이 오면 마찰 항목은 새김 UX 백로그에 올린다.

## 7-1. 발송 방법과 기록 (2026-10-05 외부 고객 1호)
- **발송 도구는 Gmail 커넥터**(`send_message`)다. 커넥터가 꺼져 있으면 `set_session_connector_enabled("Gmail")`로 켜고, **도구는 그 턴이 끝난 뒤에야 쓸 수 있으므로** 짧은 `Monitor`(`sleep 20; echo ...`)로 다음 턴을 깨운 뒤 보낸다. 수신자 목록은 이 공개 저장소에 두지 않는다. 고객별 수신자와 발송 기록은 비공개 저장소 simplifier-saegim의 `docs/mailcopy/`와 해당 예약 작업 파일에서 읽는다.
- **사장님이 문안을 직접 확정해 주면 그 문안으로 보낸다.** 오타는 지투가 고치되 의미는 바꾸지 않는다(사장님 10/5). 서명에 회신 주소를 붙인다.
- **발송 뒤 확인**: `get_message(id, MINIMAL)`로 라벨이 SENT인지, 수신자 수와 제목이 맞는지 본다. 10/5 외부 고객 1호 건은 라벨 SENT와 수신자 5인을 확인했다(메시지 id와 수신자는 비공개 기록에).
- 앞선 체크인 메일에서 이미 안내한 내용(예: 새김→Carvit 이름 변경)은 다음 메일에서 다시 설명하지 않는다. 안내 이력을 먼저 확인한다.
- **교훈**: 사장님 확정 문안은 초안 v2에서 이름 변경 단락을 빼고, "MCP로 먼저 만나셨다면 이제 사이트에서 추가로 이용"을 감사 문단에 넣고, 바뀐 것에 사용량 대시보드·많이 참조한 절·버전별 가이드 확인을 더했다. 다음 메일부터 첫 초안에 이전 안내 이력과 사이트 기능을 먼저 반영한다.
- **공개 저장소에는 고객 수신자·메시지 id를 쓰지 않는다**(10/5 자동 분류기가 지투의 첫 기록을 공개 게시로 막았다).

## 이 공정의 빈칸 (채워 나갈 것)
- 외부 고객 1호 5인 계정으로 소셜 로그인 연결을 실제 확인하는 방법(점검 계정 키가 없어 못 함, 대장 N29·N139).
- 발신자 표기: 10/5는 "Carvit PO 지투 드림 · hello@carvit.ai"(사장님 문안). 보내는 Gmail 계정 주소에 회사 도메인이 보인다. hello@carvit.ai로 직접 보내는 경로(Resend)는 이 공정에 아직 연결하지 않았다.
