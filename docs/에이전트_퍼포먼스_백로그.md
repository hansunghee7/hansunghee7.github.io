# 에이전트 퍼포먼스 극대화 백로그 (2026-09-19)

사장님 지시 3가지가 기준입니다.
1. 사장님이 PowerShell을 직접 실행하는 일, 답답한 폴링 대기, 헤르메스에게 복사·붙여넣기를 최소화한다.
2. 에이전트가 쉬는 사이 헤르메스를 풀로 돌린다. 헤르메스를 적극 쓰고 Claude 토큰 사용을 최소화한다.
3. SSH, 헤르메스 고도화, 구PC Linux를 활용해 에이전트 퍼포먼스를 끌어올린다. 탐 업무 고도화 4항목 포함.

역할 분담 원칙: 오래 걸리는 실행, 초안 작성, 장비를 다루는 일은 헤르메스. 판정, 설계, 검증은 탐.
탐이 헤르메스를 부를 때는 대기열 대신 직접 호출을 기본으로 한다
(`hermes chat --oneshot`, 2026-09-19 실측 왕복 12초). 대기열(pending)은 야간·대량 작업용이다.

## 5. 문서 계층 정렬과 OKR (사장님 지시 4, 2026-09-19 밤, 미착수)

**목표**: 최상위 문서(회사 목표)부터 최하위 문서(개별 역할 노트, 스킬)까지 문서 간 정렬과 역할을 다시 정의한다. 각 문서는 에이전트의 로드 부하를 최소로 하면서, 각 역할이 자기 일을 충실히 하게 만들어야 한다. 회사 목표와 개별 조직원(페르소나)의 활동을 잇는 OKR을 벤치마킹해서 우리 규모에 맞게 고도화한다.

**방식**: 딥리서치 파이프라인(`solar-bible/docs/딥리서치_파이프라인.md`) 그대로. 헤르메스가 수집, 제미나이가 출처 대조, 탐이 판정한다. 내부고객은 사장님과 각 페르소나다.

**리서치 3갈래**
| 갈래 | 질문 | 근거 기준 |
|---|---|---|
| A. 클로드 문서 구조 모범 사례 | CLAUDE.md 계층(전역, 프로젝트, 하위 폴더), rules, skills, memory, 서브에이전트 정의는 각각 무엇을 담고 언제 로드되는가. 고수들의 구조는 무엇이며 로드 부하는 어떻게 줄이는가 | 공식 문서(code.claude.com/docs) 우선. 커뮤니티 사례는 `[커뮤니티]`로 표기하고 원문 인용 |
| B. OKR 벤치마킹 | 회사 목표와 개인 활동을 잇는 방법(OKR 원전, 소규모 팀과 1인 기업 적용 사례). 1인 + AI 조직에서 무엇이 남고 무엇이 과한가 | 원전 저서·공식 가이드·사례 글의 원문 인용 |
| C. 우리 문서 인벤토리와 정렬 진단 | 우리 문서를 계층별로 세고(줄 수, 로드 시점, 중복, 상위 목표와의 연결 유무), 어디가 어긋났는지 | 탐이 서브에이전트로 읽기 전용 실측. 표로 제출 |

**산출물 3개**
1. 문서 계층도: 최상위부터 최하위까지, 각 문서의 역할, 로드 시점, 줄 수 상한, 누가 고치는가.
2. OKR 축소판 초안: 회사 목표(O) 1~2개와 핵심 결과(KR), 페르소나별 목표 1개씩과의 연결표. 최상위(회사 목표) 결정은 사장님이 한다.
3. 이전 계획: 위 재정의에 맞춰 CLAUDE.md 다이어트 PR과 역할 노트 작성을 정렬하는 순서.

**지금 하지 않는 것 (규모 최적화)**: OKR 소프트웨어, 분기 회고 자동화, 개인 평가 점수화. 1인 + AI 규모에서는 목표 문서 한 장과 주간 점검이면 충분하다. **넘어갈 신호**: 외부 사용자, 매출, 채용이 생기면 분기 OKR을 정례화한다.

**다른 작업과의 순서**: CLAUDE.md 다이어트 PR2~4는 저위험이라 그대로 진행한다. **PR5(보호 6절 압축)와 아침·저녁 의식 스킬화는 이 리서치 결과 뒤로 미룬다**(문서 구조 자체가 바뀔 수 있음). 역할 노트는 얇게(80줄) 먼저 만들고 결과에 맞춰 조정한다.

**착수 조건과 모델**: 제미나이 3.6-flash 하루 한도가 초기화된 뒤(2026-09-20 이후 권장, 오늘 19일 검증 키 소진. 초기화 시각은 미확인이라 20일 아침에 실제로 확인). 수집은 헤르메스와 하이쿠, 갈래 C 실측은 소넷, 종합(계층도와 OKR 초안 설계)은 판단이 필요해 오퍼스를 쓰며 **쓰기 전에 사장님께 컨펌**을 받는다.
